Define installation options in `/etc/zeabur-installer/config.yaml`, review the plan with `plan`, and install with `apply`. Use this approach to keep the configuration in version control, repeat the same installation on multiple machines, or install through automation.

The [web interface](quickstart.mdx) and commands read and write the same config file and install the same components. You can also download the config file from the web interface's “Review” step, then install from the command line.

![The “Review” step shows an installation summary, with a “Download” button under “Details” to save the config file](../images/shots/installer-review.avif)

## Prepare the server and installer

Prepare a host that meets the [server requirements in the quickstart](quickstart.mdx#prepare-the-server), and download the installer for its architecture.

## Create the config file

Create `/etc/zeabur-installer/config.yaml` as root. For public domains, the minimum configuration is:

```yaml
access:
  mode: domain
  identity: login.example.com
  zeabur: zeabur.example.com
```

Replace both domains with the ones you want to use. For DNS and port requirements in public domain mode, see [connection options in the quickstart](quickstart.mdx#2-choose-how-to-connect).

If you omit `enable` and `disable`, the installer installs the [default components](../reference/installer-configuration.mdx#component-selection). If you omit `profile`, it uses `single-node`. If you omit `distribution`, it installs K3s. For a server with 8 GiB of memory or more, or to run the control plane on three servers later, add `distribution: rke2`.

For a test machine, use `local` mode instead:

```yaml
access:
  mode: local
  identity: login.<address>.sslip.io
  zeabur: zeabur.<address>.sslip.io
```

Replace `<address>` with the server's address.

For all fields, see [Installer configuration](../reference/installer-configuration.mdx). The optional `sources` field lets you use your own builds of the Catalog, images, and charts. If you omit it, the installer uses its pinned versions.

## Review the installation plan

Run:

```sh
sudo zeabur-installer plan
```

`plan` runs host checks and lists the following without changing the host:

- Kubernetes distribution and version (K3s or RKE2).
- Components and charts.
- Namespaces.
- Storage classes.
- URLs.
- Estimated idle memory usage and warnings.

If any checks fail, the output indicates that `apply` will stop. Fix these issues before starting the installation.

For JSON output, run:

```sh
sudo zeabur-installer plan --json
```

`plan --json` doesn't run host checks.

Without a config file, `plan` generates sslip.io names from the server's address and shows a preview with the default components. It uses `domain` mode when the server has a public address, and `local` mode otherwise. You must create a config file before running `apply`.

## Run the installation

After reviewing the configuration, run:

```sh
sudo zeabur-installer apply
```

`apply` runs host checks first. If any check fails, it stops before making any changes.

Once the checks pass, it configures the host, installs K3s or RKE2 with CIS hardening, sets up namespaces and connection rules, configures storage, installs the selected components, and then installs Zeabur Identity and Zeabur.

`apply` determines what to install from the configuration at the time it runs. If you change the YAML after running `plan`, `apply` uses the updated configuration.

### Resume an interrupted installation

After fixing the cause of the interruption, run the command again with the same configuration:

```sh
sudo zeabur-installer apply
```

Each step checks what's already complete and resumes where it left off.

## Register an admin account and sign in

When installation finishes, the terminal prints:

- The Zeabur URL.
- The Zeabur Identity URL.
- A passkey registration link for the first admin account.

In `local` mode, first import this certificate into your browser's or system's trust store:

```text
/var/lib/rancher/zeabur-installer/local-ca.crt
```

Open the registration link, register a passkey, and then open the Zeabur URL to sign in.

<Callout type="warn">
The registration link for the first admin account creates an admin account. Whoever opens it first gets full control of the cluster. Share it only with the person who will manage the cluster. The link can only be used once and expires after 24 hours.
</Callout>

## Check the installation

Run:

```sh
sudo zeabur-installer doctor
```

This checks K3s or RKE2, components, the default storage class, Zeabur Identity, and Zeabur.

| Exit code | Result |
| --- | --- |
| `0` | Healthy |
| `1` | Warning |
| `2` | Critical |
| `3` | Checks couldn't run, for example, because the command wasn't run as root |

## Common issues and fixes

| Issue | Fix |
| --- | --- |
| A port is in use, for example, by another running Kubernetes installation | Stop the process using the port, or use a clean host, then run `apply` |
| Certificates haven't been issued in `domain` mode | Check DNS for both domains and whether TCP port 80 is reachable from outside the host. Fix the issue, then run `apply` again |
| The browser doesn't trust the certificate in `local` mode | Import `/var/lib/rancher/zeabur-installer/local-ca.crt` into your browser's or system's trust store |
| The registration link for the first admin account has expired | Run `sudo zeabur-installer setup-link` on the server to generate a new link |

## Install with AI Agents

AI Agents such as Claude Code or Codex can follow the steps above to install for you. First let the AI Agent reach the server over SSH with an account that can run `sudo`, and sign in with a key. Don't give the AI Agent a password.

Paste the following to the AI Agent and replace `<user>@<server>` with your server:

```text
Install Zeabur on the server <user>@<server>. Connect over SSH and use sudo for commands that need root.

1. Following "Download and verify binaries" at https://oss.zeabur.com/docs/zeabur/reference/releases, download zeabur-installer from the latest release at https://github.com/zeabur-oss/zeabur/releases, choosing linux-amd64 or linux-arm64 from the server's `uname -m`. Verify the signature of SHA256SUMS, the file's SHA-256 and the build provenance, and extract only when all three pass. If any of them fails, stop and tell me. Don't change the verification options to make it pass.
2. Ask me for the two domains for Zeabur and sign-in (Identity). If this is a test machine, use local mode with zeabur.<address>.sslip.io and login.<address>.sslip.io. Write /etc/zeabur-installer/config.yaml following https://oss.zeabur.com/docs/zeabur/get-started/advanced-install.
3. Run sudo zeabur-installer plan, summarize the changes, warnings and failed checks for me, and wait for my go-ahead.
4. Once I agree, run sudo zeabur-installer apply. If it fails partway, fix the cause, then run it again with the same config.
5. When the installation finishes, run sudo zeabur-installer doctor and report the result.
6. Give me the registration link for the first administrator exactly as printed. Don't open it and don't register a passkey yourself.

For other details, see https://oss.zeabur.com/llms.txt.
```

To click through the web interface yourself, ask the AI Agent to use the [one command from the quickstart](quickstart.mdx#one-command) instead and hand you the link with the token to open.

<Callout type="warn">
The registration link for the first administrator creates an admin account, and whoever opens it first controls the whole cluster. Have the AI Agent give you the link, and don't let it open the link itself.
</Callout>
