---
title: Deploy your first service
description: Deploy a public Nginx image, from creating a project to opening it in a browser.
---

Put an Nginx page online: create a project, enter an image, review the changes, apply them, and open the Nginx welcome page in a browser. You don't need a Git repository. It takes about five minutes.

Before you start, you need a Zeabur installation you can sign in to and a domain that can point to the cluster, such as `web.example.com`. If an administrator has already configured an application domain, the form suggests an address, and you don't need to configure DNS yourself.

## Create a project

Open **Projects**, click **New project**, and enter `hello` in **Name**. This also becomes the Kubernetes Namespace name and can't be changed after creation.

![New project dialog with hello entered as the name](../images/shots/project-new.avif)

Click **Review changes**. Zeabur lists what it will do: create the `hello` Namespace, add a project label, and apply Pod Security `baseline`, which lets containers run as root but blocks access to the host. If everything looks right, click **Create**.

![Review screen for creating the hello project, showing the Namespace and security settings](../images/shots/project-new-review.avif)

If you don't see **New project**, your role doesn't have permission to create namespaces. Ask an administrator to create a project and add you to it, then continue with the next step.

## Deploy Nginx

In the `hello` project, click **Add**, then select **Docker image**:

| Field | Value |
| --- | --- |
| **Image** | `docker.io/nginxinc/nginx-unprivileged:1.30.5-alpine-slim` |
| **Name** | `web` |
| **Port** | `8080` |
| **Public domain** | Turn on, then use the suggested address or the domain you prepared |

Zeabur detects that `nginx-unprivileged` runs as user 101 and automatically selects **Strict**. The form explains why. This image listens on `8080`. You can also use `nginx:latest`, for which Zeabur selects **Compatible**. You can still switch the setting before creating the service.

After you enter the image, the form reads its declared ports and should fill in `8080` automatically.

![Image deployment form with the image, name web, detected port 8080, and public domain turned on](../images/shots/image-form.avif)

## Review changes, then apply

Click **Review changes**. Zeabur lists three objects to create:

- A `web` Deployment that runs the image with 1 replica
- A `web` Service that forwards `8080` to the container
- A `web` Ingress that routes the domain to the `web` Service

![Review screen for deploying web, listing the Deployment, Service, and Ingress to create](../images/shots/image-review.avif)

Nothing has been added to the cluster yet. If the domain is wrong, go back to the form and fix it. Once everything looks right, click **Create**. Zeabur takes you to the service page.

## Open the address

In the service's **Overview** tab, wait for the replicas to show `1/1` **Ready**. Then open **Networking** and click the domain. The browser displays the Nginx welcome page.

If **This address only supports HTTP** appears below the domain, the cluster isn't configured to issue certificates automatically. Open the address with `http://`. For HTTPS, ask an administrator to configure a cert-manager issuer.

Go to **Logs** to see the access log from opening the page.

The service's **Overview** tab looks like this. Use the tabs at the top to switch to **Logs**, **Networking**, **Variables**, and **Settings**:

![Overview tab for the web service, showing replicas, the image, and navigation tabs](../images/shots/service-overview.avif)

## Verify the result

- The service's **Overview** tab shows `1/1` **Ready**, and opening the address in a browser displays the Nginx welcome page.
- You can also use kubectl to see the three objects you created, each with the label `app.kubernetes.io/name: web`:

```sh
kubectl get namespace hello --show-labels
kubectl -n hello get deploy,svc,ingress -l app.kubernetes.io/name=web
```

The Namespace has `zeabur.com/project=true`, the Deployment's `READY` value is `1/1`, and the Ingress's `HOSTS` value is the domain you entered.

These are standard Kubernetes objects. You can create the same service with `kubectl apply` without Zeabur. For the full YAML, see “Do the same with kubectl” in [Deploy a container image](../deploy/image.mdx).

## If the page doesn't load

| What you see | What to check first |
| --- | --- |
| The replica never becomes ready, and events say the image can't be pulled | Check the image name and version for typos, and whether the node can reach Docker Hub |
| The replica count stays at 0, and events mention Pod Security | Check that **Compatible** is selected for an image that needs root. If the project still enforces `restricted`, ask an administrator to change the project's Pod Security level to `baseline` |
| The service is `1/1` ready, but the address doesn't open | Check that DNS points to the cluster's entry point and **Port** is `8080` |
| **These changes expired** appears when you apply | Click **Review again**, review the new diff, and apply |

## Clean up

In the upper-right corner of the `web` service, open **More** and select **Delete service**. Zeabur lists the objects to delete first: the Deployment, Service, and Ingress. Review the list, then apply.

To delete the project too, open the project's **Settings**, find **Danger zone**, and click **Delete project**. Review what will be deleted, then enter `hello` to confirm. See [Delete a project](../configure/delete-project.mdx). **Remove from Zeabur** in the same section only removes the project label. The Namespace and everything in it remain.
