---
title: Connect an existing cluster with a kubeconfig
description: Run zeaburctl ui on your own computer to open an existing cluster's services with a kubeconfig. No Zeabur Identity, and nothing is installed in the cluster.
---

If you have a kubeconfig that reaches the cluster, you can open Zeabur on your own computer. Nothing is added to the cluster and you don't need Zeabur Identity. Reads, **Review changes** and applied changes all use that kubeconfig's rights.

## Prepare

| You need | What it's for |
| --- | --- |
| A kubeconfig that reaches the cluster | Zeabur uses its current context. Add `--context <name>` to use another |
| `zeaburctl` for your computer | Download it from [Releases and verification](../reference/releases.mdx). It runs on Linux and on macOS with Apple silicon; on Windows, run it in WSL |
| Rights to read | With rights to read Namespaces, Deployments, replicas and events, you can see services and their status. This is the **Viewer** role's rights |
| Rights to change | To deploy or change a service you need to create and edit Deployments, Services and Ingresses in the project. This is the **Developer** role's rights. A new project also needs the right to create a Namespace |

The cluster's RBAC decides these rights, and Zeabur never adds any. For what each role can do, see [Member roles](../reference/permissions.mdx#member-roles).

## Open Zeabur

```sh
zeaburctl ui
```

The terminal prints a link. Open it in your browser. `zeaburctl ui` listens only on `127.0.0.1` on your computer, and the token in the link works once. Add `--context production` to open another cluster. Press `Ctrl-C` to close it. Applied changes stay in the cluster.

## What you see first

- **Projects** lists Namespaces that carry Zeabur's project label as projects, and the rest under **Other namespaces**. Open one and its services, domains and environment variables are already there, with nothing to import.
- Where Zeabur can't read something, the screen says which rights are missing, for example "Some checks need rights you don't have.", rather than staying blank.
- If you don't see **New project**, your account can't create a Namespace. Ask an administrator to create the project, or deploy in an existing Namespace.
- This route has no sign-in and no members: whoever holds the kubeconfig has its rights. To let a team sign in one by one, [install Zeabur in the cluster](../install/existing-cluster.mdx).

What `zeaburctl ui` sends for the [experience program](../reference/telemetry.mdx), and how to turn it off, is on that page. It also check GitHub for a newer version; set `NO_UPDATE_NOTIFIER` to turn that off, see [Update check](../reference/telemetry.mdx#update-check).
