Use Zeabur OSS to see the services, logs, and domains in your Kubernetes cluster. When you change a setting, **Review changes** comes before anything is applied. Pick the starting point that matches your environment. For what Zeatend, Zeabur Identity, Zeabur Catalog and Zeabur Builder each do, see the [overview](https://oss.zeabur.com/docs/overview/).

## Start with one server

On a new Linux server, Zeatend sets up Kubernetes, then one `helm install` adds Zeabur OSS.

[Install Zeabur OSS on a server](get-started/quickstart.mdx)

## Use an existing Kubernetes cluster

You need cluster admin access and Helm. The chart installs Zeabur Identity too, and kube-apiserver must trust it, as [Install Zeabur OSS in an existing cluster](install/existing-cluster.mdx) shows. The Zeabur OSS address must open over HTTPS so the browser offers passkeys.

When the install finishes, sign in to Zeabur OSS with a passkey, then find an existing Namespace under **Projects** or add a project to deploy services.

[Install Zeabur OSS in an existing cluster](install/existing-cluster.mdx)
