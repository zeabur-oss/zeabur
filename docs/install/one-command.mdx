---
title: Install with Zeatend
description: On a new Linux server, Zeatend sets up Kubernetes, then one helm install installs Zeabur OSS.
---

When you finish this page, a new Linux server runs Kubernetes and Zeabur OSS, and you sign in to Zeabur OSS over HTTPS with a passkey.

Already have a cluster? [Install Zeabur OSS in an existing cluster](existing-cluster.mdx). To have Claude Code or Codex do it, see [Let an agent install for you](agent.mdx).

## Before you begin

- **A Linux server** with a public IP address, and ports 80 and 443 open to the internet. Let's Encrypt checks the addresses over port 80. For memory and disk, see Zeatend's [Supported servers and files](https://oss.zeabur.com/docs/zeatend/reference/hosts/).
- **Root on the server**, over SSH. Run the commands below as root. If you sign in as a regular user, run `sudo -i` first.
- **Zeatend, Helm 4 and `zeabur-identityctl` on the server.** To get Zeatend, see [Download Zeatend](https://oss.zeabur.com/docs/zeatend/get-started/install/#download-zeatend) in Zeatend's docs. For `zeabur-identityctl`, see Zeabur Identity's [Release files and verification](https://oss.zeabur.com/docs/identity/reference/releases/).

<Steps>
<Step>

### Choose the domain

Set `DOMAIN` on the server as [Choose the domain](existing-cluster.mdx#choose-the-domain) shows. With your own domain, point its DNS records at this server.

</Step>
<Step>

### Set up Kubernetes with Zeatend

```sh
zeatend plan
```

`zeatend plan` checks the server and lists what it will install. It changes nothing. If a line says `FAIL`, fix what that line says first, as Zeatend's [Check the plan](https://oss.zeabur.com/docs/zeatend/get-started/install/#check-the-plan) shows. With no `FAIL`, install:

```sh
zeatend apply
```

`zeatend apply` installs K3s and shows each step. The install keeps running if your SSH session drops. Run `zeatend apply` again to follow it.

</Step>
<Step>

### Let the cluster trust sign-in

Kubernetes accepts the sign-in tokens of the Zeabur Identity you install in the next step only when Zeatend's `apiServer.authenticationConfig` names Zeabur Identity as a token issuer. `zeabur-identityctl kube-config` prints that setting. It reads the cluster, so it runs now, after the cluster exists. The second `zeatend apply` restarts K3s with the setting:

```sh
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
mkdir -p /etc/zeatend
authn=$(mktemp)
zeabur-identityctl kube-config --issuer "https://identity.$DOMAIN" --distro k3s --discovery public > "$authn" && {
  printf 'distribution: k3s\napiServer:\n  authenticationConfig:\n'
  sed 's/^/    /' "$authn"
} > /etc/zeatend/config.yaml &&
  zeatend apply
```

`zeabur-identityctl` also prints how to install the setting by hand. Ignore that part, because Zeatend does it. If it prints an error instead, the Zeatend configuration isn't written and `zeatend apply` doesn't run. Fix what the error says, then run the block again.

</Step>
<Step>

### Install Zeabur OSS

Helm uses the K3s kubeconfig that the previous step set. In a new SSH session, run `export KUBECONFIG=/etc/rancher/k3s/k3s.yaml` first. Run `helm install` as [Install with Helm](existing-cluster.mdx#install-with-helm) shows, and sign in with a passkey as [Create the admin account](existing-cluster.mdx#create-the-admin-account) shows. The previous step already made the cluster trust sign-in, so skip "Let the cluster trust sign-in" there.

</Step>
</Steps>

After you sign in, install the other components you need on the **Cluster** → **Components** page. See [View and install cluster components](../cluster/components.mdx).
