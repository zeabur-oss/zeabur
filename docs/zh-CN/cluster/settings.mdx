左侧的 **设置** 包含整个集群共用的配置：**集群名称**、**用量历史** 和 **登录设置**。新服务网址使用的域名在 **集群** → **概览** 的 **域名** 区域。这些配置都保存在 ConfigMap 中，有权限修改这份 ConfigMap 的人就能修改配置，通常是集群管理员。

**偏好设置** 中的语言和主题只保存在你的浏览器中，不影响其他人。

![设置页，从上到下是偏好设置、集群名称、登录设置和用量历史](../images/shots/cluster-settings.avif)

## 开始之前

- Zeabur 已安装在集群中。用 `zeaburctl ui` 在本机运行时，Zeabur 不保存配置，名称沿用 kubeconfig 中的集群名称，用量历史需要用 `--metrics-service` 指定。
- 你有权限更新 Zeabur 所在 Namespace（默认为 `zeabur`）中的 ConfigMap `zeabur-settings`，首次配置时还需要有权限创建它。

## 修改集群名称

集群名称显示在侧边栏和每个页面上，管理多个集群时用来区分。集群本身不会发生任何变更。

<Steps>
<Step>

### 填写名称

前往 **设置** → **集群名称**，在 **名称** 中填写新名称，最多 63 个字符，只能有一行。点击 **保存**。

</Step>
<Step>

### 改回默认名称

点击 **改用默认名称**，即可改回安装时的 `clusterName`。如果安装时没有配置，则使用 Zeabur 网址的主机名。

</Step>
</Steps>

## 选择用量历史的数据源

服务和节点的 **用量** 图表、磁盘用量，都从支持 Prometheus HTTP API 的存储服务读取。Zeabur 通过 Kubernetes API，以各用户自己的权限读取数据。启用 Zeabur Proxy 后，服务的用量历史改由 Proxy 从默认存储服务读取，项目成员只能看到自己项目的指标。

前往 **设置** → **用量历史**，在 **历史数据来源** 中填写该存储服务的 Service，格式为 `namespace/name:port`。默认使用 Zeabur 推荐的 VictoriaMetrics：`observability/vmsingle-vm-victoria-metrics-k8s-stack:8428`。点击 **保存** 后，**状态** 会显示：

| 状态 | 含义 |
| --- | --- |
| **有响应** | 能读取数据。 |
| **找不到** | 这个 Service 不存在，或尚未安装指标组件。 |
| **没有权限** | 你没有权限通过 Kubernetes API 读取这个 Service。 |
| **没有响应** | Service 存在，但没有响应 Prometheus API 查询。 |

能直接读取存储服务的人可以看到所有项目的指标，因此只应向有权限查看整个集群的人开放。改用其他存储服务后，Zeabur Proxy 不会读取它，项目成员将看不到用量历史，只有能直接读取的人才能看到。点击 **改回默认**，即可恢复安装时的配置。

## 配置新服务的域名

新服务的建议网址为 `<服务>-<项目>.<域名>`。前往 **集群** → **概览** 的 **域名** 区域，点击 **编辑**，通过 **添加域名** 加入域名，再点击 **保存**。第一个域名为默认域名，最多可添加 20 个。点击 **改回安装时的域名**，即可恢复安装时的配置。

每个域名旁边会显示 DNS 是否指向这个集群。需要添加的通配符记录见[配置 DNS 记录](../configure/dns.mdx)。

![集群页的域名区域，列出应用域名 apps.example.com，并标注已指向这个集群](../images/shots/cluster-domains.avif)

## 登录设置

**设置** → **登录设置** 决定管理员账号闲置多久后退出登录，以及是否只能使用不会同步的通行密钥登录。这两项保存在 Zeabur Identity 的配置文件中，说明和 kubectl 操作方式见[权限](../reference/permissions.mdx)。

## 你的账号和通行密钥

左侧的 **账号** 列出你的用户名、用户组、在各项目中的角色，以及通行密钥和关联账号。通行密钥、关联账号和会话都由 Zeabur Identity 管理。点击 **管理登录方式**，前往 Zeabur Identity 添加或移除通行密钥、退出其他设备上的登录。

建议在手机上再添加一个通行密钥作为备用，以免丢失一台设备后无法登录。

## 用 kubectl 完成相同操作

集群名称、用量历史和域名都保存在 `zeabur` Namespace 中的 ConfigMap `zeabur-settings` 中。未填写的键使用安装时的值。`domain-suffixes` 每行填写一个域名，也可以用逗号分隔，第一个为默认域名：

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: zeabur-settings
  namespace: zeabur
data:
  cluster-name: tokyo-prod
  metrics-store: observability/vmsingle-vm-victoria-metrics-k8s-stack:8428
  domain-suffixes: |
    apps.example.com
    example.net
```

要恢复默认值，删除对应的键：

```sh
kubectl -n zeabur patch configmap zeabur-settings --type json -p '[{"op":"remove","path":"/data/cluster-name"}]'
```

安装时的值来自 Chart 的 `clusterName`、`metricsStore.service` 和 `domains.suffixes`。使用 Installer 安装时，域名来自配置文件中的 `suffixes`，见 [Installer 配置](../reference/installer-configuration.mdx)。

## 确认结果

- 侧边栏显示新的集群名称。
- **用量历史** 的 **状态** 为 **有响应**，服务的 **用量** 标签页中有图表。
- 添加服务时，网址默认使用第一个域名。
- 运行 `kubectl -n zeabur get configmap zeabur-settings -o yaml` 能看到你配置的值。

## 移除 Zeabur 后

只有 Zeabur 会读取这些配置，删除 `zeabur-settings` 不影响任何服务。
