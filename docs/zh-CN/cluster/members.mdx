打开 **成员**，点击 **邀请**，选择对方能访问的项目，再把设置链接发给对方。对方打开链接、添加通行密钥后，就能登录。

## 开始之前

- 集群已安装 Zeabur Identity，且 Zeabur Identity 以 `--invitations` 运行，设置链接才能使用。
- 你已用管理员账号登录 Zeabur。更改成员会修改 Zeabur Identity 的用户和 Kubernetes 的角色绑定。
- 项目角色需要启用 Chart 的 `memberRoles.enabled`（默认开启）。关闭后，邀请表单只能选择是否授予 **管理员** 权限。

## 邀请一位成员

<Steps>
<Step>

### 填写账号

在 **成员** 中点击 **邀请**。填写 **用户名**，**显示名称** 可以留空。用户名只能包含小写字母、数字、`-` 和 `.`，最多 63 个字符。

如果填写的是已有成员的用户名，这个链接会为该账号添加一把通行密钥，原有权限不变。

只想邀请别人加入一个项目的话，打开该项目的 **设置**，在 **成员** 中点击 **邀请**。这个项目会预先勾选，角色是开发者。这一部分也会列出谁能打开这个项目。

</Step>
<Step>

### 选择可访问的项目

在 **权限** 中选择 **管理员** 或 **指定项目**。选择 **管理员** 后，对方会获得管理员账号，可以完全控制整个集群，包括所有项目、节点和成员。管理员账号只能用通行密钥登录，不能用 GitHub 或 Google，见[管理员账号和普通账号](../reference/permissions.mdx#管理员账号和普通账号)。

选择 **指定项目** 时，勾选项目，再为每个项目选择角色。刚勾选时默认为 **查看者**：

| 角色 | 对方能做什么 |
| --- | --- |
| **开发者** | 部署、修改变量、重启、读取日志、打开终端，也能读取机密变量的值。 |
| **查看者** | 查看状态和事件，不能读取日志、做任何修改、打开终端或读取机密变量的值。 |

同一位成员可以在不同项目中担任不同角色。未勾选任何项目的成员也能登录，但只能看到节点和项目名称。

列表只列出项目。要在其他 Namespace 中授予角色，点击列表下方的 **同时显示 N 个不是项目的 Namespace**。

![邀请成员窗口，选择了指定项目，blog 的角色为查看者，shop 的角色为开发者](../images/shots/members-invite.avif)

</Step>
<Step>

### 检查后发送链接

点击 **检查变更**，确认新增的账号和项目权限，再点击 **邀请 erin**（`erin` 是用户名）。

![检查邀请的窗口，列出新账号和项目权限](../images/shots/members-invite-review.avif)

复制生成的链接，通过只有对方能收到的渠道发送。

![邀请完成后显示的设置链接和有效期](../images/shots/members-invite-link.avif)

邀请链接在 7 天内有效，只能使用一次，完整链接也只显示这一次。对方设置好通行密钥后，回到 **成员**，查看其 **通行密钥** 列是否显示数字，再让对方登录并打开分配的项目。

</Step>
</Steps>

<Callout type="warn">
谁先打开设置链接，谁就能为这个账号添加通行密钥并登录。如果链接发错人或泄露，在 **待使用的设置链接** 中点击 **撤销**，再生成新链接。
</Callout>

## 调整权限或处理设备丢失

在成员行的操作菜单中选择 **更改权限**，调整项目和角色，点击 **检查变更** 后再点击 **保存权限**。权限立即生效，但对方已打开的终端会一直保持到关闭为止。

将成员改为 **管理员** 后，其账号就变为管理员账号，之后只能用通行密钥登录，通过 GitHub 或 Google 登录的会话会结束。取消 **管理员** 后，账号就改回普通账号。

要为成员添加一台备用设备，选择 **新的设置链接**。这个链接在 24 小时内有效，只能使用一次，原有通行密钥和会话都会保留。

设备丢失或被盗时，选择 **丢失设备后重置**，勾选 **同时移除其通行密钥、关联账号和会话**，再点击 **重置并生成链接**。在对方打开新链接之前，任何人都无法用这个账号登录。

## 用 kubectl 完成相同操作

成员是 Zeabur Identity 的 `User`，存放在 `zeabur-identity` Namespace 中。权限通过普通角色绑定授予，名称均为 `zeabur-member-<用户名>`：一个 ClusterRoleBinding 绑定到 `zeabur-member`，让成员能登录并看到节点和项目名称；每个分配的项目再各有一个 RoleBinding，绑定到 `zeabur-project-developer` 或 `zeabur-project-viewer`。Kubernetes 看到的用户名是 `zeabur:<用户名>`。

下面将 `erin` 设为普通账号，并授予其 `shop` 项目的开发者权限：

```yaml
apiVersion: identity.zeabur.com/v1alpha1
kind: User
metadata:
  name: erin
  namespace: zeabur-identity
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  username: erin
  displayName: Erin Lin
  groups: []
  accountType: Regular
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: zeabur-member-erin
  labels:
    app.kubernetes.io/managed-by: zeabur
    zeabur.com/member: erin
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: zeabur-member
subjects:
  - apiGroup: rbac.authorization.k8s.io
    kind: User
    name: zeabur:erin
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: zeabur-member-erin
  namespace: shop
  labels:
    app.kubernetes.io/managed-by: zeabur
    zeabur.com/member: erin
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: zeabur-project-developer
subjects:
  - apiGroup: rbac.authorization.k8s.io
    kind: User
    name: zeabur:erin
```

要授予管理员权限，将 `accountType` 改为 `Admin`，无需另外绑定角色。`groups` 不能填写 `admins`，这个组只能由账号类型决定。

应用后，用 `zeabur-identityctl invite` 生成设置链接，发给对方：

```sh
zeabur-identityctl invite --username erin
```

要更改权限，修改 RoleBinding 的 `roleRef`（`roleRef` 不支持修改，需要删除后重建），或在其他项目中创建相同的 RoleBinding。移除成员时，先删除角色绑定，再删除其设置链接、通行密钥和会话，最后删除 `User`：

```sh
kubectl delete clusterrolebinding,rolebinding -A -l zeabur.com/member=erin
kubectl -n zeabur-identity delete zbinvite,zbcred,zbgrant -l identity.zeabur.com/user=erin
kubectl -n zeabur-identity delete zbuser erin
```

其他操作，例如通过组授权、停用账号，见 Zeabur Identity 的[管理用户](https://oss.zeabur.com/docs/identity/managing-users)。

## 确认结果

- **成员** 中列出 `erin`，对方设置好通行密钥后，**通行密钥** 列显示数字，权限列显示 `shop` 和角色。
- `kubectl get clusterrolebinding,rolebinding -A -l zeabur.com/member=erin` 列出一个 ClusterRoleBinding，以及每个项目各一个 RoleBinding。
- 对方登录后，在自己的电脑上运行 `kubectl auth whoami`，用户名应为 `zeabur:erin`。管理员可以用 `kubectl auth can-i --as zeabur:erin -n shop create deployments` 检查，开发者输出 `yes`，查看者输出 `no`。

## 常见失败

- **没有安装 Zeabur Identity**：请集群管理员安装 Zeabur Identity，或使用它所在的 Namespace 启动 Zeabur。
- 界面提示 Zeabur 不知道 Zeabur Identity 的网址：使用 `--issuer-url` 启动 Zeabur。
- 界面提示 Zeabur Identity 目前不接受设置链接：使用 `--invitations` 运行 Zeabur Identity。
- **安装 Zeabur 时未启用成员角色**：使用 `memberRoles.enabled=true` 升级 Chart，或将这位成员设为管理员。完整的权限对照见[权限](../reference/permissions.mdx)。
- 无法更改自己的权限、重置或移除自己：请另一位管理员处理。自己的备用通行密钥可以在账号页面添加。
- 变更已过期：重新 **检查变更**。

## 移除成员

先在 **待使用的设置链接** 中撤销尚未使用的链接。要禁止某位成员继续登录，在该成员的操作菜单中选择 **移除成员**，确认后移除。

移除成员会删除其通行密钥、关联账号、会话、设置链接，以及 Zeabur 创建的角色绑定。项目和服务都会保留。并非由 Zeabur 创建、但指定了 `zeabur:<用户名>` 的角色绑定也会保留，需要管理员另外检查。
