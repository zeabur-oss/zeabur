## 开始之前

- 你已用管理员账号登录 Zeabur。
- 集群装了 Zeabur Identity，由它负责 Zeabur 的登录。它要以 `--invitations` 运行，设置链接才能使用。
- 安装 Zeabur 时没有关闭 Chart 的 `memberRoles.enabled`（默认开启）。关闭后，邀请只能选择是否授予**管理员**权限。

## 邀请一位成员

<Steps>
<Step>

### 填写账号

打开**成员**，点击**邀请**。填写**用户名**。**显示名称**可以不填。

用户名只能包含小写字母、数字、`-` 和 `.`，最多 63 个字符。填写的是已有成员时，链接会为他再添加一把通行密钥，权限不变。

只想把人加进一个项目，也可以从那个项目开始：打开项目的**设置**，在**成员**的**邀请别人加入这个项目**旁点击**邀请**。这个项目会预先勾选，角色是开发者。

</Step>
<Step>

### 选择他能用的项目

在**权限**中选择**指定项目**，勾选项目，再为每个项目选择角色。刚勾选的项目默认是**查看者**。

| 角色 | 能做什么 |
| --- | --- |
| **开发者** | 部署、修改变量、重启、查看日志、打开终端，也能查看机密变量的值。 |
| **查看者** | 查看状态和事件。不能查看日志、不能修改、不能打开终端，也不能查看机密变量的值。 |

同一个人可以在不同项目担任不同角色。一个项目都没勾选的人也能登录，但只能看到节点和项目名称。

![邀请成员窗口，选择了指定项目，blog 的角色为查看者，shop 的角色为开发者](../images/shots/members-invite.avif)

选择**管理员**后，对方可以完全控制整个集群，包括所有项目、节点和成员。管理员只能用通行密钥登录，不能用 GitHub 或 Google，见[管理员账号和普通账号](../reference/permissions.mdx#管理员账号和普通账号)。

列表只列出项目。集群里还有其他 Namespace 时，点击列表下方的**同时显示 N 个不是项目的 Namespace**。Namespace 是 Kubernetes 用来分组的单位，每个项目就是一个 Namespace。

</Step>
<Step>

### 检查变更

点击**检查变更**。窗口会列出要新增的账号和每个项目的权限。确认无误后，点击**邀请 erin**（`erin` 是用户名）。

![检查邀请的窗口，列出新账号和项目权限](../images/shots/members-invite-review.avif)

</Step>
<Step>

### 把链接发给对方

复制窗口里的设置链接，通过只有对方能收到的渠道发过去。

![邀请完成后显示的设置链接和有效期](../images/shots/members-invite-link.avif)

链接 7 天内有效，只能使用一次。完整链接只显示这一次。

</Step>
<Step>

### 确认他能登录

对方打开链接，添加通行密钥。回到**成员**，他那一行的**通行密钥**列会出现数字。然后请他登录，打开你分给他的项目。

![成员页列出每位成员的角色、通行密钥数量和上次登录时间](../images/shots/members-list.avif)

</Step>
</Steps>

<Callout type="warn">
谁先打开设置链接，谁就能为这个账号添加通行密钥并登录。如果链接发错人或泄露，在**待使用的设置链接**中点击**撤销**，再生成新链接。
</Callout>

## 更改权限

在成员那一行点击 **⋯**，选择**更改权限**。调整项目和角色，点击**检查变更**，再点击**保存权限**。

权限立即生效。对方已经打开的终端，会一直保持到关闭为止。

把成员改为**管理员**后，他只能用通行密钥登录。他通过 GitHub 或 Google 登录的会话会结束。取消**管理员**，账号就改回普通账号。

## 添加一台设备，或处理丢失的设备

要为成员添加一台备用设备，在他那一行点击 **⋯**，选择**新的设置链接**。这个链接 24 小时内有效，只能使用一次。原有的通行密钥和会话都会保留。

设备丢失或失窃时，点击 **⋯**，选择**丢失设备后重置**。勾选**同时移除他的通行密钥、关联的账号和会话（设备丢失或被盗时）**，再点击**重置并生成链接**。在对方打开新链接之前，没有人能用这个账号登录。

![丢失设备后重置的窗口，勾选了同时移除通行密钥、关联的账号和会话](../images/shots/members-reset.avif)

## 移除成员

先在**待使用的设置链接**中撤销尚未使用的链接。然后在成员那一行点击 **⋯**，选择**移除成员**，确认后移除。

移除会删除他的通行密钥、关联的账号、会话、设置链接，以及 Zeabur 为他创建的权限。项目和服务都会保留。

## 遇到问题

| 看到的情况 | 怎么处理 |
| --- | --- |
| **没有安装 Zeabur Identity** | 请集群管理员安装 Zeabur Identity，或在启动 Zeabur 时指定 Zeabur Identity 所在的 Namespace。 |
| 界面提示 Zeabur 不知道 Zeabur Identity 的网址 | 使用 `--issuer-url` 启动 Zeabur。 |
| 界面提示 Zeabur Identity 目前不接受设置链接 | 使用 `--invitations` 运行 Zeabur Identity。 |
| **安装 Zeabur 时未启用成员角色** | 使用 `memberRoles.enabled=true` 升级 Chart，或将这位成员设为管理员。完整的权限对照见[权限](../reference/permissions.mdx)。 |
| 无法更改自己的权限、重置或移除自己 | 请另一位管理员处理。自己的备用通行密钥可以在账号页面添加。 |
| 界面提示变更已过期 | 重新点击**检查变更**。 |
| 对方登录后看不到项目 | 在**成员**确认他那一行列出了项目和角色。没有的话，用**更改权限**添加。 |

## 用 kubectl 完成相同操作

成员是 Zeabur Identity 的 `User`，存放在 `zeabur-identity` Namespace 中。权限通过普通角色绑定授予，名称均为 `zeabur-member-<用户名>`：一个 ClusterRoleBinding 绑定到 `zeabur-member`，让成员能登录并看到节点和项目名称；每个分配的项目再各有一个 RoleBinding，绑定到 `zeabur-project-developer` 或 `zeabur-project-viewer`。Kubernetes 看到的用户名是 `zeabur:<用户名>`。

下面将 `erin` 设为普通账号，并授予其 `shop` 项目的开发者权限：

```yaml
apiVersion: identity.zeabur.com/v1alpha1
kind: User
metadata:
  name: erin
  namespace: zeabur-identity
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  username: erin
  displayName: Erin Lin
  groups: []
  accountType: Regular
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: zeabur-member-erin
  labels:
    app.kubernetes.io/managed-by: zeabur
    zeabur.com/member: erin
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: zeabur-member
subjects:
  - apiGroup: rbac.authorization.k8s.io
    kind: User
    name: zeabur:erin
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: zeabur-member-erin
  namespace: shop
  labels:
    app.kubernetes.io/managed-by: zeabur
    zeabur.com/member: erin
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: zeabur-project-developer
subjects:
  - apiGroup: rbac.authorization.k8s.io
    kind: User
    name: zeabur:erin
```

要授予管理员权限，将 `accountType` 改为 `Admin`，无需另外绑定角色。`groups` 不能填写 `admins`，这个组只能由账号类型决定。

应用后，用 `zeabur-identityctl invite` 生成设置链接，发给对方：

```sh
zeabur-identityctl invite --username erin
```

要更改权限，修改 RoleBinding 的 `roleRef`（`roleRef` 不支持修改，需要删除后重建），或在其他项目中创建相同的 RoleBinding。移除成员时，先删除角色绑定，再删除其设置链接、通行密钥和会话，最后删除 `User`：

```sh
kubectl delete clusterrolebinding,rolebinding -A -l zeabur.com/member=erin
kubectl -n zeabur-identity delete zbinvite,zbcred,zbgrant -l identity.zeabur.com/user=erin
kubectl -n zeabur-identity delete zbuser erin
```

其他操作，例如通过组授权、停用账号，见 Zeabur Identity 的[管理用户](https://oss.zeabur.com/docs/identity/managing-users)。

用 kubectl 确认：

- `kubectl get clusterrolebinding,rolebinding -A -l zeabur.com/member=erin` 列出一个 ClusterRoleBinding，以及每个项目一个 RoleBinding。
- 对方登录后，在他的电脑上运行 `kubectl auth whoami`，用户名是 `zeabur:erin`。
- 管理员可以运行 `kubectl auth can-i --as zeabur:erin -n shop create deployments` 检查。开发者会输出 `yes`，查看者会输出 `no`。

移除成员时，并非由 Zeabur 创建、但指定了 `zeabur:<用户名>` 的角色绑定会保留，需要管理员另外检查。
