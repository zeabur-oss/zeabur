数据库密码存放在 OpenBao、1Password 或 AWS Secrets Manager 时，External Secrets Operator 会将密码复制为集群中的机密变量，服务按普通机密变量读取。之后在机密库中修改密码，它会按配置的间隔更新机密变量。

## 开始之前

- 集群需要先安装 cert-manager，由它为 webhook 签发证书。
- 准备外部机密库和只读凭证。以下示例使用 `shop` Namespace。

## 安装

在服务器上用 zeabur-installer 安装 **External Secrets Operator**：在安装程序页面的**组件**中勾选它，或将它加入配置文件的 `enable`，步骤见[查看与安装集群组件](./components.mdx)。

安装后不会创建任何 SecretStore，在你添加之前，它不会连接任何机密库。Catalog 安装 chart `2.12.0`，镜像 `ghcr.io/external-secrets/external-secrets:v2.12.0` 通过 digest 固定。

## 连接 OpenBao 或 Vault

以下配置让 `shop` Namespace 中的 `shop-secrets` ServiceAccount 通过 Kubernetes 身份验证登录 OpenBao，只能读取 `secret` 下以 `shop/` 开头的机密变量。先在 OpenBao 中运行：

```sh
bao auth enable kubernetes
bao write auth/kubernetes/config kubernetes_host=https://kubernetes.default.svc
bao secrets enable -path=secret kv-v2
bao policy write shop-read - <<'EOF2'
path "secret/data/shop/*" { capabilities = ["read"] }
EOF2
bao write auth/kubernetes/role/shop bound_service_account_names=shop-secrets \
  bound_service_account_namespaces=shop policies=shop-read ttl=1h
```

接着在集群中应用 ServiceAccount 和 SecretStore：

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: shop-secrets
  namespace: shop
---
apiVersion: external-secrets.io/v1
kind: SecretStore
metadata:
  name: openbao
  namespace: shop
spec:
  provider:
    openBao:
      server: http://openbao.openbao.svc:8200
      path: secret
      version: v2
      auth:
        kubernetes:
          path: kubernetes
          role: shop
          serviceAccountRef:
            name: shop-secrets
```

使用 HashiCorp Vault 时，将 provider 改为 `vault`、CLI 改用 `vault`，并将 `auth.kubernetes` 下的 `path` 字段改为 `mountPath`。如果机密库位于集群外，使用 HTTPS 和 `caProvider`。

## 连接 1Password

在 1Password 中创建只能读取 `shop` 保险库的 service account，将它的令牌存入机密变量。`onepasswordSDK` 直接使用这个令牌，无需搭建 Connect server：

```sh
kubectl -n shop create secret generic onepassword-token --from-literal=token='<service account token>'
```

```yaml
apiVersion: external-secrets.io/v1
kind: SecretStore
metadata:
  name: onepassword
  namespace: shop
spec:
  provider:
    onepasswordSDK:
      vault: shop
      auth:
        serviceAccountSecretRef:
          name: onepassword-token
          key: token
```

ExternalSecret 的 `remoteRef.key` 写成 `<项目>/<字段>`，例如 `db/password`。如果已有 1Password Connect server，改用 `onepassword` provider。

## 连接 AWS Secrets Manager

创建一个 IAM 用户，仅授予它对这个 Namespace 所需机密变量的 `secretsmanager:GetSecretValue` 和 `secretsmanager:DescribeSecret` 权限，再将它的访问密钥存入机密变量：

```sh
kubectl -n shop create secret generic aws-sm --from-literal=access-key-id='<id>' --from-literal=secret-access-key='<secret>'
```

```yaml
apiVersion: external-secrets.io/v1
kind: SecretStore
metadata:
  name: aws
  namespace: shop
spec:
  provider:
    aws:
      service: SecretsManager
      region: ap-northeast-1
      auth:
        secretRef:
          accessKeyIDSecretRef: {name: aws-sm, key: access-key-id}
          secretAccessKeySecretRef: {name: aws-sm, key: secret-access-key}
```

## 创建 ExternalSecret

以下示例从 `openbao` SecretStore 读取 `shop/db` 的 `password`，同步为 `shop` Namespace 中的 `db` 机密变量：

```yaml
apiVersion: external-secrets.io/v1
kind: ExternalSecret
metadata:
  name: db
  namespace: shop
spec:
  refreshInterval: 1h
  secretStoreRef: {kind: SecretStore, name: openbao}
  target: {name: db}
  data:
    - secretKey: password
      remoteRef: {key: shop/db, property: password}
```

使用其他机密库时，将 `secretStoreRef.name` 换成对应的 SecretStore，`remoteRef` 按机密库的格式填写，例如 1Password 写成 `{key: db/password}`。

运行 `kubectl -n shop get externalsecret db`，确认 `READY` 为 `True`、`STATUS` 为 `SecretSynced`。之后就会出现 `db` 机密变量，按普通机密变量供服务使用，见[配置环境变量](../configure/variables.mdx)。

在 Zeabur 项目的**对象**页面中打开这个 ExternalSecret，确认**状况**中的 Ready 为 True，原因为 SecretSynced，也能确认同步成功。

![项目对象页面中的 ExternalSecret db，状况 Ready 为 True，原因为 SecretSynced](../images/shots/external-secret-synced.avif)

机密库中的变更会在 `refreshInterval` 内写入机密变量。如果服务通过环境变量读取机密变量，需要重启才能获取新值。

## 权限与风险

- controller 能读写整个集群的机密变量，也能为任何 ServiceAccount 创建令牌。`external-secrets` Namespace 仅向管理员开放。
- Chart 将 SecretStore 和 ExternalSecret 的写入权限加入 Kubernetes 内置的 `edit`、`admin` 角色。Zeabur 的开发者和查看者角色没有这些权限，需要由管理员创建。
- 每个 Namespace 使用自己的 SecretStore，凭证也只能读取这个 Namespace 所需的机密变量。ClusterSecretStore 向所有 Namespace 开放，能创建 ExternalSecret 的人就能读取其凭证有权访问的所有机密变量。使用时配置 `spec.conditions`，只列出允许使用它的 Namespace。
- 机密库凭证只授予读取权限。PushSecret 会将集群中的机密变量写回机密库，覆盖原值。
- 同步后的值是普通 Kubernetes 机密变量，适用相同的 etcd 加密、RBAC 和审计日志，见[安全性](../reference/security.mdx)。
