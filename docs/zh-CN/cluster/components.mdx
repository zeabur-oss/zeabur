打开 **集群** → **组件**，**已安装** 列出检测到的组件，**目录** 列出 Zeabur Catalog 中的组件。组件由 zeabur-installer 在服务器上安装和移除，Zeabur 只显示状态和需要运行的命令。

![集群组件页的已安装列表和目录](https://oss.zeabur.com/shots/zeabur/zh-CN/light/cluster-components.avif)

## 开始之前

- 你需要有权限读取整个集群的 CRD、IngressClass 和各 Namespace 的工作负载，组件页才能检测到已安装的组件。
- 要安装或移除组件，你需要能以 root 身份登录最初运行 zeabur-installer 的服务器。
- 如果集群不是用 zeabur-installer 安装的，参见[用自己的工具安装](#用自己的工具安装)。

## 确认集群里有什么

**已安装** 列出检测到的组件、版本和安装来源（K3s、HelmChart 或 Helm），并标明版本是 Zeabur Catalog 的 **已测试版本**，还是 **比已测试版本新**。组件停止运行时会标为 **异常**。

**目录** 支持按 **已安装** 或 **推荐** 筛选，也可以在 **搜索组件** 中按名称或用途查找。

如果备份、通知这类功能页已经可用，组件卡片却仍显示 **安装**，说明组件页没有检测到它，通常是因为安装时使用了其他名称或方式。先找到现有部署，不要重复安装。

## 安装组件

<Steps>
<Step>

### 查看要运行的命令

在组件卡片上点击 **安装**，弹窗会列出需要在服务器上运行的命令。**新增** 菜单、模板、构建配置或数据库备份缺少组件时，点击 **安装方式** 也会打开同一个弹窗，一次列出这件事缺少的所有组件，`enable` 的内容可以直接复制。

Zeabur 通过 `kube-system` 中的 ConfigMap `zeabur-installer` 判断集群是不是 zeabur-installer 安装的。找不到时，弹窗只列出 `zeaburctl components export` 命令；读取不到时，两种方式都会列出。

</Step>
<Step>

### 在服务器上安装

通过 SSH 登录服务器，选择一种方式：

<Tabs items={["安装程序页面", "配置文件"]}>
<Tab value="安装程序页面">

```sh
sudo zeabur-installer gui
```

在自己的电脑上建立 SSH 隧道，再打开服务器输出的链接：

```sh
ssh -L 8085:127.0.0.1:8085 root@server.example.com
```

在 **组件** 中勾选要安装的组件，进入 **确认** 查看内容后点击 **安装**。

</Tab>
<Tab value="配置文件">

在 `/etc/zeabur-installer/config.yaml` 的 `enable` 中添加组件 ID，可以一次添加多个：

```yaml
enable:
  - volume-backup/velero
```

如果组件需要填写参数值，按 [Installer 配置](../reference/installer-configuration.mdx#组件选择)填写 `inputs` 和 `secretFiles`。先查看 `plan`，再运行 `apply`：

```sh
sudo zeabur-installer plan
sudo zeabur-installer apply
```

</Tab>
</Tabs>

</Step>
<Step>

### 确认安装结果

回到 **集群** → **组件**，**已安装** 中会出现该组件及其版本。再到需要它的功能页确认，例如 Velero 对应 **集群** → **备份**，VictoriaMetrics 对应 **集群** → **通知**。

</Step>
</Steps>

## 移除组件

已安装的组件卡片上有 **移除**，弹窗会列出命令。在安装程序页面取消勾选，或从配置文件的 `enable` 中移除该组件；如果组件默认就会安装，则将其添加到 `disable`，再运行 `apply`。

`plan` 和安装程序的 **确认** 页面会列出要移除的组件、会保留哪些内容，以及会一并删除的 CRD。遇到以下两种情况，`apply` 会停止，不做任何更改：

- 仍有资源在使用该组件，例如仍有它的自定义资源（包括会一并删除的 CRD 对应的对象）、仍有 Longhorn 的卷，或仍有副本从 zot 拉取镜像。页面会列出这些资源，先删除或迁移它们。
- 移除组件会一并删除组件保存的数据，例如 Longhorn。先备份，再将组件 ID 写入配置文件的 `allowDataLoss`，或在 **确认** 页面勾选同意。

移除后，组件的 Namespace 和卷会保留。有些 Chart 会一并删除 CRD 及其所有对象，其他 CRD 会保留。确认不再需要保留的资源后，如何手动删除，参见 [Installer 命令](../reference/installer.mdx#卸载组件)。

zeabur-installer 只移除自己安装的组件。通过 Helm、Flux 或 Argo CD 安装的组件，需要用原来的工具移除。

## 用自己的工具安装

如果集群不是用 zeabur-installer 安装的，或想用 GitOps 管理组件，可以用 `zeaburctl components export` 输出组件的 manifest：

```sh
zeaburctl components export volume-backup/velero > velero.yaml
zeaburctl components export volume-backup/velero --format helm
```

一次要安装多个时，把 ID 都写上，例如 `zeaburctl components export builds/zeabur-builder image-updates/keel`，内容会依次接在一起。

默认输出 K3s/RKE2 的 `HelmChart`，由集群内置的 helm-controller 安装。其他集群可用 `--format` 改为 `helm`、`flux` 或 `argocd`。组件需要填写的值会保留为 `<名称>`，先替换为实际值，再用 `kubectl apply -f` 应用，或提交到 GitOps 仓库。命令说明参见 [zeaburctl](../reference/zeaburctl.mdx#components-export)。

通过这种方式安装的组件，后续调整和移除都需要在原来的文件或工具中完成。

### 替换 K3s/RKE2 内置组件

如果导出内容的开头要求先禁用内置版本，按集群发行版处理每台 server，再应用：

- K3s：在 `/etc/rancher/k3s/config.yaml` 中将列出的组件添加到 `disable`，重启 `k3s`。
- RKE2：对于 metrics-server，在 `/etc/rancher/rke2/config.yaml` 中将 `rke2-metrics-server` 添加到 `disable`；对于 Traefik，在同一文件中配置 `ingress-controller: none`。然后重启 `rke2-server`。

<Callout type="warn">
禁用内置的 Traefik 会删除 Traefik 的 CRD 和所有 IngressRoute、Middleware 对象，新组件开始运行前，Ingress 流量会中断。禁用内置的 metrics-server 时，新版本开始运行前 metrics API 无法使用。选择可以接受中断的时段切换。
</Callout>

## 常见失败

- 组件页显示权限不足：将页面列出的缺失权限交给集群管理员。
- `apply` 提示组件仍在使用：处理列出的对象，再重新运行 `apply`。
- `apply` 要求填写 `allowDataLoss`：先备份组件数据，确定要删除后再填写。
- 安装后一直没有出现在 **已安装** 中：查看 `kube-system` 中 `helm-install-<名称>` Job 的日志，以及组件的工作负载是否已启动。
