在**集群** → **概览**的**节点**中查看各台主机的状态。要增加一台主机运行服务，见[添加节点](#添加节点)。主机需要停机维护时，在该节点的操作菜单中选择**停止调度**，需要迁移副本时再用 kubectl 的 `drain`。

![集群概览中的节点列表](../images/shots/cluster-nodes.avif)

## 开始之前

- 准备一台能以 root 身份操作的新 VM。K3s 只能添加工作节点；RKE2 可以添加工作节点和服务器，有三台服务器时坏一台控制平面也不会停。
- 所有节点应位于同一家云服务商的同一区域，可以分布在该区域内的不同可用区。跨服务商或跨区域时，延迟会拖慢 etcd、Kubernetes API 和存储。
- 停止调度和恢复调度需要修改 Node 的权限。`drain` 和 `delete node` 在 kubectl 终端中运行，使用的是你自己的权限。节点终端需要用管理员账号打开。

节点之间的防火墙需要开放：

| 方向 | K3s | RKE2 |
| --- | --- | --- |
| 连接到服务器 | TCP 6443（[限制来源](../reference/security.mdx#kubernetes-api)） | TCP 9345、6443 |
| 所有节点之间 | TCP 10250，UDP 8472（flannel VXLAN） | TCP 10250、9099，UDP 8472（Canal VXLAN） |
| 服务器之间 | 不需要 | TCP 2379–2381 |

由 Zeabur 开源版 0.2 安装的 K3s 集群使用 Calico，UDP 端口是 4789，而不是 8472。UDP 端口只对集群节点开放，不要对互联网开放。如果防火墙拦截了该端口，不同节点上的副本就无法互相连接。

## 添加节点

Zeabur 开源版不负责添加节点。用 Zeatend 装好的集群，按 Zeatend 的[添加节点](https://oss.zeabur.com/zh-CN/docs/zeatend/operations/add-nodes/)操作：要开放哪些端口、怎么让新服务器加入、最后怎么撤销令牌，那一页都有说明。用其他方式装的集群，按发行版自己的步骤添加。节点在**节点**列表显示 `Ready` 后，新的副本就能调度到它上面。

RKE2 的 etcd 需要过半数的服务器才能运行。要在少一台服务器时继续运行，至少需要三台服务器。如果只有两台，任意一台停机都会导致整个集群停止运行。K3s 集群只有一台服务器，这台服务器停机时控制平面也会停止，恢复后才能继续运行。

## 节点停机维护

### 只需重启

在节点菜单中选择**停止调度**，节点行就会标记为已停止调度。这会阻止新的副本调度到该节点，已经运行的副本会留在原处。如果只是重启，做到这一步就够了，不需要运行 `drain`。

也可以在 Zeabur 开源版**集群**页面标题旁点击**打开 kubectl 终端**，运行：

```sh
kubectl cordon <node>
```

将 `<node>` 替换为节点名称。重启完成后，再恢复调度。

### 先迁移副本再维护

在 Zeabur 开源版**集群**页面标题旁点击**打开 kubectl 终端**，先列出该节点上的副本及其使用的 PVC：

```sh
kubectl get pods -A --field-selector spec.nodeName=<node> -o custom-columns=NS:.metadata.namespace,POD:.metadata.name,PVC:.spec.volumes[*].persistentVolumeClaim.claimName
```

对照列表中的 PVC，确认哪些使用该节点的 `local-path` 卷。这些卷的数据只保存在该节点上，不会随副本迁移到其他节点。

确认后，运行：

```sh
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
```

`drain` 会停止该节点的调度，并驱逐副本，让控制器在其他节点重新创建副本。DaemonSet 管理的副本会留在原处。运行时注意：

- `drain` 会遵守 PodDisruptionBudget；预算不允许驱逐时，`drain` 会一直重试。
- 遇到不属于任何控制器的副本，`drain` 会停止。这类副本删除后不会自动启动，确认可以删除后，再在命令末尾加上 `--force`。
- `--delete-emptydir-data` 会清空所驱逐副本的 `emptyDir` 临时数据。
- 使用该节点 `local-path` 卷的副本也会遭到驱逐。重新创建的副本无法在其他节点使用这些卷，原节点恢复运行之前会一直处于 `Pending` 状态。`drain` 不会导致数据丢失；对这些副本来说，结果与直接停机相同，都需要等待该节点恢复运行。

如果 Zeabur 开源版本身也运行在该节点上，`drain` 期间页面会断开连接约一分钟。刷新页面并重新登录；kubectl 终端也会断开连接，需要重新打开。

等待 `drain` 完成后，再将节点停机维护。

## 恢复调度

维护完成、节点恢复运行后，在节点菜单中选择**恢复调度**。

也可以在 Zeabur 开源版**集群**页面标题旁点击**打开 kubectl 终端**，运行：

```sh
kubectl uncordon <node>
```

恢复调度后，新的副本就能调度到该节点。

## 移除节点

**不要移除集群中唯一的节点，也不要移除最后一台控制节点。**

先在 Zeabur 开源版**集群**页面标题旁点击**打开 kubectl 终端**，确认控制节点数量：

```sh
kubectl get nodes -l node-role.kubernetes.io/control-plane
```

如果只剩一台控制节点，不要删除。如果移除后剩余的 server 节点不足三台，控制平面再少一台就无法运行。

`local-path` 卷的数据只保存在该 VM 上。移除节点后，使用这些卷的副本将无处启动。按照“节点停机维护”的步骤检查副本与卷，再运行 `drain`，完成后才删除节点：

```sh
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
kubectl delete node <node>
```

接着登录已移除的 VM，运行：

```sh
sudo zeatend uninstall
```

节点不是用 Zeatend 加入的，就改用发行版的卸载脚本，例如 `k3s-agent-uninstall.sh`。

**删除 Kubernetes 节点后，还需要完成 VM 上的卸载**。在卸载前，只要 `k3s-agent` 或 RKE2 重启，该 VM 就会再次加入集群。

`/var/lib/zeabur/storage` 下的卷会保留在 VM 上。确认不再需要这些数据后，再加上 `--delete-volumes`。

如果集群使用 Longhorn，Longhorn 会为已删除的节点保留节点数据。节点上还有副本时，Longhorn 不允许删除这个节点。请先确认每个卷在其他节点上都有健康的副本，再运行：

```sh
kubectl -n longhorn-system patch nodes.longhorn.io <node> --type=merge -p '{"spec":{"allowScheduling":false}}'
for r in $(kubectl -n longhorn-system get replicas.longhorn.io -o jsonpath='{range .items[?(@.spec.nodeID=="<node>")]}{.metadata.name}{"\n"}{end}'); do kubectl -n longhorn-system delete replicas.longhorn.io "$r" --wait=false; done
kubectl -n longhorn-system delete nodes.longhorn.io <node>
```

## 打开节点终端

**节点终端**会在主机上打开一个具有完整 root 权限的 shell。用管理员账号登录，在节点行点击**节点终端**，查看即将创建的终端副本和时限，再点击**打开终端**。

<Callout type="warn">
节点终端可以修改主机上的所有文件、进程和网络接口。在终端中执行的操作不经过 Zeabur 开源版和 Kubernetes 的权限检查，也无法撤销。
</Callout>

节点会记录一条事件，注明谁在什么时间打开了终端。

关闭终端时，Zeabur 开源版会移除终端副本，副本最多保留 30 分钟。如果副本仍然存在，在节点下方的终端副本列表中点击**移除终端副本**，检查后确认。

## 常见问题

- 加入时无法连接服务器：在新 VM 上运行 `sudo zeatend plan`，它会逐一检查端口。K3s 需要 TCP 6443，RKE2 需要 TCP 9345 和 6443，上表中的其他端口也要开放。
- 新节点已就绪，但不同节点上的服务无法互相连接：检查 UDP 8472（由 Zeabur 开源版 0.2 安装的 K3s 集群是 4789），以及网络策略是否已放行新节点。
- `drain` 一直没有进展：`drain` 在等待 PodDisruptionBudget 放行，或停在不属于任何控制器的副本上。用 `kubectl get pdb -A` 查看哪个预算阻止了驱逐，处理后再运行一次。
- 副本在新节点上处于 `Pending` 状态：副本使用的是旧节点的 `local-path` 卷，需要等待旧节点恢复运行。
- 终端副本**无法启动**：查看该副本的事件，常见原因是镜像下载失败。
