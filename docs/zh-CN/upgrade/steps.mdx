description: 查看当前的 Zeabur 版本，按安装方式用 Helm、Argo CD、Flux 或 zeaburctl 升级，用 Zeatend 升级 Kubernetes，并在升级后确认新版本。

先看你是怎么安装的，再按对应的小节升级。升级不会自动发生，Zeabur 只会告诉你有新版本。

## 交给 Agent 升级

Claude Code 或 Codex 这类 Agent 可以替你按照这一页和升级须知操作。在能通过 SSH 连接服务器的电脑上运行 Agent，粘贴下面的提示词，并告诉它服务器的地址：

```text
Upgrade Zeabur on my server to the latest version by following https://oss.zeabur.com/docs/zeabur/upgrade/steps.
```

Agent 会查明 Zeabur 的安装方式，阅读中间每一版的升级须知，再告诉你要改哪些内容。创建快照和升级后用通行密钥登录需要你自己操作，Agent 会在这些步骤停下来等你。

## 查看版本

集群页面始终显示 `Zeabur v<版本>`。有新版本时，页面会出现通知，附上新版的版本号和发行说明链接。“设置”›“关于”也会显示版本。在这两个地方点击“升级方法”，都会按你的安装方式列出步骤，附上可以复制的命令和这一页的链接。

用 `zeaburctl ui` 打开时，页面显示的是 `zeaburctl` 自己的版本。检查更新的细节，以及怎么关掉通知，见[检查更新](../reference/telemetry.mdx#检查更新)。

## 升级前

- 到 [GitHub Releases](https://github.com/zeabur-oss/zeabur/releases) 阅读要升级的版本的发行说明。
- 读[升级须知](notes.mdx)，跨过几版就读那几节，先把每一版要做的事做完。
- 先给服务器或集群留一份快照。需要退回旧版时，只能还原升级前的快照，见[退回旧版](#退回旧版)。
- 项目的数据另外用 Velero 备份，见[备份集群并从备份还原](../cluster/backups.mdx)。

## 用 Helm 升级

如果 `kubectl -n kube-system get configmap zeabur-installer` 找到了 ConfigMap，说明这台服务器是用 zeabur-installer 装好的。从 v0.2 升级到 v0.3 时，不要按这一节操作，改为按升级须知中的[用 zeabur-installer 安装的集群](notes.mdx#用-zeabur-installer-安装的集群)操作。

把 `<版本>` 换成要升级的版本：

```sh
helm upgrade zeabur oci://ghcr.io/zeabur-oss/charts/zeabur \
  --version <版本> \
  --namespace zeabur --reset-then-reuse-values
kubectl -n zeabur rollout status deployment/zeabur
```

`--reset-then-reuse-values` 会先采用新版 chart 的默认值，包括镜像，再应用你之前设置的值。用 `--reuse-values` 的话，镜像会停在旧版。

在用 [Zeatend](../install/one-command.mdx) 装好的服务器上，和安装时一样在服务器上运行。先 `export KUBECONFIG=/etc/rancher/k3s/k3s.yaml`，RKE2 则是 `/etc/rancher/rke2/rke2.yaml`。再运行 `sudo -E helm upgrade …`，然后等待副本就绪：K3s 用 `sudo k3s kubectl …`，RKE2 用 `sudo -E /var/lib/rancher/rke2/bin/kubectl …`。

## 用 Argo CD 升级

把 Argo CD Application 里的 chart 版本改成新版，再同步。Argo CD 不连集群就生成 manifest，所以要事先创建固定的签名密钥并设置 `planKey.existingSecret`，做法见[用 GitOps 管理 chart](../install/existing-cluster.mdx#用-gitops-管理-chart)。

## 用 Flux 升级

把 Flux HelmRelease 里的 chart 版本改成新版，提交后等 Flux 同步。

## 用 zeaburctl ui 升级

Zeabur 运行在你自己的电脑上，没有服务器要升级。到[发行文件与验证](../reference/releases.mdx)下载新版 `zeaburctl`，验证后替换旧文件，再运行一次 `zeaburctl ui`。

## 用 Zeatend 升级 Kubernetes

在用 Zeatend 装好的服务器上，K3s、RKE2 或 KubeSolo 由 Zeatend 升级，和 Zeabur 分开。每个 Zeatend 版本都固定安装一个版本，所以换上新版 Zeatend，Kubernetes 也会随之更新。

1. 在服务器上按 [Zeatend 的 README](https://github.com/zeabur-oss/zeatend#download-zeatend) 下载新版 Zeatend。
2. 运行 `sudo zeatend plan`，查看会升到哪个版本以及主机检查的结果。这一步不会做任何改动。
3. 运行 `sudo zeatend apply`。

`apply` 会装上新版本，再重启 K3s、RKE2 或 KubeSolo。Kubernetes API 会有一小段时间没有响应，运行中的服务照常工作。有多个节点时，先逐台升级服务器，再升级工作节点。

Kubernetes 一次只能升一个小版本。新版本跨度更大时，`plan` 会在做任何改动之前停下，并写明要先应用哪个版本。把那个版本写进 `/etc/zeatend/config.yaml` 的 `version`，运行 `apply`。`plan` 每写出一个版本就照做一次，最后删掉 `version`，再运行一次 `apply`。

### 用 zeabur-installer 安装的服务器

Zeatend 可以直接接管这些服务器。没有 `/etc/zeatend/config.yaml` 时，Zeatend 会读取 `/etc/zeabur-installer/config.yaml`，安装程序关闭的组件也会继续保持关闭。下载 Zeatend 后，同样运行 `plan` 和 `apply`。Zeatend 不会改动 Zeabur 本身；要升级 Zeabur，先阅读[升级须知](notes.mdx)。

## 升级后

- Zeabur 的副本换新后，所有人都要重新登录。chart 只运行一个副本，会话保存在内存里。
- 运行 `zeaburctl --version`，或打开集群页面，确认版本。
- Helm、Argo CD 和 Flux 可以运行 `kubectl -n zeabur rollout status deployment/zeabur`，等新的副本就绪。

## 退回旧版

要退回旧版，还原升级前的快照。
