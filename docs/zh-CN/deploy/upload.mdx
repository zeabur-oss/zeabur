在项目中选择 **新增** → **上传文件夹**，将文件夹拖入虚线框，填写服务名称和端口，再点击 **检查变更**。应用变更后，文件夹会立即上传，上传完成后开始首次构建。

不需要 Git 仓库。浏览器将文件夹打包后，直接发送到集群中的 registry。Zeabur 不会保存它，也不会将它放入配置文件、机密变量或卷。

## 开始前

- 条件与[从 Git 部署](./git.mdx)相同：已安装 Zeabur Builder 和 Keel，chart 已配置 `builds.registry`，你有在项目中创建服务和 Build 的权限。缺少组件时，**上传文件夹** 下方会写出缺少哪些，点击后会列出安装命令。
- Zeabur Builder 必须配置 `registry.tokenKey`，上传时才能获取有时效的令牌。未配置时，上传会停在 **Zeabur Builder 不允许上传**。
- 你需要有读取项目中机密变量的权限。Zeabur Builder 将上传令牌写入 `<服务名称>-upload` 机密变量，Zeabur 使用你的权限读取它，不使用自身的权限。

## 创建服务

<Steps>
<Step>

### 选择文件夹

打开 **新增** → **上传文件夹**，将文件夹拖入虚线框，或点击 **选择文件夹**。如果已有 `.zip` 文件，直接拖入或点击 **选择 .zip 文件**。从 GitHub 下载的 `.zip` 通常会多包一层文件夹，Zeabur 会自动去掉这一层。

打包时：

- 不会上传 `.gitignore` 排除的文件，子文件夹中的 `.gitignore` 仅作用于该文件夹。只读取最上层的 `.dockerignore`，匹配规则从最上层开始计算，与 Docker 一致。
- 一律不上传 `.git` 文件夹。
- 浏览器无法读取文件权限，因此会将以 `#!` 开头的文件设为可执行。

打包完成后，虚线框会显示文件数、打包后的大小，以及排除的文件数。

![上传文件夹表单，虚线框支持拖入文件夹或压缩包，下方是名称、端口和构建方式](../images/shots/upload-form.avif)

打包后的大小上限为 256 MiB，解压后的大小上限为 1 GiB。如果超出限制，虚线框会列出最大的几项，将它们加入 `.gitignore`（例如 `node_modules/`）后重新选择。

</Step>
<Step>

### 配置构建和运行方式

**名称**、**端口**、**公开域名**、**环境变量**、**构建变量**、**规格**和**安全性**的含义与[从 Git 部署](./git.mdx)相同。

**构建方式** 选择 **Railpack** 时，构建器会判断所用语言。选择 **Dockerfile** 时，使用文件夹最上层的 Dockerfile。要构建其中的某个子文件夹，在 **更多设置** 的 **根目录** 中填写其路径，例如 `apps/web`。

</Step>
<Step>

### 检查并应用

点击 **检查变更**，核对 Deployment 和 Build。应用后，页面会跳转到服务，**构建** 标签页会显示上传进度：获取许可、上传、开始构建。上传完成前，请保持页面打开。

构建成功后，Keel 会将服务更新为新镜像，**新构建完成后自动部署** 默认开启。

</Step>
</Steps>

## 上传新版本

在服务的 **构建** 标签页点击 **上传文件夹**，选择新版本的文件夹。Zeabur 会沿用该服务的构建方式和配置。

## 用 zeaburctl 上传

在终端和脚本中可以使用 [`zeaburctl up`](../reference/zeaburctl.mdx#up)，无需知道 registry 或 Zeabur 的地址。使用 Zeabur Identity 登录时，文件夹会交给集群中的 Zeabur。使用安装程序提供的管理员 kubeconfig 等其他凭证时，命令会在你的电脑上运行相同的步骤，凭证不会离开你的电脑。

```sh
zeaburctl up ./site --project shop --service site
```

如果服务不存在，命令会创建服务。在脚本或 CI 中，必须同时填写 `--project` 和 `--service`，且项目必须已存在。

## 确认结果

上传完成后，**构建** 标签页会出现一条构建记录，构建成功后，**概览** 会显示服务就绪。用 kubectl 查看：

```sh
kubectl -n shop get build site
kubectl -n shop get buildruns
```

Build 的 `SOURCE` 为 `Archive`，`REVISION` 为上传内容的 digest。BuildRun 的 `PHASE` 变为 `Succeeded` 后，Deployment 的镜像会更新为 `archive-<时间>-<digest 前 7 位>` 这种 tag。

## 用 kubectl 做同样的事

上传时创建的对象与[从 Git 部署](./git.mdx#用-kubectl-完成相同操作)相同，只有 Build 的来源不同：`spec.source` 为 `archive`，而非 `git`，也没有 `credentialsRef`。按照 Git 页面的 YAML 创建 Deployment、Service、`<服务名称>-env`，将 `web` 替换为 `site`，再创建以下 Build：

```yaml
apiVersion: builder.zeabur.com/v1alpha1
kind: Build
metadata:
  name: site
  labels:
    app.kubernetes.io/name: site
  annotations:
    builder.zeabur.com/upload-token-request: u1
spec:
  builderRef: railpack
  source:
    archive: {}
  output:
    image: zot.zot.svc:5000/shop/site
  notify:
    - type: keel
      url: http://keel.keel.svc.cluster.local:9300/v1/webhooks/native
```

annotation `builder.zeabur.com/upload-token-request` 的值可以自行指定。每次改为新值，Zeabur Builder 都会签发一个新令牌，写入 `<服务名称>-upload` 机密变量，有效期为 15 分钟。接着用 [ORAS](https://oras.land) 将文件夹推送到 registry，再将 digest 写入 Build：

```sh
kubectl -n shop wait build/site --for=jsonpath='{.status.uploadToken.request}'=u1
printf '{"auths":{"localhost:5000":{"registrytoken":"%s"}}}' \
  "$(kubectl -n shop get secret site-upload -o jsonpath='{.data.token}' | base64 -d)" > auth.json
kubectl -n zot get secret zot-tls -o jsonpath='{.data.ca\.crt}' | base64 -d > ca.crt
kubectl -n zot port-forward svc/zot 5000:5000 &
tar -czf source.tar.gz -C ./site .
oras push --registry-config auth.json --ca-file ca.crt \
  localhost:5000/shop/site/source:upload-1 \
  --artifact-type application/vnd.zeabur.source.v1+tar \
  source.tar.gz:application/vnd.oci.image.layer.v1.tar+gzip
kubectl -n shop patch build site --type=merge \
  -p '{"spec":{"source":{"archive":{"digest":"sha256:<oras 输出的 digest>"}}}}'
```

上传新版本时，更换 annotation 的值、推送新内容，再修改 `digest`。网页和 `zeaburctl up` 会应用 `.gitignore`、`.dockerignore` 和大小限制，自行打包时需要自行排除不需要的文件。推送格式和限制见 [Zeabur Builder 的说明](https://oss.zeabur.com/docs/builder/archive-source)。

## 上传卡住时

| 页面上的情况 | 下一步 |
| --- | --- |
| **等待文件夹** | 上传尚未开始，或上传途中关闭了页面。在 **构建** 中点击 **上传文件夹**。 |
| **Zeabur Builder 不允许上传** | 确认 Zeabur Builder 已配置 `registry.tokenKey`，且你能读取 `<服务名称>-upload` 机密变量。 |
| **文件夹上传失败** | 点击 **重试**。令牌在 15 分钟后失效，Zeabur 会重新获取一个。 |
| **文件夹已上传，但构建没有开始** | 点击 **重试**。如果仍然失败，在 **构建** 中查看 Build 的状况。 |
| 构建报告找不到来源 | 上传内容可能已由 registry 清理。registry 默认只保留每个服务最近 20 次上传的内容，重新上传即可。 |

## 删除服务

删除服务时会一并删除它的 Build，Zeabur Builder 也会清理 registry 中该服务的上传内容。
