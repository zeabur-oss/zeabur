---
title: 从应用模板部署
description: 从 Zeabur Catalog 的模板中选择应用，填写域名和必要字段后部署到项目。
---

完成这一页后，项目中会多出一个应用，例如 Miniflux，连同它的服务、数据库和公开域名。打开域名就能使用。模板来自当前这一版 Zeabur 开源版内置的 [Zeabur Catalog](https://github.com/zeabur-oss/catalog)，部署时不会从外部下载模板。

## 开始前

- 已有项目，并有创建服务的权限。模板的内容使用你自己的权限创建，检查变更时会列出权限不足、无法创建的内容。
- 已安装模板需要的组件，例如使用 PostgreSQL 的模板需要 CloudNativePG。模板列表会在模板下方显示**需要先安装…**。
- 如果模板需要公开域名，准备一个指向集群入口的域名。如果模板需要 HTTPS，集群管理员要先指定证书签发者，见[添加公开域名与 HTTPS](../configure/domains.mdx)。

## 部署模板

<Steps>
<Step>

### 选择应用

打开**新建** → **应用模板**。每个模板都会说明用途，以及需要多少 CPU 和内存。在上方输入名称即可筛选。

![应用模板列表，筛选 n8n 后列出三个模板，每个模板都说明用途及所需的 CPU 和内存](../images/shots/template-list.avif)

</Step>
<Step>

### 安装缺少的组件

如果尚未安装模板需要的组件，表单上方会写出缺少的所有组件和**安装方式**按钮。点击后会一次列出这些组件的安装命令，按照[查看与安装集群组件](../cluster/components.mdx)的步骤安装，再回来部署。缺少组件时，**检查变更**无法继续。

</Step>
<Step>

### 填写域名和字段

- **公开域名**：默认由模板名称和项目名称组成，可以改成自己的域名。
- **部署前须知**：模板作者列出的已知风险和处理方式，默认折叠，展开后才能查看内容，目前只有英文。部署前先阅读，例如首次启动前谁能创建管理员账号。
- 其他字段：名称和说明会随界面语言显示。标有**选填**的字段可以留空。

密码和密钥会在你的浏览器中生成，并存入模板指定的机密变量，例如 Miniflux 的 `miniflux-secrets`。部署后，可以在使用这些值的服务的**变量**中显示这些值。

![部署 Miniflux 的表单，包含公开域名字段，下方说明密码会存入机密变量 miniflux-secrets](../images/shots/template-form.avif)

</Step>
<Step>

### 检查并应用

点击**检查变更**，确认要创建的内容后应用。**会启动的服务**会列出模板的服务、数据库和域名，下方显示峰值所需的 CPU 和内存。如果项目中已经部署过同一模板，页面会列出已存在的内容，需要先删除，或改为部署到其他项目。所有内容都创建在这个项目中。

![部署 Miniflux 的检查页面，列出将创建的机密变量、服务、数据库和域名](../images/shots/template-review.avif)

</Step>
</Steps>

## 确认结果

应用变更后，模板的服务和数据库会出现在项目中。打开各服务的**概览**，等待副本就绪，再打开模板的公开域名，确认能看到应用页面。

## 遇到问题

- 名称已存在：模板使用固定的名称。如果同一项目中已经部署过相同模板，或存在同名的机密变量，检查变更时会列出冲突。改为在其他项目中部署。
- 字段格式不符：字段下方会说明要求的格式，按要求修改后重新检查。
- 检查变更提示集群不支持某种对象：模板需要的组件尚未安装完成，或仍在启动。到**组件**页面确认状态。

## 交给 Agent 部署

Claude Code 或 Codex 这类 Coding Agent 可以用 `zeaburctl templates export` 替你部署模板。把模板 ID 和项目填进这段提示再粘贴：

```text
把 Zeabur Catalog 的模板 <模板> 部署到我集群的项目 <项目>，按照 https://oss.zeabur.com/zh-CN/docs/zeabur/deploy/templates.md 操作。
先问我要用哪个 kubeconfig context，kubectl、`zeaburctl templates export` 和 `zeaburctl doctor` 都用 --context 指定。zeaburctl 的版本要与我的 Zeabur 开源版相同。
只部署 `zeaburctl templates export <模板> --project <项目>` 输出的内容。不要自己选择版本或值，也不要自己写 manifest、Compose 文件或 Helm 命令。
输出中每个 <名称> 占位符的值都要问我。拿到值后再导出一次：<domain> 用 --domain，<clusterIssuer> 用 --cluster-issuer，其他占位符用 --set <名称>=<值>。把这次的输出保存为一个文件，模板只用这个文件部署。
如果 zeaburctl 提示集群缺少组件，先问我集群适合 helmchart、flux 还是 argocd 哪种 --format，把 `zeaburctl components export <组件> --format <格式>` 输出的内容另存为一个文件，先装好组件。
每次写入集群前，先给我看 `kubectl diff --server-side -f <文件>` 的结果，等我同意后，再对同一个文件运行 `kubectl apply --server-side -f <文件>`。
完成后运行 `zeaburctl doctor --output json`，告诉我结果。
```

Agent 需要 zeaburctl、kubectl，以及能连接集群的 kubeconfig。它用你的权限写入，在你同意 diff 之前，集群不会有任何改动。

## 用 kubectl 完成相同操作

### 导出 YAML 再应用

模板部署到项目时会写入一组对象，`zeaburctl templates export` 会将它们输出，与网页界面写入的相同，标签也一样。它使用这个 zeaburctl 内置的模板，因此 zeaburctl 的版本要与 Zeabur 开源版相同：

```sh
umask 077
zeaburctl templates export miniflux --project shop \
  --domain miniflux.example.com --cluster-issuer letsencrypt > miniflux.yaml
kubectl diff --server-side -f miniflux.yaml
kubectl apply --server-side -f miniflux.yaml
```

- 输出最前面是存放模板密码和密钥的机密变量。每次运行都会生成新值，因此只导出一次，应用那一份文件。之后再导出一次并应用，会替换运行中应用的密码。不要将这份文件纳入版本控制。
- 模板需要填写的字段用 `--set <名称>=<值>` 传入，例如 `--set adminEmail=me@example.com`。字段名称位于模板 `template.yaml` 的 `inputs` 中。没有提供的必填字段，以及没有提供的 `--domain` 和 `--cluster-issuer`，会以 `<名称>` 占位符出现。应用前用这些选项提供值，再导出一次。`--cluster-issuer` 是集群管理员为 Zeabur 开源版设置的签发者（`domains.clusterIssuer`）。
- 集群缺少模板需要的组件时，命令会指出来，并给出安装它的 `zeaburctl components export` 命令。详见 [zeaburctl](../reference/zeaburctl.mdx#templates-export)。

删除整个模板：

```sh
kubectl -n shop delete all,ingress,pvc,secret,configmap,networkpolicy -l app.kubernetes.io/instance=miniflux
```

数据库等 operator 的对象也带有相同标签，用 `kubectl -n shop get <种类> -l app.kubernetes.io/instance=miniflux` 找到后再删除。删除卷和数据库时，也会删除其中的数据。

### 确认部署

模板中的每个对象，以及存放生成密码的 Secret，都带有三个标签：`app.kubernetes.io/instance` 和 `templates.zeabur.com/template` 是模板 ID，`app.kubernetes.io/version` 是应用版本。列出本次部署的对象：

```sh
kubectl -n shop get deploy,statefulset,svc,ingress,pvc,secret -l app.kubernetes.io/instance=miniflux
```

如果模板使用数据库，还要确认 operator 的对象已就绪，例如 `kubectl -n shop get clusters.postgresql.cnpg.io -l app.kubernetes.io/instance=miniflux` 的 `STATUS` 是 `Cluster in healthy state`。operator 是在集群中管理数据库的组件。

### 限制应用向外连接

模板不会拦截整个项目的流量。哪些来源能连接项目中的副本，由项目的 NetworkPolicy `zeabur-project` 决定，见[安全性](../reference/security.mdx)。出站连接不受限制，应用可以连接模型服务、Webhook、邮件服务器和用于备份的 S3。

要限制某个应用的出站连接，自行添加 NetworkPolicy。下面的示例只允许 Umami 查询 DNS 和连接自己的数据库：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: umami-egress
spec:
  podSelector:
    matchLabels:
      templates.zeabur.com/template: umami
      app.kubernetes.io/name: umami
  policyTypes: [Egress]
  egress:
  - to:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: kube-system
      podSelector:
        matchLabels:
          k8s-app: kube-dns
    ports:
    - {protocol: UDP, port: 53}
    - {protocol: TCP, port: 53}
  - to:
    - podSelector:
        matchLabels:
          cnpg.io/cluster: umami-db
    ports:
    - {protocol: TCP, port: 5432}
```

用 `kubectl apply -n <项目的命名空间> -f umami-egress.yaml` 应用。`podSelector` 只选择应用的副本，不要选中数据库：数据库需要连接 Kubernetes API 和用于备份的 S3，拦截这些连接会导致数据库停止运行，备份也会失败。
