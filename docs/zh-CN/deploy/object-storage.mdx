在项目中选择**新增** → **对象存储**，填写容量和第一个存储桶，再点**检查变更**。存储服务就绪后，用**连接到服务**添加 S3 端点和密钥，让应用上传文件。

## 开始前

- 已有项目，并有创建对象存储的权限。为应用添加连接时，还需要修改该服务的权限。显示秘密访问密钥需要读取机密变量的权限。
- 管理员已安装 SeaweedFS Operator，见[查看与安装集群组件](../cluster/components.mdx)。
- 集群有可用的存储类和空间。
- 准备使用兼容 S3 的应用或客户端。创建表单配置的端点供集群内使用。

## 创建存储服务

<Steps>
<Step>

### 选择名称、容量与存储桶

打开**新增** → **对象存储**，填写：

| 字段 | 填写方式 |
| --- | --- |
| **名称** | 例如 `files`。最多 30 个字符，以小写字母开头，只能包含小写字母、数字和连字符。 |
| **存储空间** | 文件数据的卷大小，默认为 `10Gi`。 |
| **存储桶** | 例如 `uploads`。可以留空，之后再添加。名称由 3 到 63 个小写字母、数字或连字符组成，开头和结尾必须是字母或数字。 |
| 存储类 | 选择存放文件的存储空间，能否扩容取决于存储类。 |

容量字段设置的是 volume server 的数据空间。master 和 filer 也各有 1 GiB 的持久存储空间。

</Step>
<Step>

### 选择应用并检查变更

可以先在创建表单的**连接到服务**中勾选应用，也可以等对象存储就绪后再连接。点击**检查变更**，确认名称、容量、存储桶和要修改的服务，再应用变更。

![新增对象存储的表单，已填写名称 files、容量和存储桶 uploads，并在连接到服务中勾选 web](../images/shots/object-storage-form.avif)

这份变更会创建 SeaweedFS 存储服务、供应用使用的身份和密钥，以及选定的存储桶。

</Step>
<Step>

### 等待存储服务就绪

从项目打开对象存储的**概览**，等待状态变为**就绪**，并确认**组成部分**和**存储桶**。刚创建时可能还没有生成连接密钥，可以到**事件**和**日志**查看 operator 的创建进度。

</Step>
</Steps>

<Callout type="warn">
创建表单中的 master、volume、filer 和 S3 gateway 各运行一份，文件数据只有一份。存储节点故障时，没有另一份数据可以接替。重要文件需要另行备份或复制到其他存储服务。
</Callout>

![对象存储 files 的概览，列出组成部分与存储桶](../images/shots/object-storage.avif)

## 将 S3 连接添加到应用

1. 在对象存储的**概览** → **连接**中点击**连接到服务**。
2. 勾选同一项目中的应用，选择**存储桶**，确认**变量名**和**会添加的变量**。
3. 点击**检查变更**，核对将更新的服务并应用变更。
4. 让应用的 S3 客户端读取这些变量，再上传并读回一个测试文件。

如果没有名称冲突，也没有手动改名，默认添加以下变量：

| 变量 | 内容 |
| --- | --- |
| `S3_ENDPOINT` | 私有 S3 HTTP 端点，例如 `http://files-s3.shop.svc:8333`。以页面显示的实际值为准。 |
| `S3_ACCESS_KEY_ID` | 从机密变量读取的访问密钥 ID。 |
| `S3_SECRET_ACCESS_KEY` | 从机密变量读取的秘密访问密钥。 |
| `S3_REGION` | `us-east-1`。 |
| `S3_BUCKET` | 本次选择的存储桶，未选择时不添加。 |

如果应用已有同名变量，表单会提示冲突，或建议在变量名称前加上对象存储的名称。将**会添加的变量**与应用实际使用的配置逐项对照。添加变量会更新服务副本。

需要手动配置时，在**连接**中复制**端点**、**区域**和**访问密钥 ID**。有权限时，点击**私密访问密钥**旁的**显示**。端点使用集群 DNS，集群外的计算机无法直接使用这个地址。

<Callout type="warn">
这组密钥可以读写此对象存储中的所有存储桶。`S3_BUCKET` 只决定应用默认使用哪个桶，不会改变权限范围。不要把这组密钥放进浏览器前端，或交给不受信任的客户端。
</Callout>

## 新增与删除存储桶

要新增存储桶，在**概览**的**存储桶**中点击**新建存储桶**，填写名称，**检查变更**后应用。等待该行显示 `Ready`，再让应用使用。

存储桶列表会列出容量和对象数量，尚无统计数据时显示**尚未统计**。上传、下载和浏览文件需要使用 S3 客户端，这个页面只管理存储桶。

删除时，点击存储桶所在行的删除按钮，阅读确认内容，再应用变更。Zeabur 创建的存储桶使用 `Delete` 回收策略，删除时会一并移除文件。如果已有存储桶使用保留策略，确认内容会说明文件将保留在存储服务中。

<Callout type="warn">
删除使用 `Delete` 策略的存储桶会删除其中的文件。先用能连接该端点的 S3 客户端复制要保留的内容，确认目标位置可以读取，再删除源文件。
</Callout>

## 保留文件与修改配置

对象存储页面提供**概览**、**日志**、**事件**和**设置**。要扩展文件数据的空间，在**设置** → **存储空间**中填写更大的值，例如 `20Gi`，点击**检查变更**，确认后点击**扩容到 20Gi**。Operator 会直接扩容磁盘，所有文件都会保留。容量只能增加，字段下方会说明当前存储类是否支持扩容。

要修改其他 operator 配置，在**设置**上方切换到 **YAML**，修改并检查变更后应用。

要将文件保留在其他位置，从能连接私有端点的应用或 S3 客户端，将存储桶内容复制到另一个 S3 服务，并确认复制的内容可以读取。文件的定时复制与还原由该工具管理，这个页面没有数据库那样的**备份**选项卡或还原按钮。

## 确认结果

**概览**显示**就绪**，**组成部分**中的 master、volume、filer、S3 都在运行，**存储桶**每一行显示 `Ready`，且**连接**中有**访问密钥 ID**，就可以使用。用 kubectl 查看：

```sh
kubectl -n shop get seaweed files
kubectl -n shop get buckets.seaweed.seaweedfs.com
kubectl -n shop get secret files-app -o jsonpath='{.data.accessKey}' | base64 -d
```

SeaweedFS Operator 根据 S3Credentials 创建 `files-app` 机密变量，其中包含 `accessKey` 和 `secretKey`。这个机密变量出现后，应用就能连接。从集群内的副本使用 S3 客户端列出存储桶，例如 `aws --endpoint-url http://files-s3.shop.svc:8333 s3 ls`，能看到 `uploads` 就说明密钥和端点都正确。

## 用 kubectl 完成相同操作

对象存储由 SeaweedFS Operator 管理，Zeabur 只写入 operator 读取的对象，移除 Zeabur 后仍可正常运行。下面的 YAML 等同于在表单中使用名称 `files`、容量 `10Gi`、存储桶 `uploads` 创建对象存储，保存为 `files.yaml` 后，用 `kubectl -n shop apply -f files.yaml` 应用：

```yaml
apiVersion: seaweed.seaweedfs.com/v1
kind: Seaweed
metadata:
  name: files
spec:
  image: chrislusf/seaweedfs:4.48
  volumeServerDiskCount: 1
  master:
    replicas: 1
    persistence:
      enabled: true
      resources:
        requests:
          storage: 1Gi
    podSecurityContext:
      runAsNonRoot: true
      runAsUser: 1000
      runAsGroup: 1000
      fsGroup: 1000
      seccompProfile:
        type: RuntimeDefault
    containerSecurityContext:
      allowPrivilegeEscalation: false
      capabilities:
        drop: [ALL]
  volume:
    replicas: 1
    requests:
      storage: 10Gi
    podSecurityContext:
      runAsNonRoot: true
      runAsUser: 1000
      runAsGroup: 1000
      fsGroup: 1000
      seccompProfile:
        type: RuntimeDefault
    containerSecurityContext:
      allowPrivilegeEscalation: false
      capabilities:
        drop: [ALL]
  filer:
    replicas: 1
    persistence:
      enabled: true
      resources:
        requests:
          storage: 1Gi
    podSecurityContext:
      runAsNonRoot: true
      runAsUser: 1000
      runAsGroup: 1000
      fsGroup: 1000
      seccompProfile:
        type: RuntimeDefault
    containerSecurityContext:
      allowPrivilegeEscalation: false
      capabilities:
        drop: [ALL]
  s3:
    replicas: 1
    port: 8333
    podSecurityContext:
      runAsNonRoot: true
      runAsUser: 1000
      runAsGroup: 1000
      fsGroup: 1000
      seccompProfile:
        type: RuntimeDefault
    containerSecurityContext:
      allowPrivilegeEscalation: false
      capabilities:
        drop: [ALL]
---
apiVersion: seaweed.seaweedfs.com/v1
kind: S3Identity
metadata:
  name: files-app
spec:
  seaweedRef:
    name: files
---
apiVersion: seaweed.seaweedfs.com/v1
kind: S3Credentials
metadata:
  name: files-app
spec:
  seaweedRef:
    name: files
  identityRef:
    name: files-app
---
apiVersion: seaweed.seaweedfs.com/v1
kind: S3Policy
metadata:
  name: files-app
spec:
  seaweedRef:
    name: files
  statements:
    - effect: Allow
      actions: ["s3:*"]
      resources: ["*"]
---
apiVersion: seaweed.seaweedfs.com/v1
kind: S3PolicyBinding
metadata:
  name: files-app
spec:
  seaweedRef:
    name: files
  policyRef:
    name: files-app
  subjects:
    - kind: S3Identity
      name: files-app
---
apiVersion: seaweed.seaweedfs.com/v1
kind: Bucket
metadata:
  name: files-uploads
spec:
  name: uploads
  clusterRef:
    name: files
  reclaimPolicy: Delete
  access:
    - user: files-app
      actions: [Read, Write, List, Tagging]
```

- Seaweed 是存储服务本身。S3 端点是 `files-s3`，端口为 8333。
- S3Identity、S3Credentials、S3Policy、S3PolicyBinding 创建供应用使用的账号 `files-app`，并允许这个账号访问所有存储桶。
- 每个存储桶对应一个 Bucket，名称为 `<对象存储名称>-<存储桶名称>`，`spec.name` 才是 S3 看到的名称。新增存储桶就是再创建一个 Bucket。
- 要指定存储类，在 `master.persistence`、`filer.persistence` 中添加 `storageClassName`，在 `volume` 中添加 `storageClassName`。
- 扩容：修改 `spec.volume.requests.storage`，例如 `kubectl -n shop patch seaweed files --type=merge -p '{"spec":{"volume":{"requests":{"storage":"20Gi"}}}}'`。

**连接到服务**只是为服务添加环境变量。保存为 `connect.yaml`，用 `kubectl -n shop patch deployment web --patch-file connect.yaml` 应用：

```yaml
spec:
  template:
    spec:
      containers:
        - name: web
          env:
            - name: S3_ENDPOINT
              value: http://files-s3.shop.svc:8333
            - name: S3_ACCESS_KEY_ID
              valueFrom:
                secretKeyRef:
                  name: files-app
                  key: accessKey
            - name: S3_SECRET_ACCESS_KEY
              valueFrom:
                secretKeyRef:
                  name: files-app
                  key: secretKey
            - name: S3_REGION
              value: us-east-1
            - name: S3_BUCKET
              value: uploads
```

删除存储桶或整个对象存储，就是删除这些对象：

```sh
kubectl -n shop delete buckets.seaweed.seaweedfs.com files-uploads
kubectl -n shop delete s3policybinding/files-app s3policy/files-app s3credentials/files-app s3identity/files-app
kubectl -n shop delete seaweed files
```

先删除存储桶，再删除账号，最后删除 Seaweed，与界面的**删除对象存储**顺序相同。使用 `Delete` 回收策略的存储桶会连同文件一起删除。

## 无法连接或没有密钥时

| 情况 | 下一步 |
| --- | --- |
| **新增**菜单要求先安装组件 | 请管理员安装 SeaweedFS Operator。 |
| 状态一直为**未知**或组成部分未就绪 | 查看**事件**、**日志**和 operator 的报告，确认卷和相关副本能启动。 |
| **访问密钥 ID** 为空 | 等待 operator 创建凭证，再刷新页面。检查凭证对象和副本的事件。 |
| 无法显示秘密访问密钥 | 确认自己有读取该项目机密变量的权限。 |
| **连接到服务**中没有可选服务 | 先创建同一项目中的应用，确认可以修改这个应用，且该服务不由其他工具管理。 |
| 已有对象存储无法**连接到服务** | 此操作需要可识别的应用密钥。先根据实际端点和密钥手动配置应用。 |
| S3 客户端无法连接端点 | 确认客户端位于集群内，使用页面列出的端点和区域，并核对密钥和存储桶名称。 |

## 删除对象存储

先断开应用与对象存储的连接，或将服务改为连接到要保留的目标位置。接着在对象存储右上角的**更多**中选择**删除对象存储**。

删除列表包含存储桶、身份与密钥相关对象、Seaweed，以及 Zeabur 找到的数据卷。逐项确认后再应用变更。是否保留底层磁盘，取决于磁盘的回收策略。

<Callout type="warn">
删除整个对象存储会中断 S3 连接，删除存储桶和卷也可能移除所有文件。先完成数据复制，并确认应用已改为连接新目标，再执行删除。
</Callout>
