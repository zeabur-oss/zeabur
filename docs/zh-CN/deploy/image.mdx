在项目中选择**新增** → **Docker 镜像**，填写镜像和端口，完成**检查变更**后应用，即可启动服务。需要保留文件、登录私有 registry 或调整资源时，展开**更多设置**。

## 开始前

- 已有项目，以及在该项目中创建服务的权限。公开域名、机密变量和卷各有独立的权限，表单会根据可用权限显示选项。
- 镜像已推送到节点可访问的 registry，并提供与节点架构匹配的版本。
- 知道应用实际监听的端口。首次部署时，可以先按照[第一个项目](../get-started/first-project.mdx)完成公开镜像的部署流程。
- 需要保存数据时，集群已有可分配卷的默认存储类。

## 创建服务

<Steps>
<Step>

### 指定镜像

打开**新增** → **Docker 镜像**，在**镜像**中填写完整引用，例如 `ghcr.io/acme/web:1.4`。使用固定 tag 或 digest，方便核对部署版本。未指定版本时，registry 会使用 `latest`。

确认**名称**。名称最多 40 个字符，可包含小写字母、数字和连字符，必须以字母开头，且不能与项目中的已有名称冲突。

</Step>
<Step>

### 确认端口和域名

Zeabur 会读取镜像声明的端口。确认**端口**与应用实际监听的端口号一致。如果镜像声明了多个端口号，根据应用用途选择。

不接受连接的后台服务，将**端口**留空。此时只创建 Deployment，没有私有地址，也无法添加公开域名。

要提供 HTTP 网站，开启**公开域名**。如果管理员配置了应用域名，表单会推荐网址。未配置时，自行填写网址，并将 DNS 指向集群入口。表单还会显示当前使用的证书签发者，或注明仅支持 HTTP。详见[添加公开域名](../configure/domains.mdx)。

![部署镜像表单，端口自动填入镜像声明的 8080，公开域名填入推荐的网址](../images/shots/image-form.avif)

</Step>
<Step>

### 按需展开更多设置

| 设置 | 填写方式与结果 |
| --- | --- |
| **环境变量** | 每行填写一个 `KEY=value`。如果应用通过 `PORT` 决定监听地址和端口，在这里手动添加 `PORT`。 |
| **将值存入 Secret** `<名称>-env` | 默认开启，变量值会存入这个机密变量。没有创建机密变量的权限时，变量会直接写入 Deployment，也无法使用私有 registry。此时不要在这里填写密码。 |
| **卷** | 开启后填写**挂载路径**，例如 `/data`，以及**卷大小**，例如 `5Gi`。创建的是新的空白卷。 |
| **规格** | 选择**小**、**中**或**大**，字段下方会列出 CPU 预留量、内存预留量和上限。 |
| **副本数** | 可选 1 到 20，挂载卷时固定为 1。 |
| **私有 registry** | 开启后填写 **Registry**、**用户名**、**密码**，例如 registry 主机 `ghcr.io`。Zeabur 会创建用于下载镜像的机密变量。 |
| **安全性** | Zeabur 读取镜像的 `User`：数字 UID 不是 0（例如 `101`、`1000:1000`）时选择**严格**；未指定用户，或指定 `root`、`0`、`nginx` 这类用户名时选择**兼容**。表单会说明原因，创建前仍可切换。 |

<Callout type="warn">
挂载卷的服务只运行一个副本。更新时会先停止旧副本，再启动新副本，期间服务会中断。
</Callout>

</Step>
<Step>

### 检查将要新增的对象

点击**检查变更**。核对镜像、名称、端口和公开域名。新增卷时，还要检查容量和挂载路径。应用后会进入新服务。

![部署 web 前的确认界面，列出要创建的 Deployment、Service 和 Ingress](../images/shots/image-review.avif)

需要配置表单未提供的容器字段时，点击**以 YAML 编辑**，表单会将当前配置带入创建页面。修改 YAML 后再次**检查变更**，确认所有文档后创建。

</Step>
</Steps>

## 确认结果

在服务**概览**中确认副本就绪，再查看**日志**，确认应用是否已启动。填写端口后，Zeabur 会为服务添加 TCP 就绪检查，副本能够接受连接后才会收到流量。

![服务概览，显示副本状态和公开网址](../images/shots/service-overview.avif)

如果有公开域名，到**网络**打开网址，确认应用能够响应。私有服务可以由集群内的其他服务通过**私有网络**中显示的地址访问。

用 kubectl 查看时，Zeabur 创建的对象都带有 `app.kubernetes.io/name: <服务名称>`：

```sh
kubectl -n shop get deploy,svc,ingress,secret,pvc -l app.kubernetes.io/name=web
kubectl -n shop rollout status deployment/web
```

如果 `deployment.apps/web` 的 `READY` 为 `1/1`，且 `rollout status` 输出 `successfully rolled out`，则表示副本已通过就绪检查。Ingress 的 `HOSTS` 是你填写的域名，`ADDRESS` 是集群入口的地址。

部署后需要调整变量或卷时，前往[环境变量](../configure/variables.mdx)和[卷](../configure/volumes.mdx)。

## 用 kubectl 完成相同操作

表单创建的是普通 Kubernetes 对象，没有 Zeabur 专属字段。将下面的 YAML 保存为 `web.yaml`，用 `kubectl -n shop apply -f web.yaml` 应用，结果与在表单中选择**严格**、**小**规格并开启公开域名相同：

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: web-env
  labels:
    app.kubernetes.io/name: web
type: Opaque
stringData:
  APP_ENV: production
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
  labels:
    app.kubernetes.io/name: web
spec:
  replicas: 1
  selector:
    matchLabels:
      app.kubernetes.io/name: web
  template:
    metadata:
      labels:
        app.kubernetes.io/name: web
    spec:
      automountServiceAccountToken: false
      securityContext:
        runAsNonRoot: true
        seccompProfile:
          type: RuntimeDefault
      containers:
        - name: web
          image: ghcr.io/acme/web:1.4
          ports:
            - containerPort: 8080
          envFrom:
            - secretRef:
                name: web-env
          resources:
            requests:
              cpu: 100m
              memory: 128Mi
            limits:
              memory: 256Mi
          readinessProbe:
            tcpSocket:
              port: 8080
          securityContext:
            allowPrivilegeEscalation: false
            capabilities:
              drop: [ALL]
---
apiVersion: v1
kind: Service
metadata:
  name: web
  labels:
    app.kubernetes.io/name: web
spec:
  selector:
    app.kubernetes.io/name: web
  ports:
    - name: http
      port: 8080
      targetPort: 8080
---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web
  labels:
    app.kubernetes.io/name: web
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt
spec:
  tls:
    - hosts: [web.example.com]
      secretName: web-tls
  rules:
    - host: web.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: web
                port:
                  number: 8080
```

与表单选项的对应关系：

- **兼容**：Pod 的 `securityContext` 只保留 `seccompProfile`，容器的 `securityContext` 只保留 `allowPrivilegeEscalation: false`。
- **中**、**大**规格：CPU 和内存预留量分别为 `250m`／`256Mi`（上限 `512Mi`）和 `500m`／`512Mi`（上限 `1Gi`）。
- 没有证书签发者时，Ingress 不带 annotation 和 `tls`。将 `letsencrypt` 替换为集群实际的 ClusterIssuer 名称，可用 `kubectl get clusterissuer` 查看。
- 多个端口：Service 的第一个端口名为 `http`，其余端口名为 `port-<编号>`。
- 关闭**将值存入 Secret** 时，变量改为写入容器的 `env`，不创建 `web-env`。

私有 registry 的账号和密码存放在 `kubernetes.io/dockerconfigjson` 类型的机密变量中，名称为 `<服务名称>-registry`，Deployment 通过 `imagePullSecrets` 引用它：

```sh
kubectl -n shop create secret docker-registry web-registry \
  --docker-server=ghcr.io --docker-username=acme --docker-password=<令牌>
kubectl -n shop label secret web-registry app.kubernetes.io/name=web
kubectl -n shop patch deployment web -p '{"spec":{"template":{"spec":{"imagePullSecrets":[{"name":"web-registry"}]}}}}'
```

卷对应一个 PVC，名称为 `<服务名称>-<卷名称>`：

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: web-data
  labels:
    app.kubernetes.io/name: web
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests:
      storage: 5Gi
```

挂载时，Deployment 的 `spec.replicas` 固定为 `1`，并添加 `strategy: {type: Recreate}`，Pod 的 `volumes` 中填写 `persistentVolumeClaim: {claimName: web-data}`，容器的 `volumeMounts` 中填写 `mountPath: /data`。对于已创建的服务，到[卷](../configure/volumes.mdx)通过表单添加更方便。

## 常见失败情况

| 情况 | 处理方式 |
| --- | --- |
| 无法读取镜像的端口 | 根据提示检查镜像名称、tag 和 registry 的账号与密码。如果知道实际端口，可以直接填写。 |
| 镜像只有其他架构的版本 | 改用支持节点架构的 tag，或重新构建对应架构的镜像。 |
| 无法下载镜像 | 在**概览**或**部署记录**中查看原因，确认节点可以连接到 registry，并核对私有 registry 的凭证。 |
| 容器因 root 或权限问题无法启动 | 检查镜像的用户、目录权限和安全配置。需要 root 的镜像选择**兼容**。要保持严格模式，改用以非 root 数字 UID 运行的镜像。如果项目仍强制使用 `restricted`，请管理员将项目的 Pod Security 级别改为 `baseline`。 |
| 副本一直未就绪 | 查看**日志**，确认应用已监听表单指定的端口，再到**设置**调整健康检查。 |
| 卷一直未就绪 | 查看存储相关事件，确认默认存储类、可用空间和可调度的节点。 |
| 服务已就绪但网址无法打开 | 到**网络**根据 DNS、入口和服务的连接检查结果处理，见[公开域名](../configure/domains.mdx)。 |

## 删除服务

在服务右上角的**更多**中选择**删除服务**。删除流程会列出由该服务创建且没有其他服务使用的网络、机密变量和卷。其他服务仍在使用的对象会保留。

<Callout type="warn">
删除卷可能同时删除文件，结果取决于底层磁盘的回收策略。应用前查看变更中列出的卷和回收策略，先移出需要保留的数据。
</Callout>
