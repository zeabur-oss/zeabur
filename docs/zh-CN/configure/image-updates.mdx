---
title: 自动更新镜像
description: 让 Keel 把服务换成镜像的新版本、选择检查时间、关闭自动更新，以及更新失败时如何处理。
---

使用镜像仓库镜像的服务（例如 PostgreSQL 或 Redis），可以在镜像有新版本时自动换上。到服务的**设置** → **自动更新**，选好要更新哪些版本、Keel 什么时候检查，然后保存。每次更新都会重启服务。

## 开始前

- 你需要项目中修改服务的权限。
- 集群需要有 Keel 组件。缺少时，这一部分会给出提示并提供安装。
- 只有 Deployment、StatefulSet 和 DaemonSet 有这一部分，Job 和定时任务没有。从 Git 或上传文件夹构建的服务，改用**构建**选项卡中的**新构建完成后自动部署**（见[重启、回滚与暂停服务](./restart-rollback.mdx#自动部署新构建)）。
- 从项目的**新建** → **数据库**创建的数据库没有这一部分，数据库和镜像都由各自的 operator 管理。
- Helm、Argo CD 或 Flux 管理的服务会显示这一部分，但不能在这里修改，请到对应的工具中设置 annotation。

## 开启自动更新

<Steps>
<Step>

### 选择更新哪些版本

到服务的**设置** → **自动更新**，在**更新哪些版本**中选择一项：

| 选项 | `redis:7.2.4` 会换成 | `postgres:16.4` 会换成 |
| --- | --- | --- |
| **只更新补丁版本** | `7.2.5`、`7.2.6`……，不会到 `7.3.0` | 不会更新，Keel 把 `16.5` 视为次要版本 |
| **补丁版本和次要版本** | `7.3.0`、`7.4.1`……，不会到 `8.0.0` | `16.5`、`16.6`……，不会到 `17.0` |
| **所有新版本** | 所有更新的版本，包括 `8.0.0` | 所有更新的版本，包括 `17.0` |
| **同一个标签的新镜像** | 以 `7.2.4` 重新推送的镜像 | 以 `16.4` 重新推送的镜像 |

列表下方会写出这个服务会换到哪些版本。升级主要版本可能需要迁移数据，例如 PostgreSQL 升级主要版本前要先备份再执行升级，所以数据库建议选择**补丁版本和次要版本**，主要版本不会改变。PostgreSQL 的标签如果只有两段数字（例如 `16.4`），不要选择**只更新补丁版本**，否则永远不会更新。

按版本更新的选项需要版本号标签：一到三段数字，例如 `8`、`1.27`、`7.2.4`，或者 `latest`。Keel 把 `8` 视为 `8.0.0`，更新后标签会变成完整的版本号，例如 `8.0.2`。`latest` 会先换成最新的版本号标签。标签含有其他文字时（例如 `1.30-alpine`），只能选择**同一个标签的新镜像**。服务有多个容器时，每个容器都要使用版本号标签。

</Step>
<Step>

### 选择什么时候更新

在**什么时候更新**中选择一项：

- **一有新版就更新**：Keel 每小时检查一次。
- **每天**，再选择时间。
- **每周一次**，再选择星期和时间。

![db 的自动更新：postgres:18 选择补丁版本和次要版本，每周日 03:00 检查，下方写出换算后的 UTC 时间](../images/shots/image-updates.avif)

时间按浏览器的时区选择，下方会写出换算后的 UTC 时间。Zeabur 开源版保存的是 UTC 时间，所以全年都不会改变：

- 你所在地区开始或结束夏令时后，Keel 仍在同一个 UTC 时间检查，按你的时钟就会早或晚一小时，表单也会改为显示新的当地时间。
- 只修改**更新哪些版本**，已保存的 UTC 时间不会改变。修改了**什么时候更新**、星期或时间，就会按你现在的时钟重新换算 UTC 时间。
- 在相差半小时的时区（例如印度），时间以 `:30` 结尾，换成 UTC 正好是整点。

</Step>
<Step>

### 保存并检查变更

点击**保存**。检查页面会写出服务要换到哪些版本、Keel 什么时候检查，并列出要添加到工作负载上的 annotation：`keel.sh/policy`、`keel.sh/trigger: poll` 和 `keel.sh/pollSchedule`。选择**同一个标签的新镜像**时，还会添加 `keel.sh/match-tag`。在检查页面点击**保存**应用。

![db 的检查页面：会更新到补丁版本和次要版本，每周日 03:00（UTC）检查，并列出要添加的 Keel annotation](../images/shots/image-updates-review.avif)

</Step>
</Steps>

## 关闭自动更新

在**自动更新**中把**更新哪些版本**改为**关闭**，点击**保存**。检查页面会写出服务不再自动更新，并移除 `keel.sh/policy`、`keel.sh/trigger`、`keel.sh/pollSchedule` 和 `keel.sh/match-tag`。点击**关闭**应用。服务会继续使用当前的镜像。

![db 的检查页面：不再自动更新，并移除四个 Keel annotation](../images/shots/image-updates-off-review.avif)

如果 Keel 是在 Zeabur 开源版之外设置的（例如用 kubectl），列表会显示**Zeabur 之外的设置**和使用的规则，选择**关闭**或其他选项就会替换。

## 固定到摘要（digest）的镜像

用摘要指定的镜像（例如 `redis@sha256:…`）内容永远不会改变，所以这一部分只显示说明，没有选项。要自动更新，到**设置**，将顶部的切换项从**设置**切换到 **YAML**，点击**编辑**，把容器的 `image` 改成标签，检查并应用后，再开启自动更新。

原本已开启自动更新、之后才改用摘要的服务，仍会显示表单，可以关闭自动更新。

## 更新失败时

Keel 换好镜像就结束，不会等待新副本就绪，失败时也不会回滚（[#1014](https://github.com/zeabur-oss/zeabur/issues/1014)）。

- 设置了[就绪检查](./service-settings.mdx)的 Deployment，新副本没有通过检查时，旧副本会继续接收流量，服务显示**部署卡住**。
- StatefulSet 一次替换一个副本，所以只有一个副本的 StatefulSet（例如 Redis）要等新副本就绪才会恢复服务。

处理步骤：

1. 先关闭自动更新。不关闭的话，Keel 下次检查又会换成同一个版本。
2. 在**概览**的**部署进度**或**部署记录**中回滚（见[重启、回滚与暂停服务](./restart-rollback.mdx#回滚到之前的版本)）。
3. 修复问题后，再开启自动更新。

要收到更新失败的通知，到项目的**设置** → **通知**添加渠道，选择**部署失败**事件（见[通知](../cluster/notifications.mdx)）。这个事件目前只覆盖 Deployment，StatefulSet 和 DaemonSet 还不会发出（[#1015](https://github.com/zeabur-oss/zeabur/issues/1015)）。

## 用 kubectl 执行相同操作

下面的示例使用项目 `demo` 和 StatefulSet `db`。计划的第一列是秒，时间为 UTC：`0 0 3 * * 0` 表示每周日 03:00（UTC）。

| Zeabur 开源版操作 | kubectl |
| --- | --- |
| **补丁版本和次要版本**、**每周一次**周日 03:00 UTC | `kubectl -n demo annotate statefulset db keel.sh/policy=minor keel.sh/trigger=poll keel.sh/pollSchedule="0 0 3 * * 0"` |
| **只更新补丁版本**、**一有新版就更新** | `kubectl -n demo annotate --overwrite statefulset db keel.sh/policy=patch keel.sh/trigger=poll keel.sh/pollSchedule=@hourly` |
| **同一个标签的新镜像**、**每天** 03:00 UTC | `kubectl -n demo annotate --overwrite statefulset db keel.sh/policy=force keel.sh/match-tag=true keel.sh/trigger=poll keel.sh/pollSchedule="0 0 3 * * *"` |
| **关闭** | `kubectl -n demo annotate statefulset db keel.sh/policy- keel.sh/trigger- keel.sh/pollSchedule- keel.sh/match-tag-` |

查看服务当前的设置：

```sh
kubectl -n demo get statefulset db -o jsonpath='{.metadata.annotations}'
```

## 遇到问题

| 页面或结果 | 后续处理 |
| --- | --- |
| 没有**自动更新**这一部分 | 服务是从源代码构建的、是 Job 或定时任务，或者是从**新建** → **数据库**创建的数据库。 |
| 只能选择**同一个标签的新镜像** | 标签不是版本号，例如 `1.30-alpine`。改成 `1.30` 这类版本号标签。 |
| 显示镜像固定到某个摘要 | 把镜像改成标签。 |
| 这一部分提示缺少 Keel | 在这一部分或**集群** → **组件**中安装 Keel 组件。 |
| PostgreSQL 服务一直没有更新 | 标签只有两段数字（例如 `16.4`），又选择了**只更新补丁版本**。改选**补丁版本和次要版本**。 |
| 更新后服务显示**部署卡住** | 先关闭自动更新再回滚，见[更新失败时](#更新失败时)。 |
