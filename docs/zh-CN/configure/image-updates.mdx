---
title: 自动更新镜像
description: 让 Keel 把用镜像部署的服务（例如 Redis 或 PostgreSQL）自动换成新版本。
---

用镜像仓库中的镜像部署的服务，可以让 Keel 自动换上新版本：你设置允许更新的版本范围，以及每小时、每天或每周什么时候检查。每次更新都会重启服务。

## 开始之前

- 集群已安装 Keel 组件。还没安装时，**自动更新**部分会显示安装按钮，安装完成后再回到服务的**设置**。
- 服务是 Deployment、StatefulSet 或 DaemonSet，镜像使用标签，例如 `7.2.4`、`8`、`1.27` 或 `latest`，而不是摘要（digest）。从 Git 或上传文件夹构建的服务，改用**构建**选项卡中的**新构建完成后自动部署**。
- 从**新建** → **数据库**创建的 PostgreSQL 数据库使用 CloudNativePG 和下方的 [Zeabur 数据库更新程序](#cloudnativepg-数据库)。其他 operator 管理的数据库尚不支持自动更新。

<Steps>
<Step>

### 打开自动更新

到服务的**设置**，向下滚动到**自动更新**，或点击顶部的**自动更新**直接跳转。

</Step>
<Step>

### 选择更新哪些版本

展开**更新哪些版本**菜单，选择一项：

| 选项 | `7.2.4` 会升级到 |
| --- | --- |
| **只更新补丁版本** | `7.2.5`、`7.2.6`……，不会自动升级到 `7.3` |
| **补丁版本和次要版本** | `7.3`、`7.4`……，不会自动升级到 `8` |
| **所有新版本** | 任何更新的版本，包括 `8` |
| **同一个标签的新镜像** | 版本号不变，同一个标签推送了新镜像就换上 |

选好后，菜单下方会写出这个服务会升级到哪里。

Redis 建议选择**只更新补丁版本**。PostgreSQL 的版本号只有两段，`16.4` 到 `16.5` 在 Keel 看来是次要版本，所以 `postgres:16.4` 要选择**补丁版本和次要版本**，才会升级到 `16.x` 的新版本，`17` 仍会等你决定。PostgreSQL 升级主要版本要先备份，再用 `pg_upgrade` 或导出导入迁移数据，Keel 不会替你完成这一步。

标签写成 `8` 时，Keel 会把它视为 `8.0.0`，第一次更新后标签会变成完整的版本号，例如 `8.0.5`。

</Step>
<Step>

### 选择什么时候更新

在**什么时候更新**中选择：

- **一有新版就更新**：Keel 每小时检查一次。
- **每天**：再选择**时间**。
- **每周一次**：再选择**星期**和**时间**。

星期和时间按浏览器的时区选择，下方会写出换算后的 UTC 时间。例如在冬季的 Europe/Amsterdam 时区选择星期日 03:00，就是星期日 02:00（UTC）。

![postgres:18 服务的自动更新：补丁版本和次要版本、每周一次、星期日、03:00，下方写出换算后的 UTC 时间](../images/shots/image-updates.avif)

Zeabur 开源版保存的是 UTC 时间，不会随夏令时调整。上面的例子到了夏季，Keel 会在阿姆斯特丹时间 04:00 检查。之后只修改**更新哪些版本**，时间会保持原来保存的 UTC 时间。要随换季调整，重新选择一次时间再保存。

</Step>
<Step>

### 保存并应用

点击**保存**，会打开变更检查页面。确认内容后，再点击一次**保存**应用。

![检查页面写着 db 会自动更新到新的补丁版本和次要版本，每周日 03:00（UTC）检查，每次更新都会重启服务](../images/shots/image-updates-review.avif)

应用后，**自动更新**部分显示当前的设置，再次修改之前，**保存**按钮会是灰色。

Keel 到了时间就检查镜像仓库，有符合条件的新版本就换上，服务会重启。更新过的版本会出现在服务的**部署记录**中。

</Step>
</Steps>

## 关闭自动更新

在**更新哪些版本**中选择**关闭**，点击**保存**。变更检查页面会列出 Zeabur 开源版要从服务移除的 Keel 设置：`keel.sh/policy`、`keel.sh/trigger` 和 `keel.sh/pollSchedule`，选择了**同一个标签的新镜像**的服务还有 `keel.sh/match-tag`。点击**关闭**应用，服务会继续使用当前的镜像。

![检查页面写着 db 不再自动更新，并列出会移除的 keel.sh/policy、keel.sh/pollSchedule 和 keel.sh/trigger](../images/shots/image-updates-off-review.avif)

## 固定到摘要（digest）的镜像

镜像写成 `redis@sha256:…` 时，服务固定使用这个摘要对应的镜像，Keel 不会换成其他版本。**自动更新**部分只会显示提示，没有表单。

要自动更新，先把镜像改回标签，例如 `redis:7.2.4`。已经开启自动更新的服务改用摘要后，这一部分仍会显示表单，你仍然可以关闭。

## 更新失败时

Keel 更新后不会等待服务恢复健康，也还不会自动回滚（[#1014](https://github.com/zeabur-oss/zeabur/issues/1014)）。

- **让旧版本继续服务**：到**设置** → **健康检查**设置**就绪检查**，例如 Redis 设为 **TCP**、端口 `6379`。没有卷的 Deployment 会逐个替换副本：新副本没有通过就绪检查时，旧副本会继续服务，服务显示**部署卡住**。有卷的 Deployment 和只有一个副本的 StatefulSet 会先停止旧副本，新镜像通过检查之前，服务都无法使用。
- **回到旧版本**：先把自动更新**关闭**，再到**部署记录**点击**回滚**。如果不关闭，Keel 下次检查又会换上同一个新版本。StatefulSet 还要删除卡在新镜像上的 Pod，例如 `kubectl -n demo delete pod db-0`，Kubernetes 才会用旧镜像重新启动它。
- **失败时通知**：到项目的**设置** → **通知**点击**添加渠道**，选择 **Webhook**、Slack 或其他接收位置，事件勾选**部署失败**。这对 Deployment 有效；StatefulSet 和 DaemonSet 的部署通知在 [#1015](https://github.com/zeabur-oss/zeabur/issues/1015) 中跟进。

## CloudNativePG 数据库

数据库的**设置**沿用服务表单的版本与计划字段。选择同一标签的新镜像并设置计划，再检查并保存更改。关闭时会移除相同的四个 Keel 注解。保存计划不会更改数据库的镜像、存储空间或备份设置。

管理员须在 Zeabur Helm chart 启用 `databaseUpdater.enabled`。Chart 会安装 Zeabur 数据库更新程序，使用独立权限，以及 Zeabur 版本固定的镜像。更新程序复用未修改的 Keel 库，不需要安装修改过的 Keel 或更改目录。**设置**会显示更新程序是否就绪；就绪时才能启用或更改计划，不可用时仍可**关闭**已有的自动更新。

请使用明确的主版本标签，例如 `ghcr.io/cloudnative-pg/postgresql:18-standard-trixie`。更新程序按各数据库的计划检查此标签，将新摘要写入 `spec.imageName`，再由 CloudNativePG 逐一更新实例。`18-standard-trixie@sha256:…` 会保留标签并更新摘要。镜像仓库与标签保持不变，因此更新程序不会选择其他 PostgreSQL 主版本或镜像类型；发布者也须确保该标签保持在指定的主版本。固定日期的标签只有在发布者替换其内容时才会更新。

只有摘要的引用、`latest` 与设置了 `spec.imageCatalogRef` 的 Cluster 不适用；镜像目录的更新由其所有者管理。更新程序会跳过状态不正常的数据库，并在写入前检查镜像的平台兼容性。计划决定何时开始检查，不限制更新必须在何时完成。更新程序不会自动回滚，请在更新后检查数据库状态。上方服务的部署记录与失败通知行为不适用于 Cluster。

## 用 kubectl 执行相同操作

Keel 只读取工作负载上的 annotation。以下以项目 `demo`、Deployment `redis` 为例，每周日 03:00 UTC 只更新补丁版本：

```sh
kubectl -n demo annotate deployment redis \
  keel.sh/policy=patch keel.sh/trigger=poll keel.sh/pollSchedule="0 0 3 * * 0"
```

`pollSchedule` 有 6 个字段，第一个是秒。**自动更新**部分会读取这些设置，显示为**只更新补丁版本**、**每周一次**。关闭时移除这些 annotation：

```sh
kubectl -n demo annotate deployment redis keel.sh/policy- keel.sh/trigger- keel.sh/pollSchedule-
```
