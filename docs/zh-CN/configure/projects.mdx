## 开始前

- 你需要有创建项目的权限。找不到**新建项目**时，请管理员帮你创建项目，再把你加进去。
- 想好项目名称。名称只能使用小写字母、数字和连字符，开头和结尾必须是字母或数字，最多 63 个字符，也不能以 `kube-` 开头。

## 创建项目

<Steps>
<Step>

### 填写名称

打开**项目**页，点击**新建项目**。在**名称**中填写 `hello`。**显示名称**可以留空，填写后会代替名称显示在界面上。

![新建项目窗口，名称填为 hello](../images/shots/project-new.avif)

项目在集群中是一个 Namespace，也就是 Kubernetes 用来分开放置一组服务的空间。项目名称就是 Namespace 的名称，所以创建后不能修改。同名的 Namespace 已经存在时，表单会提示你改用它，做法见[下一节](#将已有的-namespace-加入-zeabur-开源版)。

</Step>
<Step>

### 检查并创建

点击**检查变更**，页面会列出 Zeabur 开源版要做的事：

- 创建 `hello` Namespace，加上项目标签。安全级别设为 `baseline`：服务可以以 root 身份运行，但不能访问宿主机。
- 没有另外设置的服务，拿不到连接 Kubernetes API 用的令牌。
- 集群中有带 `zeabur.com/platform: "true"` 标签的 Namespace 时，还会[隔离这个项目](#隔离其他项目)，其他项目的服务连接不进来。

![创建项目 hello 前的确认页面，说明将创建的 Namespace 和安全配置](../images/shots/project-new-review.avif)

确认后点击**创建**，界面会进入新项目。

</Step>
</Steps>

## 将已有的 Namespace 加入 Zeabur 开源版

集群中已经有应用时，可以把它所在的 Namespace 变成项目，不用重新部署。这需要该 Namespace 的 `zeabur-manage` 权限，通常只有管理员具备，见[项目 Namespace 的保护](../reference/permissions.mdx#项目-namespace-的保护)。

1. 在**项目**页的**其他 Namespace** 中找到那个 Namespace。

   ![项目页的其他 Namespace 列出集群中尚未作为项目的 Namespace](../images/shots/existing-namespaces.avif)

2. 在对应行打开菜单，选择**使用这个 Namespace**，检查后应用。

Zeabur 开源版只会为 Namespace 添加项目标签 `zeabur.com/project: "true"`。其中的服务、数据和安全配置都不会改变。

不想再在 Zeabur 开源版中看到它时，打开项目**设置**的**危险区域**，点击**从 Zeabur 开源版移除**。这只会移除项目标签，Namespace 及其中的所有内容都会保留。要连同内容一起删除，见[删除项目](./delete-project.mdx)。

## 修改名称、描述和图标

1. 打开项目**设置**的**基本信息**，修改这三项：
   - **项目名称**：代替 Namespace 名称显示在界面上，最多 64 个字符。
   - **描述**：项目的用途，显示在名称下方，最多 500 个字符。
   - **图标**：点击**更换图标**，从 16 个图标中选择一个。

   ![项目设置的基本信息，有项目名称、描述和图标](../images/shots/project-details.avif)

2. 点击**保存详细信息**，检查后应用。

项目的开发者可以修改这三项。Namespace 上的其他标签和注解只有管理员能修改。

## 设置构建的内存和 CPU

构建因为内存不够而失败时，失败信息会链接到这一节。

1. 打开项目**设置**的**构建**，填写这个项目每次构建最多能用的内存和 CPU，例如 `2Gi` 和 `2`。留空就用 Zeabur Builder 的默认值。填写的数量不能超过集群中最大的节点能提供的量。节点就是集群中的一台服务器。
2. 点击**保存构建上限**，检查后应用。之后开始的构建就会使用新的值。

修改构建上限需要该 Namespace 的 `patch` 和 `zeabur-manage` 权限。开发者看得到这两个字段，但不能保存。

## 隔离其他项目

隔离后，其他项目的服务就连接不到这个项目的服务。

1. 打开项目**设置**的**网络**，查看**其他项目**这一行：
   - **集群中的任何副本都能连接到这个项目的服务。**：尚未隔离。
   - **无法连接到这个项目的服务。项目内的服务和 Zeabur 开源版组件不受影响。**：已经隔离。

   ![项目设置的网络，其他项目一行说明当前是否隔离](../images/shots/project-network.avif)

2. 尚未隔离时，点击**隔离**，检查后应用。

隔离后，项目内的服务仍能相互连接。Traefik、数据库 operator 这类 Zeabur 开源版组件也能连接进来，因为它们所在的 Namespace 带有 `zeabur.com/platform: "true"` 标签，`kube-system` 也一样。

要让另一个项目连接进来，点击**允许其他项目连入**，选择项目，点击**允许**，检查后应用。那个项目的所有服务就能连接到这个项目的所有服务。要取消，在对应行点击**移除**。

界面上没有取消隔离的按钮，需要用 kubectl 处理，见页面最后的[隔离和允许其他项目](#隔离和允许其他项目)。隔离是否真正生效，取决于集群的网络插件（CNI）是否支持 NetworkPolicy。

## 确认结果

**项目**页会列出这个项目，并显示你设置的名称、描述和图标。项目**设置**的**网络**会显示当前是否隔离，以及哪些项目能连接进来。

## 遇到问题

| 界面或结果 | 处理方法 |
| --- | --- |
| **已经有同名的 Namespace，可以改用已有的 Namespace。** | 换一个名称，或在**其他 Namespace** 中将那个 Namespace 加入 Zeabur 开源版。 |
| 加入或移除项目时，集群返回 **Only an admin can change the namespace's labels** | 只有管理员能修改 Namespace 的标签，请管理员操作。 |
| **这是 Kubernetes 为自身组件保留的 Namespace，不能作为项目。** | 以 `kube-` 开头的 Namespace 和节点终端使用的 `zeabur-node-shell` 都不能作为项目。 |
| 创建项目时，检查页面没有隔离这一项 | 集群中没有带 `zeabur.com/platform: "true"` 标签的 Namespace。Zeabur 开源版无法判断 Ingress controller 在哪里，所以不隔离，以免公开域名打不开。Ingress controller 是把域名的流量转给服务的组件。请管理员为它所在的 Namespace 添加标签，再到**网络**点击**隔离**。 |
| 隔离后公开域名无法打开 | Ingress controller 所在的 Namespace 没有 `zeabur.com/platform: "true"` 标签。为那个 Namespace 添加标签，或在 `zeabur-project` 中添加一条允许连入的规则。 |

## 用 kubectl 完成相同操作

项目的所有配置都是 Namespace 上的标签、annotation 和普通的 NetworkPolicy。移除 Zeabur 开源版后，Kubernetes 仍会执行这些配置。

### 创建项目

与 Zeabur 开源版创建的内容相同：

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: demo
  labels:
    zeabur.com/project: "true"
    pod-security.kubernetes.io/enforce: baseline
    pod-security.kubernetes.io/audit: baseline
    pod-security.kubernetes.io/warn: baseline
  annotations:
    zeabur.com/display-name: Demo shop
    zeabur.com/description: The shop's web and worker
    zeabur.com/icon: storefront
---
apiVersion: v1
kind: ServiceAccount
metadata:
  name: default
  namespace: demo
automountServiceAccountToken: false
```

`zeabur.com/icon` 可以是 `folder`、`globe`、`storefront`、`rocket`、`cube`、`database`、`cloud`、`code`、`terminal`、`chart`、`chat`、`book`、`flask`、`game`、`heart` 或 `briefcase`。

### 加入、移除项目和修改详细信息

```sh
kubectl label namespace demo zeabur.com/project=true
kubectl label namespace demo zeabur.com/project-
kubectl annotate namespace demo --overwrite zeabur.com/display-name='Demo shop'
```

项目名称、描述和图标保存在 Namespace 的 annotation 上。

### 构建上限

构建上限是 Namespace 的 `builder.zeabur.com/build-memory` 和 `builder.zeabur.com/build-cpu` 注解：

```sh
kubectl annotate namespace demo --overwrite builder.zeabur.com/build-memory=2Gi builder.zeabur.com/build-cpu=2
```

### 调整 Pod Security 级别

Zeabur 开源版没有修改项目 Pod Security 级别的界面，需要由管理员用 kubectl 修改。改为 `restricted` 后，只有**严格**的服务能启动：

```sh
kubectl label namespace demo --overwrite \
  pod-security.kubernetes.io/enforce=restricted \
  pod-security.kubernetes.io/audit=restricted \
  pod-security.kubernetes.io/warn=restricted
```

服务自身的级别见[调整服务设置](./service-settings.mdx#安全性)。

### 隔离和允许其他项目

`zeabur-project` 允许同一项目的副本、带有 `zeabur.com/platform: "true"` 标签的 Namespace 和 `kube-system` 连接进来：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-project
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector: {}
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector: {}
        - namespaceSelector:
            matchLabels:
              zeabur.com/platform: "true"
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: kube-system
```

允许项目 `shop` 连接进来：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-allow-from-shop
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector: {}
  policyTypes: [Ingress]
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: shop
```

取消隔离：

```sh
kubectl -n demo delete networkpolicy zeabur-project
```

### 确认设置

```sh
kubectl get namespace demo --show-labels
kubectl get namespace -l zeabur.com/project=true
kubectl -n demo get networkpolicy
kubectl -n demo get serviceaccount default -o jsonpath='{.automountServiceAccountToken}'
```

第一行的标签中包含 `zeabur.com/project=true` 和 `pod-security.kubernetes.io/enforce=baseline`。第二行列出所有项目。隔离后，第三行会列出 `zeabur-project`。最后一行输出 `false`。
