项目就是带有 `zeabur.com/project: "true"` 标签的 Kubernetes Namespace。在**项目**页点击**新建项目**创建项目，或将集群中已有的 Namespace 加入 Zeabur。项目的名称、描述、图标和网络隔离都在项目**设置**中修改。

## 开始前

- 创建项目需要有创建 Namespace 的权限。将已有的 Namespace 加入 Zeabur 或从中移除，需要该 Namespace 的 `zeabur-manage` 权限，通常只有管理员具备，见[项目 Namespace 的保护](../reference/permissions.mdx#项目-namespace-的保护)。
- 项目名称也是 Namespace 名称，创建后不能修改。只能使用小写字母、数字和连字符，开头和结尾必须是字母或数字，最多 63 个字符，且不能以 `kube-` 开头。

## 创建项目

<Steps>
<Step>

### 填写名称

打开**项目**页，点击**新建项目**。在**名称**中填写 `hello`，**显示名称**可以留空；填写后，界面会用显示名称代替 Namespace 名称。

![新建项目窗口，名称填为 hello](../images/shots/project-new.avif)

同名的 Namespace 已经存在时，表单会提示你改用已有的 Namespace，做法见[下一节](#将已有的-namespace-加入-zeabur)。

</Step>
<Step>

### 检查并创建

提交后，检查页面会列出要创建的对象：

- Namespace `hello`，带有项目标签和三个 Pod Security 标签，级别均为 `baseline`。服务可以以 root 身份运行，但不能访问宿主机。
- `default` ServiceAccount 设为 `automountServiceAccountToken: false`，未指定 ServiceAccount 的副本不会获得 Kubernetes API 的令牌。
- 如果集群中有带 `zeabur.com/platform: "true"` 标签的 Namespace（通过 Zeabur 安装程序安装的集群都有），还会创建 NetworkPolicy `zeabur-project`，阻止其他项目的副本连接进来。

![创建项目 hello 前的确认页面，说明将创建的 Namespace 和安全配置](../images/shots/project-new-review.avif)

确认后应用，界面会进入新项目。

</Step>
</Steps>

## 将已有的 Namespace 加入 Zeabur

**项目**页的**其他 Namespace** 会列出尚未作为项目的 Namespace。在对应行打开菜单，选择**使用这个 Namespace**，检查后应用。

Zeabur 只会为 Namespace 添加 `zeabur.com/project: "true"` 标签，不会修改其中的对象、Pod Security 标签和 NetworkPolicy。

不想再在 Zeabur 中看到这个 Namespace 时，打开项目**设置**的**危险区域**，点击**从 Zeabur 移除**。这只会移除项目标签，Namespace 及其中的所有内容都会保留。要连同内容一起删除，见[删除项目](./delete-project.mdx)。

## 修改名称、描述和图标

打开项目**设置**的**基本信息**：

- **项目名称**：代替 Namespace 名称显示，最多 64 个字符。
- **描述**：说明项目用途，显示在名称下方，最多 500 个字符。
- **图标**：点击**更换图标**，从 16 个图标中选择一个。

点击**保存详细信息**，检查后应用。这三项保存在 Namespace 的 annotation 中。项目的开发者可以修改这三项，其他 label 和 annotation 只有管理员能修改。

## 隔离其他项目

打开项目**设置**的**网络**，**其他项目**一行会说明当前状态：

- **集群中的任何副本都能连接到这个项目的服务。**：尚未隔离。点击**隔离**，检查后应用，Zeabur 会创建 NetworkPolicy `zeabur-project`。
- **无法连接到这个项目的服务。项目内的服务和 Zeabur 组件不受影响。**：已经隔离。

隔离后，项目内的副本仍能相互连接，带有 `zeabur.com/platform: "true"` 标签的 Namespace（例如 Traefik 和数据库 operator 所在的 Namespace）以及 `kube-system` 也能连接进来。

要允许另一个项目连接进来，点击**允许其他项目连入**，选择项目，点击**允许**，检查后应用。Zeabur 会创建 NetworkPolicy `zeabur-allow-from-<那个项目>`，对方的所有副本都能连接到这个项目的所有服务。要取消，在对应行点击**移除**。

界面没有取消隔离的按钮，需要用 kubectl 删除 `zeabur-project`，见下一节。规则是否真正生效，取决于集群的网络插件（CNI）是否支持 NetworkPolicy。

## 用 kubectl 完成相同操作

项目的所有配置都是 Namespace 上的标签、annotation 和普通的 NetworkPolicy。移除 Zeabur 后，Kubernetes 仍会执行这些配置。

### 创建项目

与 Zeabur 创建的内容相同：

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: demo
  labels:
    zeabur.com/project: "true"
    pod-security.kubernetes.io/enforce: baseline
    pod-security.kubernetes.io/audit: baseline
    pod-security.kubernetes.io/warn: baseline
  annotations:
    zeabur.com/display-name: Demo shop
    zeabur.com/description: The shop's web and worker
    zeabur.com/icon: storefront
---
apiVersion: v1
kind: ServiceAccount
metadata:
  name: default
  namespace: demo
automountServiceAccountToken: false
```

`zeabur.com/icon` 可以是 `folder`、`globe`、`storefront`、`rocket`、`cube`、`database`、`cloud`、`code`、`terminal`、`chart`、`chat`、`book`、`flask`、`game`、`heart` 或 `briefcase`。

### 加入、移除项目和修改详细信息

```sh
kubectl label namespace demo zeabur.com/project=true
kubectl label namespace demo zeabur.com/project-
kubectl annotate namespace demo --overwrite zeabur.com/display-name='Demo shop'
```

### 调整 Pod Security 级别

Zeabur 没有修改项目 Pod Security 级别的界面，需要由管理员用 kubectl 修改。改为 `restricted` 后，只有**严格**的服务能启动：

```sh
kubectl label namespace demo --overwrite \
  pod-security.kubernetes.io/enforce=restricted \
  pod-security.kubernetes.io/audit=restricted \
  pod-security.kubernetes.io/warn=restricted
```

服务自身的级别见[调整服务设置](./service-settings.mdx#安全性)。

### 隔离和允许其他项目

`zeabur-project` 允许同一项目的副本、带有 `zeabur.com/platform: "true"` 标签的 Namespace 和 `kube-system` 连接进来：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-project
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector: {}
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector: {}
        - namespaceSelector:
            matchLabels:
              zeabur.com/platform: "true"
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: kube-system
```

允许项目 `shop` 连接进来：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-allow-from-shop
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector: {}
  policyTypes: [Ingress]
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: shop
```

取消隔离：

```sh
kubectl -n demo delete networkpolicy zeabur-project
```

## 确认结果

**项目**页会列出这个项目，并显示你设置的名称、描述和图标。项目**设置**的**网络**会显示当前是否隔离，以及哪些项目能连接进来。

```sh
kubectl get namespace demo --show-labels
kubectl get namespace -l zeabur.com/project=true
kubectl -n demo get networkpolicy
kubectl -n demo get serviceaccount default -o jsonpath='{.automountServiceAccountToken}'
```

第一行的标签中包含 `zeabur.com/project=true` 和 `pod-security.kubernetes.io/enforce=baseline`。第二行列出所有项目。隔离后，第三行会列出 `zeabur-project`。最后一行输出 `false`。

## 遇到问题

| 界面或结果 | 处理方法 |
| --- | --- |
| **已经有同名的 Namespace，可以改用已有的 Namespace。** | 换一个名称，或在**其他 Namespace** 中将那个 Namespace 加入 Zeabur。 |
| 加入或移除项目时，集群返回 **Only an admin can change the namespace's labels** | 只有管理员能修改 Namespace 的标签，请管理员操作。 |
| **这是 Kubernetes 为自身组件保留的 Namespace，不能作为项目。** | 以 `kube-` 开头的 Namespace 和节点终端使用的 `zeabur-node-shell` 都不能作为项目。 |
| 创建项目时没有列出 `zeabur-project` | 集群中没有带 `zeabur.com/platform: "true"` 标签的 Namespace，Zeabur 无法判断 Ingress controller 在哪里，因此不会创建。请管理员为这些 Namespace 添加标签，再到**网络**点击**隔离**。 |
| 隔离后公开域名无法打开 | Ingress controller 所在的 Namespace 没有 `zeabur.com/platform: "true"` 标签。为那个 Namespace 添加标签，或在 `zeabur-project` 中添加一条允许连入的规则。 |
