打开服务的**变量**，点击**编辑**，修改后在页面底部点击**检查变更**并应用。直接配置在服务上的变量会在新副本启动时生效。值来自共享配置文件或机密变量时，需要到来源修改，并确认哪些服务需要重启。

## 开始前

- 已有一个服务，并且有权修改。服务标记为由 Helm、Argo CD 或 Flux 管理，需要回到原来的 values 或 Git 仓库修改。
- 知道应用需要的变量名称和值，例如 `APP_URL` 或 `LOG_LEVEL`。这里配置的是容器运行时的环境变量。[从 Git 部署](../deploy/git.mdx)时使用的构建变量需要在构建配置中修改。
- 密码或 API 密钥适合放在机密变量中。**直接设置**的值会显示在服务配置里。共享变量选择 **Secret** 后，只有有权读取机密变量的人才能显示值。

![服务 web 的变量选项卡](../images/shots/service-variables.avif)

## 修改这个服务的变量

<Steps>
<Step>

### 打开编辑器

进入项目，选择服务，再打开**变量** → **编辑**。在**直接设置**中修改名称或值，点击**添加变量**新增一行。有多个容器时，为新变量选择要读取的容器。

![正在编辑的环境变量：直接配置的每一行都能修改名称和值，下方有添加变量按钮](../images/shots/variables-edit.avif)

在名称栏粘贴多行 `NAME=value`，可以一次添加多个变量。只有一个容器时，也可以切换到 `.env` 编辑方式：

```dotenv
APP_URL=https://app.example.com
LOG_LEVEL=info
```

`.env` 编辑器支持引号、`export` 和 `#` 注释。从编辑内容中删除原有的一行，会将该变量标记为待移除。

</Step>
<Step>

### 检查并应用

查看标记为**新增**、**已修改**或**将移除**的行，再点击页面底部的**检查变更**。确认容器、变量名称及其他等待一起应用的配置，再应用这批变更。

直接修改变量会更新服务的 Pod template。Deployment、StatefulSet 这类持续运行的服务会用新配置替换副本。CronJob 则从下一次运行开始读取新值。

</Step>
<Step>

### 确认应用读到新配置

回到**概览**等待副本就绪，再通过应用的实际行为或**日志**确认，例如新生成的链接是否使用新的 `APP_URL`。环境变量列表会显示保存后的配置。

</Step>
</Steps>

尚未应用时，点击**放弃**可放弃这批草稿。对于已应用的变更，需要把值改回去，再次检查并应用。

## 修改来自配置文件或机密变量的值

**来自配置文件和机密变量**列出每个变量的来源。点击来源名称即可打开编辑器。来源是机密变量时，点击**显示值**才会读取当前值。也可以直接填入新值，不必先显示旧值。标记为**二进制**的配置文件数据需要用 YAML 修改。

先查看编辑器上方的**读取它的服务**。例如，`web` 和 `worker` 都读取 `app-config`，从 `web` 打开编辑器后修改值，会同时修改两个服务读取的来源。将这个来源挂载为文件的服务也会列在其中。

修改键或点击**添加键**后，提交检查。从服务页面打开的来源编辑器会把修改加入该服务的草稿，仍需在页面底部点击**检查变更**并应用。从项目**设置**打开同一个来源时，则会直接打开变更检查。

### 让正在运行的服务读到新值

修改 ConfigMap 或 Secret 的内容后，已启动容器中的环境变量会保留旧值。变更检查会列出需要重启的服务，以及可能由 Reloader 自动重启的服务。

- 手动处理时，对每个需要新值的服务执行**重启**，再检查副本是否就绪。
- 要自动处理，进入服务**设置** → **计算资源**，开启**配置文件或机密变量变更时自动重启**，再检查并应用。集群中需要有正在运行的 Stakater Reloader，仅开启选项不会重启服务。
- 开启后，无论是在 Zeabur 还是用其他工具修改来源，服务都会重启。读取这个来源的服务都开启了这个选项时，这些服务会一起重启。

看到**重新启动前可能仍在使用旧的值**，表示来源在某个副本启动后发生过修改。展开提示可以查看具体是哪些副本。已经运行完毕的 Job 不会因为来源修改而重新运行。

## 创建共享变量并让服务读取

<Steps>
<Step>

### 添加一组共享变量

进入项目**设置**中的**共享变量**，点击**添加共享变量**。输入**名称**，在**值的保存方式**中选择 **Secret** 或**明文**，再在**变量**中每行输入一个 `NAME=value`。

点击**检查变更**，确认后点击**创建**。这一步只创建共享变量，服务还不会读取。

</Step>
<Step>

### 选择服务要读取的键

回到服务的**变量**，点击**使用共享变量**。选择刚创建的那组变量。服务有多个容器时，还需要选择容器。

- **所有键**：每个键都会成为环境变量，之后添加的键也会包含在内。
- **单个键**：选择**键**，再设置容器里的**变量名**，例如将 `api-token` 读取为 `API_TOKEN`。

这个侧边面板有独立的**检查变更**和应用步骤，不会将变更加入服务页面底部的草稿。应用后，持续运行的服务会替换副本，新副本就会读到这些变量。

</Step>
<Step>

### 确认读取关系

在服务的**来自配置文件和机密变量**中确认来源名称，再回到项目**设置** → **共享变量**，确认**使用的服务**中出现该服务。等新副本就绪后，再确认应用的配置。

</Step>
</Steps>

## 用 kubectl 做同样的事

环境变量写在工作负载的 Pod template 里，共享变量是普通的 ConfigMap 或 Secret，Zeabur 不会另外保存任何数据。以下以项目 `demo`、服务 `web` 为例。

直接配置和移除一个变量，等于修改容器的 `env`：

```sh
kubectl -n demo set env deployment/web NODE_ENV=production
kubectl -n demo set env deployment/web NODE_ENV-
```

共享变量就是带有 `zeabur.com/shared-variables: "true"` 标签的 ConfigMap 或 Secret。项目**设置** → **共享变量**根据这个标签列出这些对象：

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: demo
  labels:
    zeabur.com/shared-variables: "true"
data:
  APP_URL: https://app.example.com
  LOG_LEVEL: info
---
apiVersion: v1
kind: Secret
metadata:
  name: app-secrets
  namespace: demo
  labels:
    zeabur.com/shared-variables: "true"
type: Opaque
stringData:
  api-token: change-me
```

服务读取共享变量的方式写在容器配置中。**所有键**对应 `envFrom`，**单个键**对应 `env` 的 `valueFrom`。**配置文件或机密变量变更时自动重启**对应工作负载本身（不是 Pod template）的 annotation `reloader.stakater.com/auto: "true"`，只有 Deployment、StatefulSet 和 DaemonSet 能开启：

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
  namespace: demo
  labels:
    app.kubernetes.io/name: web
  annotations:
    reloader.stakater.com/auto: "true"
spec:
  replicas: 1
  selector:
    matchLabels:
      app.kubernetes.io/name: web
  template:
    metadata:
      labels:
        app.kubernetes.io/name: web
    spec:
      containers:
        - name: web
          image: nginxinc/nginx-unprivileged:1.29
          env:
            - name: NODE_ENV
              value: production
            - name: API_TOKEN
              valueFrom:
                secretKeyRef:
                  name: app-secrets
                  key: api-token
            - name: LOG_LEVEL
              valueFrom:
                configMapKeyRef:
                  name: app-config
                  key: LOG_LEVEL
            - name: POD_NAME
              valueFrom:
                fieldRef:
                  fieldPath: metadata.name
          envFrom:
            - configMapRef:
                name: app-config
```

只需要开启或关闭自动重启时，用 annotate 即可，不会替换副本：

```sh
kubectl -n demo annotate deployment web reloader.stakater.com/auto=true
kubectl -n demo annotate deployment web reloader.stakater.com/auto-
```

修改共享来源后又没有 Reloader 时，需要手动重启读取这个来源的服务：

```sh
kubectl -n demo rollout restart deployment/web
```

移除 Zeabur 后，Kubernetes 仍会将这些变量注入容器。Reloader 是独立组件，也会继续根据 annotation 重启服务。

## 确认结果

在**变量**选项卡中，直接配置的变量列在**直接设置**，从共享变量读取的变量列在**来自配置文件和机密变量**，并显示来源名称。项目**设置** → **共享变量**中的**使用的服务**会列出读取每组共享变量的服务。

用 kubectl 查看 Pod template 中的配置，以及容器中的实际值：

```sh
kubectl -n demo get deployment web -o jsonpath='{.spec.template.spec.containers[0].env}'
kubectl -n demo get configmap,secret -l zeabur.com/shared-variables=true
kubectl -n demo exec deploy/web -- printenv NODE_ENV
```

`printenv` 输出新值，表示副本已经使用新配置启动。输出旧值时，等待新副本就绪，或按上面的步骤重启。

## 遇到问题

| 界面或结果 | 后续处理 |
| --- | --- |
| **另一个变量已经使用了这个名称**或**配置文件、机密变量或 Kubernetes 已经设置了这个名称** | 到该变量的来源修改，或换一个名称。同一个容器里的同名变量只会有一个值生效。 |
| 没有**使用共享变量** | 先到项目**设置**创建至少一组共享变量。服务正在编辑变量或由其他工具管理时，也不会显示这个按钮。 |
| **你没有读取 Secret 的权限，因此值会隐藏。** | 显示机密变量的值需要读取 Secret 的权限，这与修改服务的权限不同，见[权限](../reference/permissions.mdx)。 |
| 共享来源已修改，应用仍使用旧值 | 重启读取这个来源的服务。已开启自动重启时，到服务**设置** → **计算资源**查看 Reloader 是否正在运行。 |
| 显示变更已过期 | 重新检查当前的来源和值，再应用新的变更。 |

## 停止读取或清除配置

对于直接配置的变量，可以在**编辑**中点击该行的移除按钮，再检查并应用。

对于整组导入的变量，在来源行选择**停止读取**，再检查并应用。这会移除服务的读取关系，保留共享来源。

对于只读取单个键的变量，在来源旁选择**移除变量**，再检查并应用。共享来源和其中所有的键都会保留，只移除服务上的这个变量。

要删除整组共享变量，先在项目**设置** → **共享变量**中确认**使用的服务**已清空，再到项目**对象**打开对应的 ConfigMap 或 Secret，在 **YAML** 中点击**删除**，检查后应用。仍有服务读取其中的键时，之后启动的副本会因为找不到这个来源而无法启动。

应用的公开网址变更后，还需要一起查看[域名](./domains.mdx)与 `APP_URL` 等变量。维护期间的访客流量可以另用[维护模式](./maintenance.mdx)处理。
