服务卡住时，点击服务页面顶部的**重启**，替换为一批新副本。新版本有问题时，到**部署记录**选择之前的版本并点击**回滚**。要一次处理整个项目，到项目**设置**的**批量操作**。每个操作都会先打开检查页面，确认后应用。

## 开始前

- 有权限修改项目中的服务。
- Helm、Argo CD 或 Flux 管理的服务也能重启，重启只添加一个 annotation。回滚会替换整个 Pod template，因此这些工具管理的服务不能在这里回滚。

## 重启服务

<Steps>
<Step>

### 点击重启

进入服务，点击页面顶部的**重启**。检查页面的标题是**重启 web**，会说明服务是否会中断。

![重启 web 的检查页面，说明 2 个副本会逐一替换、服务不会中断，且资源充足](../images/shots/restart-review.avif)

</Step>
<Step>

### 应用并等待新副本

应用后，Kubernetes 按服务的更新方式替换副本。Deployment 默认先启动新副本，等新副本就绪后再停止旧副本。只有一个副本或使用 `Recreate` 的服务会短暂中断。

在**概览**的**部署进度**中查看已就绪的新副本数量。新副本全部就绪、旧副本全部消失后，重启就完成了。

</Step>
</Steps>

Job 和定时任务没有**重启**操作。要再次运行定时任务，使用[定时任务](../deploy/cron-jobs.mdx)的立即运行功能。

## 回滚到之前的版本

每次更换镜像或修改 Pod template 的配置，**部署记录**就会新增一个修订版本，例如 `#3`。标记为**运行中**的是当前版本。

<Steps>
<Step>

### 比较两个版本

到服务的**部署记录**，在要回到的版本上点击**比较**，查看这个版本与当前版本的 Pod template 有哪些差异。显示**两个模板相同。**时，回滚不会改变任何内容。

![部署记录中修订版本 #2 的比较结果，以红绿对照显示镜像从 1.4.1 更换为 1.4.2](../images/shots/release-compare.avif)

</Step>
<Step>

### 回滚

点击该版本的**回滚**。检查页面的标题是**将 web 回滚到 #2**，确认后应用。

回滚只还原 Pod template，也就是镜像、环境变量、资源和健康检查等配置。容器读取的 ConfigMap 和 Secret 内容不会随之还原为旧值，检查页面也会提醒这一点。

![将 web 回滚到 #2 的检查页面，提醒回滚不会修改配置文件和机密变量的内容](../images/shots/rollback-review.avif)

</Step>
<Step>

### 确认版本

回滚本身也算一次部署，**部署记录**会为旧的修订版本分配新编号，并标记为**运行中**。等**概览**中的副本全部就绪后，再到应用中确认。

</Step>
</Steps>

部署卡住时，**概览**的**部署进度**也会显示**回滚**按钮，用于回到上一个正常版本。

能回滚到多久之前的版本，取决于工作负载的 `revisionHistoryLimit`，默认保留 10 个。Job 和 CronJob 不保留发布记录。

## 自动部署新构建

从 Git 或上传文件夹构建的服务，在**构建**选项卡中开启**新构建完成后自动部署**，每次构建完成就会立即上线。关闭后，构建成功时点击**部署最新版**手动上线。这需要集群中有 Keel，具体做法及对应的 kubectl 操作见[从 Git 构建并部署服务](../deploy/git.mdx)。

## 暂停或重启整个项目

到项目**设置**的**批量操作**：

- **暂停所有服务**：点击**暂停**，将项目中正在运行的 Deployment 和 StatefulSet 的副本数全部调整为 0。服务、配置和卷上的数据都会保留。Helm、Argo CD 或 Flux 管理的服务会跳过，检查页面会列出跳过的服务，因为这些工具下次同步时会将副本数改回去。
- **重启所有服务**：点击**重启**，项目中的每个 Deployment、StatefulSet 和 DaemonSet 都会分批替换为新副本。

应用暂停操作后，通知中会提供**撤销**，点击即可将每个服务恢复到原来的副本数。错过通知时，需要到每个服务的**设置** → **计算资源**，将**副本数**改回去，Zeabur 不会另行记录原来的数值。

## 用 kubectl 执行相同操作

这些操作与 kubectl 内置命令写入相同的字段，没有 Zeabur 专用的对象。以下以项目 `demo`、Deployment `web` 为例。

| Zeabur 的操作 | kubectl |
| --- | --- |
| **重启** | `kubectl -n demo rollout restart deployment/web` |
| **回滚**到 `#2` | `kubectl -n demo rollout undo deployment/web --to-revision=2` |
| **暂停所有服务** | `kubectl -n demo scale deployment,statefulset --all --replicas=0` |
| **重启所有服务** | `kubectl -n demo rollout restart deployment,statefulset,daemonset` |
| 开启**新构建完成后自动部署** | `kubectl -n demo annotate deployment web keel.sh/policy=force` |

**重启**会写入 Pod template 的 annotation `kubectl.kubernetes.io/restartedAt`，值为当前时间，与 `kubectl rollout restart` 相同。**回滚**会将 `spec.template` 替换为该修订版本的内容。

`kubectl scale --all` 不会跳过 Helm 等工具管理的服务。要排除这些服务，改为逐一列出服务名称。暂停前先记下每个服务的副本数，之后才能改回去：

```sh
kubectl -n demo get deployment,statefulset -o custom-columns=NAME:.metadata.name,REPLICAS:.spec.replicas
```

## 确认结果

**部署记录**中标记为**运行中**的修订版本是当前版本。**概览**中的副本数和就绪状态反映重启或暂停的结果，已暂停的服务显示 0 个副本。

```sh
kubectl -n demo rollout status deployment/web
kubectl -n demo rollout history deployment/web
kubectl -n demo get pods -l app.kubernetes.io/name=web
```

`rollout status` 输出 `successfully rolled out` 表示新副本已全部就绪。`rollout history` 列出所有修订版本，最后一条是当前版本。`get pods` 的 `AGE` 会对应刚才重启的时间。

## 遇到问题

| 页面或结果 | 后续处理 |
| --- | --- |
| 没有**重启**按钮 | 你没有修改服务的权限，或服务是 Job 或定时任务。 |
| 回滚时页面提示服务由 Helm、Argo CD 或 Flux 管理 | 回到对应工具，使用那个工具的版本回滚功能，例如 `helm rollback`。 |
| **部署记录**只有一条 | 服务还没有更换过 Pod template，或旧的 ReplicaSet 数量超过 `revisionHistoryLimit`，Kubernetes 已将其清理。 |
| 回滚后应用仍然出错 | ConfigMap 和 Secret 的内容没有回滚，到[环境变量](./variables.mdx)将值改回去。 |
| 重启后一直停在**部署卡住** | 查看**概览**中说明的原因和副本事件，常见原因是镜像拉取失败或健康检查未通过。 |
