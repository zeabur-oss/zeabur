在服务 **网络** 的 **公开域名** 中点击 **添加域名**，输入域名并加入变更，检查后应用，再到 DNS 提供商添加界面列出的记录。网址能访问服务且 HTTPS 证书就绪后，访客就能打开网站。

## 开始前

- 服务有接收 HTTP 流量的端口，而且 **私有网络** 中能看到它的私有地址。域名会将请求转发到这个地址。如果没有，先按界面上的说明开放端口。
- 有域名的 DNS 管理权限，或有人能代为修改 DNS。
- 有权限修改项目的域名。如果路由由 Helm、Argo CD 或 Flux 管理，需要回到原来的 values 或 Git 仓库修改。
- 集群安装了 cert-manager 和可用的签发者，才能自动签发、续期证书。通配符域名（例如 `*.example.com`）需要使用支持 DNS-01 的签发者。

![web 服务的网络选项卡，列出公开域名与私有网络](../images/shots/service-networking.avif)

## 添加域名

<Steps>
<Step>

### 填写主机名

进入服务 **网络**，在 **公开域名** 中点击 **添加域名**，输入 `app.example.com`。字段中只填写主机名，不加 `https://`、端口或路径。

![公开域名的添加字段中填入 app.example.com，下方预先列出要添加的 DNS 记录](../images/shots/domain-add.avif)

集群有多个签发者时，表单会显示 **签发者**，可以保留默认选项，也可以另选一个。如果这个域名无法获取证书，检查变更时会提示它仅支持 HTTP。

集群中有 Gateway 接受这个项目的路由时，表单会多一个 **路由** 选项，默认是 **Ingress（默认）**，也可以选择某个 Gateway 的 listener，域名就会通过 HTTPRoute 挂到那个 Gateway 上。选择 Gateway 后，表单不再显示签发者，HTTPS 证书由 listener 提供。只有能读取集群 Gateway 的账号才能看到这个选项，看不到时请集群管理员协助。

</Step>
<Step>

### 加入草稿，再检查变更

点击 **加入变更**，域名会先放入这个服务的草稿，集群还没有改动。点击页面底部的 **检查变更**，确认域名、转发目标和证书配置后应用。

![保存前确认 web 的变更：app.example.com 会连接到 web，并使用 HTTPS](../images/shots/domain-review.avif)

表单没有端口字段，因此检查时需要查看 **转发到** 的服务和端口。服务已有 Ingress 时，新域名会加到同一个 Ingress 上，沿用它的后端。只有 HTTPRoute 时，新域名会加到那条 HTTPRoute 上。两者都没有时，Zeabur 会创建新的 Ingress，转发到服务第一个 Kubernetes Service 的第一个端口。选择 Gateway 后，新域名会加到该 Gateway 上转发到这个服务的 HTTPRoute，没有就创建一条。

</Step>
<Step>

### 配置 DNS

到 DNS 提供商添加界面列出的记录，照抄类型、名称和值：

- 目标是 IPv4 地址时，使用 `A`。
- 目标是 IPv6 地址时，使用 `AAAA`。
- 目标是另一个主机名时，使用 `CNAME`。

如果域名位于集群的应用域名下，例如 `shop.apps.example.com`，界面会改为提示管理员添加通配符记录 `*.apps.example.com`。已有这条记录时，无需另外配置。Zeabur 不会替你修改 DNS。

界面显示 **Zeabur 不知道集群的入口地址，请向管理员询问要指向哪个地址** 时，先向集群管理员获取入口的对外地址，再配置 DNS。

</Step>
<Step>

### 打开网址确认

回到 **公开域名** 查看 DNS 和证书状态。DNS 还没指向集群或证书仍在签发时，域名行会显示下一步。签发失败时，展开 **cert-manager 的消息** 查看原因，cert-manager 也会自行重试。

状态变成 **配置正确** 后，在浏览器中打开网址，确认看到的是这个服务，且浏览器没有证书警告。如果应用会生成完整网址，再到[环境变量](./variables.mdx)更新 `APP_URL` 这类配置。

</Step>
</Steps>

## 侧边面板的变更也会加入草稿

证书、重定向和密码、维护与错误页面这三个侧边面板，最后一个按钮都是 **加入变更**。这些变更会与新增、改名的域名放在同一份草稿中，域名行会标上 **已修改**，旁边有 **撤销**。全部改好后，点击页面底部的 **检查变更**，确认后一起应用。只有一种变更时，按钮会显示对应的操作（例如 **添加域名**），混合多种变更时显示 **应用 N 项变更**。

同一项配置修改两次，后一次会替换前一次，草稿中只保留最后的版本。

项目还没有[页面服务器](./maintenance.mdx#页面服务器)时，维护与错误页面的变更中会包含部署 **Error pages** 模板这一项，与其他变更一起检查、应用。

## 更换 HTTPS 证书

在域名行点击 **app.example.com 的证书**，打开侧边面板。

### 使用自动续期的签发者

选择 **由签发者签发，自动续期**，指定 **签发者**，点击 **加入变更**。同一个 Ingress 的域名共用一个签发者，因此修改后，面板列出的其他域名也会改由这个签发者签发。

通配符域名显示需要 DNS-01 时，请集群管理员按[下一节](#创建通配符域名的签发者)创建签发者，再回到域名中选择它。

### 创建通配符域名的签发者

Let's Encrypt 只支持通过 DNS-01 验证签发通配符证书。集群管理员需要用 `kubectl` 创建 DNS-01 签发者，让 cert-manager 的 DNS-01 solver 使用 DNS 提供商的 API 令牌完成验证。令牌只存放在集群中的 Secret，Zeabur 不经手；**集群** → **概览** 的 **证书** 只列出签发者和状态，不能添加。

以下以 Cloudflare 为例。先创建 API 令牌，将 DNS 编辑权限限制在要使用的那个 zone，再将下方的占位符替换为你的令牌：

```sh
kubectl -n cert-manager create secret generic cloudflare-dns \
  --from-literal=api-token='<只能编辑这个 zone 的 token>'
```

Secret 必须放在 `cert-manager` Namespace。`ClusterIssuer` 只会读取 cert-manager 配置的 *cluster resource namespace* 中的 Secret；这里使用的是 `cert-manager`。

接着创建 `letsencrypt-dns` 签发者。将 `you@example.com` 替换为你的联系邮箱：

```sh
kubectl apply -f - <<'EOF'
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-dns
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    email: you@example.com
    privateKeySecretRef:
      name: letsencrypt-dns-account-key
    solvers:
      - dns01:
          cloudflare:
            apiTokenSecretRef:
              name: cloudflare-dns
              key: api-token
EOF
```

创建后，确认签发者的状态：

```sh
kubectl get clusterissuer letsencrypt-dns
```

等 `READY` 显示 `True`，回到 Zeabur 的 **集群** → **概览** 的 **证书**，就能看到 `letsencrypt-dns` 和它的就绪状态。配置通配符域名时，在 **签发者** 中选择 `letsencrypt-dns`。

如果使用 Route 53、Cloud DNS、DigitalOcean 或 Azure DNS 等其他提供商，需要换成对应的 solver，并按照 [cert-manager 的 DNS-01 文档](https://cert-manager.io/docs/configuration/acme/dns01/)配置凭证与权限。

### 上传自己的证书

选择 **我自己的证书**，粘贴或点击 **上传文件** 提供：

- **证书（PEM）**：先放网站证书，再放中间证书。
- **私钥（PEM）**：提供未加密、与证书配对的私钥。

点击 **加入变更**，再从页面底部检查并应用。Zeabur 会检查证书的有效期、域名和密钥是否配对，再将证书和密钥存入 Secret，之后不会再显示密钥。自己的证书不会自动续期，需要在到期前上传新证书。

同一个 Ingress 的其他域名还在向 cert-manager 申请证书时，这个域名会移到独立的 Ingress。新的 Ingress 沿用原来的规则、class、标签、注解和错误页面，检查变更时会列出这次迁移。原来的 Ingress 配置了密码、重定向或维护模式时无法迁移，面板会说明需要先取消哪一项。

域名由 HTTPRoute 提供时，证书配置在集群的 Gateway 上，域名行显示 **HTTPS 由 Gateway 决定**。要更换证书，请集群管理员到 Gateway 修改。

## 将一个域名重定向到另一个域名

由 Traefik 提供的 Ingress 和 HTTPRoute 上会显示重定向选项。在来源域名行点击 **app.example.com 的重定向或密码**，选择 **转到另一个域名**，输入 **要转到的域名**。

只填目标主机名，例如 `www.example.com`。重定向后使用 HTTPS，并保留路径，`app.example.com/docs` 会重定向到 `https://www.example.com/docs`。目标域名需要先有自己的 DNS、路由与可用证书。

**重定向类型** 可选 **临时（302）** 或 **永久（301）**。浏览器会记住永久重定向，之后即使取消也会继续跳转，因此先用临时重定向确认目标。

点击 **加入变更**，从页面底部检查并应用，再打开来源域名测试。重定向只对这个域名生效，同一个 Ingress 的其他域名仍会显示原服务。通配符域名不能作为重定向的来源或目标。

HTTPRoute 的重定向作用于整条路由。同一条 HTTPRoute 还有其他域名时，这个域名会移到独立的路由，其他域名留在原处。Zeabur 会在路由最前面添加一条重定向规则，匹配原有所有规则的路径；原有规则保持不变，取消重定向时只移除这一条。

要取消重定向，在同一个面板中改选 **显示 web**（`web` 是服务名称），再加入变更并应用。

## 让访客先输入密码

在域名行点击 **app.example.com 的重定向或密码**，开启 **要求输入密码**，填写 **用户名** 与 **密码**。用户名不能包含空格或冒号，密码至少 8 个字符，最多 72 个字节。密码只能设置在 Traefik 提供的 Ingress 上，HTTPRoute 的域名目前无法在这里设置密码。

<Callout type="warn">
先确认所有受保护的域名都有 HTTPS。HTTP 上的 Basic auth 会以明文传输登录信息。
</Callout>

密码作用于整个 Ingress。面板列出 `www.example.com` 这类共用同一个 Ingress 的域名时，它们也会要求输入同一组账号密码。加入变更、检查并应用后，用无痕窗口打开网址，确认会弹出密码提示，输入后能看到服务。

集群只保存密码的 bcrypt 哈希值，忘记密码时只能更换。已有密码时，点击 **更改** 更换账号密码。关闭 **要求输入密码** 再应用，就会移除这个 Ingress 的密码。

重定向在密码验证之前执行。来源域名同时配置了重定向时，访客无需输入密码就会直接跳转到目标。目标需要密码保护时，在目标域名自己的面板中设置。

## 改名、移除与清理 DNS

- 改名：点击域名行的编辑按钮，输入新名称，点击 **加入变更**，再从页面底部检查并应用。接着配置新域名的 DNS。如果使用自己上传的证书，需要换成涵盖新名称的证书。
- 移除其中一个域名：点击该行的移除按钮，从页面底部检查并应用，再到 DNS 提供商删除不再使用的记录。
- 移除路由的最后一个域名：移除按钮会说明将一并移除哪条路由，例如 **移除 app.example.com 及没有其他域名的路由 web**。检查变更时会列出要删除的 Ingress 或 HTTPRoute。

尚未应用的域名变更，可以在该行点击 **撤销**，或点击页面底部的 **放弃** 丢弃整份草稿。在侧边面板中点击 **加入变更** 之前关闭面板，不会留下任何变更。

## 用 kubectl 做同样的事

域名、证书、重定向和密码都是普通的 Ingress、HTTPRoute、Secret 和 Traefik Middleware。Zeabur 没有自己的 CRD 或控制器，移除 Zeabur 后，网站仍由 Traefik 和 cert-manager 提供。以下以项目 `demo`、服务 `web`（Service 端口 `8080`）、域名 `app.example.com` 为例。

### 添加域名

服务还没有路由时，Zeabur 会创建名为 `<服务>-<域名，点换成连字符>` 的 Ingress。cert-manager 根据 annotation 签发证书，存到 `<Ingress 名称>-tls`：

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web-app-example-com
  namespace: demo
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt
spec:
  tls:
    - hosts: [app.example.com]
      secretName: web-app-example-com-tls
  rules:
    - host: app.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: web
                port:
                  number: 8080
```

将 `letsencrypt` 替换为集群中签发者的名称，用 `kubectl get clusterissuer` 查询。服务已有 Ingress 时，Zeabur 会将新域名作为另一条 `rules` 加到同一个 Ingress，并在 `tls` 中添加一条记录。

选择 Gateway 的域名对应一条 HTTPRoute，`parentRefs` 指向 Gateway 和它的 listener：

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: web-app-example-com
  namespace: demo
spec:
  parentRefs:
    - name: public
      namespace: gateway
      sectionName: https
  hostnames: [app.example.com]
  rules:
    - backendRefs:
        - name: web
          port: 8080
```

### 使用自己的证书

自己的证书是一个 `kubernetes.io/tls` Secret，Ingress 的 `tls.secretName` 指向它。Zeabur 创建的 Secret 名称是 `<Ingress 名称>-cert`，`ownerReferences` 指向 Ingress。Ingress 只有这个域名时，用 kubectl 创建 Secret，再将 Ingress 改为读取它，并移除 cert-manager 的 annotation：

```sh
kubectl -n demo create secret tls web-app-example-com-cert --cert=fullchain.pem --key=privkey.pem
kubectl -n demo patch ingress web-app-example-com --type=json -p='[{"op":"replace","path":"/spec/tls/0/secretName","value":"web-app-example-com-cert"}]'
kubectl -n demo annotate ingress web-app-example-com cert-manager.io/cluster-issuer-
kubectl -n demo delete certificate web-app-example-com-tls
```

最后一行会删除 cert-manager 之前为这个域名创建的 Certificate，Zeabur 换成自己的证书时也会这样做。

### 重定向和密码

重定向和密码是 Traefik 的 Middleware，`ownerReferences` 指向 Ingress，删除 Ingress 时会一并删除。Ingress 的 annotation `traefik.ingress.kubernetes.io/router.middlewares` 按顺序列出它们，格式是 `<项目>-<Middleware 名称>@kubernetescrd`，以逗号分隔。重定向排在第一位，密码排在最后一位。

重定向的名称是 `<Ingress 名称>-redirect-<来源域名，点换成连字符>`，只匹配来源域名，并保留路径。`permanent: true` 是 301，`false` 是 302：

```yaml
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: web-app-example-com-redirect-app-example-com
  namespace: demo
spec:
  redirectRegex:
    regex: ^https?://app\.example\.com(:[0-9]+)?/(.*)
    replacement: https://www.example.com/${2}
    permanent: false
```

密码的 Secret 和 Middleware 都叫 `<Ingress 名称>-basic-auth`。Secret 的 `users` 是一行 htpasswd，密码使用 bcrypt 哈希。用 `htpasswd -nbB` 生成这一行：

```sh
kubectl -n demo create secret generic web-app-example-com-basic-auth \
  --from-literal=users="$(htpasswd -nbB ops '换成你的密码')"
```

```yaml
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: web-app-example-com-basic-auth
  namespace: demo
spec:
  basicAuth:
    secret: web-app-example-com-basic-auth
    removeHeader: true
```

最后将两个 Middleware 写入 Ingress 的 annotation，重定向在前：

```sh
kubectl -n demo annotate ingress web-app-example-com --overwrite \
  traefik.ingress.kubernetes.io/router.middlewares=demo-web-app-example-com-redirect-app-example-com@kubernetescrd,demo-web-app-example-com-basic-auth@kubernetescrd
```

要取消重定向或密码，先从 annotation 移除对应项，再删除 Middleware（以及密码的 Secret）。如果顺序相反，Traefik 找不到 Middleware，域名会返回 404。

### 移除域名

Ingress 只剩这个域名时，删除整个 Ingress。它拥有的 Middleware、维护 Ingress 和自己上传的证书 Secret 会一并删除：

```sh
kubectl -n demo delete ingress web-app-example-com
```

Ingress 还有其他域名时，用 `kubectl edit` 只移除这个域名的 `rules` 和 `tls.hosts`。

## 确认结果

在服务 **网络** 的 **公开域名** 中，域名行会显示 DNS 和证书状态，以及 **转发到** 的服务和端口。配置了重定向或密码的域名，旁边的按钮会显示当前配置。

用 kubectl 查看路由和证书：

```sh
kubectl -n demo get ingress
kubectl -n demo get certificate
kubectl -n demo get middleware.traefik.io
```

`kubectl get ingress` 的 `HOSTS` 列包含这个域名，`ADDRESS` 列是入口的对外地址。`kubectl get certificate` 的 `READY` 是 `True`，表示 cert-manager 已签发证书。最后从集群外确认：

```sh
curl -sI https://app.example.com/
```

响应状态码来自服务本身（例如 `200`）。配置了重定向时是 `301` 或 `302`，`location` 指向目标域名。配置了密码时是 `401`。

## 遇到问题

| 界面或结果 | 后续处理 |
| --- | --- |
| 没有 **添加域名** | 先查看 **私有网络** 中有没有私有地址，再确认你有修改域名的权限。 |
| **指向别处** | 核对 DNS 记录和界面列出的目标。前面有 CDN 或代理时也会显示这个状态，此时需要确认 CDN 的源站指向集群。 |
| DNS 正确，证书一直在签发或 **证书签发失败** | 展开 **cert-manager 的消息**，核对签发者，以及验证所需的 DNS 记录或入口配置。 |
| 没有重定向或密码按钮 | 域名由 Traefik 以外的 Ingress controller 提供，需要在它自己的配置中处理。 |
| 状态为 **尚未确认**，或浏览器无法访问 | 依次核对 DNS、入口地址、服务是否就绪和连接规则。Zeabur 从集群内检查，结果可能与你的浏览器不同。 |

要暂时阻止访客访问，同时保留域名和服务，使用[维护模式](./maintenance.mdx)。
