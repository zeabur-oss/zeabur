表单中没有的配置，直接写 YAML。在项目的**对象**页点击**创建**，粘贴 YAML，即可创建 ConfigMap、Deployment、Service 或集群提供的任何自定义资源。要修改已有对象，打开对象并切换到 YAML 视图，点击**编辑**或**删除**。每次写入前都会打开检查页面，确认后才应用。

## 开始前

- 你有权在项目中创建或修改这类对象。权限不足时，表单会先提醒，检查变更时再向集群确认。
- Zeabur 只在项目的 Namespace 中创建对象。Namespace、ClusterRole 这类集群级对象，需要用 kubectl 创建。
- Helm、Argo CD 或 Flux 管理的对象不能在这里编辑或删除，需要回到对应工具修改。重启操作除外，见[重启、回滚与暂停服务](./restart-rollback.mdx)。

## 从 YAML 创建对象

<Steps>
<Step>

### 打开编辑器

进入项目，在**对象**页点击**创建**，或在搜索中选择**在 demo 创建…**。页面标题为**在 demo 创建**。

</Step>
<Step>

### 编写 YAML

在**要创建的 YAML** 中粘贴一份或多份文档，文档之间用 `---` 分隔。不知道怎么写时，点击**插入示例**，从**常用类型**、**自定义资源**或**其他可创建的类型**中选择一种，编辑器会插入对应对象的模板。

下面的 YAML 会创建一个 ConfigMap、一个读取它的 Deployment 和一个 Service：

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: hello-config
  namespace: demo
data:
  MESSAGE: hello
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello
  namespace: demo
  labels:
    app.kubernetes.io/name: hello
spec:
  replicas: 1
  selector:
    matchLabels:
      app.kubernetes.io/name: hello
  template:
    metadata:
      labels:
        app.kubernetes.io/name: hello
    spec:
      automountServiceAccountToken: false
      securityContext:
        seccompProfile:
          type: RuntimeDefault
      containers:
        - name: hello
          image: nginxinc/nginx-unprivileged:1.29
          ports:
            - containerPort: 8080
          envFrom:
            - configMapRef:
                name: hello-config
          securityContext:
            allowPrivilegeEscalation: false
---
apiVersion: v1
kind: Service
metadata:
  name: hello
  namespace: demo
  labels:
    app.kubernetes.io/name: hello
spec:
  selector:
    app.kubernetes.io/name: hello
  ports:
    - name: http
      port: 8080
      targetPort: 8080
```

可以省略 `namespace`，Zeabur 会填入当前项目。

</Step>
<Step>

### 查看问题和创建顺序

编辑器旁会列出 **N 个问题**，点击某个问题会跳转到对应行。需要先修正问题，才能检查变更：

- YAML 格式错误，或缺少 `apiVersion`、`kind`、`metadata.name`。
- 对象属于整个集群，例如 Namespace。
- `namespace` 填写的是其他项目。
- 集群没有提供这类对象，例如没有安装 cert-manager，却写了 Certificate。
- 同一个对象写了两次。
- 已有同名对象。创建不会修改已有对象，要修改它，使用**编辑**。

**创建顺序**列出实际执行的顺序：先创建配置文件、机密变量、磁盘和 ServiceAccount，再创建 Service，然后是工作负载，最后是其他对象，让工作负载启动时能读取所需内容。

![在 shop 创建对象的编辑器，粘贴了三份 YAML，右侧的创建顺序依次为 ConfigMap、Service、Deployment](../images/shots/objects-create.avif)

</Step>
<Step>

### 检查并创建

点击**检查变更**，确认页面上要创建的对象，再点击**创建 3 个对象**。

![在 shop 创建 3 个对象的检查页面，列出创建顺序、将启动的服务和两条提醒](../images/shots/objects-create-review.avif)

</Step>
</Steps>

Kubernetes 无法一次撤销多个对象的创建。如果集群拒绝其中一个对象，之前已创建的对象会保留，页面显示**已创建 1/3 个**，并列出**尚未创建**的对象。这时选择**删除刚创建的 1 个**回到原状，或选择**保留**，修正 YAML 后只创建剩余对象。

## 查看对象

项目的**对象**页按类型列出 Namespace 中的所有对象，可以用**筛选对象**按名称查找。其他对象生成的对象会标注**自动生成**和**由 Deployment 创建**这类来源，例如 Deployment 生成的 ReplicaSet 和 Pod。

点击对象，可以查看它的状态、**状况**和 YAML。也可以进入服务的**设置**，将上方的**设置**切换为 **YAML**，查看服务的 YAML。

机密变量的值在 YAML 中显示为 `(hidden)`。

## 编辑对象的 YAML

<Steps>
<Step>

### 编辑

在 YAML 视图中点击**编辑**。编辑器显示集群中的当前配置，修改后会原样写入。机密变量的值保留为 `(hidden)` 就不会改变，要修改则填入新值。

</Step>
<Step>

### 检查并应用

点击**检查变更**。检查页面会列出修改了哪些字段，以及服务是否会中断。**技术细节**中有 **YAML 差异**和**字段所有者**，后者列出上次写入各个字段的工具，例如 `kubectl` 或 `helm`。确认后应用。

</Step>
</Steps>

Zeabur 只写入你修改的字段，写入每处修改前，都会确认集群中的值与开始编辑时相同。如果编辑期间有人修改了同一个对象，应用会失败，需要重新打开后再修改一次。

`status`、`resourceVersion`、`ownerReferences` 这类由集群维护的字段，即使修改也不会写入。Pod、ReplicaSet 这类由其他对象生成的对象不能编辑或删除，需要修改其所属对象。

如果修改了用 `kubectl apply` 写入的字段，检查页面会提醒**下次运行 kubectl apply 时会把 hello 的 …改回去**。这时也要更新你手上的 YAML 文件，否则下次 apply 又会覆盖这些修改。

## 删除对象

在 YAML 视图中点击**删除**，检查页面会列出删除后的影响，确认后应用。删除后无法撤销。删除工作负载时，它生成的 ReplicaSet 和 Pod 也会一并删除。

## 用 kubectl 完成相同操作

**创建**对应 `kubectl create`，遇到已存在的对象会失败。以下以项目 `demo` 为例：

```sh
kubectl -n demo create -f hello.yaml
kubectl -n demo edit deployment hello
kubectl -n demo delete deployment hello
```

`kubectl create -f` 按文件中的顺序创建，不会像 Zeabur 那样重新排序，将 ConfigMap 和 Secret 放在前面。

Zeabur 写入时不会添加自己的字段，用 `kubectl apply` 管理的对象仍然可以继续用 kubectl apply 管理。在 Zeabur 中修改的字段，也要同步更新到你的 YAML 文件中。

## 确认结果

**对象**页会列出新创建的对象。工作负载也会出现在项目的服务列表中，**概览**显示副本是否就绪。

```sh
kubectl -n demo get configmap,deployment,service -l app.kubernetes.io/name=hello
kubectl -n demo get configmap hello-config
kubectl -n demo get deployment hello -o yaml
kubectl -n demo get deployment hello --show-managed-fields -o jsonpath='{.metadata.managedFields[*].manager}'
```

前两行确认对象都已存在。`-o yaml` 的内容与你在 Zeabur 中看到的 YAML 相同。最后一行列出写入过这个对象的程序，与检查页面中**字段所有者**的数据来源相同。

## 遇到问题

| 页面提示或结果 | 处理方法 |
| --- | --- |
| **Namespace … 属于整个集群，Zeabur 只在项目内创建对象。** | 用 kubectl 创建，或请管理员处理。 |
| **这个集群没有提供 Certificate（cert-manager.io/v1）。** | 先安装提供这类对象的组件，或确认 `apiVersion` 是否拼写有误。 |
| **已有名为 hello 的 Deployment。创建不会修改已有对象。** | 改用该对象的**编辑**，或换一个名称。 |
| **已创建 1/3 个** | 查看拒绝原因，选择**删除刚创建的 1 个**，或选择**保留**后修正剩余对象。 |
| 编辑或删除时提示对象由 Helm、Argo CD 或 Flux 管理 | 回到对应工具的 values 或 Git 仓库修改。 |
| **这类对象由 Kubernetes 自行管理，要修改请编辑其所属对象。** | 这类对象由其他对象生成，例如 Pod。修改它所属的 Deployment。 |
| 应用时提示对象已发生变化 | 编辑期间有人修改了它。重新打开 YAML，再修改一次。 |
