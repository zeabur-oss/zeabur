---
title: 删除项目
description: 删除项目的 Namespace 和里面的所有内容，先看清楚哪些数据会留下，再确认删除。
---

项目就是一个 Kubernetes Namespace。在项目**设置**的**危险区域**点击**删除项目**，Zeabur 会删掉这个 Namespace 和里面的服务、数据库、卷、配置与机密变量，效果和 `kubectl delete namespace` 一样。删除后无法恢复，只能从备份重建。

只想让 Namespace 不再出现在 Zeabur，改用同一处的**从 Zeabur 移除**：只去掉项目标签，什么都不删除。

## 开始前

- 你要能删除这个 Namespace（`delete namespaces/<项目>`），也要能删除里面的数据库对象。少了哪一项，检查页面会列出来，应用时集群也会拒绝。
- Zeabur 自己的 Namespace、`kube-` 开头的系统 Namespace、installer 安装的组件（标有 `zeabur.com/platform=true`）和 `zeabur-terminals` 都不能从这里删除。

## 检查要删除的内容

<Steps>
<Step>

### 看哪些会一起删除

点击**删除项目**后，检查页面分成两部分。**会一起删除**列出：

- 服务的名称。
- 每个数据库和上次备份的时间。
- 每个卷、上次备份的时间，以及数据会不会留下。卷的 PersistentVolume 配置为 `Retain` 时，数据会留在那个 PersistentVolume；配置为 `Delete` 时，数据跟着删除。读不到 PersistentVolume 时，Zeabur 改看 StorageClass 的 `reclaimPolicy`，两者都读不到就直接说不确定。
- 你在这个项目打开过的工具 Pod。这些 Pod 在 `zeabur-terminals` 里，Zeabur 会在 Namespace 删除后一并清掉。

数据库或卷一天内没有成功的备份时，旁边会出现**先备份一次**。点击后会改为检查这次备份，应用后等备份完成，再回来删除项目。这个按钮用的是数据库页面和卷备份原有的**立即备份**，只有已经配置好备份的数据库和卷才会出现。

</Step>
<Step>

### 看哪些会留下

**会保留**列出 S3 里的备份，以及项目以外的内容，例如其他项目和集群配置。

K8up 的卷备份还原时要用 restic 密码。这个密码存在项目里的 Secret（例如 `data-redis-0-backup`），会跟项目一起删除。之后还想还原卷，删除前先另存：

```sh
kubectl -n shop get secret data-redis-0-backup -o jsonpath='{.data.RESTIC_PASSWORD}' | base64 -d
```

集群备份（Velero）会把整个 Namespace 连同 Secret 一起存起来，从集群备份还原就不需要另外保存。

</Step>
<Step>

### 留意会重建的对象

项目里有对象由 Helm、Argo CD 或 Flux 管理时，检查页面会提醒：删除后，这些工具可能会按自己的配置重新创建。要先在工具那边移除这个应用，项目才不会重新出现。

</Step>
<Step>

### 输入项目名称并删除

在下方输入项目名称，也可以点击提示里的项目名称自动填入，再点击**删除项目**。

</Step>
</Steps>

## 删除时发生什么

Zeabur 用你的身份按顺序删除：

1. 先删除数据库对象，例如 CloudNativePG 的 `Cluster`，让 operator 有机会按自己的方式收尾。Zeabur 最多等一分钟，让数据库消失。operator 没有在运行时就无法收尾，项目会卡在删除中，项目页面会列出还没删掉的对象和各自的 finalizer。
2. 再删除 Namespace，Kubernetes 接着删掉里面剩下的内容。
3. 最后删掉你在这个项目打开的工具 Pod。

删除期间，项目列表会标**正在删除…**，项目页上方会说明还剩什么。通常一两分钟就会消失。

## 项目一直删不掉

Namespace 会等里面每个对象的 finalizer 都移除后才消失。每个 finalizer 由当初加上的控制器在清理完成后移除；控制器没有在运行，对象就会一直留着。

项目页会列出还带着 finalizer 的对象，以及查看这些对象的命令。以项目 `shop` 为例：

```sh
kubectl get namespace shop -o yaml
kubectl get clusters.postgresql.cnpg.io orders -n shop -o yaml
```

`status.conditions` 会写明还剩哪些资源、哪些 finalizer 在等。通常的处理方式是让对应的 operator 恢复运行，operator 清理完就会自己移除 finalizer。

### 强制删除

控制器已经被移除，或一直清理不完时，在项目页上方点击**强制删除**。只要有对象在等待 finalizer，就会出现这个按钮。控制器通常会自己处理完，多等一会儿更稳妥；确实等不到，再强制删除。

检查页面会列出每个对象和要移除的 finalizer。强制删除会：

- Namespace 报告还在等待的对象，`metadata.finalizers` 会设为 `[]`。只改已经在删除的对象。
- 不改 Namespace 自己的 `spec.finalizers`。之后 Kubernetes 会删除剩下的东西，再删除 Namespace。
- 以你的身份运行，所以你需要这些对象的 `patch` 权限。

finalizer 移除后，控制器就没办法清理自己在集群外创建的东西，例如对象存储里的备份或云磁盘，这些要自己检查并删除。

`kubernetes.io/...` 的 finalizer（例如 `kubernetes.io/pvc-protection`）通常是还有 Pod 在用这个磁盘，或节点宕机了，建议先处理那个 Pod 或节点，直接移除可能会留下磁盘。

输入项目名称，再点击**强制删除项目**。

用 kubectl 时，对项目页列出的每个对象运行：

```sh
kubectl patch clusters.postgresql.cnpg.io orders -n shop --type merge -p '{"metadata":{"finalizers":[]}}'
```

## 用同样的名称重建项目

删掉项目后，要把同样的名称交给另一个团队，先等 70 分钟。

Zeabur Builder 推送镜像用的 registry 令牌，认的是仓库名称，也就是项目名称，不认 Namespace 的 UID。项目删掉后又有人用同样名称创建了项目，旧项目此前签发的令牌在到期前，仍然可以推送到新项目的仓库。构建用的令牌最长 70 分钟（默认构建时限 60 分钟，再加 10 分钟），上传源代码归档的令牌是 15 分钟。自己删掉再自己重建同一个项目，不用在意这件事。

日志和用量的历史记录也是按项目名称保存的。用同样名称创建的新项目，**日志** 和 **用量** 会显示已删除项目的记录，直到日志和用量的存储过了保留期限才会消失。不想让另一个团队看到这些记录，请集群管理员先把它们从日志和用量的存储里删除。

## 从备份找回项目

到**集群** → **备份**，在**备份记录**选择删除前的备份，点击**还原已删除的项目**（原项目还在时，按钮是**从备份创建新项目**），步骤见[备份集群并从备份还原](../cluster/backups.mdx#从备份还原)。

数据库和卷自己的 S3 备份也还在，可以在新项目里[还原成新数据库](../deploy/databases.mdx#还原为新数据库并切换服务)或[从备份还原文件](./volumes.mdx#从备份还原文件)。

## 用 kubectl 做同样的事

```sh
kubectl delete clusters.postgresql.cnpg.io --all -n shop   # 每种数据库各一行，先删数据库
kubectl delete namespace shop
```

列出 `zeabur-terminals` 里属于 `shop` 的工具 Pod，再逐一删除：

```sh
kubectl get pods -n zeabur-terminals -l zeabur.com/project=shop
```

只运行 `kubectl delete namespace shop` 也会删掉所有内容，差别在于数据库和其他对象同时删除，operator 不一定来得及收尾。
