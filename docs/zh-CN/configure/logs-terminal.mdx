服务出问题时，先看**日志**选项卡的输出，再到**部署记录**选项卡切换到**事件**，查看 Kubernetes 做了什么，然后在**用量**选项卡确认资源是否不足。要在副本中运行命令，点击服务页面顶部的**终端**。要查看或修改卷中的文件，使用**文件**选项卡。

## 开始前

- 查看日志、事件和用量需要项目的读取权限。打开终端和**文件**选项卡需要在副本中运行命令的权限（`pods/exec`），项目的开发者有此权限。
- 这些功能都需要运行中的副本。副本数为 0 或副本尚未启动时，页面会显示**没有运行中的副本**。
- 日志和用量的**历史记录**需要集群额外安装存储服务，见下面各节。

## 查看日志

打开服务的**日志**选项卡，页面会显示一个副本的输出。

- 服务有多个副本或多个容器时，在顶部切换**副本**和**容器**。
- **实时跟踪**会持续接收新行。向上滚动时会暂停，点击**跳到最新**返回底部。
- 在**筛选**中输入文本，只保留匹配的行。在开头加上 `-` 会排除匹配的行，例如 `-healthz`。
- 按**错误**、**警告**、**信息**筛选日志级别。
- **上一次运行**显示容器上次崩溃或重启前的输出，排查崩溃原因时先看这里。
- **下载**将当前日志保存为文件。

![服务的日志选项卡，顶部可切换副本，列出一个副本的输出，并按错误、警告、信息筛选](../images/shots/service-logs.avif)

副本替换后，旧副本的日志就会从集群中消失。要查看已替换副本的日志，使用**历史记录**。

### 历史记录

**历史记录**列出所有副本写入的日志，包括已替换的副本。它从日志存储服务读取数据，需要集群管理员在 Zeabur 的 Helm chart 中开启 `proxy.enabled`。默认读取 VictoriaLogs，地址通过 `proxy.logs.url` 设置。通过安装器安装 VictoriaLogs 后会自动开启。如果集群没有 VictoriaLogs，将 `proxy.logs.enabled` 设为 false。未开启时，页面显示**还没有开启日志历史记录**。

## 查看事件

打开服务的**部署记录**选项卡，切换到**事件**，查看副本调度到哪个节点、下载镜像、健康检查失败、内存超过上限（OOMKilled）等 Kubernetes 事件，最新事件排在前面。点击**警告**只看警告。

Kubernetes 只保留大约一小时内的事件。排查更早的问题需要查看日志的**历史记录**。

## 查看用量

打开服务的**用量**选项卡：

- **当前用量**：每个副本的 CPU 和内存用量，与预留量、上限并列显示。内存用量接近上限时会标记**接近内存上限**，超过上限时容器会重启。此功能需要集群安装 metrics-server，未安装时点击**安装**，查看需要在服务器上运行的命令。
- **历史记录**：一段时间内的用量图，会标出 OOMKilled 和重启的时间点。此功能需要兼容 Prometheus 的指标存储服务，例如 VictoriaMetrics 或 Prometheus。如果没有，点击**安装 VictoriaMetrics**；如果已有，点击**改用其他存储服务**，指定它的 Kubernetes Service。

集群管理员在 Helm chart 中开启 `proxy.enabled` 后，项目的查看者和开发者都能看到自己项目的**历史记录**。Zeabur Proxy 会先确认你是该项目的成员，查询也只能获取该项目的指标。如果未开启，或在配置中改用其他存储服务，Zeabur 会直接读取存储服务。能直接读取的人可以看到所有项目的指标，因此只有管理员能查看。

![服务的用量选项卡，上方是每个副本当前的 CPU 和内存用量，下方是历史用量图](../images/shots/service-usage.avif)

用量长期超过预留量或接近上限时，到[调整副本、资源和健康检查](./service-settings.mdx)调整**计算资源**。

## 打开终端

<Steps>
<Step>

### 打开

进入服务，点击页面顶部的**终端**。终端会在页面底部打开，连接到当前选中的副本。也可以从服务的**更多**菜单或搜索中打开。

</Step>
<Step>

### 运行命令

终端在容器中运行 shell，例如：

```sh
printenv DATABASE_URL
wget -qO- http://localhost:8080/healthz
```

在这里修改的文件只保留在当前副本中，副本替换后就会消失。需要保留的数据应放在[卷](./volumes.mdx)中。

![服务页面底部的终端，标签显示已连接，已输入 ls](../images/shots/terminal-connected.avif)

</Step>
</Steps>

15 分钟没有输入或输出，终端会自动关闭，点击**重新连接**即可再次打开。

### 镜像没有 shell 时

distroless 这类精简镜像没有 shell，终端会说明这一点，并显示**打开调试终端**。点击后会在同一个副本中添加一个 busybox 调试容器，名称以 `zeabur-debug-` 开头。它可以看到应用正在运行的进程，也会挂载相同的卷。

![镜像没有 shell 时的终端，说明镜像不含 shell，并提供打开调试终端的按钮](../images/shots/terminal-no-shell.avif)

<Callout type="warn">
Kubernetes 无法提前移除调试容器，它会一直留在副本中，直到副本替换，例如重启服务时。之后在同一个副本中打开终端，会直接使用这个调试容器。
</Callout>

### 没有权限时

没有 `pods/exec` 权限时，终端会列出一份 Role 和 RoleBinding，交给管理员应用。这份配置只授予当前项目的终端权限，见下面的 kubectl 一节。

## 浏览文件

打开服务的**文件**选项卡，选择**副本**和**容器**，即可浏览容器中的文件，执行**上传**、**下载**、**新建文件夹**、**重命名**或**删除**。每个位置都会标出所属类型：

| 类型 | 替换副本后 |
| --- | --- |
| 磁盘 | 保留 |
| 临时空间 | 删除 |
| 镜像 | 修改只保留在当前容器中，重启后消失 |
| 配置文件、机密变量 | 只读，需要到[环境变量](./variables.mdx)修改 |

文件读写与 `kubectl cp` 一样，通过 `tar` 完成。如果镜像没有 `tar`，点击**加入调试容器**，改由调试容器读取卷，但无法读取镜像本身的文件。

## 打开 kubectl 终端

要在浏览器中使用 kubectl 或 helm，在页面底部的终端区域或搜索中选择**打开 kubectl 终端**。Zeabur 会在 `zeabur-terminals` Namespace 中为你启动一个临时容器，其中的 kubectl 和 helm 以你的身份运行，使用你自己的权限，默认在当前项目中操作。

在项目以外的页面（例如**集群**页面）打开时，会打开整个集群的 kubectl 终端，确认页面标题为**打开集群的 kubectl 终端**。它默认在 `default` Namespace 中操作，你有权限的 Namespace 都能操作。

这个容器最多运行 30 分钟，最后一个终端关闭 1 分钟后就会删除。其中的凭证会过期，重新打开终端就会换上新的凭证。

## 用 kubectl 完成相同操作

以下以项目 `demo`、Deployment `web` 为例。

| Zeabur 中的操作 | kubectl |
| --- | --- |
| **日志**，**实时跟踪** | `kubectl -n demo logs deployment/web -f` |
| 指定副本和容器 | `kubectl -n demo logs web-7c9d8b6f5-x2k4p -c web` |
| **上一次运行** | `kubectl -n demo logs web-7c9d8b6f5-x2k4p --previous` |
| **事件** | `kubectl -n demo events --for deployment/web` |
| **当前用量** | `kubectl -n demo top pod -l app.kubernetes.io/name=web` |
| **终端** | `kubectl -n demo exec -it deployment/web -- sh` |
| **打开调试终端** | `kubectl -n demo debug -it web-7c9d8b6f5-x2k4p --image=busybox:1.37.0 --target=web` |
| **文件**中的下载 | `kubectl -n demo cp web-7c9d8b6f5-x2k4p:/data/report.csv ./report.csv` |

`kubectl events --for` 列出这个 Deployment 本身的事件。副本的事件需要用 `kubectl -n demo events --for pod/<副本名称>` 查看，或用 `kubectl -n demo get events --sort-by=.lastTimestamp` 查看整个项目的事件。

要让其他人能打开终端和使用**文件**选项卡，应用与页面上相同的 Role 和 RoleBinding：

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: zeabur-terminal
  namespace: demo
rules:
  - apiGroups: [""]
    resources: ["pods"]
    verbs: ["get"]
  - apiGroups: [""]
    resources: ["pods/exec"]
    verbs: ["get", "create"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: zeabur-terminal-alice-example.com
  namespace: demo
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: zeabur-terminal
subjects:
  - kind: User
    apiGroup: rbac.authorization.k8s.io
    name: "alice@example.com"
```

在 `subjects` 的 `name` 中填写此人在 Kubernetes 中的用户名。

## 确认结果

**日志**显示副本的输出，开启**实时跟踪**时会不断出现新行。终端连接成功时，标签显示**已连接**，调试容器显示**已连接到调试容器**。

```sh
kubectl -n demo get pod -l app.kubernetes.io/name=web -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.ephemeralContainers[*].name}{"\n"}{end}'
kubectl -n zeabur-terminals get pods
kubectl auth can-i create pods/exec -n demo --as=alice@example.com
```

第一行列出每个副本及其中的调试容器，打开过调试终端的副本会出现以 `zeabur-debug-` 开头的名称。第二行列出当前的 kubectl 终端，名称以 `zeabur-tools-` 开头，只有管理员能看到。第三行返回 `yes` 表示此人能打开终端。

## 遇到问题

| 页面提示或结果 | 处理方法 |
| --- | --- |
| **没有运行中的副本** | 服务的副本数为 0，或副本尚未启动。到**概览**查看原因。 |
| **没有上一次运行：容器尚未重启过。** | 容器没有崩溃过，改看本次运行的日志。 |
| **还没有开启日志历史记录** | 请管理员在 Helm chart 中开启 `proxy.enabled`。 |
| **实时用量需要 metrics-server。** | 点击**安装**，或请管理员安装 metrics-server。 |
| **15 分钟没有输入或输出，已关闭。** | 点击**重新连接**。 |
| 终端没有响应，提示需要权限 | 将页面上的 Role 和 RoleBinding 交给管理员应用。 |
| **这个镜像没有 tar。** | 点击**加入调试容器**，通过调试容器读取卷。 |
| 调试容器一直留在副本中 | Kubernetes 无法移除它。重启服务，替换为新的副本。 |
