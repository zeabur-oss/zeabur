应用需要保留上传的文件时，进入服务**设置** → **存储**，添加卷并指定应用写入的路径。应用变更后，写入这个路径的文件在副本重启或更换节点后都会保留。这里也能配置 K8up 备份，定期将卷中的文件复制到 S3 兼容存储。

## 开始前

- 确认应用写入数据的路径，例如 `/data`。容器中不在卷上的文件会在副本替换后消失。
- 集群有可用的存储类，你也有权限添加卷、修改服务。
- 如果服务由 Helm、Argo CD 或 Flux 管理，要回到原来的 values 或 Git 仓库修改。
- 要备份，集群需要安装 K8up，并准备可写入的 S3 兼容存储和访问密钥。管理员可以先登记 [S3 目标](../cluster/s3-destinations.mdx)，这样就能在备份表单中直接选择。
- 升级 K8up 的 Helm chart 时，Helm 不会更新 `crds/` 中的 CRD，升级后需要自行用 `kubectl apply` 应用新版 CRD。

## 添加卷

<Steps>
<Step>

### 指定挂载路径与大小

打开服务**设置** → **存储**。没有卷时，点击**添加卷**。已有卷时，先点击**编辑**，再点击**添加卷**。

输入**挂载路径**（例如 `/data`）和**大小**（例如 `5Gi`，默认 `1Gi`）。挂载路径必须是绝对路径，也不能与这个服务已有的挂载路径重复。

![存储空间新增一行卷，挂载路径为 /data、大小为 5Gi，状态标为新增](../images/shots/volume-add.avif)

服务有多个容器时，在新卷所在行的**挂载到容器**中选择要挂载的容器。检查页面也会显示容器名称。

</Step>
<Step>

### 选择存储类

在**存储类**中选择数据存放的位置。每个选项都会说明是否支持扩容，以及卷与节点的关系：

- **本地磁盘**最快，但固定在一个节点上，使用它的副本只能在该节点运行。
- **多副本磁盘**将数据复制到多个节点，副本更换节点时，数据会随之迁移。
- 其他存储类的行为由其驱动程序决定。

不选则使用集群的默认存储类。如果选择不支持扩容的存储类，需要一次分配足够的容量。

要自定义名称，展开**高级**，修改**名称**、**PVC 名称**和**访问模式**。这个表单始终会创建新的 PVC，如果填写正在使用的 PVC 名称，集群会拒绝创建。

</Step>
<Step>

### 检查并应用

点击页面下方的**检查变更**，确认要创建的卷、大小和挂载路径，再应用。Zeabur 会先创建 PVC，再将它挂载到容器的指定路径。

添加或修改挂载会更新 Pod template，持续运行的服务会替换副本。新卷最初是空的，容器原本在这个路径下的文件不会迁移过去。要保留这些文件，先将文件复制出来，挂载卷后再放回去。

</Step>
<Step>

### 确认挂载与数据

等卷的状态变为**就绪**、服务副本也就绪后，通过应用上传一个文件，再**重启**服务，确认文件仍然存在。

每个卷所在行都会显示存储类、数据所在的节点、是否支持扩容，以及删除卷后是否保留数据。如果集群收集了 kubelet 的卷指标，还会显示用量。要查看 PVC 名称、对应的 PersistentVolume 和访问模式，进入项目**对象**页或用 kubectl 查询。

</Step>
</Steps>

StatefulSet 的卷在创建时就已固定（`volumeClaimTemplates` 创建后不能修改），所以这里不能为它添加或移除卷，只能扩容或修改挂载。Job 创建后不能修改 Pod template，要为 Job 添加卷，需编辑它的 YAML。

## 扩容或调整挂载

在**存储**点击**编辑**，增大已有卷的**大小**，再从页面下方检查并应用。只有支持扩容的存储类才能增大容量，而且不能缩小。多个服务挂载同一个 PVC 时，会共同使用扩容后的空间。

已有挂载也可以修改**挂载路径**或**只读**。修改路径只会改变数据在容器中的位置，应用配置中的数据路径也要相应修改。如果路径写在[环境变量](./variables.mdx)中，可以与挂载放进同一份草稿一起检查。

如果存储类不支持扩容，需要在支持扩容的存储类中创建新卷，将数据复制过去，再让服务改为挂载新卷。已有 PVC 不能更换存储类。

## 配置卷备份

<Steps>
<Step>

### 选择要备份的卷

在服务**设置** → **存储**下方的**备份**中找到卷，点击**备份这个卷**。如果集群尚未安装 K8up，点击**打开 K8up**，请管理员安装。

</Step>
<Step>

### 填写 S3 目标与保留规则

表单顶部会先显示备份以哪个用户身份运行，原则上与服务一致：

- 服务指定了非 root 用户时，备份使用同一个用户。
- 服务指定 root，或没有指定用户且安全性不是**严格**时，备份使用 root，以便读取所有文件。
- 服务没有指定用户且安全性为**严格**时，备份使用 K8up 的非 root 用户，会跳过只有服务用户才能读取的文件。在服务的安全性设置中指定用户，就能一并备份这些文件。

如果项目只允许“严格”服务，而备份需要以 root 身份运行，表单会说明原因，并阻止创建这项备份。点击**打开安全性设置**，将服务改为**严格**，或请管理员允许项目使用“兼容”服务。

选择已登记的 S3 目标，或自行填写**端点**、**存储桶**、**访问密钥 ID**、**私密访问密钥**。如果存储服务需要区域，再填写**区域**。

**文件夹**留空时使用 `<项目>/<PVC 名称>`，例如项目 `shop` 的 PVC `data-redis-0` 会存放在 `shop/data-redis-0`。

**定时**可选**每天 03:00（UTC）** 或**每周日 03:00（UTC）**。保留规则默认为**保留最新几份** 3 份、**每日备份保留天数** 7 天、**每周备份保留周数** 4 周。K8up 会在备份一小时后（04:00 UTC）按这组规则清理旧备份。

</Step>
<Step>

### 检查备份对象与运行身份

点击面板中的**检查变更**。这个面板有独立的应用步骤，不会加入上方存储配置的草稿。

检查页面会列出存放密钥和仓库密码的 Secret、PVC 上的备份标签和注解，以及 K8up Schedule。如果备份不以 root 身份运行，还会有一个 PodConfig。以 PVC `data-redis-0` 为例，Secret 和 Schedule 都叫 `data-redis-0-backup`。

确认后应用。选择已登记的 S3 目标时，密钥会复制到项目的 Secret 中。之后如果目标更换密钥，需要单独更新这份副本。

</Step>
<Step>

### 运行一次并确认结果

创建定时任务不会立即备份。点击该卷的**立即备份**，检查并应用，K8up 就会立即运行一次。

在**这些卷的备份**中查看本次运行的状态、完成时间和失败信息。只有显示**成功**，才表示文件已复制到 S3。

如果这个卷原本就由涵盖多个卷的 K8up 定时任务备份，**立即备份**会沿用该定时任务的选择条件，其他卷也会一起备份。

</Step>
</Steps>

<Callout type="warn">
单独保存备份 Secret 中的 `RESTIC_PASSWORD`。这是 Zeabur 生成的 restic 仓库密码，没有它就无法读取 S3 中的备份。删除项目或备份 Secret 前，先将它保存到其他地方。
</Callout>

## 从备份还原文件

在**备份**中，点击有备份点的卷旁的**从备份点创建新卷**，选择时间点，检查并应用。K8up 会将该时间点的文件还原到新卷，原卷保持不变。StatefulSet 的卷改用**停止服务、清空卷、还原到原处**。

如果没有还原权限，需要请管理员处理，准备以下信息：

- 来源 S3 端点、存储桶和文件夹，可通过 K8up Schedule 的 `spec.backend` 确认。
- S3 访问密钥，以及备份 Secret 中的 `RESTIC_PASSWORD`。
- 要还原哪份备份。Zeabur 的运行记录没有 restic 快照 ID，需要从备份仓库查询。
- 目标 PVC，以及要重新挂载它的服务。

有 Secret 读取权限的人可以用 `kubectl` 获取备份 Secret。以项目 `shop`、PVC `data-redis-0` 为例：

```sh
kubectl -n shop get secret data-redis-0-backup -o yaml
```

这份 Secret 包含 S3 密钥和仓库密码，应存入团队的密码管理工具，不要粘贴到 issue 或聊天消息中。

备份区域的 **K8up：还原**链接指向 [K8up 的还原说明](https://docs.k8up.io/k8up/2.16/how-tos/restore.html)。建议先还原到另一个新卷，确认文件没有问题，再停止服务写入，改为挂载新卷。

### 下载某个备份时间点的文件

1. 按照上面的步骤，将该时间点的文件还原到新卷。不要点击**把服务改挂到新卷**，否则运行中的服务会改用旧文件。
2. 新卷尚未由任何服务挂载。用一个临时 Pod 挂载它。以下以项目 `shop`、新卷 `data-restored-1025` 为例：

   ```sh
   kubectl -n shop apply -f - <<'EOF'
   apiVersion: v1
   kind: Pod
   metadata:
     name: restore-view
   spec:
     securityContext:
       runAsNonRoot: true
       runAsUser: 65532
       fsGroup: 65532
       seccompProfile:
         type: RuntimeDefault
     containers:
       - name: restore-view
         image: busybox:1.37
         command: ["sleep", "3600"]
         securityContext:
           allowPrivilegeEscalation: false
           capabilities:
             drop: ["ALL"]
         volumeMounts:
           - name: data
             mountPath: /restored
     volumes:
       - name: data
         persistentVolumeClaim:
           claimName: data-restored-1025
   EOF
   kubectl -n shop wait --for=condition=Ready pod/restore-view
   ```

3. 将整个文件夹打包为 `backup.tgz`，或只复制需要的文件：

   ```sh
   kubectl -n shop exec restore-view -- tar czf - -C /restored . > backup.tgz
   kubectl -n shop cp restore-view:/restored/path/to/file ./file
   ```

4. 下载完成后，删除临时 Pod 和新卷：

   ```sh
   kubectl -n shop delete pod restore-view
   kubectl -n shop delete pvc data-restored-1025
   ```

数据库使用**更多** → **导出**下载转储文件，见[下载数据库转储文件](../deploy/databases.mdx#下载数据库转储文件)。如果需要更早时间点的内容，先**还原为新数据库**，再从新数据库导出。

K8up 备份时，应用照常运行，K8up 直接复制卷上的文件。如果卷中存放的是正在写入的数据库，复制出的文件可能不一致，应改用[数据库自身的备份](../deploy/databases.mdx)。要备份整个集群的对象，见[集群备份](../cluster/backups.mdx)。

## 用 kubectl 完成相同操作

卷使用普通的 PVC，备份使用 K8up 的 Schedule 和 Secret。移除 Zeabur 后，挂载和备份定时任务仍会正常运行。以下以项目 `demo`、Deployment `web`、卷名称 `uploads` 为例。

### 添加卷

Zeabur 创建的 PVC 名称为 `<服务>-<卷名称>`，访问模式默认为 `ReadWriteOnce`。要指定存储类，添加 `storageClassName`：

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: web-uploads
  namespace: demo
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests:
      storage: 5Gi
```

再将它挂载到容器：在 Pod template 中添加一项 `volumes`，在容器中添加一项 `volumeMounts`。这与 Zeabur 写入的 JSON Patch 相同：

```sh
kubectl -n demo patch deployment web --type=json -p='[
  {"op":"add","path":"/spec/template/spec/volumes/-","value":{"name":"uploads","persistentVolumeClaim":{"claimName":"web-uploads"}}},
  {"op":"add","path":"/spec/template/spec/containers/0/volumeMounts/-","value":{"name":"uploads","mountPath":"/srv/uploads"}}
]'
```

如果 Pod template 中还没有 `volumes`，或容器中还没有 `volumeMounts`，`/-` 会失败，改用 `kubectl edit deployment web` 直接添加这两段。如果创建服务时就添加了卷，Zeabur 会将 Deployment 设为 1 个副本和 `strategy: Recreate`，避免新旧副本争用同一个 ReadWriteOnce 磁盘。之后才添加卷时，不会修改这两项配置，检查页面会提醒多个副本共用 ReadWriteOnce 磁盘的限制。

### 扩容

增大 PVC 的 `spec.resources.requests.storage`。存储类必须设置 `allowVolumeExpansion: true`，而且不能缩小容量：

```sh
kubectl -n demo patch pvc web-uploads -p '{"spec":{"resources":{"requests":{"storage":"10Gi"}}}}'
```

### 配置备份

备份需要三项内容：存放 S3 密钥和 restic 密码的 Secret、PVC 上的标签和 annotation，以及 K8up 的 Schedule。Secret 和 Schedule 都叫 `<PVC 名称>-backup`：

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: web-uploads-backup
  namespace: demo
type: Opaque
stringData:
  AWS_ACCESS_KEY_ID: AKIAEXAMPLE
  AWS_SECRET_ACCESS_KEY: change-me
  RESTIC_PASSWORD: a-long-random-password
---
apiVersion: k8up.io/v1
kind: Schedule
metadata:
  name: web-uploads-backup
  namespace: demo
spec:
  backend:
    repoPasswordSecretRef:
      name: web-uploads-backup
      key: RESTIC_PASSWORD
    s3:
      endpoint: https://s3.example.com
      bucket: backups/demo/web-uploads
      accessKeyIDSecretRef:
        name: web-uploads-backup
        key: AWS_ACCESS_KEY_ID
      secretAccessKeySecretRef:
        name: web-uploads-backup
        key: AWS_SECRET_ACCESS_KEY
  podSecurityContext:
    runAsUser: 0
  backup:
    schedule: "0 3 * * *"
    labelSelectors:
      - matchLabels:
          zeabur.com/backup-volume: web-uploads
  prune:
    schedule: "0 4 * * *"
    retention:
      keepLast: 3
      keepDaily: 7
      keepWeekly: 4
```

`bucket` 是存储桶加上文件夹，Zeabur 的默认文件夹为 `<项目>/<PVC 名称>`。如果 S3 需要区域，在 Secret 中添加 `AWS_DEFAULT_REGION`，并在 `backend` 中添加 `envFrom: [{secretRef: {name: web-uploads-backup}}]`。如果备份不以 root 身份运行，Zeabur 会改为写入同名的 K8up PodConfig，并将 `podSecurityContext` 替换为 `podConfigRef`。

接着为 PVC 添加 Schedule 用于选择卷的标签，以及 K8up 的 annotation：

```sh
kubectl -n demo label pvc web-uploads zeabur.com/backup-volume=web-uploads
kubectl -n demo annotate pvc web-uploads k8up.io/backup=true
```

**立即备份**使用一个 K8up Backup，内容是 Schedule 的 `backup`，再加上相同的 `backend` 和 `podSecurityContext`：

```yaml
apiVersion: k8up.io/v1
kind: Backup
metadata:
  name: web-uploads-now
  namespace: demo
spec:
  labelSelectors:
    - matchLabels:
        zeabur.com/backup-volume: web-uploads
  backend:
    repoPasswordSecretRef:
      name: web-uploads-backup
      key: RESTIC_PASSWORD
    s3:
      endpoint: https://s3.example.com
      bucket: backups/demo/web-uploads
      accessKeyIDSecretRef:
        name: web-uploads-backup
        key: AWS_ACCESS_KEY_ID
      secretAccessKeySecretRef:
        name: web-uploads-backup
        key: AWS_SECRET_ACCESS_KEY
  podSecurityContext:
    runAsUser: 0
```

**停止备份**只删除 Schedule（和 PodConfig），保留 Secret：

```sh
kubectl -n demo delete schedule.k8up.io web-uploads-backup
```

## 确认结果

在服务**设置** → **存储**中，卷的状态应为**就绪**，所在行会显示存储类。**备份**下方的**这些卷的备份**会列出每次运行，只有显示**成功**，才表示文件已复制到 S3。

用 kubectl 确认：

```sh
kubectl -n demo get pvc web-uploads
kubectl -n demo get schedule.k8up.io,backup.k8up.io
kubectl -n demo get snapshot.k8up.io
```

PVC 的 `STATUS` 为 `Bound`，`CAPACITY` 为当前大小。扩容时，要等 `CAPACITY` 变为新的大小才算完成。Backup 运行完成后，`COMPLETION` 会显示 `Succeeded`，`kubectl get snapshot.k8up.io` 会新增一条本次的快照记录。

## 遇到问题

| 页面或结果 | 后续处理 |
| --- | --- |
| 卷一直处于**等待存储**状态 | 查看副本和 PVC 的事件，确认存储类可用。如果卷所在行显示**固定在第一个副本运行的节点**，需要等副本调度到节点后才会创建。 |
| 副本更换节点后无法启动 | 查看卷是否固定在某个节点。本地磁盘的数据不会随副本迁移到新节点。 |
| 多个副本无法同时挂载 | Deployment 的副本共用同一个 PVC。访问模式为 ReadWriteOnce 时，只有同一节点上的副本才能挂载，需要改用支持多节点的存储类和访问模式。 |
| **这个卷名称超过 63 个字符，K8up 无法通过标签选择它。** | Zeabur 使用 PVC 名称作为标签值来选择卷。名称过长时，无法在这里配置备份，需要请管理员单独编写 K8up Schedule。 |
| 备份**失败**或**部分失败** | 阅读本次运行的失败信息，核对 S3 密钥，以及备份用户是否能读取文件。 |
| 创建后没有运行记录 | 点击**立即备份**运行一次，再查看 K8up 和备份副本的状态。 |
| 看不到备份配置或结果 | 备份区域会说明是集群未安装 K8up，还是你没有读取权限。 |

## 移除挂载与停止备份

尚未应用的存储修改，可以点击页面下方的**放弃**丢弃。对于已应用的挂载，在**编辑**中点击该行的移除按钮，再检查并应用。移除挂载只会让容器不再挂载这个卷，PVC 和数据都会保留。

要停止备份，在**备份**中点击该卷旁的**停止备份**，检查后点击**停止备份**。K8up 不再备份这个卷，S3 上已完成的备份会保留。备份 Secret 也会保留，其中包含还原这些备份所需的密码。只有专为这个卷创建的定时任务才有这个按钮，涵盖多个卷的定时任务需要请管理员调整。

要彻底删除卷，在**存储**中点击该卷所在行的删除按钮，检查后点击**删除卷**。服务不再挂载这个路径，PVC 也会一并删除。StatefulSet 和 Job 的卷没有这个按钮。

<Callout type="warn">
删除 PVC 前，先查看卷所在行。如果显示**删除后数据不保留**（回收策略 `Delete`），数据会一并删除。如果显示**删除后数据仍保留**（`Retain`），管理员之后需要自行处理留下的 PersistentVolume。
</Callout>
