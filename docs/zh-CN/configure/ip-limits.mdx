进入服务的**网络**，在 **IP 限制**中配置两项限制：**谁能打开域名**只允许指定的 IP 或 CIDR 范围访问服务的公开域名，**能连到哪里**限制服务的副本能主动连接哪些 IP。两项配置相互独立，检查并应用后才会写入集群。

## 开始前

- 谁能访问域名：域名必须使用 Traefik 提供的 Ingress。Gateway 域名（HTTPRoute）没有对应的配置，服务只有 Gateway 域名时，面板会显示**通过 Gateway 的域名无法在这里限制**。
- 能连到哪里：集群的网络插件需要支持 NetworkPolicy，K3s 内置的控制器就支持。插件不支持时，对象仍然能创建，但不会阻止任何连接。
- 需要有修改项目域名和 NetworkPolicy 的权限。服务由 Helm、Argo CD 或 Flux 管理时，需要在原来的 values 或 Git 仓库中修改。
- 这与项目设置中的**隔离**不同。隔离控制其他项目能否连接进来，IP 限制针对单个服务，不会修改项目的 `zeabur-project` 规则。

## 限制谁能访问域名

<Steps>
<Step>

### 输入允许的 IP

在 **IP 限制**的**谁能打开域名**中点击**编辑**，开启**只允许这些 IP**，每行输入一个 IP 或 CIDR 范围，例如 `203.0.113.0/24`。支持 IPv4 和 IPv6。

![谁能访问 web 的编辑界面，已开启只允许这些 IP，并输入两行 IP 范围](../images/shots/ip-limit-form.avif)

</Step>
<Step>

### 检查并应用

点击**检查变更**，确认列表后应用。这个服务每个通过 Traefik 的 Ingress 都会配置一份限制，同一个 Ingress 上的所有域名都适用，包括其他服务共用的域名。

其他 IP 访问域名时会收到 403 响应。限制位于 Ingress 中间件列表的最前面，先于重定向和密码验证执行。

</Step>
</Steps>

要取消限制，回到同一个面板关闭开关。每次修改都会用完整列表替换原来的列表。

### Traefik 看到的 IP

Traefik 默认按连接的源地址匹配。集群入口会修改源地址时，匹配的就不再是访客的 IP，限制可能会阻止所有人，也可能放行所有人。

- 使用 Zeabur 安装程序安装的 Traefik，其 Service 的 `externalTrafficPolicy` 为 `Local`，连接到 Traefik 所在节点的请求会保留访客地址。这项配置来自 Zeabur Catalog 的 Traefik 模板。ServiceLB 从其他节点转发请求时是否保留地址，尚未验证。
- 前面还有 CDN、反向代理或云负载均衡器时，Traefik 看到的是这些代理的地址。这时需要在 Middleware 中配置 `ipStrategy`，读取 `X-Forwarded-For`，并让 Traefik 的 entry point 信任该层代理的地址（`forwardedHeaders.trustedIPs`）。Zeabur 不会替你修改这些配置。
- 后续修改列表时，Zeabur 只修改 `sourceRange`，你在 Middleware 上添加的 `ipStrategy` 会保留。

应用后，分别从允许和不允许的 IP 连接一次，确认结果。

```yaml
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: api-ip-allow
spec:
  ipAllowList:
    sourceRange: [203.0.113.0/24]
    ipStrategy:
      depth: 1
```

配置项见 Traefik 的 [ipAllowList](https://doc.traefik.io/traefik/reference/routing-configuration/http/middlewares/ipallowlist/) 文档。

## 限制服务能连接到哪里

<Steps>
<Step>

### 输入允许连接的 IP

在**能连到哪里**中点击**编辑**，开启**只允许连到这些 IP**，每行输入一个 IP 或 CIDR 范围。单个 IP 会写成 `/32`（IPv6 为 `/128`）。

列表可以留空。留空时，服务只能连接同一项目中的服务和 DNS。

</Step>
<Step>

### 检查并应用

点击**检查变更**。检查界面会将风险标为高，因为应用后，列表以外的连接（包括更新软件包、调用外部 API）都会失败。确认后应用。

![限制 web 能连接到哪里的检查界面，警告 web 只能连接列表中的 IP、同一项目中的服务和 DNS](../images/shots/ip-limit-out-review.avif)

</Step>
</Steps>

应用后，服务的副本只能连接以下目标：

- 同一项目中的所有副本。
- 集群的 DNS（`kube-system` 中的 `kube-dns`，端口 53，UDP 和 TCP）。
- 列表中的 IP。

其他项目的服务、集群外的其他地址都无法连接。服务连接同一项目中的数据库不受影响。

规则根据副本模板的标签选择副本，因此适用于同一服务的所有副本，也包括新创建的副本。

## 用 kubectl 配置和移除

这两种限制都是普通的 Kubernetes 对象，没有 finalizer，也没有依赖 Zeabur 的字段。移除 Zeabur 后仍然有效。

**谁能打开域名**：每个 Ingress 都有一个 Middleware，名称为 `<Ingress 名称>-ip-allow`，`ownerReferences` 指向 Ingress，Ingress 的 annotation `traefik.ingress.kubernetes.io/router.middlewares` 中会列出这个 Middleware。要移除限制，先从 annotation 中移除 `<项目>-<Ingress 名称>-ip-allow@kubernetescrd`，再删除 Middleware。要是先删除 Middleware，Traefik 会找不到，域名会返回 404。

```sh
kubectl -n shop annotate ingress api traefik.ingress.kubernetes.io/router.middlewares-
kubectl -n shop delete middleware api-ip-allow
```

上面的 annotation 命令会移除整个列表。Ingress 还有重定向、密码验证等其他中间件时，改用 `kubectl edit`，只移除这一项。

**能连到哪里**：NetworkPolicy 名称为 `<服务名称>-egress-limit`，`policyTypes` 只有 `Egress`。删除这个 NetworkPolicy 即可解除限制：

```sh
kubectl -n shop delete networkpolicy api-egress-limit
```

要调整规则，直接编辑这个 NetworkPolicy，或另外创建自己的 NetworkPolicy。多个规则的允许范围会合并，不会相互覆盖。

## 限制与 Zeabur 其他功能的关系

- 维护模式使用另一个 Ingress，不包含这份限制，所有 IP 都能看到维护页面。
- 将域名迁移到独立的 Ingress（更换证书时会发生）之前，需要先关闭这个 Ingress 的 IP 限制。
- 删除服务时，检查界面会列出 NetworkPolicy，一并删除。删除 Ingress 时，Ingress 拥有的 Middleware 也会一并删除。
