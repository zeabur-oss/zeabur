---
title: 用 kubeconfig 连接已有集群
description: 在自己的电脑上运行 zeaburctl ui，用 kubeconfig 打开已有集群中的服务。不需要 Zeabur Identity，集群里也不会安装任何东西。
---

手里有能连到集群的 kubeconfig，就能在自己的电脑上打开 Zeabur。集群里不会多出任何东西，也不需要 Zeabur Identity。读取、**检查变更**和应用，用的都是这份 kubeconfig 的权限。

## 准备

| 需要 | 用途 |
| --- | --- |
| 能连到集群的 kubeconfig | Zeabur 使用它当前的 context，要用其他 context 时加上 `--context <名称>` |
| 你电脑上的 `zeaburctl` | 到[版本与验证](../reference/releases.mdx)下载。支持 Linux 和 Apple 芯片的 macOS，Windows 请在 WSL 中运行 |
| 读取权限 | 能读取 Namespace、Deployment、副本和事件，就能查看服务及其状态，和**查看者**角色相同 |
| 修改权限 | 要部署或修改服务，需要在项目里创建和修改 Deployment、Service 和 Ingress，和**开发者**角色相同；要新建项目，还要能创建 Namespace |

这些权限由集群的 RBAC 决定，Zeabur 不会多给。两个角色各能做什么，见[权限](../reference/permissions.mdx#成员角色)。

## 打开

```sh
zeaburctl ui
```

终端会打印一个链接，用浏览器打开即可使用。`zeaburctl ui` 只在你电脑的 `127.0.0.1` 上监听，链接中的令牌只能用一次。要连接其他集群，加上 `--context production`。按 `Ctrl-C` 关闭；已应用的变更会留在集群里。

## 一开始会看到什么

- **项目**把带有 Zeabur 项目标签的 Namespace 列为项目，其余的列在**其他 Namespace**。打开其中一个，服务、域名和环境变量都已经在里面，不需要导入。
- 读不到的部分，界面会写出缺少哪些权限，例如“部分检查需要你没有的权限。”，不会留下一片空白。
- 看不到**新建项目**，说明你的账号不能创建 Namespace。请管理员创建项目，或者改在已有的 Namespace 里部署。
- 这种方式没有登录和成员，谁拿到 kubeconfig，谁就拥有它的权限。要让团队成员各自登录，请改为[把 Zeabur 安装到已有集群](../install/existing-cluster.mdx)。

`zeaburctl ui` 在[体验计划](../reference/telemetry.mdx)中会发送什么、如何关闭，都写在那一页。它也会向 GitHub 查询有没有新版本，设置 `NO_UPDATE_NOTIFIER` 就能关闭，见[检查更新](../reference/telemetry.mdx#检查更新)。
