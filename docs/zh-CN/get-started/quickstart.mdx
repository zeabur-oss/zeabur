通过 Zeabur Installer 的网页界面完成五个步骤，就能打开 Zeabur 并注册首位管理员的通行密钥。点击“安装”之前，installer 不会改动服务器。

以下安装流程适合团队使用。如果仅供自己使用，或机器内存不足 4 GiB，参见[个人使用：在小型机器上安装](personal.mdx)。

## 准备服务器

准备一台满足以下条件的服务器：

- 使用 systemd 的 Linux，架构为 amd64 或 arm64。
- 具备 root 权限。
- 内存至少 4 GiB。
- `/var/lib/rancher` 至少有 10 GiB 可用空间。低于 30 GiB 时，installer 会显示提醒。
- TCP 端口 80、443、6443、10250 未占用。使用 RKE2 时还需要 9345。
- 未安装 kubeadm、k0s、MicroK8s 或 KubeSolo，也没有安装这次没选的 K3s 或 RKE2。

从 [GitHub Releases](https://github.com/zeabur-oss/zeabur/releases) 下载与服务器架构匹配的 `zeabur-installer-v<version>-linux-<arch>.tar.gz`。验证方法参见[发行文件与验证](../reference/releases.mdx)。

发行版 installer 固定了 K3s、RKE2、Zeabur Catalog、Zeabur Identity 和 Zeabur 的版本。安装所需的文件会下载到 `/var/lib/rancher/zeabur-installer/downloads`，并校验 SHA-256。

## 打开安装界面

在服务器上运行：

```sh
sudo zeabur-installer gui
```

installer 默认只监听 `127.0.0.1:8085`，终端会输出带有令牌的链接，例如：

```text
http://127.0.0.1:8085/?token=…
```

链接下方还会打印一行 `ssh -L` 命令，其中已经填好这台服务器的地址，例如：

```sh
ssh -L 8085:127.0.0.1:8085 root@203.0.113.10
```

在自己的电脑上打开另一个终端，运行这行命令建立 SSH 隧道。用 `sudo` 运行 installer 时，用户名会换成你登录服务器的账号。

然后在自己电脑的浏览器中打开刚才带有令牌的链接。

界面右上角可以切换语言和主题。页面上方依次是“服务器”“连接方式”“组件”“确认”“安装”五个步骤。点击“继续”进入下一步，点击“上一步”返回修改。

## 1. 检查服务器

在“检查服务器”中确认主机名、架构、内存和地址，再处理未通过的检查项。在“给谁用”中选择“团队用”。内存不足 4 GiB 时只能选择“自己用”，参见[个人使用：在小型机器上安装](personal.mdx)。

在“用哪一种 Kubernetes”中选标有“推荐”的那一项即可。

![“用哪一种 Kubernetes”在 5.7 GiB 的服务器上推荐 K3s，RKE2 在下面](../images/shots/installer-distribution.avif)

| | K3s | RKE2 |
| --- | --- | --- |
| 推荐用于 | 内存不到 8 GiB 的服务器 | 8 GiB 及以上的服务器 |
| 以后加服务器 | 只能加工作节点 | 可以加工作节点，也能用三台服务器一起跑控制平面，坏一台也不会停 |
| 内存 | 本身占用少，留给应用的更多 | 本身占用更多 |

服务器较小时，只有打算以后用三台服务器跑控制平面才选 RKE2。两种都会做同样的加固配置，参见[安全](../reference/security.mdx#installer-的主机与下载权限)。

![“检查服务器”选了团队用和 K3s，下方是主机信息与检查结果](../images/shots/installer-host.avif)

检查项包括管理员权限、systemd、时钟、Swap、为崩溃转储预留的内存、其他 Kubernetes、端口、磁盘空间和磁盘加密。先修正未通过的检查项，再点击“重新检查”。

出现警告时仍可继续。例如，磁盘未加密时会出现警告：Secret 会加密，卷和数据库的文件不会。一般 VPS 无法事后加密系统盘，可以照常安装。要存放敏感数据的话，改选服务商提供加密磁盘的方案。服务商在底层做的加密，安装程序检测不到，所以警告仍会出现。

页脚会说明所选配置保存到 `/etc/zeabur-installer/config.yaml`。

## 2. 选择连接方式

在“大家如何连接到 Zeabur”中配置两个不同的域名：

- “Zeabur”：大家访问 Zeabur 的地址，例如 `zeabur.example.com`。
- “登录”：Zeabur Identity 的地址，例如 `login.example.com`。大家会在这里使用通行密钥登录。

![“大家如何连接到 Zeabur”的证书与域名配置](../images/shots/installer-access.avif)

在“证书”中选择“公开域名”或“测试机”。服务器有公网地址时，默认是“公开域名”，两个域名会预先填好 `<地址>.sslip.io` 的名称。只有私有地址时（例如 `10.x`、`192.168.x` 或 Tailscale 的 `100.64.x`），默认是“测试机”。

页面下方的“应用域名”决定新服务的建议地址。可以暂时留空，之后为每个服务填写完整域名，也可以到**集群**页面配置。

### 公开域名

使用自己的域名时，选择“公开域名”。两个域名都需要有指向这台服务器的 DNS 记录，且互联网必须能访问服务器的 TCP 80 和 443 端口。

证书由 Let's Encrypt 签发。字段下方会显示域名是否指向这台服务器。

还没有自己的域名时，可以点击“使用 sslip.io 域名”，使用 `zeabur.<地址>.sslip.io` 和 `login.<地址>.sslip.io`。这些名称会解析到服务器的公网地址，Let's Encrypt 同样能签发证书。

### 测试机

测试时，选择“测试机”，再点击“使用 sslip.io 域名”，填入：

- `zeabur.<地址>.sslip.io`
- `login.<地址>.sslip.io`

这样无需配置 DNS。证书由在服务器上创建的证书颁发机构签发。Zeabur、登录页和应用的域名都使用这个机构的证书，所以安装完成后，要先将它导入浏览器或系统并设为受信任，才能注册通行密钥。

## 3. 选择组件

在“选择组件”中先选择“预设组合”，再根据需要勾选或取消勾选各个组件。

![“选择组件”的预设组合、组件列表与内存估算](../images/shots/installer-components.avif)

| 预设组合 | 内容 |
| --- | --- |
| “精简” | Ingress、证书和 metrics-server |
| “标准” | 组件目录建议在单台服务器上安装的组件，外加 Zeabur Builder（含 zot）、镜像自动更新（Keel）和 PostgreSQL（CloudNativePG）。这是默认选项 |
| “增强” | 在“标准”基础上增加运行时威胁检测、漏洞扫描和入侵防护 |

选择“标准”，装完就能用镜像或 Git 部署应用，也能创建 PostgreSQL 数据库。Zeabur Builder 用有特权的 buildkitd 构建，逃出沙箱的构建可以接触到节点，因此 builder-system 和 zot 这两个 Namespace 只允许管理员访问。不需要从 Git 部署时，在组件列表中取消勾选 Zeabur Builder。

有些组件要先填写设置才能继续，例如 Velero 要填写 S3 的端点、存储桶、区域和访问密钥，installer 会自己生成 Velero 需要的凭据文件。

其他组件所依赖的组件会一并加入，并标注“其他组件需要”。标注“特权”的组件会以主机权限运行。

上方会显示已选数量和空闲状态下的内存估算，结果分为“够用”“快不够了”“不够用”。根据估算调整选择，再点击“继续”。

## 4. 确认并开始安装

在“确认”中核对地址、组件和内存估算，确认后点击“安装”。

![“确认”显示安装摘要、警告与详细信息](../images/shots/installer-review.avif)

摘要会列出：

- 装完以后可以做什么，还有什么要之后设置。例如数据库备份要用 S3 存储桶，装完以后在 Zeabur 里设置。展开“各组件提供的功能”可以查看每个功能由哪个组件提供。
- 空闲时的内存用量。
- 选定的组件。
- Kubernetes 的类型和版本，例如 `K3s v1.36.5+k3s1`。
- 连接方式和地址。
- 所需时间，约 10 到 20 分钟。

先阅读“安装前请注意”中的警告。例如，测试机的域名也必须通过 DNS 解析到这台服务器。只修改 hosts 文件不够，Pod 不会读取它。

展开“详细信息”可以查看 Chart 及其版本、配置文件和完整计划。点击“下载”可保存 `config.yaml`。

如果有检查项未通过，或内存估算为“不够用”，“安装”按钮将不可用。修正问题或调整组件后再开始。

## 5. 查看安装进度

“正在安装”会显示时间轴，整个过程约需 10 到 20 分钟。点击“显示日志”可以查看完整输出。

![“正在安装”显示安装时间轴与进度](../images/shots/installer-install.avif)

时间轴依次列出包检查服务器、安装 Kubernetes（K3s 或 RKE2，附带版本）、Namespace 和连接规则、存储空间、各组件、证书颁发机构、Zeabur Identity、Zeabur 和收尾。证书颁发机构只会在测试机模式下安装。

关闭页面不会中断安装。重新打开带有令牌的链接，就能继续查看进度。

## 注册首位管理员

看到“Zeabur 已就绪”后，在“首位管理员”中点击“注册通行密钥”。完成注册后，点击“打开 Zeabur”登录。

测试机模式会多一个步骤，而且要先做：在“1. 信任证书颁发机构”中点击“下载证书”，将证书导入浏览器或系统并设为信任网站，再到“2. 注册首位管理员”注册通行密钥。信任之前，浏览器会显示警告，通行密钥也无法注册。应用的域名也使用这个证书颁发机构，其他要打开这些地址的电脑也要导入。

这个账号是管理员账号，只能使用通行密钥登录，拥有整个集群的完整权限。通行密钥保存在你注册它的电脑或手机上，建议再注册第二把。日常部署、查看日志等工作，可以到**成员**中为自己邀请一个普通账号来完成，参见[管理员账号和普通账号](../reference/permissions.mdx#管理员账号和普通账号)。

![“Zeabur 已就绪”显示首位管理员的注册入口](../images/shots/installer-done.avif)

<Callout type="warn">
首位管理员的注册链接会创建管理员账号，谁先打开，谁就能完全控制集群。只将链接交给负责管理集群的人。链接只能使用一次，有效期为 24 小时。
</Callout>

证书文件也保存在服务器的以下路径：

```text
/var/lib/rancher/zeabur-installer/local-ca.crt
```

注册链接过期时，在服务器上运行以下命令，生成新链接：

```sh
sudo zeabur-installer setup-link
```

完成后，在服务器终端中按 Ctrl-C 结束 installer。K3s/RKE2 和服务会继续运行。

## 安装已停止时

看到“安装已停止”时，先查看页面指出的步骤，再阅读日志最后几行中的错误原因。可能的原因包括内存不足、服务器检查未通过或超时。

![“安装已停止”显示停止的步骤与错误信息](../images/shots/installer-failed.avif)

修正后点击“重新安装”。installer 会从头开始，跳过已就绪的部分，不会移除任何内容。

## 检查安装结果

在服务器上运行：

```sh
sudo zeabur-installer doctor
```

这会检查 K3s 或 RKE2、组件、默认存储类、Zeabur Identity 和 Zeabur。

| 退出码 | 结果 |
| --- | --- |
| `0` | 正常 |
| `1` | 警告 |
| `2` | 严重 |
| `3` | 无法运行检查，例如未使用 root 运行 |

接下来可以[部署第一个服务](first-project.mdx)。

## 改用配置文件和命令

要重复安装、将配置纳入版本控制，或无法建立 SSH 隧道时，参见[使用配置文件和命令安装](advanced-install.mdx)。网页界面写入的配置文件，就是命令行读取的同一份文件。

## 移除 Zeabur

只移除 Zeabur 时，在服务器上运行：

```sh
sudo zeabur-installer uninstall zeabur
```

K3s/RKE2、组件、Zeabur Identity 和应用会保留。其他移除方式参见[移除 Zeabur，保留服务](../leave/uninstall.mdx)。
