把一个 Nginx 网页部署到网上：创建项目、填写镜像、检查变更、应用，最后在浏览器中看到 Nginx 欢迎页。不需要 Git 仓库，大约需要五分钟。

开始前，需要能登录的 Zeabur 和能指向集群的域名，例如 `web.example.com`。如果管理员已经配置了应用域名，表单会直接推荐一个网址，也不需要自己配置 DNS。

## 创建项目

打开**项目**，点击**新建项目**，在**名称**中填写 `hello`。这个名称也是 Kubernetes Namespace 的名称，创建后不能修改。

![新建项目对话框，名称填写为 hello](../images/shots/project-new.avif)

点击**检查变更**，页面会列出 Zeabur 准备执行的操作：创建 `hello` Namespace，添加项目标签，并应用 Pod Security `baseline` 配置，允许容器以 root 运行，但禁止访问主机。确认无误后，点击**创建**。

![创建项目 hello 前的确认页面，说明将创建的 Namespace 和安全配置](../images/shots/project-new-review.avif)

如果找不到**新建项目**，说明你的角色没有创建 Namespace 的权限。请管理员先创建项目并将你加入项目，再从下一步开始。

## 部署 Nginx

在 `hello` 项目中点击**添加**，选择 **Docker 镜像**：

| 字段 | 填写内容 |
| --- | --- |
| **镜像** | `docker.io/nginxinc/nginx-unprivileged:1.30.5-alpine-slim` |
| **名称** | `web` |
| **端口** | `8080` |
| **公开域名** | 开启，使用推荐的网址或你准备的域名 |

Zeabur 检测到 `nginx-unprivileged` 以用户 101 运行，会自动选择**严格**，表单会说明选择原因。这个镜像监听 `8080`。`nginx:latest` 也能运行，Zeabur 会为它选择**兼容**；创建前仍可自行切换。

填写镜像后，表单会读取镜像声明的端口，通常会自动填入 `8080`。

![部署镜像表单，已填写镜像、名称 web、读取到的端口 8080，并开启公开域名](../images/shots/image-form.avif)

## 检查变更，再应用

点击**检查变更**，Zeabur 会列出要创建的三个对象：

- `web` Deployment，运行刚才的镜像，1 个副本
- `web` Service，将 `8080` 转发到容器
- `web` Ingress，将你的域名指向 `web` Service

![部署 web 前的确认页面，列出要创建的 Deployment、Service 和 Ingress](../images/shots/image-review.avif)

此时集群中还没有创建任何新对象。如果发现域名填错了，返回表单修改。确认无误后再点击**创建**，Zeabur 会打开服务页面。

## 打开网址

在服务的**概览**中等待副本变为 `1/1` **就绪**。然后到**网络**中点击域名，浏览器会显示 Nginx 欢迎页。

如果域名下方显示**这个网址只有 HTTP**，说明集群尚未配置自动签发证书，请使用 `http://` 打开。要使用 HTTPS，请管理员配置 cert-manager 签发者。

返回**日志**，可以看到刚才打开网页时留下的访问记录。

服务的**概览**页面如下，顶部标签页可切换到**日志**、**网络**、**环境变量**和**设置**：

![web 服务的概览页，显示副本、镜像和标签页](../images/shots/service-overview.avif)

## 确认结果

- 服务的**概览**显示 `1/1` **就绪**，在浏览器中打开网址能看到 Nginx 欢迎页。
- 使用 kubectl 也能看到刚才创建的三个对象，它们都带有标签 `app.kubernetes.io/name: web`：

```sh
kubectl get namespace hello --show-labels
kubectl -n hello get deploy,svc,ingress -l app.kubernetes.io/name=web
```

Namespace 带有 `zeabur.com/project=true`，Deployment 的 `READY` 为 `1/1`，Ingress 的 `HOSTS` 为你的域名。

这些都是普通的 Kubernetes 对象，不使用 Zeabur 也能通过 `kubectl apply` 创建完全相同的服务。完整 YAML 见[部署容器镜像](../deploy/image.mdx)中的“用 kubectl 完成相同操作”。

## 网页没有显示

| 看到的状况 | 优先检查 |
| --- | --- |
| 副本一直未就绪，事件提示无法拉取镜像 | 镜像名称和版本是否填写正确，节点能否连接 Docker Hub |
| 副本一直为 0，事件提到 Pod Security | 需要 root 的镜像是否选择了**兼容**；如果项目仍强制使用 `restricted`，请管理员将项目的 Pod Security 级别改为 `baseline` |
| `1/1` 就绪，但网址无法打开 | DNS 是否指向集群入口，**端口**是否为 `8080` |
| 点击应用时提示**这份变更已过期** | 点击**重新检查**，查看新的差异后再应用 |

## 练习后清理

在 `web` 服务右上角的**更多**中选择**删除服务**。删除时也会先列出要删除的对象，这次是 Deployment、Service 和 Ingress，确认后应用。

要同时删除项目，到项目**设置**的**危险区域**点击**删除项目**，检查要删除的内容后，输入 `hello` 确认，见[删除项目](../configure/delete-project.mdx)。同一位置的**从 Zeabur 移除**只会移除项目标签，Namespace 及其中的内容都会保留。
