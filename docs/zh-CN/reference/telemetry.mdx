体验计划会发送版本、每天的使用人数、用过哪些功能、`zeaburctl ui` 有没有连上集群，以及保存变更有没有成功，用来了解有多少人在用、该先修哪里。用 Helm 安装的 Zeabur 开源版和 `zeaburctl ui` 都默认加入，也都会提示并说明如何关闭：`helm install` 和 `helm upgrade` 在完成时提示，`zeaburctl ui` 在每次启动时提示。Zeabur Desktop 跟随 `zeaburctl ui` 的设置。

## 会发送什么

每次有人登录或保存变更，Zeabur 开源版都会发送一条事件；同一项功能、同一组值每天（UTC）第一次出现时，Zeabur 开源版也会发送一条。每条事件只带随机的安装代码和下表的属性，没有别的。用 Helm 安装时，chart 用 `uuidv4` 生成一次安装代码，保存在 ConfigMap `zeabur-installation-id`，升级时沿用；也可以用 `telemetry.installationId` 指定自己的代码。安装代码不含任何机器的信息。数据保留 13 个月。

| 事件 | 由谁发送 | 时机 |
|---|---|---|
| `signed_in` | Zeabur 开源版 | 每次有人登录 Zeabur 开源版网页界面时 |
| `feature_used` | Zeabur 开源版、`zeaburctl ui`、Zeabur Desktop | 成功使用下方表格里的功能之后。Zeabur 开源版对同一项功能、同一组值每天（UTC）只发送一次；`zeaburctl ui` 和 Zeabur Desktop 每次都发送 |
| `cluster_connected` | `zeaburctl ui`、Zeabur Desktop | 用你的 kubeconfig 连上集群，或连不上时 |
| `app_change_submitted` | Zeabur 开源版 | 有人在 Zeabur 开源版的网页界面或 API 保存变更并收到回应；每次保存发一条，不管改了什么 |

| 属性 | 事件 | 值 |
|---|---|---|
| `zeabur_version` | `signed_in`、`feature_used` | Zeabur 开源版的版本，例如 `0.1.1` |
| `day` | `feature_used` | UTC 日期，例如 `2026-10-30` |
| `person` | `signed_in`、`app_change_submitted` | 32 位十六进制数字，只在同一个安装、同一天里区分不同的人 |
| `zeabur_version` | `cluster_connected` | `zeaburctl` 或 Zeabur Desktop 的版本，例如 `0.1.1` |
| `zeabur_version` | `app_change_submitted` | Zeabur 开源版的版本 |
| `mode` | `signed_in`、`feature_used`、`cluster_connected`、`app_change_submitted` | 集群里的 Zeabur 开源版是 `in-cluster`，`zeaburctl ui` 和 Zeabur Desktop 是 `local` |
| `client` | `cluster_connected`，以及 `mode` 为 `local` 的 `feature_used` | 发送事件的程序：Zeabur Desktop 是 `desktop`，`zeaburctl ui` 是 `zeaburctl`。用来统计有多少人在用 Zeabur Desktop。 |
| `result` | `cluster_connected` | `connected`、`unreachable`、`credential_refused`、`no_read_right` 或 `other` |
| `result` | `app_change_submitted` | `accepted`；没被接受时按你收到的 HTTP 状态码：`forbidden`（403）、`invalid`（422）、`conflict`（409）、`unreachable`（502、503 或 504）或 `other` |
| `feature` | `feature_used` | 下方表格里的某一个功能 |
| `source` | `service_created` 的 `feature_used` | 服务怎么创建：`git`、`upload`、`image` 或 `template` |
| `template` | `source` 为 `template` 的 `feature_used` | 模板在 Zeabur Catalog 里的 ID，例如 `wordpress`；Catalog 里没有的 ID 不会发送 |
| `component` | `component_installed` 的 `feature_used` | 组件在 Zeabur Catalog 里的 ID，例如 `logs/victoria-logs` |
| `policy` | `auto_update_enabled` 的 `feature_used` | 更新到哪些新镜像：`same_tag`、`patch`、`minor` 或 `major` |
| `kind` | `database_created`、`domain_added`、`access_limited` 或 `data_restored` 的 `feature_used` | 数据库或对象存储：`postgresql`、`mongodb`、`mysql`、`mariadb`、`dragonfly` 或 `object-storage`。域名：名称用的是 Zeabur 开源版提供给新服务的域名后缀时是 `generated`，其他是 `custom`。访问限制：`ip_allow`、`basic_auth` 或 `maintenance`。恢复：`volume` 或 `project` |
| `$process_person_profile` | 全部 | 固定为 `false`：不创建个人档案 |
| `$geoip_disable` | 全部 | 固定为 `true`：不查询所在位置 |

| `feature` | 什么时候发送 |
|---|---|
| `service_created` | 创建服务之后 |
| `database_created` | 创建数据库或对象存储之后 |
| `domain_added` | 添加域名之后 |
| `logs_viewed` | 打开日志流之后 |
| `terminal_opened` | 打开终端之后 |
| `member_invited` | 邀请成员之后 |
| `compose` | 应用 Docker Compose 导入之后 |
| `backup_enabled` | 设置或恢复备份计划之后 |
| `notifications_configured` | 添加或修改集群或项目的通知渠道之后 |
| `component_installed` | 写入组件安装的最后一步之后 |
| `github_app_connected` | 创建 GitHub App，或修改它可以为哪些项目构建之后 |
| `node_maintenance` | 让节点停止调度新的 Pod、准备维护之后 |
| `sign_in_configured` | 修改管理员账号的登录方式之后 |
| `public_port_opened` | 把服务的端口开放到互联网之后 |
| `access_limited` | 为服务开启 IP 白名单、密码或维护页面之后 |
| `auto_update_enabled` | 设置服务自动更新到新版本镜像之后 |
| `cron_job_created` | 创建定时任务之后 |
| `rollback_used` | 把服务回滚到之前的版本之后 |
| `suggestion_applied` | 应用建议的修复之后；不会发送是哪一条建议 |
| `data_restored` | 从备份恢复卷，或从集群备份恢复项目之后 |
| `trace_viewed` | 读取服务的连接路径，或要复制的服务排查资料之后 |
| `database_exported` | 数据库导出完成之后 |

事件不会说明是谁。`person` 是用密钥算出的用户名加日期的哈希值。密钥从 Zeabur 开源版的 plan key 派生，保存在集群的 Secret 里，从不发送，所以无法从哈希值反推用户名。同一个人一整天的 `person` 都一样，Zeabur 开源版重启也不变；第二天就换成另一个，所以不同天无法关联起来。

`feature_used` 没有 `person`。Zeabur 开源版发送的只表示今天用过某项功能，不说是谁、用了几次；`zeaburctl ui` 和 Zeabur Desktop 每次都发送，并带着这台电脑的随机代码，所以看得出在这台电脑上用了几次。浏览器不会发送任何东西，是 Zeabur 开源版的服务器，或你电脑上 `zeaburctl ui`、Zeabur Desktop 的本地服务，在操作成功之后发送的。

`zeaburctl ui` 和 Zeabur Desktop 没有安装代码，所以共用一个随机代码，在第一次要发送事件时才生成，关闭时不会生成。这个代码保存在配置目录里 `zeabur` 文件夹中名为 `local-id` 的文件：Linux 是 `$XDG_CONFIG_HOME` 或 `~/.config`，macOS 是 `~/Library/Application Support`，Windows 是 `%APPDATA%`。只有你能读取它，里面不含机器、kubeconfig、令牌或用户名的任何信息。

事件通过 HTTPS 发送到 PostHog（经由 `oss-nori.zeabur.com`）。事件先放在内存里排队，在后台分批发送，所以不会拖慢 Zeabur 开源版、`zeaburctl ui` 的链接或 Zeabur Desktop 的窗口。请求没有响应、被限流或遇到服务器错误时，最多再试三次；被 PostHog 拒绝的不会重试。Zeabur 开源版、`zeaburctl ui` 或 Zeabur Desktop 退出时会等几秒让排队的事件发出，之后还没发出的就不发了，因为不会保存到磁盘。PostHog 不保存 IP 地址。

## 绝不发送

域名、主机名、IP、Git URL、镜像或服务名称、项目名称、Namespace 或资源名称、邮箱、用户名、日志、凭据、kubeconfig、集群地址、错误信息，以及集群里的内容。

## 关闭

以下任何一种都有效，其中 `DO_NOT_TRACK` 优先于其他设置。

- 在 Zeabur 开源版、`zeaburctl ui` 或 Zeabur Desktop 的环境变量中设置 `DO_NOT_TRACK=1`。空值和 `0` 以外的值都算。
- 用 Helm 安装时，设置 `telemetry.enabled=false`，做法见下方命令。
- `zeaburctl ui` 运行 `zeaburctl telemetry disable`，它会在 `local-id` 所在的 `zeabur` 文件夹里的 `config.yaml` 写上 `telemetry: false`；或设置 `ZEABUR_TELEMETRY=off`。`config.yaml` 无法解析时，`zeaburctl ui` 什么都不发送。`zeaburctl telemetry status` 会显示当前生效的设置。Zeabur Desktop 启动时也读取同一个 `config.yaml` 和 `ZEABUR_TELEMETRY`。

要删掉 `zeaburctl ui` 的代码，运行 `zeaburctl telemetry reset`。下次要发送事件时，它会生成新的代码。

用 Helm 退出：

```sh
helm upgrade <release> oci://ghcr.io/zeabur-oss/charts/zeabur --reset-then-reuse-values \
  --set telemetry.enabled=false
```

如果 Argo CD 这类工具用 `helm template` 生成 chart 内容，chart 读不到之前创建的 ConfigMap，每次都会生成新的代码。请把 `telemetry.installationId` 设为自己的 UUID，例如 `uuidgen | tr 'A-Z' 'a-z'` 的结果。

## 查看会发送的内容

设置 `ZEABUR_TELEMETRY=debug`，Zeabur 开源版会打印实际的请求内容，但不会发送。内容写在日志里：

```sh
kubectl -n zeabur set env deployment/zeabur ZEABUR_TELEMETRY=debug
kubectl -n zeabur logs deployment/zeabur | grep telemetry
```

`ZEABUR_TELEMETRY=off` 的效果和 `DO_NOT_TRACK` 一样。

## 检查更新

有新版本时，Zeabur 开源版和 `zeaburctl` 会提醒你，并说明如何升级，但不会自动升级。检查更新和体验计划各自独立，默认开启。

**检查什么**。两者都读取 `https://api.github.com/repos/zeabur-oss/zeabur/releases`，跳过草稿。除非你正在用预发布版本，否则也会跳过预发布版本。其余版本中最新的那个比你的版本新时，会显示它的版本、发布说明链接和升级方法。只要有任何一个更新的正式版本在说明里有 `### Security` 小节，就会告诉你当前版本有已知的安全问题，并附上这些版本的链接。

**在哪里运行。**

- 集群页始终显示 `Zeabur v<版本>`。不管多少人打开 Zeabur 开源版，Zeabur 开源版服务器每小时最多查询 GitHub 一次。页面每次打开时读取它的结果，一直开着时每小时再读一次。服务器会保留上次的结果。访问不了 GitHub 时先沿用，一分钟后再试。GitHub 拒绝时，等 GitHub 重新计数后再试。浏览器不会访问 GitHub。“设置”›“关于”也会显示版本，点击“升级方法”会按 Zeabur 开源版的安装方式列出步骤，分为 Helm、Argo CD 和 Flux。请参阅[升级 Zeabur 开源版](../upgrade/steps.mdx)。用 `zeaburctl ui` 打开时，页面显示的是 `zeaburctl` 自己的版本和更新方法。
- `zeaburctl` 每次运行命令都会检查。检查与命令同时进行，命令结束后 `zeaburctl` 最多再等一秒。有新版本时，会在 stderr 输出一行。它不在磁盘上保存任何东西。stderr 不是终端，或设置了 `CI` 时，不会检查。
- 没有令牌时，GitHub 每小时只响应同一个 IP 地址 60 次，共用这个地址的人一起算。用完时，`zeaburctl` 会输出提示。把 GitHub 令牌设在 `GH_TOKEN` 或 `GITHUB_TOKEN`（与 `gh` 读取的变量相同），`zeaburctl` 就会带上它，改用你自己的额度。不授予任何权限的 fine-grained 令牌就够了。

**会发送什么**。一个普通的 GitHub 请求，不带任何 ID 或 Cookie。除非你为 `zeaburctl` 设置了令牌，否则也不带令牌。GitHub 会看到请求来自哪个 IP 地址。Zeabur 开源版服务器的 user agent 是 `zeabur`，`zeaburctl` 的是 `zeaburctl/<版本>`。

**关闭**。以下任意一种都有效。关闭后，Zeabur 开源版服务器完全不会访问 GitHub。

- 用 Helm 安装时，设置 `updateCheck.enabled=false`。集群页就只显示版本。
- 在 Zeabur 开源版的环境变量中设置 `DO_NOT_TRACK=1`。`zeaburctl` 则是在你自己的环境变量中设置。这也会关闭体验计划。
- 为 `zeaburctl`（包括 `zeaburctl ui`）在你的环境变量中设置 `NO_UPDATE_NOTIFIER`，任意值都可以。这只关闭检查更新。

## 模板更新

不用升级 Zeabur 开源版，也能用上更新的模板。Zeabur 开源版会读取 Zeabur Catalog 的 API，用那里的模板替换 Zeabur 开源版内置的模板。组件，以及 Zeabur 开源版如何在集群里找到它们，仍以内置的为准。已经用模板部署的服务不会变化。模板更新和体验计划、检查更新各自独立，默认开启。

**获取什么**。从 `https://oss-catalog.zeabur.com/v1/` 获取 `catalog.json`，其中列出每个模板及其文件的哈希值。哈希值与 Zeabur 开源版当前提供的不同时，才再获取该模板的 `templates/<id>.json`。

**信任什么**。Zeabur 开源版信任它获取文件的地址：会检查 HTTPS 证书的 `https://oss-catalog.zeabur.com/v1/`，或你设置的镜像站。这些文件没有签名，所以控制这个地址的人决定 Zeabur 开源版提供哪些模板。然后 Zeabur 开源版逐个检查模板：要能读取，要是 `catalog.json` 列出的那个版本，需要的组件也要是这个 Zeabur 开源版认识的。没通过的模板不会出现，原先提供的同一个模板会保留，下次获取时 Zeabur 开源版会再请求一次。获取失败时，什么都不会改变。

**什么时候运行**。有人打开模板列表时才会获取，每 6 小时最多一次，失败时 10 分钟后再试。获取的是 Zeabur 开源版服务器，浏览器不会访问。模板只保存在内存中，重启后，在下次获取前先用内置的模板。`zeaburctl ui` 不会获取。打开模板表单或规划好之后，如果模板有了新版本，Zeabur 开源版会拒绝这次变更，请重新打开表单。

**会发送什么**。普通的请求，不带任何 ID 或 Cookie。Zeabur 开源版服务器的 user agent 是 `zeabur`。托管 `oss-catalog.zeabur.com` 的 GitHub Pages 会看到请求来自哪个 IP 地址。不会发送任何关于集群或用户的数据，所以 `DO_NOT_TRACK` 不会关闭它。

**使用镜像站**。集群无法访问互联网时，按[使用镜像](../cluster/components.mdx#使用镜像)搭好 Zeabur Catalog 的镜像，再把 `catalog.url` 设为它的地址。模板和组件都从这个地址读取。Zeabur 开源版信任镜像站的方式与信任 `oss-catalog.zeabur.com` 相同。想信任某一版而不是某个服务器，请在复制前先验证它的签名，做法见 Zeabur Catalog 的[版本与 API](https://oss.zeabur.com/zh-CN/docs/catalog/reference/releases/#验证并读取版本)。

**关闭**。以下任意一种都有效。关闭后，Zeabur 开源版只提供内置的模板，也不会为模板发出任何请求。

- 用 Helm 安装时，设置 `templateFetch.enabled=false`。
- 在 Zeabur 开源版的环境变量中设置 `ZEABUR_TEMPLATE_FETCH=false`。
