将域名、组件选择和主机配置写入 YAML，运行 `zeabur-installer --config config.yaml plan`，先查看安装内容。文件默认位于 `/etc/zeabur-installer/config.yaml`。字段使用 camelCase；字段拼写错误或存在多余字段时，installer 会直接停止。

网页界面的选择也会保存到这份文件。通过网页界面安装，见[在一台服务器上安装 Zeabur](../get-started/quickstart.mdx)；通过命令安装，见[用配置文件和命令安装](../get-started/advanced-install.mdx)；各命令的选项，见 [Installer 命令](./installer.mdx)。

## 创建集群的文件

下面的示例使用自己的域名。两个 DNS 名称都要指向服务器，外部也要能访问端口 `80`，Let's Encrypt 才能完成 HTTP-01 验证。

```yaml title="/etc/zeabur-installer/config.yaml"
profile: single-node
access:
  mode: domain
  identity: login.example.com
  zeabur: zeabur.example.com
  invitations: true
zeabur: true
host:
  requireEncryptedDisk: true
```

### 顶层字段

| 字段 | 默认值 | 用途 |
|---|---|---|
| `use` | `team` | `team` 供团队使用。`personal` 改为个人使用，可用字段见[个人使用的文件](#个人使用的文件) |
| `distribution` | `k3s` | `k3s` 或 `rke2`，见[`distribution` 与版本](#distribution-与版本) |
| `access` | 必填 | 登录服务与 Zeabur 的域名和证书模式 |
| `profile` | `single-node` | `single-node` 或 `multi-node`，选择 Catalog 中对应的组件配置 |
| `enable` | `[]` | 在[默认组件](#组件选择)之外添加的 capability 或完整组件 ID |
| `disable` | `[]` | 从默认组件中排除的 capability 或完整组件 ID |
| `allowDataLoss` | `[]` | 同意移除时一并删除数据的组件 ID，例如 `replicated-storage/longhorn` |
| `zeabur` | `true` | 安装 Zeabur Identity 与 Zeabur。`false` 只安装 K3s/RKE2 与选定组件 |
| `telemetry` | `true` | 加入[体验计划](./telemetry.mdx)。`--no-telemetry` 和 `DO_NOT_TRACK=1` 可在该次运行时关闭 |
| `inputs` | `{}` | 按组件 ID 分组的普通输入值 |
| `secretFiles` | `{}` | 按组件 ID 分组的机密文件路径 |
| `k3sVersion`、`rke2Version` | installer 固定的版本 | 覆盖 K3s 或 RKE2 的版本 |
| `host` | 空 | API 证书的附加名称和磁盘加密要求 |
| `sources` | 空 | 选填，用自行准备的 Catalog、镜像和 chart 替换固定的版本 |

`zeabur: false` 只决定本次安装什么，不会移除已安装的 Zeabur。要移除，使用 [`uninstall`](./installer.mdx#uninstall)。

### `access`

| 字段 | 默认值与规则 |
|---|---|
| `mode` | 必填。`domain` 由 cert-manager 向 Let's Encrypt 申请证书（HTTP-01）。`local` 在服务器上创建私有 CA，只适合测试机 |
| `identity` | 必填。Zeabur Identity 主机名，issuer 为 `https://<identity>` |
| `zeabur` | 必填。Zeabur 主机名，必须与 `identity` 不同 |
| `invitations` | `true`。是否接受 Zeabur **成员**页面生成的配置链接。成员仅通过版本控制管理时关闭 |
| `suffixes` | 服务器有公开地址时为 `<地址>.sslip.io`，例如 `203-0-113-7.sslip.io`，否则为空。新服务的建议网址会使用这些应用域名，默认使用第一个，例如 `[apps.example.com]`。每个域名都需要一条指向服务器的通配符记录 `*.apps.example.com`，见[配置 DNS 记录](../configure/dns.mdx)。填 `[]` 表示不建议网址 |

主机名不带 `https://`、端口或路径，只能使用小写英文字母、数字、连字符和点，至少分为两段。每段最多 63 个字符，不能以连字符开头或结尾，总长度最多 253 个字符。

浏览器和服务器都要能解析这两个名称。副本通过 DNS 解析，无法读取主机 `/etc/hosts` 中的配置。`local` 模式的 CA 证书位于 `/var/lib/rancher/zeabur-installer/local-ca.crt`，将其导入用户电脑的信任存储后，浏览器才会信任这两个网址。

### 组件选择

默认会安装 Catalog 为此 profile 推荐的所有组件，外加 `builds`（Zeabur Builder 和 zot）、`image-updates`（Keel）和 `databases/cloudnative-pg`，装完就能用镜像或 Git 部署，也能创建 PostgreSQL 数据库。Zeabur Builder 用有特权的 buildkitd 构建，逃出沙箱的构建可以接触到节点；不需要时在 `disable` 中添加 `builds`。Zeabur 需要 ingress、证书和 metrics-server 才能运行。

需要运行时检测、漏洞扫描和入侵防护时，添加：

```yaml
enable: [runtime-security, vulnerability-scanning, intrusion-prevention]
```

`enable` 可以填写 capability（例如 `runtime-security`）或完整组件 ID（例如 `volume-backup/velero`），依赖的组件会一并添加。如果 `disable` 排除了其他组件依赖的组件，`plan` 会列出两者并停止。最终安装的组件、安装顺序和排除原因，见 `plan` 的输出。

installer 只提供 Catalog 在你所选 distribution 上测试过的组件（Catalog `index.json` 中的 `testedOn`）。推荐安装但未在此测试过的组件不会安装，依赖该组件的其他组件也一样。如果 `enable` 填写了未测试过的组件，或添加的组件依赖未测试过的组件，`plan` 会停止，并列出测试过的 distribution。

从列表中去掉已安装的组件后，下次 `apply` 会将其移除。如果移除组件会一并删除数据，需要先将组件写入 `allowDataLoss`，见[移除组件](./installer.mdx#卸载组件)。

```yaml
inputs:
  volume-backup/velero:
    bucket: backups
    s3-url: https://s3.example.com
```

Catalog 定义了每个组件有哪些 input 及其类型。缺少必填值时，`plan` 会指出需要补充的字段。

installer 会自动填写 Zeabur Builder 的 `cluster-ip`（zot 的固定地址）。要修改，在 `inputs` 中填写值即可。

Velero 的 `region` input 是存储桶的区域，默认 `us-east-1`。Cloudflare R2 要填 `auto`。网页界面会分别询问访问密钥 ID 和私密访问密钥，再自己生成 `credentials` 文件。

### `secretFiles`

机密输入填写文件路径，文件权限设为 `0600`：

```yaml
secretFiles:
  volume-backup/velero:
    credentials: /root/secrets/velero-credentials
```

```sh
sudo chmod 0600 /root/secrets/velero-credentials
```

文件内容按组件 input 的格式填写，installer 会用这些文件创建组件所需的机密变量。机密值放在文件中，不要写入 `inputs`。对于 Catalog 标为 `generate: random` 的机密，如果没有指定文件，首次 `apply` 时会自动生成，之后继续沿用。

### 存储类

installer 一定会创建 `local-path`，数据存放在节点的 `/var/lib/zeabur/storage`。安装 Longhorn 后，Catalog 对此 profile 的配置决定默认存储类：`multi-node` 使用 `longhorn`，`single-node` 保持 `local-path`。`plan` 会列出默认存储类和其他存储类。

- `local-path` 的卷保留在原节点上，更改默认存储类不会迁移已有数据。
- Longhorn 成为默认存储类时，installer 原先设为默认的 `local-path` 会改为普通存储类。
- 集群已有其他默认存储类时，installer 会保留原来的默认存储类。如果本次要将 Longhorn 设为默认，`apply` 会停止，需要先删除原存储类的默认注解，再重新运行。

选择 Longhorn 后，`apply` 会在这台主机上安装 iSCSI initiator 和 NFS client、加载 `iscsi_tcp`、启动 `iscsid`。每个运行 Longhorn 的节点都需要这些，见[加入节点](../cluster/nodes.mdx)。

### `distribution` 与版本

不填写 `distribution` 就安装 K3s。服务器有 8 GiB 及以上内存，或以后想用三台服务器运行控制平面，就设为 `rke2`。

| 字段 | 默认值与用途 |
|---|---|
| `distribution` | `k3s`。K3s 更省内存，只运行一台服务器，可以再加工作节点。`rke2` 可以加工作节点和服务器，有三台服务器时坏一台控制平面也不会停 |
| `k3sVersion` | installer 固定的版本。要更换 K3s 版本时填写，例如 `v1.37.1+k3s1`。只能搭配 `distribution: k3s` |
| `rke2Version` | installer 固定的版本。要更换 RKE2 版本时填写，例如 `v1.37.1+rke2r1`。只能搭配 `distribution: rke2` |

填写了另一种的版本字段，installer 会停止，例如：`rke2Version applies to distribution: rke2; this one is k3s (set k3sVersion)`。

默认版本的文件使用编译进 installer 的 digest 验证。改用其他版本时，只能使用该 release 页面提供的 checksum 列表验证，`plan` 会将其标为不受支持的版本，也可能与 Catalog 测试过的 Kubernetes 版本不一致。

### `host`

| 字段 | 默认值与用途 |
|---|---|
| `host.tlsSan` | `[]`。Kubernetes API server 证书中额外添加的 DNS 名称或 IP 地址，仅用于 server |
| `host.requireEncryptedDisk` | `false`。设为 `true` 时，如果根目录或数据目录不在加密设备上，`apply` 就会停止 |
| `host.nodeName` | 主机名转为小写。主机名不能用作节点名称，或由 IP 地址组成（例如 `ip-10-0-0-5`）时，改用 `node-3f9a2c` 这类名称。installer 会将这个名称写入 K3s 或 RKE2 的配置，以后主机名改了，节点名称也不会跟着改变。只能使用小写字母、数字、`-` 和 `.` |

节点装好后会一直使用当初的名称。再次运行 `apply` 会沿用原来的名称；如果 `host.nodeName` 填了其他名称，`apply` 会停止，因为 Kubernetes 会把新名称当成同一地址上的第二个节点。

### `sources`

正式发行的 installer 不需要 `sources`，installer 已经固定了 Zeabur Catalog、Zeabur Identity 和 Zeabur 的版本，下载到 `/var/lib/rancher/zeabur-installer/downloads`，并使用编译进 installer 的 SHA-256 校验。

`sources` 用于改装自行构建的版本，通常用于开发测试。只填写需要替换的字段，其他字段继续使用固定的版本。自行编译的开发版 installer 没有固定任何版本，因此必须填写 `catalog`、`identityImage`、`identityctl`、`zeaburImage` 和 `zeaburChart`，`plan` 会列出缺少的字段。将路径替换为实际准备好的文件：

```yaml
sources:
  catalog: /root/releases/catalog/index.json
  identityImage: registry.example.com/identity@sha256:<digest>
  identityctl: /root/releases/zeabur-identityctl
  zeaburImage: registry.example.com/zeabur@sha256:<digest>
  proxyImage: registry.example.com/proxy@sha256:<digest>
  zeaburChart: /root/releases/zeabur-chart
```

| 字段 | 接受的内容 |
|---|---|
| `catalog` | 本地 `index.json` |
| `imageArchives` | `docker save` 生成的归档文件路径数组，K3s 或 RKE2 启动时导入 |
| `identityImage` | Zeabur Identity 镜像引用 |
| `identityctl` | 本地 `zeabur-identityctl` 可执行文件 |
| `zeaburImage` | Zeabur 镜像引用 |
| `proxyImage` | Zeabur Proxy 镜像引用。可不写，不写就用 chart 自带的镜像 |
| `zeaburChart` | Helm chart 目录或打包好的 `.tgz` |

从 `imageArchives` 中去掉的文件，下次 `apply` 时也会从 K3s 或 RKE2 的导入目录中移除。这份列表填写的是主机上已有的归档文件，与私有 registry 的访问配置无关。

## 个人使用的文件

顶层填写 `use: personal` 时，installer 改为安装 KubeSolo 和组件，不安装 Zeabur 面板和 Zeabur Identity。操作方法和限制见[个人使用：在小型机器上安装](../get-started/personal.mdx)。

```yaml title="/etc/zeabur-installer/config.yaml"
use: personal
enable: [builds]
host:
  tlsSan: [solo.example.com]
```

同一份文件只能再添加下表中的字段，不接受 `profile`、`access`、`zeabur`、`distribution`、`k3sVersion`、`rke2Version` 和 `join`。

| 字段 | 默认值与用途 |
|---|---|
| `enable` | `[]`。默认安装 Catalog 推荐 `single-node` 使用、且在 KubeSolo 上测试过的组件，例如 Ingress 和证书。可以再添加 Catalog 在 KubeSolo 上测试过的组件，例如 `builds`（Zeabur Builder，会一并安装 zot，内存需要 1800 MiB 以上）和 `databases`。其他组件会让 `plan` 停止，并列出测试过的 distribution |
| `disable` | `[]`。排除 capability 或完整组件 ID |
| `allowDataLoss` | `[]`。与创建集群的文件相同 |
| `inputs` | `{}`。与创建集群的文件相同，按组件 ID 分组 |
| `secretFiles` | `{}`。与创建集群的文件相同，文件权限必须为 `0600` |
| `host.tlsSan` | `[]`。自己的电脑使用其他地址或域名连接 API 时，将地址或域名添加到这里 |
| `host.requireEncryptedDisk` | `false`。设为 `true` 时，如果 `/var/lib/kubesolo` 不在加密设备上，`apply` 就会停止 |
| `host.nodeName` | 与创建集群时相同，写入 KubeSolo 的配置 |
| `sources.catalog` | 选填。本地 Catalog `index.json`，替换固定的版本 |

组件安装在 KubeSolo 内置的 `local-path` 存储类上，数据存放在 `/var/lib/kubesolo` 下。KubeSolo、helm-controller 和 kubectl 的版本由 installer 固定，没有可修改的字段。

## 加入已有集群的文件

顶层包含 `join` 时，installer 会将这台机器视为要加入集群的新节点，只安装 K3s 或 RKE2。同一份文件只能再添加 `distribution`、对应的版本字段（`k3sVersion` 或 `rke2Version`）、`host` 和 `sources.imageArchives`，不能添加 `profile`、`access` 等创建集群的字段。

在已有 server 上运行 `zeabur-installer node add`，获取完整 YAML，保存到新主机。文件已包含令牌和 server 配置，不需要自行拼装。

| 字段 | 默认值与规则 |
|---|---|
| `distribution` | `k3s`。集群使用的类型，按 `node add` 输出的填写 |
| `join.server` | 必填。server 的地址：K3s 用 `6443`，例如 `https://10.0.0.5:6443`；RKE2 用 `9345` |
| `join.role` | `worker`。`server` 只能用于 RKE2 |
| `join.token` | 与 `tokenFile` 二选一。直接填写令牌时，配置文件权限必须为 `0600` |
| `join.tokenFile` | 与 `token` 二选一。权限为 `0600` 的令牌文件 |
| `join.serverConfig` | `server` 必填，worker 不接受。原样复制 `node add --role server` 输出的 `disable` 和 `identity` |
| `join.longhorn` | `false`。设为 `true` 时，在 K3s 或 RKE2 启动前安装好 Longhorn 所需的主机软件包 |
| `join.nodeNames` | `[]`。集群中已有的节点名称，与 `node add` 打印的内容一致。新主机的名称已被使用时，节点会改用 `node-3f9a2c` 这类名称 |

`host.nodeName` 的用法与创建集群时相同，但不能与 `join.nodeNames` 中的名称重复。worker 不接受 `host.tlsSan`。`distribution` 和版本必须与集群一致。worker 的 bootstrap token 不能用于加入 server，需要使用 `node add --role server` 生成的配置。

## 配置无法使用时

- unknown field：检查字段大小写，删除拼写错误或层级错误的 key。
- 主机名无效：去掉 `https://` 和路径，`identity` 和 `zeabur` 必须使用不同名称。
- 缺少必填 input：根据 `plan` 列出的组件和字段补充，再运行一次 `plan`。
- K3s 设置了 `join.role: server`：K3s 只运行一台使用 SQLite 的服务器，只接受工作节点。要让控制平面在少一台服务器时继续运行，改为在三台服务器上安装 RKE2（`distribution: rke2`）。
- `host.nodeName: this host is already node …`：这台主机之前用其他名称安装过。删除 `host.nodeName`，或改为消息中的名称。
- 令牌文件权限不正确：在新主机上运行 `chmod 0600`。不要将包含令牌的配置文件放入 Git 仓库。

修改配置文件后先运行 `plan`。要移除产品、清理主机文件，见[移除 Zeabur](../leave/uninstall.mdx)。
