脚本或 CI 无需你登录，也能用 API 令牌操作项目。在项目的**设置** → **API 令牌**中创建一个，授予它**开发者**或**查看者**角色，然后复制令牌。令牌和 kubectl 一样直接调用 kube-apiserver，能做什么由 Kubernetes RBAC 决定。每个令牌都会到期。

## 开始前

- 你能在这个项目中创建 API 令牌。开发者可以，查看者不行。令牌只能获得你在这个项目中也有的角色，见[权限](./permissions.mdx)。
- 使用令牌的机器能访问 kube-apiserver 的 TCP 6443。

## 创建令牌

1. 打开项目的**设置** → **API 令牌**，点击**创建令牌**。
2. 按用途命名，例如 `github-actions`。选择角色和有效期，点击**检查**。
3. 确认变更后应用。
4. 复制令牌。Zeabur 只显示这一次。对话框中还有 kubeconfig 和集群的 CA 证书。

列表会显示每个令牌的角色、创建者和到期时间。集群通过 `--service-account-max-token-expiration` 限制令牌有效期时，kube-apiserver 会缩短令牌的有效期，列表显示的是实际到期时间。

管理员还可以勾选**每个 Namespace**，角色会应用到集群中的每个 Namespace，而不只是这个项目。

## 连接

每个请求需要三样东西：API 地址、CA 证书和令牌。

**地址**：kube-apiserver 监听每个 server 节点的 TCP 6443，例如 `https://203.0.113.10:6443`。你平时使用 kubectl 的 kubeconfig 中，`server` 一行就是这个地址。如果要通过域名或其他地址访问 API，把它添加到 [`host.tlsSan`](./installer-configuration.mdx)，证书才会包含它。

**CA 证书**：创建或续期令牌后，对话框中会显示。也可以从项目的 `kube-root-ca.crt` 配置文件读取：

```sh
kubectl -n shop get configmap kube-root-ca.crt -o jsonpath='{.data.ca\.crt}' > ca.crt
```

**kubeconfig**：复制对话框中的 kubeconfig，填写 `server` 后保存，例如保存为 `shop-ci.yaml`。CA 证书已经写在 `certificate-authority-data` 中。

```sh
export KUBECONFIG=$PWD/shop-ci.yaml
kubectl auth whoami
```

`kubectl auth whoami` 会显示 `system:serviceaccount:shop:github-actions`，kube-apiserver 记录这个令牌的请求时使用的就是这个名称。

使用 curl 时，先设置地址和令牌：

```sh
APISERVER=https://203.0.113.10:6443
TOKEN='<令牌>'
```

## 常用操作

以下以项目 `shop`、服务 `web` 为例。从镜像或 Git 部署的服务是 Deployment，容器名称与服务名称相同。**查看者**令牌只能列出服务，其他操作都需要**开发者**。

| 操作 | Method 和路径 |
|---|---|
| 列出服务 | `GET /apis/apps/v1/namespaces/shop/deployments` |
| 读取日志 | `GET /api/v1/namespaces/shop/pods/<副本>/log` |
| 重启 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web` |
| 更换镜像 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web` |
| 设置变量 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web` |
| 重新构建 | `PATCH /apis/builder.zeabur.com/v1alpha1/namespaces/shop/builds/web` |
| 调整副本数 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web/scale` |

### 列出服务

```sh
kubectl get deployments -l app.kubernetes.io/name
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments?labelSelector=app.kubernetes.io/name"
```

数据库和带卷的服务可能是 StatefulSet，路径为 `/apis/apps/v1/namespaces/shop/statefulsets`。

### 读取日志

```sh
kubectl logs -l app.kubernetes.io/name=web --tail=100
```

curl 一次读取一个副本。先查询副本名称，再读取其中一个：

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" \
  "$APISERVER/api/v1/namespaces/shop/pods?labelSelector=app.kubernetes.io/name%3Dweb"
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" \
  "$APISERVER/api/v1/namespaces/shop/pods/<副本>/log?container=web&tailLines=100"
```

### 重启

和 Zeabur 的**重启**一样，将 Pod template 的 annotation `kubectl.kubernetes.io/restartedAt` 设为当前时间。

```sh
kubectl rollout restart deployment/web
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/strategic-merge-patch+json" \
  -d "{\"spec\":{\"template\":{\"metadata\":{\"annotations\":{\"kubectl.kubernetes.io/restartedAt\":\"$(date -u +%Y-%m-%dT%H:%M:%SZ)\"}}}}}" \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web"
```

### 更换镜像

从 Git 构建的服务请改用重新构建，构建完成后 Keel 会换上新镜像。

```sh
kubectl set image deployment/web web=ghcr.io/acme/web:1.5
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/strategic-merge-patch+json" \
  -d '{"spec":{"template":{"spec":{"containers":[{"name":"web","image":"ghcr.io/acme/web:1.5"}]}}}}' \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web"
```

### 设置变量

修改的是服务**变量**标签页中**直接设置**的变量，新副本启动时会使用新值。

```sh
kubectl set env deployment/web -c web LOG_LEVEL=debug
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/strategic-merge-patch+json" \
  -d '{"spec":{"template":{"spec":{"containers":[{"name":"web","env":[{"name":"LOG_LEVEL","value":"debug"}]}]}}}}' \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web"
```

### 重新构建

和 Zeabur 的**重新构建**一样，在 Build 上设置 `builder.zeabur.com/rebuild` annotation，Zeabur Builder 会使用分支最新的提交构建。

```sh
kubectl annotate build web --overwrite builder.zeabur.com/rebuild="$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/merge-patch+json" \
  -d "{\"metadata\":{\"annotations\":{\"builder.zeabur.com/rebuild\":\"$(date -u +%Y-%m-%dT%H:%M:%SZ)\"}}}" \
  "$APISERVER/apis/builder.zeabur.com/v1alpha1/namespaces/shop/builds/web"
```

### 调整副本数

```sh
kubectl scale deployment/web --replicas=2
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/merge-patch+json" \
  -d '{"spec":{"replicas":2}}' \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web/scale"
```

## 续期和删除

点击令牌旁的**续期**，会获得同一名称、同一角色的新令牌。之前签发的令牌在到期前仍然有效。

要立即停用令牌，在它旁边选择**更多** → **删除**。为它签发的每个令牌都会失效，请求会收到 `401 Unauthorized`。

创建令牌的人离开项目后，令牌在到期或被删除前仍然有效。有人离开时，查看列表中每个令牌的创建者，删除他创建的令牌。

## Zeabur 会创建什么

Zeabur 用你自己的权限写入以下对象：

| 对象 | 内容 |
|---|---|
| 项目中的 `ServiceAccount <名称>` | 标签 `zeabur.com/api-token: "true"` 和 `app.kubernetes.io/managed-by: zeabur`。annotation 记录角色、创建者和最新令牌的到期时间 |
| 项目中的 `RoleBinding zeabur-api-token-<名称>` | 将 `zeabur-project-developer` 或 `zeabur-project-viewer` 绑定到这个 ServiceAccount |
| `ClusterRoleBinding zeabur-api-token:<项目>:<名称>` | 用于每个 Namespace 的令牌，代替 RoleBinding |

令牌本身由 ServiceAccount 的 TokenRequest 签发，Zeabur 不会将它保存到 Secret 或其他地方。删除令牌会删除 binding 和 ServiceAccount。

chart 中的三个准入策略确保这些对象只用于 API 令牌，见 [API 令牌和 RBAC](./permissions.mdx#api-令牌和-rbac)。
