---
title: 自動更新映像檔
description: 讓 Keel 把用映像檔部署的服務（例如 Redis 或 PostgreSQL）自動換成新版本。
---

從映像檔部署的服務，可以讓 Keel 自動換上新版本：你設定允許更新的版本範圍，以及每小時、每天或每週什麼時候檢查。每次更新都會重新啟動服務。

## 開始之前

- 叢集裝了 Keel 元件。還沒安裝時，**自動更新**區段會顯示安裝按鈕，裝好後再回到服務的**設定**。
- 服務是 Deployment、StatefulSet 或 DaemonSet，映像檔用標籤，例如 `7.2.4`、`8`、`1.27` 或 `latest`，不是摘要（digest）。從 Git 或上傳資料夾建置的服務，改用**建置**分頁的**新建置完成後自動部署**。
- 從**新增** → **資料庫**建立的 PostgreSQL 資料庫使用 CloudNativePG 與下方的 [Zeabur 資料庫更新程式](#cloudnativepg-資料庫)。其他 operator 管理的資料庫尚不支援自動更新。

<Steps>
<Step>

### 打開自動更新

到服務的**設定**，往下捲到**自動更新**，或按上方的**自動更新**直接跳過去。

</Step>
<Step>

### 選擇要更新哪些版本

展開**更新哪些版本**選單，選一項：

| 選項 | `7.2.4` 會升到 |
| --- | --- |
| **只更新修補版本** | `7.2.5`、`7.2.6`……，不會自動升到 `7.3` |
| **修補版本和次要版本** | `7.3`、`7.4`……，不會自動升到 `8` |
| **所有新版本** | 任何較新的版本，包括 `8` |
| **同一個標籤的新映像檔** | 版本號碼不變，同一個標籤推送了新映像檔就換上 |

選好後，選單下方會寫出這個服務會升到哪裡。

Redis 建議選**只更新修補版本**。PostgreSQL 的版本號碼只有兩段，`16.4` 到 `16.5` 在 Keel 看來是次要版本，所以 `postgres:16.4` 要選**修補版本和次要版本**，才會升到 `16.x` 的新版，`17` 仍會等你決定。PostgreSQL 換主要版本要先備份，再用 `pg_upgrade` 或匯出匯入搬資料，Keel 不會替你做這件事。

標籤寫成 `8` 時，Keel 把它當成 `8.0.0`，第一次更新後標籤會變成完整的版本號碼，例如 `8.0.5`。

</Step>
<Step>

### 選擇什麼時候更新

在**什麼時候更新**選：

- **一有新版就更新**：Keel 每小時檢查一次。
- **每天**：再選**時間**。
- **每週一次**：再選**星期**和**時間**。

星期和時間依你瀏覽器的時區選，下方會寫出換算後的 UTC 時間。例如在冬季的 Europe/Amsterdam 時區選星期日 03:00，就是星期日 02:00（UTC）。

![postgres:18 服務的自動更新：修補版本和次要版本、每週一次、星期日、03:00，下方寫出換算後的 UTC 時間](../images/shots/image-updates.avif)

Zeabur 開源版存的是 UTC 時間，不會跟著夏令時間調整。上面的例子到了夏季，Keel 會在阿姆斯特丹時間 04:00 檢查。之後只改**更新哪些版本**，時間會維持原本存的 UTC 時間。要跟著換季調整，重新選一次時間再儲存。

</Step>
<Step>

### 儲存並套用

按**儲存**，會出現變更確認畫面。確認內容後，再按一次**儲存**套用。

![檢查畫面寫著 db 會自動更新到新的修補版本和次要版本，每週日 03:00（UTC）檢查，每次更新都會重新啟動服務](../images/shots/image-updates-review.avif)

套用後，**自動更新**區段顯示目前的設定，你再修改之前，**儲存**按鈕會是灰色。

Keel 到了時間就檢查有沒有符合的新版本，有就換上，服務會重新啟動。更新過的版本會出現在服務的**部署紀錄**。

</Step>
</Steps>

## 關閉自動更新

在**更新哪些版本**選**關閉**，按**儲存**。變更確認畫面會列出 Zeabur 開源版要從服務移除的 Keel 設定：`keel.sh/policy`、`keel.sh/trigger` 和 `keel.sh/pollSchedule`，選了**同一個標籤的新映像檔**的服務還有 `keel.sh/match-tag`。按**關閉**套用，服務會繼續使用目前的映像檔。

![檢查畫面寫著 db 不再自動更新，並列出會移除的 keel.sh/policy、keel.sh/pollSchedule 和 keel.sh/trigger](../images/shots/image-updates-off-review.avif)

## 固定在摘要（digest）的映像檔

映像檔寫成 `redis@sha256:…` 時，服務固定使用這個摘要對應的映像檔，Keel 不會換成其他版本。**自動更新**區段只會顯示提示，沒有表單。

要自動更新，先把映像檔改回標籤，例如 `redis:7.2.4`。已經開了自動更新的服務改用摘要後，區段仍會顯示表單，你還是可以關閉。

## 更新失敗時

Keel 更新後不會等服務恢復健康，也還不會自動回滾（[#1014](https://github.com/zeabur-oss/zeabur/issues/1014)）。

- **讓舊版本繼續服務**：到**設定** → **健康檢查**設定**就緒檢查**，例如 Redis 設成 **TCP**、連接埠 `6379`。沒有磁碟區的 Deployment 會逐步替換副本：新副本沒通過就緒檢查時，舊副本會繼續服務，服務顯示**部署卡住**。有磁碟區的 Deployment 和只有一個副本的 StatefulSet 會先停掉舊副本，新映像檔通過檢查之前，服務都無法使用。
- **回到舊版本**：先把自動更新**關閉**，再到**部署紀錄**按**回滾**。沒有關閉時，Keel 下次檢查又會換上同一個新版本。StatefulSet 還要刪除卡在新映像檔的 Pod，例如 `kubectl -n demo delete pod db-0`，Kubernetes 才會用舊映像檔重新啟動它。
- **失敗時通知**：到專案的**設定** → **通知**按**新增管道**，送到選 **Webhook**、Slack 或其他位置，事件勾**部署失敗**。這對 Deployment 有效；StatefulSet 和 DaemonSet 的部署通知排在 [#1015](https://github.com/zeabur-oss/zeabur/issues/1015)。

## CloudNativePG 資料庫

資料庫的**設定**沿用服務表單的**更新哪些版本**與**什麼時候更新**欄位。選擇**同一個標籤的新映像檔**並設定排程，再按**檢查變更**與**儲存**。關閉時會移除相同的四個 Keel 註解。儲存排程不會變更資料庫的映像檔、儲存空間或備份設定。

管理員須在 Zeabur Helm chart 啟用 `databaseUpdater.enabled`。資料庫更新程式使用 Zeabur 的映像檔和獨立權限。**設定**會顯示更新程式是否就緒。就緒時可以設定排程，無法使用時仍可**關閉**既有的自動更新。

請使用明確的主版本標籤，例如 `ghcr.io/cloudnative-pg/postgresql:18-standard-trixie`。更新程式依各資料庫的排程檢查此標籤，將新摘要寫入 `spec.imageName`，再由 CloudNativePG 逐一更新執行個體。`18-standard-trixie@sha256:…` 會保留標籤並更新摘要。映像檔儲存庫與標籤維持不變，因此更新程式不會選取其他 PostgreSQL 主版本或映像檔類型；發布者也須確保該標籤維持在指定的主版本。固定日期的標籤只有在發布者替換其內容時才會更新。

只有摘要的參照、`latest` 與設定了 `spec.imageCatalogRef` 的 Cluster 不適用；映像檔目錄的更新由其擁有者管理。更新程式會略過狀態不正常的資料庫，並在寫入前檢查映像檔的平台相容性。排程決定何時開始檢查，不限制更新必須在何時完成。更新程式不會自動回滾，請在更新後檢查資料庫狀態。上方服務的部署紀錄與失敗通知行為不適用於 Cluster。

## 用 kubectl 做同樣的事

Keel 只看工作負載上的 annotation。以下以專案 `demo`、Deployment `redis` 為例，每週日 03:00 UTC 只更新修補版本：

```sh
kubectl -n demo annotate deployment redis \
  keel.sh/policy=patch keel.sh/trigger=poll keel.sh/pollSchedule="0 0 3 * * 0"
```

`pollSchedule` 有 6 個欄位，第一個是秒。**自動更新**區段會讀出這些設定，顯示成**只更新修補版本**、**每週一次**。關閉時移除這些 annotation：

```sh
kubectl -n demo annotate deployment redis keel.sh/policy- keel.sh/trigger- keel.sh/pollSchedule-
```
