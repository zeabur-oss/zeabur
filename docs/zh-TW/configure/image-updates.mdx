---
title: 自動更新映像檔
description: 讓 Keel 把服務換成映像檔的新版本、選擇檢查時間、關閉自動更新，以及更新失敗時怎麼處理。
---

用登錄檔映像檔的服務（例如 PostgreSQL 或 Redis），可以在映像檔有新版本時自動換上去。到服務的**設定** → **自動更新**，選好要更新哪些版本、Keel 什麼時候檢查，再儲存。每次更新都會重新啟動服務。

## 開始前

- 你需要專案裡修改服務的權限。
- 叢集要有 Keel 元件。缺少時，這一區會提示並提供安裝。
- Deployment、StatefulSet 和 DaemonSet 才有這一區，Job 和排程工作沒有。從 Git 或上傳資料夾建置的服務，改用**建置**分頁的**新建置完成後自動部署**（見[重新啟動、回滾與暫停服務](./restart-rollback.mdx#自動部署新的建置)）。
- 從專案的**新增** → **資料庫**建立的資料庫沒有這一區，資料庫和映像檔都由各自的 operator 管理。
- Helm、Argo CD 或 Flux 管理的服務會顯示這一區，但不能在這裡修改，請到那個工具設定 annotation。

## 開啟自動更新

<Steps>
<Step>

### 選擇更新哪些版本

到服務的**設定** → **自動更新**，在**更新哪些版本**選一項：

| 選項 | `redis:7.2.4` 會換成 | `postgres:16.4` 會換成 |
| --- | --- | --- |
| **只更新修補版本** | `7.2.5`、`7.2.6`……，不會到 `7.3.0` | 不會更新，Keel 把 `16.5` 當成次要版本 |
| **修補版本和次要版本** | `7.3.0`、`7.4.1`……，不會到 `8.0.0` | `16.5`、`16.6`……，不會到 `17.0` |
| **所有新版本** | 所有更新的版本，包括 `8.0.0` | 所有更新的版本，包括 `17.0` |
| **同一個標籤的新映像檔** | 以 `7.2.4` 重新推送的映像檔 | 以 `16.4` 重新推送的映像檔 |

清單下方會寫出這個服務會換到哪些版本。換主要版本可能要搬移資料，像 PostgreSQL 換主要版本就要先備份再升級，所以資料庫建議選**修補版本和次要版本**，主要版本不會改變。PostgreSQL 的標籤如果只有兩段數字（例如 `16.4`），不要選**只更新修補版本**，否則永遠不會更新。

依版本更新的選項需要版本號碼標籤：一到三段數字，例如 `8`、`1.27`、`7.2.4`，或是 `latest`。Keel 把 `8` 當成 `8.0.0`，更新後標籤會變成完整的版本號碼，例如 `8.0.2`。`latest` 會先換成最新的版本號碼標籤。標籤含有其他文字時（例如 `1.30-alpine`），只能選**同一個標籤的新映像檔**。服務有多個容器時，每個容器都要用版本號碼標籤。

</Step>
<Step>

### 選擇什麼時候更新

在**什麼時候更新**選一項：

- **一有新版就更新**：Keel 每小時檢查一次。
- **每天**，再選時間。
- **每週一次**，再選星期和時間。

![db 的自動更新：postgres:18 選修補版本和次要版本，每週日 03:00 檢查，下方寫出換算後的 UTC 時間](../images/shots/image-updates.avif)

時間依瀏覽器的時區選，下方會寫出換算後的 UTC 時間。Zeabur 開源版存的是 UTC 時間，所以整年都不會改變：

- 你所在的地方開始或結束日光節約時間後，Keel 仍在同一個 UTC 時間檢查，換成你的時鐘就早或晚一小時，表單也會改顯示新的當地時間。
- 只改**更新哪些版本**，存好的 UTC 時間不會改變。改了**什麼時候更新**、星期或時間，就會依你現在的時鐘重新換算 UTC 時間。
- 在差半小時的時區（例如印度），時間會是 `:30` 結尾，換成 UTC 剛好是整點。

</Step>
<Step>

### 儲存並檢查變更

按**儲存**。檢查畫面會寫出服務要換到哪些版本、Keel 什麼時候檢查，並列出要加到工作負載上的 annotation：`keel.sh/policy`、`keel.sh/trigger: poll` 和 `keel.sh/pollSchedule`。選**同一個標籤的新映像檔**時，還會加上 `keel.sh/match-tag`。在檢查畫面按**儲存**套用。

![db 的檢查畫面：會更新到修補版本和次要版本，每週日 03:00（UTC）檢查，並列出要加上的 Keel annotation](../images/shots/image-updates-review.avif)

</Step>
</Steps>

## 關閉自動更新

在**自動更新**把**更新哪些版本**改成**關閉**，按**儲存**。檢查畫面會寫出服務不再自動更新，並移除 `keel.sh/policy`、`keel.sh/trigger`、`keel.sh/pollSchedule` 和 `keel.sh/match-tag`。按**關閉**套用。服務會繼續使用現在的映像檔。

![db 的檢查畫面：不再自動更新，並移除四個 Keel annotation](../images/shots/image-updates-off-review.avif)

Keel 若是在 Zeabur 開源版以外設定的（例如用 kubectl），清單會顯示**Zeabur 以外的設定**和使用的規則，選**關閉**或其他選項就會取代。

## 固定在摘要（digest）的映像檔

用摘要指定的映像檔（例如 `redis@sha256:…`）內容永遠不會改變，所以這一區只顯示說明，沒有選項。要自動更新，到**設定**把上方的切換從**設定**換到 **YAML**，按**編輯**，把容器的 `image` 改成標籤，檢查並套用後，再開啟自動更新。

原本已開啟自動更新、之後才改成摘要的服務，仍會顯示表單，可以關閉自動更新。

## 更新失敗時

Keel 換好映像檔就結束，不會等新副本就緒，失敗時也不會回滾（[#1014](https://github.com/zeabur-oss/zeabur/issues/1014)）。

- 設定了[就緒檢查](./service-settings.mdx)的 Deployment，新副本沒通過檢查時，舊副本會繼續接收流量，服務顯示**部署卡住**。
- StatefulSet 一次替換一個副本，所以只有一個副本的 StatefulSet（例如 Redis）要等新副本就緒才會恢復服務。

處理步驟：

1. 先關閉自動更新。不關的話，Keel 下次檢查又會換成同一個版本。
2. 在**概覽**的**部署進度**或**部署紀錄**回滾（見[重新啟動、回滾與暫停服務](./restart-rollback.mdx#回滾到之前的版本)）。
3. 修好問題後，再開啟自動更新。

要收到更新失敗的通知，到專案的**設定** → **通知**新增管道，選**部署失敗**事件（見[通知](../cluster/notifications.mdx)）。這個事件目前只涵蓋 Deployment，StatefulSet 和 DaemonSet 還不會發出（[#1015](https://github.com/zeabur-oss/zeabur/issues/1015)）。

## 用 kubectl 做同樣的事

下面的範例用專案 `demo` 和 StatefulSet `db`。排程的第一欄是秒，時間是 UTC：`0 0 3 * * 0` 是每週日 03:00（UTC）。

| Zeabur 開源版操作 | kubectl |
| --- | --- |
| **修補版本和次要版本**、**每週一次**週日 03:00 UTC | `kubectl -n demo annotate statefulset db keel.sh/policy=minor keel.sh/trigger=poll keel.sh/pollSchedule="0 0 3 * * 0"` |
| **只更新修補版本**、**一有新版就更新** | `kubectl -n demo annotate --overwrite statefulset db keel.sh/policy=patch keel.sh/trigger=poll keel.sh/pollSchedule=@hourly` |
| **同一個標籤的新映像檔**、**每天** 03:00 UTC | `kubectl -n demo annotate --overwrite statefulset db keel.sh/policy=force keel.sh/match-tag=true keel.sh/trigger=poll keel.sh/pollSchedule="0 0 3 * * *"` |
| **關閉** | `kubectl -n demo annotate statefulset db keel.sh/policy- keel.sh/trigger- keel.sh/pollSchedule- keel.sh/match-tag-` |

檢視服務現在的設定：

```sh
kubectl -n demo get statefulset db -o jsonpath='{.metadata.annotations}'
```

## 遇到問題

| 畫面或結果 | 接著處理 |
| --- | --- |
| 沒有**自動更新**這一區 | 服務是從原始碼建置的、是 Job 或排程工作，或是從**新增** → **資料庫**建立的資料庫。 |
| 只能選**同一個標籤的新映像檔** | 標籤不是版本號碼，例如 `1.30-alpine`。改成 `1.30` 這類版本號碼標籤。 |
| 顯示映像檔固定在某個摘要 | 把映像檔改成標籤。 |
| 這一區提示缺少 Keel | 在這一區或**叢集** → **元件**安裝 Keel 元件。 |
| PostgreSQL 服務一直沒有更新 | 標籤只有兩段數字（例如 `16.4`），又選了**只更新修補版本**。改選**修補版本和次要版本**。 |
| 更新後服務顯示**部署卡住** | 先關閉自動更新再回滾，見[更新失敗時](#更新失敗時)。 |
