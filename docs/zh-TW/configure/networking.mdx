服務的**網路**分頁管三件事：**連線位址**列出用戶端連到這個服務的位址，包括叢集內的位址，以及部分 Service 類型在叢集外的位址；**開放連接埠**讓叢集外的用戶端不經網域直接連進來；**連線規則**決定哪些服務能連進來、這個服務能連到哪裡。公開網域和 HTTPS 見[加上公開網域與 HTTPS](./domains.mdx)。

![web 服務的網路分頁，列出公開網域與連線位址](../images/shots/service-networking.avif)

## 開始前

- 有權修改專案裡的服務。由 Helm、Argo CD 或 Flux 管理的服務不能從這裡開放連接埠或加規則，要回到那個工具修改。
- 連線規則要靠叢集的網路外掛（CNI）執行。K3s 內建的控制器支援，外掛不支援時規則建得起來，但不會擋任何連線。
- 開放連接埠要有負載平衡器，例如 K3s 內建的 ServiceLB。

## 用私有位址連到其他服務

**連線位址**的每張卡片是一個 Kubernetes Service，標出它的類型，例如 `ClusterIP`。每個連接埠下，**本專案**是短位址，例如 `web:8080`。同專案的服務直接用這個位址連線，例如 `http://web:8080`。

從其他專案連線時，用**同叢集的其他專案**後面的完整位址，例如 `web.demo.svc.cluster.local:8080`。專案開啟**隔離**時，對方專案要先在專案**設定**的**網路**加進**允許其他專案連入**，見[隔離其他專案](./projects.mdx#隔離其他專案)。

這些位址只在叢集裡有效，網際網路連不到。

### 節點連接埠與負載平衡器

`NodePort` 或 `LoadBalancer` 類型的 Service 也會在叢集外開放連接埠，卡片會標**對網際網路開放**，資料庫則標**資料庫對外開放**，這些卡片排在最前面。用 YAML 或其他工具建立的 Service 也一樣。

- **節點**列出每個節點的位址加上節點連接埠，例如 `198.51.100.5:31379`。位址用節點的外部 IP，沒有時用內部 IP。Zeabur 開源版讀不到節點時，會說明節點讀不到，只顯示**節點連接埠 31379**。
- **負載平衡器**列出負載平衡器給這個 Service 的每個位址，加上 Service 的連接埠。

節點連接埠預設在 30000 到 32767 之間，Service 沒指定時由叢集挑選。要透過節點連線，節點的防火牆必須放行這個連接埠。

### 服務沒有私有位址時

只會主動往外連的背景服務不需要私有位址。要讓其他服務或公開網域連進來，填上應用程式監聽的連接埠，按**新增私有位址**。就緒檢查或容器有宣告連接埠時，會先幫你填好。勾選**同時加上公開網域**，位址建好後會接著新增網域。

Zeabur 開源版會像 `kubectl expose` 一樣，建立和服務同名的 ClusterIP Service：用服務的 `matchLabels` 挑選副本，並帶上容器宣告的每個連接埠。服務還用 `matchExpressions` 挑選副本時，Service 沒辦法照抄，就不能這樣新增。

想自己執行的話，打開**改用 kubectl**。只有一個連接埠的 Deployment 會是 `kubectl expose` 指令，例如：

```sh
kubectl -n demo expose deployment web --port=8080
```

`kubectl expose` 不接受 StatefulSet 和 DaemonSet，這兩種會改成給 `kubectl apply` 用的 Service YAML。

## 開放連接埠到網際網路

資料庫、遊戲伺服器、MQTT 這類不走 HTTP 的服務，用對外連接埠讓叢集外的用戶端連進來。

<Steps>
<Step>

### 選連接埠

到服務**網路**的**連線位址**，按**開放連接埠**，在**連接埠**選要開放的連接埠。只有 ClusterIP Service 的連接埠可以選。

要讓用戶端用別的號碼連，在**外部連接埠**填那個號碼，例如服務在 8080，對外用 12345。留空就用同一個號碼。

</Step>
<Step>

### 檢查並套用

按**檢查變更**，確認後套用。

</Step>
<Step>

### 拿到位址

列表會多一個 `LoadBalancer` Service，例如 `db-public-5432`，標著**把 db:5432 開放到網際網路**。**負載平衡器**列出位址和連接埠，例如 `203.0.113.7:5432`，旁邊有複製按鈕。顯示**連接埠 5432 正在等負載平衡器分配位址**時，負載平衡器還在處理，或節點上這個連接埠已經有別的服務在用。

</Step>
</Steps>

<Callout type="warn">
開放的連接埠前面沒有密碼或 HTTPS，網際網路上任何人都連得到，服務要自己檢查連線的是誰。開放資料庫時，畫面會標**資料庫對外開放**。只有專案裡的服務要連資料庫時，改用私有位址。
</Callout>

ServiceLB 會在每個節點監聽外部連接埠，所以整個叢集裡同一個外部連接埠只能開放一次。同專案已經有服務開放了同一個外部連接埠時，Zeabur 開源版會拒絕。

要關閉，在那個 Service 按**關閉**，檢查後套用。

## 用連線規則限制連入和連出

**連線規則**的上方寫出目前誰能連進來，例如 **web 只接受 1 個服務連入**，下面分成**連入**和**連出**兩欄列出允許、部分允許或封鎖的對象。專案沒有任何規則時，所有連線都允許。

按**新增規則**，選一種：

| 規則 | 效果 |
| --- | --- |
| **隔離這個服務** | 只有同專案的副本能連進來，這個服務也只能連到同專案的服務和 DNS，連不到網際網路。 |
| **允許來自公開網域的流量** | 讓 Traefik 把公開網域的請求送進來。 |
| **允許某個服務連入…** | 選一個同專案的服務，讓那個服務連進來。 |

規則可以疊加。常見的組合是先**隔離這個服務**，再加**允許來自公開網域的流量**和需要連進來的服務。

<Callout type="warn">
隔離後，加上**允許來自公開網域的流量**之前，服務的公開網域都連不上。
</Callout>

要讓隔離的服務連到外部 API，到同一頁的 **IP 限制**把位址加進**能連到哪裡**，見[限制能連入和連出的 IP](./ip-limits.mdx)。

要刪除規則，點規則名稱進入**物件**頁，在 YAML 檢視按**刪除**。

## 用 kubectl 做同樣的事

私有位址是一般的 ClusterIP Service，對外連接埠是 `LoadBalancer` Service，連線規則是一般的 NetworkPolicy。以下以專案 `demo` 為例。

### 私有位址

```yaml
apiVersion: v1
kind: Service
metadata:
  name: web
  namespace: demo
  labels:
    app.kubernetes.io/name: web
spec:
  selector:
    app.kubernetes.io/name: web
  ports:
    - name: http
      port: 8080
      targetPort: 8080
```

`selector` 要和 Deployment 的 Pod 標籤相同。

### 對外連接埠

Zeabur 開源版開放連接埠時建立 `<Service 名稱>-public-<連接埠>`，複製來源 Service 的 `selector` 和那個連接埠，類型改成 `LoadBalancer`。標籤 `app.kubernetes.io/name` 是服務名稱，刪除服務時會一起刪掉。開放 `db` 的 5432：

```yaml
apiVersion: v1
kind: Service
metadata:
  name: db-public-5432
  namespace: demo
  labels:
    app.kubernetes.io/name: db
spec:
  type: LoadBalancer
  selector:
    app.kubernetes.io/name: db
  ports:
    - name: postgres
      port: 5432
      targetPort: 5432
      protocol: TCP
```

關閉就刪除這個 Service：

```sh
kubectl -n demo delete service db-public-5432
```

填了外部連接埠時，`port` 是外部連接埠，`targetPort` 沿用來源連接埠的，名稱仍然用來源連接埠。把 `web` 的 8080 開放在 12345：

```yaml
metadata:
  name: web-public-8080
spec:
  type: LoadBalancer
  ports:
    - port: 12345
      targetPort: 8080
      protocol: TCP
```

### 連線規則

Zeabur 開源版建立的規則都帶 `app.kubernetes.io/managed-by: zeabur` 標籤，名稱是 `zeabur-<規則>-<服務>`，超過 63 個字元會截斷。以下以服務 `api` 為例。

**隔離這個服務**：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-isolate-api
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector:
    matchLabels:
      app.kubernetes.io/name: api
  policyTypes: [Ingress, Egress]
  ingress:
    - from:
        - podSelector: {}
  egress:
    - to:
        - podSelector: {}
    - to:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: kube-system
          podSelector:
            matchLabels:
              k8s-app: kube-dns
      ports:
        - protocol: UDP
          port: 53
        - protocol: TCP
          port: 53
```

**允許某個服務連入**，這裡讓 `web` 連到 `api`：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-allow-web-api
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector:
    matchLabels:
      app.kubernetes.io/name: api
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector:
            matchLabels:
              app.kubernetes.io/name: web
```

**允許來自公開網域的流量**。規則允許兩個地方的 Traefik：K3s 內建的在 `kube-system`，另一個在有 `zeabur.com/platform: "true"` 標籤的 Namespace：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-allow-ingress-api
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector:
    matchLabels:
      app.kubernetes.io/name: api
  policyTypes: [Ingress]
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: kube-system
          podSelector:
            matchLabels:
              app.kubernetes.io/name: traefik
        - namespaceSelector:
            matchLabels:
              zeabur.com/platform: "true"
          podSelector:
            matchLabels:
              app.kubernetes.io/name: traefik
```

刪除規則：

```sh
kubectl -n demo delete networkpolicy zeabur-isolate-api
```

## 確認結果

**連線位址**列出每個 Service、它的類型和每個連接埠的位址，資料庫會標**資料庫對外開放**。**連線規則**列出套用到這個服務的規則名稱，以及**連入**和**連出**各自允許誰。

```sh
kubectl -n demo get service
kubectl -n demo get networkpolicy -l app.kubernetes.io/managed-by=zeabur
kubectl -n demo run probe --rm -it --restart=Never --image=busybox:1.37 -- wget -qO- -T 3 http://api:8080
```

`get service` 的 `TYPE` 欄，只給叢集內用的 Service 是 `ClusterIP`，對外連接埠是 `LoadBalancer`。`EXTERNAL-IP` 是負載平衡器的位址，`PORT(S)` 冒號後面是節點連接埠，例如 `5432:31379/TCP`。最後一行從同專案一個臨時的副本連到 `api`。`api` 隔離了而且沒有允許 `probe` 時，會在 3 秒後逾時。從叢集外用 `nc -vz 203.0.113.7 5432` 確認對外連接埠連得上。

## 遇到問題

| 畫面或結果 | 接著處理 |
| --- | --- |
| **web 沒有私有位址** | 按**新增私有位址**，或執行**改用 kubectl** 裡的指令。 |
| 一直顯示**正在等負載平衡器分配位址** | 節點上這個連接埠已經有別的服務在用，或叢集沒有負載平衡器。換一個連接埠，或請管理員確認 ServiceLB。 |
| 開放連接埠時回覆已有服務開放同一個連接埠 | 同專案已經開放了這個連接埠號碼，先關閉那一個。 |
| 隔離後公開網域逾時 | 加上**允許來自公開網域的流量**。 |
| 隔離後服務連不到外部 API | 隔離只允許連到同專案和 DNS。在 **IP 限制**的**能連到哪裡**加上外部 API 的位址。 |
| 加了規則，連線卻照樣通 | 叢集的網路外掛不支援 NetworkPolicy。 |
