---
title: 加上公開網域與 HTTPS
description: 將網域接到服務，設定 HTTPS 憑證、轉址與訪客密碼。
---

在服務 **網路** 的 **公開網域** 按 **新增網域**，輸入網域並加入變更，檢查後套用，再到 DNS 供應商新增畫面列出的紀錄。網址能連到服務且 HTTPS 憑證就緒後，訪客就能開啟網站。

## 開始前

- 服務有接收 HTTP 流量的連接埠，而且 **私有網路** 看得到它的私有位址。網域會把請求轉送到這個位址；沒有的話，先照畫面上的說明開放連接埠。
- 擁有網域的 DNS 管理權限，或有人能代為修改 DNS。
- 有權修改專案的網域。如果路由由 Helm、Argo CD 或 Flux 管理，要回到原本的 values 或 Git 儲存庫修改。
- 叢集裝了 cert-manager 和可用的簽發者，憑證才會自動簽發、更新。萬用字元網域（例如 `*.example.com`）要用支援 DNS-01 的簽發者。

## 新增網域

<Steps>
<Step>

### 填入主機名稱

進入服務 **網路**，在 **公開網域** 按 **新增網域**，輸入 `app.example.com`。欄位只填主機名稱，不加 `https://`、連接埠或路徑。

叢集有多個簽發者時，表單會出現 **簽發者**，可以保留預設或改選另一個。如果這個網域拿不到憑證，檢查變更時會提示它只有 HTTP。

</Step>
<Step>

### 加入草稿，再檢查變更

按 **加入變更**，網域會先放進這個服務的草稿，叢集還沒有改動。從頁面下方按 **檢查變更**，確認網域、轉送目標和憑證設定後套用。

表單沒有連接埠欄位，所以要在檢查時看 **轉送到** 的服務和連接埠。服務已經有路由時，新網域加在同一個 Ingress 上，沿用它的後端；沒有的話，Zeabur 建立新的 Ingress，轉送到服務第一個 Kubernetes Service 的第一個連接埠。

</Step>
<Step>

### 設定 DNS

到 DNS 供應商新增畫面列出的紀錄，照抄類型、名稱和值：

- 目標是 IPv4 位址時，使用 `A`。
- 目標是 IPv6 位址時，使用 `AAAA`。
- 目標是另一個主機名稱時，使用 `CNAME`。

如果網域在叢集的應用程式網域底下，例如 `shop.apps.example.com`，畫面會改成請管理員新增萬用字元紀錄 `*.apps.example.com`；已經有這筆紀錄，就不用另外設定。Zeabur 不會替你修改 DNS。

畫面顯示 **Zeabur 不知道叢集的入口位址，請問管理員要指向哪個位址。** 時，先向叢集管理員要入口的對外位址，再設定 DNS。

</Step>
<Step>

### 開啟網址確認

回到 **公開網域** 查看 DNS 和憑證狀態。DNS 還沒指向叢集或憑證還在簽發時，網域列會寫出下一步；簽發失敗時，展開 **cert-manager 的訊息** 看原因，cert-manager 也會自己重試。

狀態變成 **設定正確** 後，從瀏覽器開啟網址，確認看到的是這個服務、瀏覽器沒有憑證警告。如果應用程式會產生完整網址，再到[環境變數](./variables.mdx)更新 `APP_URL` 這類設定。

</Step>
</Steps>

## 更換 HTTPS 憑證

在網域列按 **app.example.com 的憑證**，開啟側邊面板。面板有自己的 **檢查變更** 和套用步驟，不會加入頁面下方的網域草稿；草稿裡還有新增或改名的網域時，建議先套用草稿再改憑證。

### 使用自動更新的簽發者

選 **由簽發者簽發，自動更新**，指定 **簽發者**，再檢查並套用。同一個 Ingress 的網域共用一個簽發者，所以改了以後，面板列出的其他網域也會改由這個簽發者簽發。

萬用字元網域顯示需要 DNS-01 時，請叢集管理員到 **叢集** → **概覽** 的 **憑證** 按 **新增 DNS-01 簽發者**，選擇 DNS 服務商並填入權杖或金鑰，再回到網域選它。

### 上傳自己的憑證

選 **我自己的憑證**，貼上或按 **上傳檔案** 提供：

- **憑證（PEM）**：先放網站憑證，再放中繼憑證。
- **私密金鑰（PEM）**：提供未加密、與憑證配對的私密金鑰。

檢查後套用。Zeabur 會檢查憑證的有效日期、網域名稱和金鑰是否配對，再把憑證和金鑰存進 Secret，之後不會再顯示金鑰。自己的憑證不會自動更新，要在到期前上傳新的。

同一個 Ingress 的其他網域還在用 cert-manager 簽發的憑證時，面板不能只替這個網域改用自己的憑證，會提示先移除網域再重新加入。**新增網域** 表單只能選簽發者，所以要讓網域有自己的 Ingress：重新加入時選一個和原 Ingress 不同的簽發者，Zeabur 會為它建立新的 Ingress，套用後再回到憑證面板上傳。

網域由 HTTPRoute 提供時，憑證設定在叢集的 Gateway 上，要請叢集管理員到 Gateway 更改。

## 將一個網域轉到另一個網域

轉址和密碼只出現在由 Traefik 提供的 Ingress 上。在來源網域列按 **app.example.com 的轉址或密碼**，選 **轉到另一個網域**，輸入 **要轉到的網域**。

只填目標主機名稱，例如 `www.example.com`。轉址後使用 HTTPS，路徑保留；`app.example.com/docs` 會轉到 `https://www.example.com/docs`。目標網域要先有自己的 DNS、路由與可用憑證。

**轉址類型** 可選 **暫時（302）** 或 **永久（301）**。瀏覽器會記住永久轉址，之後取消也會繼續轉，所以先用暫時轉址確認目標。

在側邊面板按 **檢查變更** 並套用，再開啟來源網域測試。轉址只對這個網域生效，同一個 Ingress 的其他網域照樣顯示原服務。萬用字元網域不能當轉址的來源或目標。

要取消轉址，在同一個面板改選 **顯示 web**（`web` 是服務名稱），再檢查並套用。

## 讓訪客先輸入密碼

在網域列按 **app.example.com 的轉址或密碼**，開啟 **要求輸入密碼**，填入 **使用者名稱** 與 **密碼**。使用者名稱不能含空白或冒號；密碼至少 8 個字元，最多 72 個位元組。

<Callout type="warn">
先確認受保護的所有網域都有 HTTPS。HTTP 上的 Basic auth 會把登入資訊以明文傳送。
</Callout>

密碼設在整個 Ingress 上。面板列出 `www.example.com` 這類共用同一個 Ingress 的網域時，它們也會要求同一組帳號密碼。檢查後套用，再用無痕視窗開啟網址，確認會跳出密碼提示，輸入後能看到服務。

叢集只保存密碼的 bcrypt 雜湊值，忘記密碼時只能換一組。已有密碼時按 **變更** 換帳號密碼；關閉 **要求輸入密碼** 再套用，就會拿掉這個 Ingress 的密碼。

轉址排在密碼前面。來源網域同時設了轉址，訪客不用輸入密碼就會被轉到目標；目標要密碼保護，就在目標網域自己的面板設定。

## 改名、移除與清除 DNS

- 改名：按網域列的編輯按鈕，輸入新名稱，按 **加入變更**，再從頁面下方檢查並套用。接著設定新網域的 DNS；如果用的是自己上傳的憑證，要換一份涵蓋新名稱的憑證。
- 移除其中一個網域：按該列的移除按鈕，從頁面下方檢查並套用，再到 DNS 供應商刪除不再使用的紀錄。
- 路由只剩這一個網域時，檢查變更會拒絕移除，要改成刪除整個路由。進入專案 **物件** 找到該 Ingress 或 HTTPRoute，在 **YAML** 按 **刪除**，檢查後套用。Zeabur 為它建立的轉址、密碼 Middleware 和 Secret 會一起刪除。

還沒套用的網域變更，可以在該列按 **復原**，或按頁面下方 **捨棄** 放棄整份草稿。憑證、轉址和密碼面板沒有套用前，關掉面板就不會改動。

## 遇到問題

| 畫面或結果 | 接著處理 |
| --- | --- |
| 沒有 **新增網域** | 先看 **私有網路** 有沒有私有位址，再確認你有修改網域的權限。 |
| **指向別處** | 核對 DNS 紀錄和畫面列出的目標。前面有 CDN 或代理時也會顯示這個狀態，這時要確認 CDN 的來源指到叢集。 |
| DNS 正確，憑證一直在簽發或 **憑證簽發失敗** | 展開 **cert-manager 的訊息**，核對簽發者，以及驗證要用的 DNS 紀錄或入口設定。 |
| 沒有轉址或密碼按鈕 | 網域由 HTTPRoute 或其他 Ingress controller 提供，要在它們自己的設定處理。 |
| 狀態 **尚未確認**，或瀏覽器連不上 | 依序核對 DNS、入口位址、服務是否就緒和連線規則。Zeabur 從叢集裡檢查，結果可能和你的瀏覽器不同。 |

要暫時擋住訪客、保留網域和服務，用[維護模式](./maintenance.mdx)。
