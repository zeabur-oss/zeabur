---
title: 儲存檔案與備份磁碟區
description: 為服務掛載持續保存的磁碟區、擴充容量，並用 K8up 將檔案備份到 S3 相容儲存空間。
---

應用程式要保留上傳的檔案時，進入服務 **設定** → **儲存空間**，新增磁碟區並指定應用程式寫入的路徑。套用後，寫進這個路徑的檔案在副本重新啟動或換節點後都會留著。同一處也能設定 K8up 備份，定期把磁碟區的檔案複製到 S3 相容儲存空間。

## 開始前

- 知道應用程式寫入資料的路徑，例如 `/data`。容器裡不在磁碟區上的檔案，副本替換後就會消失。
- 叢集有可用的儲存類別，你也有權新增磁碟區、修改服務。
- 如果服務由 Helm、Argo CD 或 Flux 管理，要回到原本的 values 或 Git 儲存庫修改。
- 要備份的話，叢集要裝 K8up，並準備可寫入的 S3 相容儲存空間和存取金鑰。管理員可以先登錄 [S3 目的地](../cluster/s3-destinations.mdx)，備份表單就能直接選用。

## 新增磁碟區

<Steps>
<Step>

### 指定掛載路徑與大小

開啟服務 **設定** → **儲存空間**。沒有磁碟區時按 **新增磁碟區**；已有磁碟區時先按 **編輯**，再按 **新增磁碟區**。

輸入 **掛載路徑**（例如 `/data`）和 **大小**（例如 `5Gi`，預設 `1Gi`）。掛載路徑要是絕對路徑，也不能和這個服務已有的掛載重複。

服務有多個容器時，新磁碟區會掛到第一個容器（不含 init 容器）。要掛到其他容器，先建立磁碟區，再到服務 **設定** 的 **YAML** 把那筆 `volumeMounts` 移到目標容器，`volumes` 保持不動，檢查後套用。

</Step>
<Step>

### 選擇儲存類別

在 **儲存類別** 選擇資料放在哪裡。每個選項會寫出能不能擴充，以及磁碟區和節點的關係：

- **本機磁碟** 最快，但固定在一個節點上，用到它的副本只能在那個節點執行。
- **複寫磁碟** 把資料複寫到多個節點，副本換節點時資料會跟著移動。
- 其他儲存類別的行為由它的驅動程式決定。

不選就用叢集的預設儲存類別。選了不能擴充的類別，要一次給足容量。

要自訂名稱時，展開 **進階** 修改 **名稱**、**PVC 名稱** 和 **存取模式**。這個表單一定會建立新的 PVC，填已在使用的 PVC 名稱，叢集會拒絕。

</Step>
<Step>

### 檢查並套用

按頁面下方 **檢查變更**，確認要建立的磁碟區、大小和掛載路徑，再套用。Zeabur 會先建立 PVC，再把它掛到容器的路徑上。

新增或修改掛載會更新 Pod template，持續執行的服務會替換副本。新磁碟區一開始是空的，容器原本在這個路徑下的檔案不會搬過去；要保留它們，先把檔案複製出來，掛上磁碟區後再放回去。

</Step>
<Step>

### 確認掛載與資料

等磁碟區狀態變成 **就緒**、服務副本也就緒後，從應用程式上傳一個檔案，再 **重新啟動** 服務，確認檔案還在。

**給 Kubernetes 使用者的細節** 會列出 PVC、背後的 PersistentVolume、儲存類別和存取模式。叢集有收集 kubelet 的磁碟區指標時，這裡也會顯示用量。

</Step>
</Steps>

StatefulSet 的磁碟區在建立時就固定了（`volumeClaimTemplates` 建立後不能改），所以這裡不能替它新增或移除磁碟區，只能擴充容量或修改掛載。Job 建立後不能改 Pod template，要替 Job 加磁碟區，編輯它的 YAML。

## 擴充容量或調整掛載

在 **儲存空間** 按 **編輯**，加大既有磁碟區的 **大小**，再從頁面下方檢查並套用。只有可以擴充的儲存類別能加大，而且不能縮小。多個服務掛同一個 PVC 時，它們一起用加大後的空間。

既有掛載也可以改 **掛載路徑** 或 **唯讀**。改路徑只會改變資料在容器裡的位置，應用程式設定的資料路徑也要跟著改；如果路徑寫在[環境變數](./variables.mdx)裡，可以和掛載放進同一份草稿一起檢查。

儲存類別不能擴充時，要在可以擴充的類別建立新磁碟區，把資料複製過去，再把服務改掛新的磁碟區。既有 PVC 不能換儲存類別。

## 設定磁碟區備份

<Steps>
<Step>

### 選擇要備份的磁碟區

在服務 **設定** → **儲存空間** 下方的 **備份** 找到磁碟區，按 **備份這個磁碟區**。叢集還沒裝 K8up 時，按 **開啟 K8up** 請管理員安裝。

</Step>
<Step>

### 填入 S3 目的地與保留規則

選擇已登錄的 S3 目的地，或自己填 **端點**、**儲存貯體**、**存取金鑰 ID**、**私密存取金鑰**。儲存服務需要區域時，再填 **區域**。

**資料夾** 留白時是 `<專案>/<PVC 名稱>`，例如專案 `shop` 的 PVC `data-redis-0` 會放在 `shop/data-redis-0`。

**排程** 可選 **每天 03:00 UTC** 或 **每週日 03:00 UTC**。保留規則預設 **保留最新幾份** 3 份、**每日備份保留天數** 7 天、**每週備份保留週數** 4 週；K8up 會在備份一小時後（04:00 UTC）依這組規則清掉舊備份。

</Step>
<Step>

### 檢查備份物件與執行身分

按面板的 **檢查變更**。這個面板有自己的套用步驟，不會加入上方儲存設定的草稿。

檢查畫面會列出存放金鑰和儲存庫密碼的 Secret、PVC 上的備份標籤和註解，以及 K8up Schedule；備份不以 root 執行時，還有一個 PodConfig。以 PVC `data-redis-0` 為例，Secret 和 Schedule 都叫 `data-redis-0-backup`。

面板也會寫出備份用哪個使用者執行，原則是和服務一致：

- 服務指定了非 root 使用者，備份就用同一個使用者。
- 服務指定 root，或沒有指定使用者、安全性也不是 **嚴格**，備份就用 root，才能讀到每個檔案。如果專案強制 restricted Pod Security，root 的 Pod 會遭拒絕，備份會一直失敗，要請管理員讓專案也允許 **相容** 的服務。
- 服務沒有指定使用者、安全性是 **嚴格** 時，備份用 K8up 的非 root 使用者，只有服務使用者能讀的檔案會略過。在服務的安全性設定指定使用者，就能一起備份。

確認後套用。選用已登錄的 S3 目的地時，金鑰會複製一份到專案的 Secret；之後目的地換了金鑰，這份副本要另外更新。

</Step>
<Step>

### 執行一次並確認結果

建立排程不會馬上備份。按該磁碟區的 **立即備份**，檢查並套用，K8up 會立刻執行一次。

在 **這些磁碟區的備份** 查看這次執行的狀態、完成時間和失敗訊息，顯示 **成功** 才表示檔案已經複製到 S3。

如果這個磁碟區原本就由一個涵蓋多個磁碟區的 K8up 排程備份，**立即備份** 會沿用那個排程的選取條件，其他磁碟區也會一起備份。

</Step>
</Steps>

<Callout type="warn">
另外保存備份 Secret 裡的 `RESTIC_PASSWORD`。這是 Zeabur 產生的 restic 儲存庫密碼，少了它，S3 裡的備份就讀不出來。刪除專案或備份 Secret 之前，先把它存到別處。
</Callout>

## 從備份還原檔案

Zeabur 沒有磁碟區備份的還原操作。還原時由叢集管理員建立 K8up 的 Restore 物件，把備份複製到指定的磁碟區。

準備以下資料交給管理員：

- 來源 S3 端點、儲存貯體與資料夾，可從 K8up Schedule 的 `spec.backend` 確認。
- S3 存取金鑰，以及備份 Secret 的 `RESTIC_PASSWORD`。
- 要還原哪一份備份。Zeabur 的執行紀錄沒有 restic 快照 ID，要從備份儲存庫查詢。
- 目標 PVC 與要接回它的服務。

有讀取 Secret 權限的人可以用 `kubectl` 取出備份 Secret。以專案 `shop`、PVC `data-redis-0` 為例：

```sh
kubectl -n shop get secret data-redis-0-backup -o yaml
```

這份 Secret 有 S3 金鑰和儲存庫密碼，存進團隊的密碼管理工具，不要貼進 issue 或聊天訊息。

備份區的 **K8up：還原** 連到 [K8up 的還原說明](https://docs.k8up.io/k8up/2.16/how-tos/restore.html)。建議先還原到另一個新的磁碟區，確認檔案沒問題，再停掉服務的寫入、改掛新磁碟區。

K8up 備份時應用程式照常執行，直接複製磁碟區上的檔案。如果磁碟區放的是正在寫入的資料庫，複製出來的檔案可能不一致，改用[資料庫自己的備份](../deploy/databases.mdx)。要備份整個叢集的物件，見[叢集備份](../cluster/backups.mdx)。

## 遇到問題

| 畫面或結果 | 接著處理 |
| --- | --- |
| 磁碟區一直 **等待儲存空間** | 查看副本和 PVC 的事件，確認儲存類別可用。儲存類別標示 **在第一個副本執行的節點上建立** 時，要等副本排到節點後才會建立。 |
| 副本換節點後無法啟動 | 看磁碟區是不是固定在某個節點。本機磁碟的資料不會跟著副本搬到新節點。 |
| 多個副本無法同時掛載 | Deployment 的副本共用同一個 PVC。存取模式是 ReadWriteOnce 時，只有同一個節點上的副本能掛載，要改用支援多節點的儲存類別和存取模式。 |
| **這個磁碟區名稱超過 63 個字元，K8up 無法用標籤選取它。** | Zeabur 用 PVC 名稱當標籤值選取磁碟區，名稱太長就無法從這裡設定備份，要請管理員另外寫 K8up Schedule。 |
| 備份 **失敗** 或 **部分失敗** | 讀該次的失敗訊息，核對 S3 金鑰、備份使用者能不能讀檔案，以及專案的 Pod Security。 |
| 建立後沒有執行紀錄 | 按 **立即備份** 跑一次，再看 K8up 和備份 Pod 的狀態。 |
| 看不到備份設定或結果 | 備份區會說明是叢集沒裝 K8up，還是你沒有權限讀取。 |

## 移除掛載與停止備份

還沒套用的儲存修改，按頁面下方 **捨棄** 放棄。已套用的掛載，在 **編輯** 按該列的移除按鈕，再檢查並套用。移除掛載只是讓容器不再掛這個磁碟區，PVC 和資料都還在。

要停止備份，到專案 **物件**（列表裡沒有 K8up 的種類時，先按 **掃描全部種類**），開啟對應的 Schedule，在 **YAML** 按 **刪除**，檢查後套用。S3 上已有的備份不會刪除；還要還原的話，備份 Secret 要留著。確定不再備份這個磁碟區後，可以再刪掉 PodConfig，以及 PVC 上的 `zeabur.com/backup-volume` 標籤和 `k8up.io/backup` 註解。

要完全刪除磁碟區，先移除所有服務的掛載，再到 **物件** 開啟該 PVC，在 **YAML** 按 **刪除**，檢查後套用。

<Callout type="warn">
刪除 PVC 前，先看 **給 Kubernetes 使用者的細節** 裡的回收政策。顯示 **刪除磁碟區時，資料也會刪除**（`Delete`）時，資料會跟著消失；顯示 **刪除磁碟區後，資料仍會保留**（`Retain`）時，管理員之後要自己處理留下的 PersistentVolume。
</Callout>
