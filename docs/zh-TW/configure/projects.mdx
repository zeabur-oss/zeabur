## 開始前

- 你要有建立專案的權限。找不到**新增專案**時，請管理員幫你建立專案，再把你加進去。
- 想好專案名稱。名稱只能用小寫英文字母、數字和連字號，開頭和結尾要是字母或數字，最多 63 個字元，也不能用 `kube-` 開頭。

## 建立專案

<Steps>
<Step>

### 填入名稱

到**專案**頁，按**新增專案**。**名稱**填 `hello`。**顯示名稱**可以留白，填了就會取代名稱顯示在畫面上。

![新增專案視窗，名稱填了 hello](../images/shots/project-new.avif)

專案在叢集裡是一個 Namespace，也就是 Kubernetes 用來分開放置一組服務的空間。專案名稱就是 Namespace 的名稱，所以建立後不能改。同名的 Namespace 已經存在時，表單會提示你改用它，做法見[下一節](#把既有的-namespace-加進-zeabur-開源版)。

</Step>
<Step>

### 檢查並建立

按**檢查變更**，畫面會列出 Zeabur 開源版要做的事：

- 建立 `hello` Namespace，加上專案標籤。安全等級設為 `baseline`：服務可以用 root 執行，但不能存取主機。
- 沒有另外設定的服務，拿不到連 Kubernetes API 用的權杖。
- 叢集裡有標了 `zeabur.com/platform: "true"` 的 Namespace 時，還會[隔離這個專案](#隔離其他專案)，其他專案的服務連不進來。

![建立專案 hello 前的確認畫面，說明會建立的 Namespace 與安全性設定](../images/shots/project-new-review.avif)

確認後按**建立**，畫面會進入新的專案。

</Step>
</Steps>

## 把既有的 Namespace 加進 Zeabur 開源版

叢集裡已經有應用程式時，可以把它所在的 Namespace 變成專案，不用重新部署。這要有那個 Namespace 的 `zeabur-manage` 權限，通常只有管理員有，見[專案 Namespace 的保護](../reference/permissions.mdx#專案-namespace-的保護)。

1. 到**專案**頁的**其他 Namespace**，找到那個 Namespace。

   ![專案頁的其他 Namespace 列出叢集裡還不是專案的 Namespace](../images/shots/existing-namespaces.avif)

2. 在那一列打開選單，選**使用這個 Namespace**，檢查後套用。

Zeabur 開源版只替 Namespace 加上專案標籤 `zeabur.com/project: "true"`。裡面的服務、資料和安全性設定都保持原樣。

不想再在 Zeabur 開源版看到它時，到專案**設定**的**危險區域**按**從 Zeabur 開源版移除**。這只會拿掉專案標籤，Namespace 和裡面的一切都會保留。要連同內容一起刪掉，見[刪除專案](./delete-project.mdx)。

## 修改名稱、描述和圖示

1. 到專案**設定**的**基本資訊**，修改這三項：
   - **專案名稱**：取代 Namespace 名稱顯示在畫面上，最多 64 個字元。
   - **描述**：專案的用途，顯示在名稱下方，最多 500 個字元。
   - **圖示**：按**更換圖示**，從 16 個圖示選一個。

   ![專案設定的基本資訊，有專案名稱、描述和圖示](../images/shots/project-details.avif)

2. 按**儲存詳細資料**，檢查後套用。

專案的開發者可以改這三項。Namespace 上的其他標籤和註解只有管理員能改。

## 設定建置的記憶體和 CPU

建置因為記憶體不夠而失敗時，失敗訊息會連到這一節。

1. 到專案**設定**的**建置**，填這個專案每次建置最多能用的記憶體和 CPU，例如 `2Gi` 和 `2`。留空就用 Zeabur Builder 的預設值。填的數量不能超過叢集裡最大的節點能給的量。節點就是叢集裡的一台主機。
2. 按**儲存建置上限**，檢查後套用。之後開始的建置就會用新的值。

改建置上限要有那個 Namespace 的 `patch` 和 `zeabur-manage` 權限。開發者看得到這兩個欄位，但不能儲存。

## 隔離其他專案

隔離後，其他專案的服務就連不到這個專案的服務。

1. 到專案**設定**的**網路**，看**其他專案**這一列：
   - **叢集裡任何副本都連得到這個專案的服務。**：還沒有隔離。
   - **連不到這個專案的服務。專案內的服務和 Zeabur 開源版元件不受影響。**：已經隔離。

   ![專案設定的網路，其他專案一列說明目前是否隔離](../images/shots/project-network.avif)

2. 還沒隔離時，按**隔離**，檢查後套用。

隔離後，專案裡的服務仍然互相連得到。Traefik、資料庫 operator 這類 Zeabur 開源版元件也連得到，因為它們所在的 Namespace 標了 `zeabur.com/platform: "true"`，`kube-system` 也一樣。

要讓另一個專案連進來，按**允許其他專案連入**，選擇專案，按**允許**，檢查後套用。那個專案的所有服務就連得到這個專案的所有服務。要取消，在那一列按**移除**。

畫面上沒有取消隔離的按鈕，要用 kubectl 處理，見頁面最後的[隔離和允許其他專案](#隔離和允許其他專案)。隔離是否真的生效，要看叢集的網路外掛（CNI）支不支援 NetworkPolicy。

## 確認結果

**專案**頁會列出這個專案，顯示你設定的名稱、描述和圖示。專案**設定**的**網路**寫出目前是否隔離，以及哪些專案能連進來。

## 遇到問題

| 畫面或結果 | 接著處理 |
| --- | --- |
| **已經有同名的 Namespace，可以改為使用既有的 Namespace。** | 換一個名稱，或到**其他 Namespace** 把那個 Namespace 加進 Zeabur 開源版。 |
| 加入或移出專案時，叢集回覆 **Only an admin can change the namespace's labels** | 只有管理員能改 Namespace 的標籤，請管理員操作。 |
| **這是 Kubernetes 留給自身元件的 Namespace，不能當作專案。** | `kube-` 開頭的 Namespace 和節點終端機用的 `zeabur-node-shell` 都不能當作專案。 |
| 建立專案時，檢查畫面沒有隔離這一項 | 叢集裡沒有標了 `zeabur.com/platform: "true"` 的 Namespace。Zeabur 開源版找不到 Ingress controller 在哪裡，所以不隔離，以免公開網域打不開。Ingress controller 是把網域的流量轉給服務的元件。請管理員替它所在的 Namespace 加上標籤，再到**網路**按**隔離**。 |
| 隔離後公開網域打不開 | Ingress controller 所在的 Namespace 沒有 `zeabur.com/platform: "true"` 標籤。替那個 Namespace 加上標籤，或在 `zeabur-project` 加一條允許連入的規則。 |

## 用 kubectl 做同樣的事

專案的一切都是 Namespace 上的標籤、annotation 和一般的 NetworkPolicy。移除 Zeabur 開源版之後，這些設定照樣由 Kubernetes 執行。

### 建立專案

和 Zeabur 開源版建立的內容相同：

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: demo
  labels:
    zeabur.com/project: "true"
    pod-security.kubernetes.io/enforce: baseline
    pod-security.kubernetes.io/audit: baseline
    pod-security.kubernetes.io/warn: baseline
  annotations:
    zeabur.com/display-name: Demo shop
    zeabur.com/description: The shop's web and worker
    zeabur.com/icon: storefront
---
apiVersion: v1
kind: ServiceAccount
metadata:
  name: default
  namespace: demo
automountServiceAccountToken: false
```

`zeabur.com/icon` 可以是 `folder`、`globe`、`storefront`、`rocket`、`cube`、`database`、`cloud`、`code`、`terminal`、`chart`、`chat`、`book`、`flask`、`game`、`heart` 或 `briefcase`。

### 加入、移出專案和修改詳細資料

```sh
kubectl label namespace demo zeabur.com/project=true
kubectl label namespace demo zeabur.com/project-
kubectl annotate namespace demo --overwrite zeabur.com/display-name='Demo shop'
```

專案名稱、描述和圖示存在 Namespace 的 annotation 上。

### 建置上限

建置上限是 Namespace 的 `builder.zeabur.com/build-memory` 和 `builder.zeabur.com/build-cpu` 註解：

```sh
kubectl annotate namespace demo --overwrite builder.zeabur.com/build-memory=2Gi builder.zeabur.com/build-cpu=2
```

### 調整 Pod Security 等級

Zeabur 開源版沒有修改專案 Pod Security 等級的畫面，由管理員用 kubectl 改。改成 `restricted` 後，只有**嚴格**的服務能啟動：

```sh
kubectl label namespace demo --overwrite \
  pod-security.kubernetes.io/enforce=restricted \
  pod-security.kubernetes.io/audit=restricted \
  pod-security.kubernetes.io/warn=restricted
```

服務自己的等級見[調整服務設定](./service-settings.mdx#安全性)。

### 隔離和允許其他專案

`zeabur-project` 允許同專案的副本、`zeabur.com/platform: "true"` 的 Namespace 和 `kube-system` 連入：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-project
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector: {}
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector: {}
        - namespaceSelector:
            matchLabels:
              zeabur.com/platform: "true"
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: kube-system
```

允許專案 `shop` 連進來：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-allow-from-shop
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector: {}
  policyTypes: [Ingress]
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: shop
```

取消隔離：

```sh
kubectl -n demo delete networkpolicy zeabur-project
```

### 確認設定

```sh
kubectl get namespace demo --show-labels
kubectl get namespace -l zeabur.com/project=true
kubectl -n demo get networkpolicy
kubectl -n demo get serviceaccount default -o jsonpath='{.automountServiceAccountToken}'
```

第一行的標籤裡有 `zeabur.com/project=true` 和 `pod-security.kubernetes.io/enforce=baseline`。第二行列出所有專案。隔離後，第三行會列出 `zeabur-project`。最後一行印出 `false`。
