---
title: 部署第一個服務
description: 從公開映像檔建立網頁服務，檢查變更、套用並打開公開網址。
---

建立 `hello` 專案，部署不需要 root 的 Nginx 映像檔，再打開公開網域。每一步都先**檢查變更**，確認後才套用；不需要 Git repository 或建置設定。

## 先準備登入與網域

需要已可登入的 Zeabur、建立專案與部署服務的權限，以及能指向叢集入口的網域。如果管理員設定了應用程式網域（例如 `apps.example.com`），表單會建議網址；否則準備像 `web.example.com` 的完整網域，並設定 DNS。

這次使用公開映像檔 `docker.io/nginxinc/nginx-unprivileged:1.30.5-alpine-slim`。它以非 root 使用者執行，可以保留預設的 **嚴格（建議）** 安全性；官方的 `nginx` 映像檔以 root 啟動，在嚴格的專案裡無法執行。

## 建立專案

1. 開啟**專案**，按**新增專案**。
2. 在**名稱**填入 `hello`。這也是 Namespace 名稱，建立後不能修改。**顯示名稱**可留空。
3. 按**檢查變更**，確認只會新增 `hello` Namespace 與專案標籤，並採用嚴格的 Pod Security 設定。
4. 按**建立**套用變更，進入 `hello` 專案。

若 `hello` 已存在，改用另一個未使用的名稱。只有專案開發者權限時，請管理員先建立專案並授權，再從下一步開始。

## 填入映像檔與連接埠

在專案按**新增**，選擇**Docker 映像檔**，填入：

| 欄位 | 值 |
| --- | --- |
| **映像檔** | `docker.io/nginxinc/nginx-unprivileged:1.30.5-alpine-slim` |
| **名稱** | `web` |
| **連接埠** | `8080` |
| **公開網域** | 開啟，使用建議的網域，或填入自己的完整網域。 |

表單會讀取映像檔宣告的連接埠，確認是 `8080`。連接埠留空代表背景服務，不接受連線。

這次不新增環境變數或磁碟區，**更多設定**保持原值。如果網域下方寫著「這個網址只有 HTTP」，等一下就用 `http://` 開啟；需要 HTTPS 時，請管理員設定 cert-manager 簽發者。

## 檢查變更，再套用

按**檢查變更**。確認下列內容與剛才填入的值一致：

- 在 `hello` 建立名為 `web` 的 Deployment，執行指定的映像檔與 1 個副本。
- 建立 `web` Service，連接埠 `8080` 轉送到容器的 `8080`。
- 建立 `web` Ingress，網域是要公開的那個網址，轉送到 `web` Service。
- 有設定憑證簽發者時，Ingress 包含對應的 cert-manager annotation 與 TLS 設定。

這時叢集裡還沒有任何新物件。值填錯就回表單修改；核對完成後按**建立**套用，Zeabur 會帶你到服務頁。

## 確認服務與網址

先在服務**概覽**確認副本達到 `1/1` **就緒**，再到**網路**打開公開網域。瀏覽器應顯示 Nginx 的預設歡迎頁。

接著到**日誌**查看 Nginx 的存取紀錄，剛才開啟網頁的請求應該出現在這裡。

## 如果沒有看到網頁

| 情況 | 下一步 |
| --- | --- |
| 找不到**新增專案**或部署入口 | 確認目前角色。管理員可在**成員**給專案開發者權限；建立 Namespace 仍需對應的叢集權限。 |
| 檢查變更過期或資源已改變 | 按**重新檢查**，核對新的差異後再套用。 |
| 映像檔無法拉取 | 在服務狀態與事件確認映像檔名稱、版本、節點架構，以及節點到 registry 的連線。 |
| 安全性阻止啟動 | 核對使用的是 `nginx-unprivileged`，且沒有改成以 root 執行的映像檔。 |
| `1/1` 就緒，但網域無法連線 | 在**網路**檢查網域、DNS 與路由，確認 DNS 指向 Ingress 入口，連接埠填的是 `8080`。 |
| HTTPS 憑證尚未就緒 | 核對管理員指定的 ClusterIssuer 與 DNS，查看憑證狀態；有設定 TLS 時要等憑證核發。 |

## 清掉練習資源

在 `web` 服務右上角的**更多**選擇**刪除服務**，檢查刪除清單後套用。這個練習沒有磁碟區，沒有需要保留的應用程式資料。

這份教學的刪除清單應包含 `web` Deployment、Service 和 Ingress；Zeabur 會一併列出它建立、沒有其他服務使用的相關物件。也可以改用 `kubectl` 清掉教學的三個物件：

```sh
kubectl -n hello delete deployment/web service/web ingress/web
```

專案**設定**裡的**不再顯示為專案**只移除 Zeabur 專案標籤，Namespace 與裡面的物件都會留下。要連練習 Namespace 一起清掉，先確認 `hello` 沒有其他資料，再執行：

```sh
kubectl delete namespace hello
```
