---
title: 用 kubeconfig 連接既有叢集
description: 在自己的電腦執行 zeaburctl ui，用 kubeconfig 打開既有叢集的服務。不需要 Zeabur Identity，叢集裡也不會安裝任何東西。
---

手上有能連到叢集的 kubeconfig，就能在自己的電腦打開 Zeabur。叢集裡不會多出任何東西，也不用 Zeabur Identity。讀取、**檢查變更**和套用，用的都是這份 kubeconfig 的權限。

## 準備

| 需要 | 用途 |
| --- | --- |
| 能連到叢集的 kubeconfig | Zeabur 用它目前的 context，要用別的 context 時加上 `--context <名稱>` |
| 你電腦用的 `zeaburctl` | 到[版本與驗證](../reference/releases.mdx)下載。支援 Linux 和 Apple 晶片的 macOS，Windows 請在 WSL 執行 |
| 讀取的權限 | 讀得到 Namespace、Deployment、副本和事件，就能看服務與狀態，和**檢視者**角色相同 |
| 修改的權限 | 要部署或修改服務，需要在專案裡建立和修改 Deployment、Service 和 Ingress，和**開發者**角色相同；要新增專案，還要能建立 Namespace |

這些權限都由叢集的 RBAC 決定，Zeabur 不會多給。兩個角色各能做什麼，見[權限](../reference/permissions.mdx#成員角色)。

## 開啟

```sh
zeaburctl ui
```

終端機會印出一個連結，用瀏覽器打開就能使用。`zeaburctl ui` 只在你電腦的 `127.0.0.1` 監聽，連結內的權杖只能用一次。要連到其他叢集，加上 `--context production`。按 `Ctrl-C` 關閉；已套用的變更會留在叢集裡。

## 一開始會看到什麼

- **專案**把有 Zeabur 專案標籤的 Namespace 列為專案，其他的列在**其他 Namespace**。打開其中一個，服務、網域和環境變數都已經在裡面，不用匯入。
- 讀不到的部分，畫面會寫出缺少哪些權限，例如「部分檢查需要你沒有的權限。」，不會留一片空白。
- 看不到**新增專案**，表示你的帳號不能建立 Namespace。請管理員建立專案，或改在既有的 Namespace 裡部署。
- 這種方式沒有登入和成員，誰拿到 kubeconfig，就有 kubeconfig 的權限。要讓團隊各自登入，改為[把 Zeabur 裝進既有叢集](../install/existing-cluster.mdx)。

`zeaburctl ui` 在[體驗計畫](../reference/telemetry.mdx)會傳送什麼、怎麼關閉，都寫在那一頁。它也會向 GitHub 查詢有沒有新版，設定 `NO_UPDATE_NOTIFIER` 就能關閉，見[檢查更新](../reference/telemetry.mdx#檢查更新)。
