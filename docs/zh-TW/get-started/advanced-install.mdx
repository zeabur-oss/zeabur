把安裝選擇寫進 `/etc/zeabur-installer/config.yaml`，用 `plan` 查看安裝步驟，再用 `apply` 安裝。這個方式適合把設定放進版本控制、在多台機器重複同樣的安裝，或透過自動化工具安裝。

[網頁介面](quickstart.mdx)和指令讀寫同一份設定檔，安裝的內容相同。你也可以在網頁介面的「確認」步驟下載設定檔，再用指令安裝。

![「確認」顯示安裝摘要，「詳細資料」有「下載」按鈕可存下設定檔](../images/shots/installer-review.avif)

## 準備伺服器與 installer

依照[快速開始的伺服器條件](quickstart.mdx#先準備伺服器)準備主機，並下載符合架構的 installer。

## 建立設定檔

以 root 權限建立 `/etc/zeabur-installer/config.yaml`。使用公開網域時，最小設定如下：

```yaml
access:
  mode: domain
  identity: login.example.com
  zeabur: zeabur.example.com
```

把兩個網域換成你要使用的網域。公開網域模式的 DNS 和連接埠需求，見[快速開始的連線方式](quickstart.mdx#2-選擇連線方式)。

未填 `enable` 和 `disable` 時安裝[預設元件](../reference/installer-configuration.mdx#元件選擇)，未填 `profile` 時使用 `single-node`，未填 `distribution` 時安裝 K3s。伺服器有 8 GiB 以上記憶體，或之後想用三台伺服器執行控制平面，就加上 `distribution: rke2`。

測試機可以改用 `local` 模式：

```yaml
access:
  mode: local
  identity: login.<位址>.sslip.io
  zeabur: zeabur.<位址>.sslip.io
```

把 `<位址>` 換成伺服器位址。

所有欄位見 [Installer 設定](../reference/installer-configuration.mdx)。`sources` 是選填欄位，用來改裝自己建置的 Catalog、映像檔和 chart。未填時使用 installer 釘選的版本。

## 查看安裝步驟

執行：

```sh
sudo zeabur-installer plan
```

`plan` 會執行主機檢查，並列出以下內容，不會改動主機：

- Kubernetes 的種類和版本（K3s 或 RKE2）。
- 元件和 chart。
- Namespace。
- 儲存類別。
- 網址。
- 閒置記憶體估算和警告。

檢查有未通過的項目時，輸出會指出 `apply` 將會停下。先修正這些項目，再開始安裝。

需要 JSON 輸出時，執行：

```sh
sudo zeabur-installer plan --json
```

`plan --json` 不會執行主機檢查。

沒有設定檔時，`plan` 會用這台伺服器的位址產生 sslip.io 名稱，以預設元件提供參考。伺服器有公開位址時用 `domain` 模式，否則用 `local` 模式。執行 `apply` 前一定要建立設定檔。

## 執行安裝

確認設定後執行：

```sh
sudo zeabur-installer apply
```

`apply` 會先執行主機檢查。只要有一項失敗，就會在改動任何東西之前停下。

通過檢查後，依序設定主機、安裝做好 CIS 強化的 K3s 或 RKE2、Namespace 和連線規則、儲存空間、選定的元件，再安裝 Zeabur Identity 和 Zeabur。

`apply` 依執行當下的設定計算安裝內容。如果在執行 `plan` 後修改 YAML，`apply` 就會依新內容安裝。

### 中斷後繼續安裝

修正中斷原因後，用同一份設定重新執行：

```sh
sudo zeabur-installer apply
```

每一步都會先檢查已完成的部分，並從中斷處繼續。

## 註冊管理員並登入

安裝完成時，終端機會印出：

- Zeabur 網址。
- Zeabur Identity 網址。
- 第一位管理員的通行密鑰註冊連結。

使用 `local` 模式時，先把以下憑證匯入瀏覽器或系統的信任清單：

```text
/var/lib/rancher/zeabur-installer/local-ca.crt
```

開啟註冊連結，註冊通行密鑰，再開啟 Zeabur 網址登入。

<Callout type="warn">
第一位管理員的註冊連結會建立管理員帳號，誰先開啟，誰就能完整控制叢集，只交給要管理叢集的人。連結只能使用一次，24 小時內有效。
</Callout>

## 檢查安裝結果

執行：

```sh
sudo zeabur-installer doctor
```

這會檢查 K3s 或 RKE2、元件、預設儲存類別、Zeabur Identity 和 Zeabur。

| 結束碼 | 結果 |
| --- | --- |
| `0` | 正常 |
| `1` | 警告 |
| `2` | 嚴重 |
| `3` | 檢查無法執行，例如沒有用 root 執行 |

## 常見停止原因與處理方式

| 遇到的情況 | 處理方式 |
| --- | --- |
| 連接埠被占用，例如還有其他 Kubernetes 在執行 | 先停掉占用的程式，或換乾淨的主機，再執行 `apply` |
| `domain` 模式的憑證還沒核發 | 檢查兩個網域的 DNS，以及 TCP 80 連接埠能否從外部連到。修正後重新執行 `apply` |
| `local` 模式下，瀏覽器顯示憑證不受信任 | 把 `/var/lib/rancher/zeabur-installer/local-ca.crt` 匯入瀏覽器或系統的信任清單 |
| 第一位管理員的註冊連結過期 | 在伺服器執行 `sudo zeabur-installer setup-link`，產生新的連結 |

## 用 AI Agents 安裝

Claude Code、Codex 這類 AI Agents 也能照上面的流程幫你安裝。請先讓 AI Agent 能用 SSH 連到伺服器，帳號要能執行 `sudo`，並用金鑰登入，不要把密碼交給 AI Agent。

把下面這段貼給 AI Agent，並將 `<user>@<server>` 換成你的伺服器：

```text
請幫我在 <user>@<server> 這台伺服器安裝 Zeabur，用 SSH 連線，需要 root 的指令用 sudo。

1. 依 https://oss.zeabur.com/zh-TW/docs/zeabur/reference/releases 的「下載與驗證執行檔」，下載 https://github.com/zeabur-oss/zeabur/releases 上最新發行版的 zeabur-installer，並依伺服器的 `uname -m` 選擇 linux-amd64 或 linux-arm64。驗證 SHA256SUMS 的簽章、檔案的 SHA-256 和建置來源，三項都通過才解壓縮。任何一項沒通過就停下來告訴我，不要為了讓驗證通過而修改驗證參數。
2. 問我 Zeabur 和登入（Identity）要用的兩個網域。如果這是測試機，改用 local 模式，網域用 zeabur.<位址>.sslip.io 和 login.<位址>.sslip.io。依 https://oss.zeabur.com/zh-TW/docs/zeabur/get-started/advanced-install 寫好 /etc/zeabur-installer/config.yaml。
3. 執行 sudo zeabur-installer plan，把變更、警告和沒通過的檢查整理給我看，等我確認可以再繼續。
4. 我同意後執行 sudo zeabur-installer apply。中途失敗時，先修好原因，再用同一份設定重新執行。
5. 安裝完成後執行 sudo zeabur-installer doctor，回報結果。
6. 把第一位管理員的註冊連結原樣交給我，不要自己開啟，也不要自己註冊通行密鑰。

其他細節見 https://oss.zeabur.com/llms.txt。
```

想自己在安裝介面上操作，可以請 AI Agent 改用[快速開始的一行指令](quickstart.mdx#用一行指令)，把含權杖的連結交給你，由你自己開啟。

<Callout type="warn">
第一位管理員的註冊連結會建立管理員帳號，誰先開啟就由誰掌控整個叢集。只讓 AI Agent 把連結交給你，不要讓它自己開啟。
</Callout>
