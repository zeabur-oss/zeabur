title: 升級 Zeabur 開源版
description: 查看目前的 Zeabur 開源版版本，依安裝方式用 Helm、Argo CD、Flux 或 zeaburctl 升級，用 Zeatend 升級 Kubernetes，並在升級後確認新版本。
---

先看你是怎麼安裝的，再照該段升級。升級不會自動發生，Zeabur 開源版只會告訴你有新版本。

## 交給 Agent 升級

Claude Code 或 Codex 這類 Coding Agent 可以替你照著這一頁和升級須知執行。貼上這段提示，在能用 SSH 連到伺服器的電腦上執行 Agent，並告訴它伺服器的位址：

```text
照著 https://oss.zeabur.com/zh-TW/docs/zeabur/upgrade/steps.md 把我伺服器上的 Zeabur 開源版升級到最新版。
```

這個網址指向[本頁的 Markdown 版](https://oss.zeabur.com/zh-TW/docs/zeabur/upgrade/steps.md)。Agent 會查出 Zeabur 開源版的安裝方式，讀過中間每一版的升級須知，並列出要改動的內容。快照由你建立，升級後也要由你用通行密鑰登入；到了這些步驟，Agent 會停下來等你。

## 查看版本

叢集頁面一律顯示 `Zeabur v<版本>`。有新版本時，頁面會出現通知，寫出是哪一版，並附上發行說明連結。「設定」›「關於」也會顯示版本。在這兩個地方按「升級方式」，都會依你的安裝方式列出步驟，附上可以複製的指令和這一頁的連結。

用 `zeaburctl ui` 開啟時，頁面顯示 `zeaburctl` 本身的版本。檢查更新的細節，以及怎麼關掉通知，見[檢查更新](../reference/telemetry.mdx#檢查更新)。

## 選哪一版

升級到這份文件寫的版本，也就是 [CHANGELOG](../../../CHANGELOG.md) 最新標題裡的版本號，不含日期，例如 `0.3.0` 或 `0.3.0-beta.2`。文件寫的是預發行版時，就升級到那一版。GitHub 不會把預發行版標成 Latest，所以 Latest 標籤可能指向較舊的版本。

發行標籤有 `v`，例如 `v0.3.0-beta.2`。`--version` 要給沒有 `v` 的版本，也就是 `0.3.0-beta.2`。

## 升級前

- 到 [GitHub Releases](https://github.com/zeabur-oss/zeabur/releases) 讀要升級的版本的發行說明。
- 讀[升級須知](notes.mdx)，跨過幾版就讀那幾節，先把每一版要做的事做完。
- 先替伺服器或叢集留一份快照。要退回舊版時，只能還原升級前的快照，見[退回舊版](#退回舊版)。
- 專案的資料另外用 Velero 備份，見[備份叢集並從備份還原](../cluster/backups.mdx)。

## 用 Helm 升級

如果 `kubectl -n kube-system get helmchart zeabur` 找得到 `HelmChart`，表示 Zeabur 開源版還是由 zeabur-installer v0.2 設定的 K3s `HelmChart` 在跑。從 v0.2 升到 v0.3 時，請改照升級須知裡的[用 zeabur-installer 安裝的叢集](notes.mdx#用-zeabur-installer-安裝的叢集)，不要照這一節操作。找不到 `HelmChart` 的話，Zeabur 開源版就是由 Helm release 在跑，就算 `zeabur-installer` ConfigMap 還在，也照這一節操作。

把 `<版本>` 換成[選哪一版](#選哪一版)決定的版本：

```sh
helm upgrade zeabur oci://ghcr.io/zeabur-oss/charts/zeabur \
  --version <版本> \
  --namespace zeabur --reset-then-reuse-values
kubectl -n zeabur rollout status deployment/zeabur
```

`--reset-then-reuse-values` 會先採用新版 chart 的預設值，包括映像檔，再套用你先前設定的值。用 `--reuse-values` 的話，映像檔會停在舊版。

在用 [Zeatend](../install/one-command.mdx) 裝好的伺服器上，和安裝時一樣在伺服器上執行。先 `export KUBECONFIG=/etc/rancher/k3s/k3s.yaml`，RKE2 則是 `/etc/rancher/rke2/rke2.yaml`。再執行 `sudo -E helm upgrade …`，接著等待副本就緒：K3s 用 `sudo k3s kubectl …`，RKE2 用 `sudo -E /var/lib/rancher/rke2/bin/kubectl …`。

## 用 Argo CD 升級

把 Argo CD Application 裡的 chart 版本改成新版，再同步。Argo CD 不連叢集就產生 manifest，所以要事先建立固定的簽章金鑰並設定 `planKey.existingSecret`，做法見[用 GitOps 管理 chart](../install/existing-cluster.mdx#用-gitops-管理-chart)。

## 用 Flux 升級

把 Flux HelmRelease 裡的 chart 版本改成新版，提交後等 Flux 同步。

## 用 zeaburctl ui 升級

Zeabur 開源版跑在你自己的電腦上，沒有伺服器要升級。到[發行檔與驗證](../reference/releases.mdx)下載新版 `zeaburctl`，驗證後取代舊檔，再執行一次 `zeaburctl ui`。

## 用 Zeatend 升級 Kubernetes

在用 Zeatend 裝好的伺服器上，K3s、RKE2 或 KubeSolo 由 Zeatend 升級，和 Zeabur 開源版分開。每一版 Zeatend 都固定安裝一個版本，所以換上新版 Zeatend，Kubernetes 也會跟著更新。

1. 在伺服器上照 [Zeatend 的 README](https://github.com/zeabur-oss/zeatend#download-zeatend) 下載新版 Zeatend。
2. 執行 `sudo zeatend plan`，看會升到哪一版和主機檢查的結果。這一步不會改動任何東西。
3. 執行 `sudo zeatend apply`。

`apply` 會裝上新版本，再重新啟動 K3s、RKE2 或 KubeSolo。Kubernetes API 會有一小段時間沒有回應，執行中的服務照常運作。有多個節點時，先一台一台升級伺服器，再升級工作節點。

Kubernetes 一次只能升一個小版本。新版本跳得更遠時，`plan` 會在改動任何東西之前停下，並寫出要先套用哪一版。把那一版寫進 `/etc/zeatend/config.yaml` 的 `version`，執行 `apply`。`plan` 每寫出一版就照做一次，最後刪掉 `version`，再執行一次 `apply`。

### 用 zeabur-installer 裝的伺服器

Zeatend 可以直接接手這些伺服器。沒有 `/etc/zeatend/config.yaml` 時，Zeatend 會讀 `/etc/zeabur-installer/config.yaml`，安裝程式關掉的元件也會繼續關著。下載 Zeatend 後，一樣執行 `plan` 和 `apply`。Zeatend 不會更動 Zeabur 開源版本身；要升級 Zeabur 開源版，先讀[升級須知](notes.mdx)。

## 升級後

- Zeabur 開源版的副本換新後，所有人都要重新登入。chart 只執行一個副本，工作階段存在記憶體裡。
- 執行 `zeaburctl --version`，或開啟叢集頁面，確認版本。
- Helm、Argo CD 和 Flux 可以執行 `kubectl -n zeabur rollout status deployment/zeabur`，等新的副本就緒。

## 退回舊版

要退回舊版，還原升級前的快照。沒有快照就不支援退回。
