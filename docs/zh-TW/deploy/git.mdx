---
title: 從 Git 建置並部署服務
description: 連接 Git 儲存庫、完成第一次建置，並選擇新映像檔何時上線。
---

在專案選擇 **新增** → **從 Git 部署**，填入儲存庫與應用程式的連接埠，再 **檢查變更**。套用後，Zeabur Builder 會開始建置；第一個映像檔完成並部署後，服務才會啟動。

## 開始前

- 已有專案，以及在專案建立服務、Kubernetes Service 和 Build 的權限。使用私有儲存庫或建置變數時，也需要建立機密的權限。
- 叢集已安裝 Zeabur Builder、容器 registry 和 Keel。缺少元件時，新增選單會顯示原因；registry 與 Keel 的提示會連到 **元件**。安裝方式見[管理叢集元件](../cluster/components.mdx)。
- 管理員已在 Zeabur chart 的 `builds.registry` 指定建置輸出的 registry，並讓 Builder 與節點能存取它。預設值是 `zot.zot.svc:5000`。
- 準備應用程式實際監聽的連接埠。要公開網站，另備可指向叢集入口的網域。

## 建立服務

<Steps>
<Step>

### 填寫儲存庫和建置方式

開啟 **新增** → **從 Git 部署**，在 **儲存庫** 填入 HTTPS 或 SSH 網址，例如 `https://github.com/acme/web`。

**分支** 留空會追蹤儲存庫的預設分支；要固定追蹤 `main`，就在這裡填 `main`。

在 **建置方式** 選擇：

- **Railpack**：讓建置器判斷應用程式語言。
- **Dockerfile**：使用儲存庫裡的 Dockerfile。

在 **更多設定** 的 **根目錄** 指定要建置的資料夾，例如 `apps/web`。選擇 Dockerfile 時，**Dockerfile** 欄位的路徑從這個根目錄算起；留空使用 `Dockerfile`。

</Step>
<Step>

### 設定執行方式

確認 **名稱**，並填入 **連接埠**。例如程式監聽 `8080`，這裡就填 `8080`；Zeabur 也會加入 `PORT=8080`，除非你已自行設定 `PORT`。

背景服務不接受連線時，把 **連接埠** 留空。要讓網站對外開放，開啟 **公開網域** 並確認網域；DNS 與 HTTPS 的設定見[加入公開網域](../configure/domains.mdx)。

在 **更多設定** 分開填入：

- **環境變數**：容器執行時讀取，每行一個 `KEY=value`。
- **建置變數**：只有建置階段使用，例如下載私有套件的權杖。值以 BuildKit secret 傳入；Dockerfile 用 `RUN --mount=type=secret,id=KEY` 讀取。
- **規格**：服務執行時的 CPU 和記憶體。
- **安全性**：預設 **嚴格（建議）**。用 Dockerfile 建置時，以數字 UID 指定非 root 使用者，例如 `USER 1000`。

</Step>
<Step>

### 允許讀取私有儲存庫

在 **儲存庫存取** 選擇符合儲存庫的方式：

| 選項 | 操作 |
| --- | --- |
| **公開儲存庫** | 不加認證資訊。 |
| **部署金鑰** | 適用 `github.com`、`gitlab.com`。按 **建立部署金鑰**，複製 **公開金鑰**，用旁邊的連結加入該儲存庫的部署金鑰，保留唯讀權限。 |
| **存取權杖** | 填入能讀取儲存庫的 **帳號** 與 **權杖**，透過 HTTPS 存取。GitHub 預填 `x-access-token`，GitLab 預填 `oauth2`。 |

</Step>
<Step>

### 檢查並套用

按 **檢查變更**，核對服務名稱、公開網域、機密與 Build。若選擇 **相容**，也要檢查是否同時降低整個專案的 Pod 安全等級。

套用後，開啟服務的 **建置** 分頁，查看建置狀態與各次建置的 **日誌**。第一次建置完成前，服務的映像檔標籤是 `pending`，還沒有可執行的版本。

</Step>
</Steps>

## 確認服務已上線

在 **建置** 確認已有成功的映像檔，再到 **概覽** 確認服務就緒。若開啟公開網域，到 **網路** 打開網址，確認看到應用程式。

## 新提交與自動部署

分支有新的提交時，Zeabur Builder 會建置新映像檔，完成後通知 Keel，Keel 再把服務換成新映像檔。建置紀錄會標出每次建置的觸發原因，例如**新的提交**或**推送觸發**。Builder 怎麼偵測新提交、怎麼接 Git 主機的 webhook，見 [Zeabur Builder 文件](https://zeabur.com/oss/docs/builder/)。

服務 **建置** 分頁的 **新建置完成後自動部署** 預設開啟，控制的是建置完成後要不要馬上上線。

要馬上建置一次，在 **建置** 按 **重新建置**，檢查變更後套用；Builder 會用分支最新的提交。想先確認建置結果再上線，就關閉 **新建置完成後自動部署**，建置成功後按 **部署最新版**，檢查並套用映像檔變更。

要改建置資料夾、Dockerfile 或建置變數，到服務 **設定** 的 **建置** 修改，下一次建置開始生效。

## 建置或部署停住時

| 畫面上的情況 | 接著做 |
| --- | --- |
| **從 Git 部署** 提示缺少 registry 或 Keel | 到 **元件** 檢查安裝狀態。若管理員已設定 registry，仍顯示缺少 registry，請管理員檢查元件偵測結果與 `builds.registry`。 |
| 儲存庫存取遭拒 | 使用部署金鑰時，在 **建置** 按 **顯示部署金鑰**，確認已加到正確的儲存庫；使用權杖時，檢查讀取範圍與有效期限。修正後 **重新建置**。 |
| 找不到分支或建置器 | 依建置頁的原因檢查儲存庫分支，以及叢集內對應的 Railpack 或 Dockerfile 建置器。 |
| 建置成功，服務仍使用舊映像檔 | 檢查 **新建置完成後自動部署**、Keel 狀態；也可按 **部署最新版** 手動套用。 |
| 容器啟動後沒有回應 | 查看服務 **日誌**，確認程式監聽的連接埠與表單相同，再查看 **網路** 的連線檢查。 |

## 刪除試用服務

在服務右上角的 **更多** 選 **刪除服務**。檢查將刪除與保留的物件再套用。沒有其他服務使用同一個 Build 時，刪除流程也會刪除它；表單建立的 Git 認證機密只有在沒有其他 Build 使用時才一起刪除。

若使用部署金鑰，另到 Git 主機移除這次加入的公開金鑰；若建立專用權杖，也到 Git 主機撤銷它。
