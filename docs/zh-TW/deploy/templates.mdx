---
title: 從應用程式範本部署
description: 從 Zeabur Catalog 的範本挑一個應用程式，填好網域和必要欄位後部署到專案。
---

做完這一頁，專案裡會多出一個應用程式，例如 Miniflux，連同它的服務、資料庫和公開網域。打開網域就能使用。範本來自這一版 Zeabur 開源版內建的 [Zeabur Catalog](https://github.com/zeabur-oss/catalog)，部署時不會連到外部下載範本。

## 開始前

- 已有專案，並有建立服務的權限。範本的內容用你自己的權限建立，權限不夠的項目會在檢查變更時列出。
- 範本需要的元件已經安裝，例如用 PostgreSQL 的範本需要 CloudNativePG。清單會在範本下方寫出**需要先安裝…**。
- 範本要公開網域時，準備一個指向叢集入口的網域。需要 HTTPS 的範本，叢集管理員要先指定憑證簽發者，見[加上公開網域與 HTTPS](../configure/domains.mdx)。

## 部署範本

<Steps>
<Step>

### 挑選應用程式

開啟**新增** → **應用程式範本**。每個範本會寫出用途，以及需要多少 CPU 和記憶體。叢集剩下的記憶體或 CPU 不夠時，範本下方會提醒。可以在上方輸入名稱篩選。

![應用程式範本清單，篩選 n8n 後列出三個範本，每個寫出用途以及需要的 CPU 和記憶體](../images/shots/template-list.avif)

</Step>
<Step>

### 安裝缺少的元件

範本需要的元件還沒安裝時，表單上方會寫出缺的所有元件，並附上**安裝方式**按鈕。按下後會一次列出這些元件的安裝指令，照[檢視與安裝叢集元件](../cluster/components.mdx)的步驟安裝，再回來部署。缺少元件時，**檢查變更**不會繼續。

</Step>
<Step>

### 填寫網域和欄位

- **公開網域**：預設用範本名稱和專案名稱組成，可以改成自己的網域。
- **部署前要知道的事**：範本作者列出的已知風險和處理方式，預設收合，展開才看得到內容，目前只有英文。部署前先看一遍，例如首次啟動前誰能建立管理員帳號。
- 其他欄位：名稱和說明會跟著介面語言顯示。標示**選填**的欄位可以留空。

密碼和金鑰會在你的瀏覽器產生，存進範本指定的機密變數，例如 Miniflux 的 `miniflux-secrets`。部署後，在用到這些值的服務的**環境變數**裡可以顯示這些值。

![部署 Miniflux 的表單，有公開網域欄位，下方說明密碼會存進機密變數 miniflux-secrets](../images/shots/template-form.avif)

</Step>
<Step>

### 檢查並套用

按**檢查變更**，確認要建立的項目後套用。**會啟動的服務**會列出範本的服務、資料庫和網域，下方寫出尖峰時要用多少 CPU 和記憶體。同一個範本在這個專案已經部署過時，畫面會寫出已經存在的項目，要先刪除，或改部署到別的專案。所有項目都建立在這個專案裡。

![部署 Miniflux 的檢查畫面，列出會建立的機密變數、服務、資料庫和網域，以及資源是否足夠](../images/shots/template-review.avif)

</Step>
</Steps>

## 確認結果

套用後，範本的服務和資料庫會出現在專案裡。打開各服務的**概覽**，等副本就緒，再打開範本的公開網域，確認看到應用程式的頁面。

## 遇到問題

- 名稱已存在：範本使用固定的名稱。同一個專案已經部署過同一個範本，或有同名的機密變數時，檢查變更會列出衝突。改在另一個專案部署。
- 欄位格式不符：欄位下方會寫出需要的格式，照格式修改後再檢查。
- 檢查變更說叢集不支援某種物件：範本需要的元件還沒裝好，或還在啟動。到**元件**頁面確認狀態。

## 交給 Agent 部署

Claude Code 或 Codex 這類 Coding Agent 可以用 `zeaburctl templates export` 替你部署範本。把範本 ID 和專案填進這段提示再貼上：

```text
把 Zeabur Catalog 的範本 <範本> 部署到我叢集的專案 <專案>，照著 https://oss.zeabur.com/zh-TW/docs/zeabur/deploy/templates.md 做。
只部署 `zeaburctl templates export <範本> --project <專案>` 印出的內容。不要自己挑版本或值，也不要自己寫 manifest、Compose 檔或 Helm 指令。
輸出裡每個 <名稱> 佔位符的值都要問我。拿到值後加上 --domain、--cluster-issuer 和 --set <名稱>=<值> 再匯出一次，存成一個檔案，之後只用這個檔案。
如果 zeaburctl 說叢集缺少元件，先問我叢集適合哪種 --format，再用 `zeaburctl components export <元件> --format <格式>` 印出的內容安裝。
每次寫入叢集前，先給我看 `kubectl diff --server-side -f <檔案>` 的結果，等我同意後，再對同一個檔案執行 `kubectl apply --server-side -f <檔案>`。
做完後執行 `zeaburctl doctor --output json`，告訴我結果。
```

Agent 需要 zeaburctl、kubectl，以及能連到叢集的 kubeconfig。它用你的權限寫入，你同意 diff 之前，叢集不會有任何改動。

## 用 kubectl 做同樣的事

### 匯出 YAML 再套用

`zeaburctl templates export` 會印出把範本部署到專案時寫入的物件，和網頁介面寫入的一樣，標籤也相同。它用的是這支 zeaburctl 內建的範本，所以 zeaburctl 的版本要和 Zeabur 開源版相同：

```sh
umask 077
zeaburctl templates export miniflux --project shop \
  --domain miniflux.example.com --cluster-issuer letsencrypt > miniflux.yaml
kubectl diff --server-side -f miniflux.yaml
kubectl apply --server-side -f miniflux.yaml
```

- 輸出最前面是存放範本密碼和金鑰的機密變數。每次執行都會產生新的值，所以只匯出一次，套用那一份檔案。之後再匯出一次並套用，會換掉運作中應用程式的密碼。這份檔案不要放進版本控制。
- 範本要你填的欄位用 `--set <名稱>=<值>` 傳入，例如 `--set adminEmail=me@example.com`。欄位名稱在範本 `template.yaml` 的 `inputs`。沒給的必填欄位，以及沒給的 `--domain` 和 `--cluster-issuer`，會以 `<名稱>` 佔位符出現，套用前要換成實際的值。`--cluster-issuer` 是叢集管理員替 Zeabur 開源版設定的簽發者（`domains.clusterIssuer`）。
- 叢集缺少範本需要的元件時，指令會說出來，並寫出安裝它的 `zeaburctl components export` 指令。詳見 [zeaburctl](../reference/zeaburctl.mdx#templates-export)。

刪掉整個範本：

```sh
kubectl -n shop delete all,ingress,pvc,secret,configmap,networkpolicy -l app.kubernetes.io/instance=miniflux
```

資料庫等 operator 的物件也帶同樣的標籤，用 `kubectl -n shop get <種類> -l app.kubernetes.io/instance=miniflux` 找出來再刪。刪除磁碟區和資料庫會一起刪掉資料。

### 確認部署

範本的每個物件，以及存放產生密碼的 Secret，都帶有三個標籤：`app.kubernetes.io/instance` 和 `templates.zeabur.com/template` 是範本 ID，`app.kubernetes.io/version` 是應用程式版本。列出這次部署的物件：

```sh
kubectl -n shop get deploy,statefulset,svc,ingress,pvc,secret -l app.kubernetes.io/instance=miniflux
```

用到資料庫的範本，也要確認 operator 的物件已就緒，例如 `kubectl -n shop get clusters.postgresql.cnpg.io -l app.kubernetes.io/instance=miniflux` 的 `STATUS` 是 `Cluster in healthy state`。operator 是在叢集裡管理資料庫的元件。

### 限制應用程式往外連

範本不會擋下整個專案的流量。誰能連進專案裡的副本，由專案的 NetworkPolicy `zeabur-project` 決定，見[安全性](../reference/security.mdx)。連出去的連線不擋，應用程式可以連到模型服務、Webhook、郵件伺服器和備份用的 S3。

想限制某個應用程式往外連，自己加一個 NetworkPolicy。下面的例子讓 Umami 只能查詢 DNS 和連到自己的資料庫：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: umami-egress
spec:
  podSelector:
    matchLabels:
      templates.zeabur.com/template: umami
      app.kubernetes.io/name: umami
  policyTypes: [Egress]
  egress:
  - to:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: kube-system
      podSelector:
        matchLabels:
          k8s-app: kube-dns
    ports:
    - {protocol: UDP, port: 53}
    - {protocol: TCP, port: 53}
  - to:
    - podSelector:
        matchLabels:
          cnpg.io/cluster: umami-db
    ports:
    - {protocol: TCP, port: 5432}
```

用 `kubectl apply -n <專案的命名空間> -f umami-egress.yaml` 套用。`podSelector` 只選應用程式的副本，不要選到資料庫：資料庫要連 Kubernetes API 和備份用的 S3，擋掉後資料庫會停擺，備份也會失敗。
