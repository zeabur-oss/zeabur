---
title: 部署容器映像檔
description: 從公開或私有 registry 執行映像檔，設定連接埠、環境變數與持久儲存空間。
---

在專案選擇 **新增** → **Docker 映像檔**，填入映像檔與連接埠，完成 **檢查變更** 後套用，就能啟動服務。需要保留檔案、登入私有 registry 或調整資源時，展開 **更多設定**。

## 開始前

- 已有專案，以及在該專案建立服務的權限。公開網域、機密與磁碟區各有自己的權限，表單會依可用權限顯示選項。
- 映像檔已推送到節點能存取的 registry，並提供節點架構對應的版本。
- 知道應用程式實際監聽的連接埠。首次部署可先依[第一個專案](../get-started/first-project.mdx)走完公開映像檔的流程。
- 要保存資料時，叢集已有可配置磁碟區的預設儲存類別。

## 建立服務

<Steps>
<Step>

### 指定映像檔

開啟 **新增** → **Docker 映像檔**，在 **映像檔** 填入完整參照，例如 `ghcr.io/acme/web:1.4`。使用固定 tag 或 digest，方便對照部署版本。沒有指定版本時，registry 會使用 `latest`。

確認 **名稱**。名稱最多 40 個字元，使用小寫字母、數字與連字號，以字母開頭，且不能和專案內既有名稱衝突。

</Step>
<Step>

### 確認連接埠與網域

Zeabur 會從映像檔讀取它宣告的連接埠。確認 **連接埠** 和應用程式真正監聽的號碼相同。映像檔宣告多個號碼時，依應用程式用途選擇。

不接受連線的背景服務，把 **連接埠** 留空。這時只建立 Deployment，沒有私有位址，也不能加公開網域。

要提供 HTTP 網站，開啟 **公開網域**。管理員設定了應用程式網域時，表單會建議網址。沒有設定時自行填寫，並把 DNS 指向叢集入口。表單也會顯示目前使用的憑證簽發者，或只有 HTTP。詳見[加入公開網域](../configure/domains.mdx)。

![部署映像檔表單，連接埠帶入映像檔宣告的 8080，公開網域填入建議的網址](https://oss.zeabur.com/shots/zeabur/zh-TW/light/image-form.avif)

</Step>
<Step>

### 按需求展開更多設定

| 設定 | 填寫方式與結果 |
| --- | --- |
| **環境變數** | 每行一個 `KEY=value`。應用程式靠 `PORT` 決定監聽位置時，在這裡自己加上 `PORT`。 |
| **把值放在 Secret** `<名稱>-env` | 預設開啟，變數的值存進這個機密。沒有建立機密的權限時，變數會直接寫在 Deployment 裡，也不能使用私有 registry。這時不要在這裡填密碼。 |
| **磁碟區** | 開啟後填入 **掛載路徑**，例如 `/data`，以及 **磁碟區大小**，例如 `5Gi`。建立的是新的空白磁碟區。 |
| **規格** | 選擇 **小**、**中** 或 **大**，欄位下方會列出 CPU 保留量、記憶體保留量與上限。 |
| **副本數** | 可選 1 到 20，掛載磁碟區時固定為 1。 |
| **私有 registry** | 開啟後填入 **Registry**、**帳號**、**密碼**，例如 registry 主機 `ghcr.io`。Zeabur 會建立映像檔下載用的機密。 |
| **安全性** | 預設 **嚴格（建議）**，容器要以非 root 使用者執行。映像檔需要 root 時選 **相容**。專案原本只允許嚴格服務時，同一份變更也會讓專案允許相容服務。 |

<Callout type="warn">
掛載磁碟區的服務只執行一個副本。更新時會先停止舊副本，再啟動新副本，這段時間服務會中斷。
</Callout>

</Step>
<Step>

### 檢查將新增的物件

按 **檢查變更**。核對映像檔、名稱、連接埠與公開網域。新增磁碟區時，也檢查容量與掛載路徑。套用後會進入新服務。

![部署 web 前的確認畫面，列出要建立的 Deployment、Service 和 Ingress](https://oss.zeabur.com/shots/zeabur/zh-TW/light/image-review.avif)

需要表單以外的容器欄位時，按 **以 YAML 編輯**，表單會把目前設定帶到建立頁。改完 YAML 再 **檢查變更**，確認所有文件後建立。

</Step>
</Steps>

## 確認成功

在服務 **概覽** 確認副本就緒，再看 **日誌** 是否已啟動應用程式。填了連接埠時，Zeabur 會替它加上 TCP 就緒檢查，副本能接受連線後才開始收到流量。

![服務概覽，顯示副本狀態與公開網址](https://oss.zeabur.com/shots/zeabur/zh-TW/light/service-overview.avif)

有公開網域時，到 **網路** 開啟網址，確認應用程式能回應。私有服務可從叢集內其他服務連到 **私有網路** 顯示的位址。

部署後要調整變數或磁碟區，前往[環境變數](../configure/variables.mdx)與[磁碟區](../configure/volumes.mdx)。

## 常見失敗

| 情況 | 處理方式 |
| --- | --- |
| 讀不到映像檔的連接埠 | 依提示檢查映像檔名稱、tag 與 registry 帳密。知道實際連接埠時可直接填寫。 |
| 映像檔只有其他架構版本 | 改用支援節點架構的 tag，或重新建置對應架構的映像檔。 |
| 無法下載映像檔 | 在 **概覽** 或 **部署紀錄** 查看原因，確認節點可連到 registry，並核對私有 registry 的認證資訊。 |
| 容器因 root 或權限問題無法啟動 | 檢查映像檔的使用者、目錄權限與安全性設定。需要 root 的映像檔選 **相容**。要維持嚴格，就改用以數字 UID 執行的映像檔。 |
| 副本一直未就緒 | 查看 **日誌**，確認應用程式已監聽表單指定的連接埠，再到 **設定** 調整健康檢查。 |
| 磁碟區一直沒有準備好 | 查看儲存空間相關事件，確認預設儲存類別、可用空間與可排程的節點。 |
| 服務就緒但網址無法開啟 | 到 **網路** 沿著 DNS、入口與服務的連線檢查處理，見[公開網域](../configure/domains.mdx)。 |

## 刪除服務

在服務右上角的 **更多** 選 **刪除服務**。刪除流程會列出服務建立、且沒有其他服務使用的網路、機密與磁碟區。其他服務還在使用的物件會保留。

<Callout type="warn">
刪除磁碟區可能連同檔案一起刪除，結果取決於底層磁碟的回收政策。套用前查看變更中列出的磁碟區與回收政策，先移出要保留的資料。
</Callout>
