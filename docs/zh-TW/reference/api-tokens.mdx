腳本或 CI 不需要你登入，也能用 API 權杖操作專案。到專案的**設定** → **API 權杖**建立一個，給它**開發者**或**檢視者**角色，再複製權杖。權杖跟 kubectl 一樣直接呼叫 kube-apiserver，能做什麼由 Kubernetes RBAC 決定。每個權杖都會到期。

## 開始前

- 你能在這個專案建立 API 權杖。開發者可以，檢視者不行。權杖只能拿到你在這個專案也有的角色，見[權限](./permissions.mdx)。
- 要用權杖的機器連得到 kube-apiserver 的 TCP 6443。

## 建立權杖

1. 打開專案的**設定** → **API 權杖**，按**建立權杖**。
2. 取個看得出用途的名稱，例如 `github-actions`。選角色和有效期間，按**檢查**。
3. 確認變更後套用。
4. 複製權杖。Zeabur 只會顯示這一次。視窗裡也有 kubeconfig 和叢集的 CA 憑證。

清單會列出每個權杖的角色、誰建立的、什麼時候到期。叢集用 `--service-account-max-token-expiration` 限制權杖效期時，kube-apiserver 會把權杖的效期縮短，清單顯示的是實際到期時間。

管理員還可以勾**每個 Namespace**，角色就會套用到叢集裡的每個 Namespace，不只這個專案。

## 連線

每個請求要三樣東西：API 位址、CA 憑證和權杖。

**位址**：kube-apiserver 在每個 server 節點的 TCP 6443 上，例如 `https://203.0.113.10:6443`。你平常用 kubectl 的 kubeconfig 裡，`server` 那一行就是這個位址。要用網域或其他位址連 API 時，把它加到 [`host.tlsSan`](./installer-configuration.mdx)，憑證才會涵蓋它。

**CA 憑證**：建立或更新權杖後，視窗裡會顯示。也可以從專案的 `kube-root-ca.crt` 設定檔讀出來：

```sh
kubectl -n shop get configmap kube-root-ca.crt -o jsonpath='{.data.ca\.crt}' > ca.crt
```

**kubeconfig**：複製視窗裡的 kubeconfig，填上 `server` 後存檔，例如 `shop-ci.yaml`。CA 憑證已經在 `certificate-authority-data` 裡。

```sh
export KUBECONFIG=$PWD/shop-ci.yaml
kubectl auth whoami
```

`kubectl auth whoami` 會顯示 `system:serviceaccount:shop:zeabur-api-token-github-actions`，kube-apiserver 記錄這個權杖的請求時用的就是這個名稱。

用 curl 時，先設好位址和權杖：

```sh
APISERVER=https://203.0.113.10:6443
TOKEN='<權杖>'
```

## 常見操作

以下以專案 `shop`、服務 `web` 為例。從映像檔或 Git 部署的服務是 Deployment，容器名稱和服務名稱相同。**檢視者**權杖只能列出服務，其他操作都要**開發者**。

| 操作 | Method 和路徑 |
|---|---|
| 列出服務 | `GET /apis/apps/v1/namespaces/shop/deployments` |
| 讀日誌 | `GET /api/v1/namespaces/shop/pods/<副本>/log` |
| 重新啟動 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web` |
| 換映像檔 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web` |
| 設定變數 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web` |
| 重新建置 | `PATCH /apis/builder.zeabur.com/v1alpha1/namespaces/shop/builds/web` |
| 調整副本數 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web/scale` |

### 列出服務

```sh
kubectl get deployments -l app.kubernetes.io/name
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments?labelSelector=app.kubernetes.io/name"
```

資料庫和有磁碟區的服務可能是 StatefulSet，路徑是 `/apis/apps/v1/namespaces/shop/statefulsets`。

### 讀日誌

```sh
kubectl logs -l app.kubernetes.io/name=web --tail=100
```

curl 一次讀一個副本。先查副本名稱，再讀其中一個：

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" \
  "$APISERVER/api/v1/namespaces/shop/pods?labelSelector=app.kubernetes.io/name%3Dweb"
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" \
  "$APISERVER/api/v1/namespaces/shop/pods/<副本>/log?container=web&tailLines=100"
```

### 重新啟動

和 Zeabur 的**重新啟動**一樣，把 Pod template 的 annotation `kubectl.kubernetes.io/restartedAt` 設成當下的時間。

```sh
kubectl rollout restart deployment/web
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/strategic-merge-patch+json" \
  -d "{\"spec\":{\"template\":{\"metadata\":{\"annotations\":{\"kubectl.kubernetes.io/restartedAt\":\"$(date -u +%Y-%m-%dT%H:%M:%SZ)\"}}}}}" \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web"
```

### 換映像檔

從 Git 建置的服務改用重新建置，建置完成後 Keel 會換上新映像檔。

```sh
kubectl set image deployment/web web=ghcr.io/acme/web:1.5
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/strategic-merge-patch+json" \
  -d '{"spec":{"template":{"spec":{"containers":[{"name":"web","image":"ghcr.io/acme/web:1.5"}]}}}}' \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web"
```

### 設定變數

改的是服務**環境變數**分頁裡**直接設定**的變數，新副本啟動時就會用新的值。

```sh
kubectl set env deployment/web -c web LOG_LEVEL=debug
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/strategic-merge-patch+json" \
  -d '{"spec":{"template":{"spec":{"containers":[{"name":"web","env":[{"name":"LOG_LEVEL","value":"debug"}]}]}}}}' \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web"
```

### 重新建置

和 Zeabur 的**重新建置**一樣，在 Build 上設 `builder.zeabur.com/rebuild` annotation，Zeabur Builder 會用分支最新的 commit 建置。

```sh
kubectl annotate build web --overwrite builder.zeabur.com/rebuild="$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/merge-patch+json" \
  -d "{\"metadata\":{\"annotations\":{\"builder.zeabur.com/rebuild\":\"$(date -u +%Y-%m-%dT%H:%M:%SZ)\"}}}" \
  "$APISERVER/apis/builder.zeabur.com/v1alpha1/namespaces/shop/builds/web"
```

### 調整副本數

```sh
kubectl scale deployment/web --replicas=2
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/merge-patch+json" \
  -d '{"spec":{"replicas":2}}' \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web/scale"
```

## 更新和刪除

按權杖旁的**更新**，會拿到同一個名稱、同一個角色的新權杖。之前簽發的權杖到期前都還能用。

要讓權杖馬上失效，在它旁邊選**更多** → **刪除**。為它簽發的每個權杖都會失效，請求會收到 `401 Unauthorized`。

建立權杖的人離開專案後，權杖到期或被刪除前都還能用。有人離開時，看清單裡每個權杖是誰建立的，把那個人建立的刪掉。

## Zeabur 建立什麼

Zeabur 用你自己的權限寫入這些物件：

| 物件 | 內容 |
|---|---|
| 專案裡的 `ServiceAccount zeabur-api-token-<名稱>` | 標籤 `zeabur.com/api-token: "true"` 和 `app.kubernetes.io/managed-by: zeabur`。annotation 記錄角色、建立者和最新權杖的到期時間 |
| 專案裡的 `RoleBinding zeabur-api-token-<名稱>` | 把 `zeabur-project-developer` 或 `zeabur-project-viewer` 綁到這個 ServiceAccount |
| `ClusterRoleBinding zeabur-api-token:<專案>:<名稱>` | 用在每個 Namespace 的權杖改用這個，不建立 RoleBinding |

權杖本身由 ServiceAccount 的 TokenRequest 簽發，Zeabur 不會把它存進 Secret 或其他地方。刪除權杖會刪掉 binding 和 ServiceAccount。

chart 裡的准入政策讓這些物件只能用在 API 權杖，也不讓 Pod 用權杖的 ServiceAccount 執行，見 [API 權杖和 RBAC](./permissions.mdx#api-權杖和-rbac)。
