---
title: API 權杖
description: 讓腳本和 CI 用各專案的角色呼叫 Kubernetes API，權杖會到期。
---

腳本或 CI 不需要任何人登入，也能用 API 權杖操作叢集。管理員在**成員**頁建立權杖，像給成員權限一樣，替它在各專案設定角色。權杖跟 kubectl 一樣直接呼叫 kube-apiserver，能做什麼由 Kubernetes RBAC 決定。每個權杖都會到期。

## 開始前

- 你是管理員。只有管理員能建立、更新、變更和刪除 API 權杖，見[權限](./permissions.mdx)。
- 要用權杖的機器連得到 kube-apiserver 的 TCP 6443。

## 建立權杖

1. 打開**成員**，在 **API 權杖**下按**建立權杖**。

   ![成員頁的 API 權杖清單：每個權杖的角色、建立者和到期時間](../images/shots/api-tokens-list.avif)

2. 取個看得出用途的名稱，例如 `deploy-shop`。勾選需要的專案，選**開發者**或**檢視者**，選好有效期間後按**檢查變更**。

   ![建立 API 權杖視窗：名稱 deploy-shop、在 shop 是開發者、有效 30 天](../images/shots/api-token-create.avif)

3. 確認變更後按**建立權杖**。
4. 視窗會顯示權杖、kubeconfig 和叢集的 CA 憑證。權杖只會顯示這一次，先別關掉視窗，照下一節存好 kubeconfig。

   ![權杖視窗：權杖、server 還空著的 kubeconfig，以及 CA 憑證](../images/shots/api-token-shown.avif)

清單會列出每個權杖的角色、誰建立的、什麼時候到期。叢集用 `--service-account-max-token-expiration` 限制權杖效期時，kube-apiserver 會把權杖的效期縮短，清單顯示的是實際到期時間。

## 把權杖做成 kubeconfig

視窗裡的 kubeconfig 已經有權杖和 CA 憑證，只差 `server`，也就是 API 位址。Zeabur 開源版只知道 kube-apiserver 在叢集內部的位址，所以要你自己填。

<Steps>
<Step>
### 找出 API 位址

kube-apiserver 在每個 server 節點的 TCP 6443 上，例如 `https://203.0.113.10:6443`。在你自己的電腦上，印出管理員 kubeconfig 用的位址：

```sh
kubectl config view --minify -o jsonpath='{.clusters[0].cluster.server}'
```

印出 `https://127.0.0.1:6443` 表示那份 kubeconfig 是在伺服器上用的。請改用你連到伺服器的位址，例如在 Zeatend 連線方式畫面填的位址。要用網域或其他位址連 API 時，把它加到 K3s 或 RKE2 設定檔的 `tls-san`（Zeatend 是 `host.tlsSan`），憑證才會涵蓋它。
</Step>
<Step>
### 存成檔案

按視窗裡 kubeconfig 的複製鈕，貼進一個檔案，例如 `deploy-shop.yaml`，並設成只有你能讀：

```sh
chmod 600 deploy-shop.yaml
```

拿到這個檔案的人，在權杖到期前都能用它的權限。
</Step>
<Step>
### 填上位址

```sh
kubectl config set-cluster zeabur --server=https://203.0.113.10:6443 --kubeconfig deploy-shop.yaml
```
</Step>
<Step>
### 試試看

```sh
export KUBECONFIG=$PWD/deploy-shop.yaml
kubectl auth whoami
kubectl get deployments
```

`kubectl auth whoami` 會顯示 `system:serviceaccount:zeabur-api-tokens:deploy-shop`，kube-apiserver 記錄這個權杖的請求時用的就是這個名稱。權杖只在一個專案有角色時，kubeconfig 會直接從那個專案開始；否則每個指令都要加 `-n <專案>`。
</Step>
<Step>
### 放進 CI

把整個檔案存成 CI 的機密，不要放進 repository。以 GitHub Actions 為例：

```sh
gh secret set KUBECONFIG_DATA < deploy-shop.yaml
```

再在工作裡寫成檔案：

```yaml
- name: Deploy
  env:
    KUBECONFIG_DATA: ${{ secrets.KUBECONFIG_DATA }}
  run: |
    export KUBECONFIG="$RUNNER_TEMP/kubeconfig"
    (umask 077; printf '%s' "$KUBECONFIG_DATA" > "$KUBECONFIG")
    kubectl set image deployment/web web=ghcr.io/acme/web:${{ github.sha }}
```

Runner 要連得到 API 位址的 TCP 6443。權杖到期後，更新權杖，再存一次新的 kubeconfig。
</Step>
</Steps>

## 用 curl 連線

curl 需要 API 位址、權杖和 CA 憑證。把視窗裡的 CA 憑證存成 `ca.crt`。在專案有角色的權杖，也可以從專案的 `kube-root-ca.crt` 設定檔讀出來：

```sh
kubectl -n shop get configmap kube-root-ca.crt -o jsonpath='{.data.ca\.crt}' > ca.crt
```

再設好位址和權杖：

```sh
APISERVER=https://203.0.113.10:6443
TOKEN='<權杖>'
```

## 權杖能做什麼

權杖只有你在各專案給它的角色，加上 `zeabur-member`，可以讀節點和 Namespace 的名稱。**檢視者**權杖能看專案裡各服務的狀態。**開發者**權杖還能：

- 換服務的映像檔、調整副本數，以及重新啟動。
- 讀取和編輯機密變數，設定環境變數。
- 讀日誌，用 `kubectl exec` 在副本裡執行指令。
- 重新建置。

權杖不能：

- 建立或刪除專案，也碰不到沒有角色的專案。
- 變更節點、叢集元件或叢集備份。
- 讀取或變更 `zeabur-api-tokens` 裡的任何東西，所以沒辦法再申請權杖。

### 不要把管理員的 kubeconfig 交給 CI

沒有管理員權杖。管理員帳號只能用通行密鑰登入，有完整權限的權杖會繞過這道關卡。它還能自己建立新的身分，所以刪掉權杖也收不回它的權限。

<Callout type="warn">
絕對不要把管理員的 kubeconfig 放進 CI、其他服務的機密，或交給 Agent 保管。管理員的 kubeconfig 能做叢集裡所有的事，一旦外洩，整個叢集和裡面所有資料都會跟著外洩。每個權杖只在需要的專案給角色，能用檢視者就不要用開發者。
</Callout>

需要在整個叢集操作時，例如建立專案、安裝元件、管理節點或叢集備份，請以管理員身分用你自己的 kubeconfig。詳見[管理員帳號和一般帳號](./permissions.mdx#管理員帳號和一般帳號)。

真的要讓叢集外的系統自動做某個管理員操作時，為這一個操作寫個小程式：給它自己的 ServiceAccount，只綁定這個操作需要的 verb 和資源，除此之外什麼都不做。

## 常見操作

以下以專案 `shop`、服務 `web` 為例。從映像檔或 Git 部署的服務是 Deployment，容器名稱和服務名稱相同。**檢視者**權杖只能列出服務，其他操作都要**開發者**。

| 操作 | Method 和路徑 |
|---|---|
| 列出服務 | `GET /apis/apps/v1/namespaces/shop/deployments` |
| 讀日誌 | `GET /api/v1/namespaces/shop/pods/<副本>/log` |
| 重新啟動 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web` |
| 換映像檔 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web` |
| 設定變數 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web` |
| 重新建置 | `PATCH /apis/builder.zeabur.com/v1alpha1/namespaces/shop/builds/web` |
| 調整副本數 | `PATCH /apis/apps/v1/namespaces/shop/deployments/web/scale` |

### 列出服務

```sh
kubectl get deployments -l app.kubernetes.io/name
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments?labelSelector=app.kubernetes.io/name"
```

資料庫和有磁碟區的服務可能是 StatefulSet，路徑是 `/apis/apps/v1/namespaces/shop/statefulsets`。

### 讀日誌

```sh
kubectl logs -l app.kubernetes.io/name=web --tail=100
```

curl 一次讀一個副本。先查副本名稱，再讀其中一個：

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" \
  "$APISERVER/api/v1/namespaces/shop/pods?labelSelector=app.kubernetes.io/name%3Dweb"
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" \
  "$APISERVER/api/v1/namespaces/shop/pods/<副本>/log?container=web&tailLines=100"
```

### 重新啟動

和 Zeabur 開源版的**重新啟動**一樣，把 Pod template 的 annotation `kubectl.kubernetes.io/restartedAt` 設成當下的時間。

```sh
kubectl rollout restart deployment/web
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/strategic-merge-patch+json" \
  -d "{\"spec\":{\"template\":{\"metadata\":{\"annotations\":{\"kubectl.kubernetes.io/restartedAt\":\"$(date -u +%Y-%m-%dT%H:%M:%SZ)\"}}}}}" \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web"
```

### 換映像檔

從 Git 建置的服務改用重新建置，建置完成後 Keel 會換上新映像檔。

```sh
kubectl set image deployment/web web=ghcr.io/acme/web:1.5
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/strategic-merge-patch+json" \
  -d '{"spec":{"template":{"spec":{"containers":[{"name":"web","image":"ghcr.io/acme/web:1.5"}]}}}}' \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web"
```

### 設定變數

改的是服務**環境變數**分頁裡**直接設定**的變數，新副本啟動時就會用新的值。

```sh
kubectl set env deployment/web -c web LOG_LEVEL=debug
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/strategic-merge-patch+json" \
  -d '{"spec":{"template":{"spec":{"containers":[{"name":"web","env":[{"name":"LOG_LEVEL","value":"debug"}]}]}}}}' \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web"
```

### 重新建置

和 Zeabur 開源版的**重新建置**一樣，在 Build 上設 `builder.zeabur.com/rebuild` annotation，Zeabur Builder 會用分支最新的 commit 建置。

```sh
kubectl annotate build web --overwrite builder.zeabur.com/rebuild="$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/merge-patch+json" \
  -d "{\"metadata\":{\"annotations\":{\"builder.zeabur.com/rebuild\":\"$(date -u +%Y-%m-%dT%H:%M:%SZ)\"}}}" \
  "$APISERVER/apis/builder.zeabur.com/v1alpha1/namespaces/shop/builds/web"
```

### 調整副本數

```sh
kubectl scale deployment/web --replicas=2
```

```sh
curl --cacert ca.crt -H "Authorization: Bearer $TOKEN" -X PATCH \
  -H "Content-Type: application/merge-patch+json" \
  -d '{"spec":{"replicas":2}}' \
  "$APISERVER/apis/apps/v1/namespaces/shop/deployments/web/scale"
```

## 更新、變更和刪除

在權杖旁邊選**更多** → **更新**，會拿到同一個名稱、同樣權限的新權杖。之前拿到的權杖，到期前都還能用。

選**更多** → **變更權限**，可以讓權杖在其他專案有角色。之前拿到的權杖也會跟著變。

要讓權杖馬上失效，選**更多** → **刪除**。之前拿到的權杖全都會失效，請求會收到 `401 Unauthorized`。

權杖不屬於建立它的人。建立者離開後，權杖在到期或管理員刪除之前都照樣能用。

## Zeabur 開源版建立什麼

Zeabur 開源版用管理員自己的權限寫入這些物件：

| 物件 | 內容 |
|---|---|
| `zeabur-api-tokens` Namespace 中的 `ServiceAccount <name>` | 標籤 `zeabur.com/api-token: <name>` 和 `app.kubernetes.io/managed-by: zeabur`。annotation 記錄誰建立的，以及最新權杖什麼時候到期 |
| 各專案中的 `RoleBinding zeabur-api-token-<name>` | 綁定 `zeabur-project-developer` 或 `zeabur-project-viewer` 給該 ServiceAccount |
| `ClusterRoleBinding zeabur-api-token-<name>` | 跟成員一樣綁定 `zeabur-member` |

權杖本身來自對該 ServiceAccount 的 TokenRequest，Zeabur 開源版不會存進 Secret 或其他地方。刪除權杖會刪掉它的 binding 和 ServiceAccount。

Chart 會建立 `zeabur-api-tokens` Namespace，裡面不跑其他東西。只有管理員在那裡有權限，所以其他人沒辦法申請權杖，也沒辦法讓 Pod 以權杖的身分執行。見[API 權杖與 RBAC](./permissions.mdx#api-權杖與-rbac)。
