在 [GitHub Releases](https://github.com/zeabur-oss/zeabur/releases) 選好版本，下載對應的 archive、`SHA256SUMS` 和簽章。驗證時把簽署者限定為 zeabur-oss 共用的 release workflow，且是為本 repository 該版本 tag 執行的那一次，通過了才解壓縮、執行。

## 檔案與平台

| 成品 | 位置或檔名 | 平台 |
|---|---|---|
| `zeaburctl` | `zeaburctl-v<version>-<os>-<arch>.tar.gz` | Linux `amd64`、`arm64`，macOS `arm64` |
| `zeabur` 伺服器 | `zeabur-v<version>-linux-<arch>.tar.gz` | Linux `amd64`、`arm64` |
| `zeabur-installer` | `zeabur-installer-v<version>-linux-<arch>.tar.gz` | Linux `amd64`、`arm64` |
| 多平台容器映像檔 | `ghcr.io/zeabur-oss/zeabur:<version>` | Linux `amd64`、`arm64` |
| Helm chart | `oci://ghcr.io/zeabur-oss/charts/zeabur`，也提供 `zeabur-<version>.tgz` | 安裝到 Kubernetes 叢集 |
| 成品 digest | `digests.txt` | image index、各平台映像檔與 chart |
| 檔案 checksum 與簽章 | `SHA256SUMS`、`SHA256SUMS.sigstore.json` | 同一份 release 的 assets |

每個 archive 裡有執行檔和 `LICENSE`。macOS 只有 Apple silicon（`arm64`）版本，沒有 Intel Mac 版本。`zeabur` 和 installer 只在 Linux 執行，macOS 上只需要 `zeaburctl`。

發行時，chart 的 `image.digest` 會釘在這次發布的 image index 上，用 chart 預設值安裝就會拿到同一份映像檔。Image tag 和 chart version 沒有開頭的 `v`，GitHub release tag 和 archive 檔名有。

## 下載與驗證執行檔

需要 GitHub CLI `gh`、cosign 3 和 GNU `sha256sum`。把 `version` 換成你選的版本，下例用 `0.1.1`：

```sh
version=0.1.1
platform=darwin-arm64
binary=zeaburctl
signer='^https://github\.com/zeabur-oss/\.github/\.github/workflows/release\.yml@'

gh release download "v$version" --repo zeabur-oss/zeabur \
  --dir "zeabur-$version" \
  --pattern SHA256SUMS \
  --pattern SHA256SUMS.sigstore.json \
  --pattern "$binary-v$version-$platform.tar.gz"
```

`platform` 可以換成 `linux-amd64` 或 `linux-arm64`。下載 installer 時，把 `binary` 改成 `zeabur-installer`，並選 Linux 平台。

zeabur-oss 的每個版本都由 [zeabur-oss/.github](https://github.com/zeabur-oss/.github) 裡共用的 release workflow 建置與簽署，所以簽署者是那個 workflow（下面的 `signer`），憑證上另外記著它是為哪個 repository、哪個 tag 執行。進入下載目錄，依序驗證 checksum 清單的簽署者、檔案內容和建置來源：

```sh
cd "zeabur-$version"

cosign verify-blob \
  --bundle SHA256SUMS.sigstore.json \
  --certificate-identity-regexp "$signer" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-github-workflow-repository zeabur-oss/zeabur \
  --certificate-github-workflow-ref "refs/tags/v$version" \
  SHA256SUMS

sha256sum --check --ignore-missing SHA256SUMS

gh attestation verify "$binary-v$version-$platform.tar.gz" \
  --repo zeabur-oss/zeabur \
  --signer-workflow zeabur-oss/.github/.github/workflows/release.yml \
  --source-ref "refs/tags/v$version"
```

三項都通過後再解壓縮：

```sh
tar -xzf "$binary-v$version-$platform.tar.gz" "$binary"
"./$binary" --version
```

checksum 不符時，重新下載那個檔案。簽署者、issuer 或 attestation 不符時，不要執行檔案，先核對 release、檔名、workflow 身分、repository 和 tag，也不要放寬驗證參數來讓它通過。

用 macOS 瀏覽器下載的檔案會帶 quarantine 標記。驗證通過後，對解出的檔案執行：

```sh
xattr -d com.apple.quarantine zeaburctl
```

用 `gh release download` 下載就不會有這個標記。macOS 版本有 Sigstore 簽章，但沒有經過 Apple notarization。

## 驗證映像檔與 chart

發行說明只寫這版改了什麼，不列 digest。`digests.txt` 每行一筆，列出各平台映像檔、image index 和 chart 的完整 registry 參照：

```text
linux/amd64  ghcr.io/zeabur-oss/zeabur@sha256:...
linux/arm64  ghcr.io/zeabur-oss/zeabur@sha256:...
index  ghcr.io/zeabur-oss/zeabur@sha256:...
chart  ghcr.io/zeabur-oss/charts/zeabur@sha256:...
```

它也列在 `SHA256SUMS` 裡。下載到同一個目錄，先用上面的流程驗證，再把裡面的 digest 交給 cosign：

```sh
gh release download "v$version" --repo zeabur-oss/zeabur \
  --dir "zeabur-$version" --pattern digests.txt
```

```sh
cosign verify \
  --certificate-identity-regexp "$signer" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-github-workflow-repository zeabur-oss/zeabur \
  --certificate-github-workflow-ref "refs/tags/v$version" \
  'ghcr.io/zeabur-oss/zeabur@sha256:<image-index-digest>'

cosign verify \
  --certificate-identity-regexp "$signer" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-github-workflow-repository zeabur-oss/zeabur \
  --certificate-github-workflow-ref "refs/tags/v$version" \
  'ghcr.io/zeabur-oss/charts/zeabur@sha256:<chart-digest>'
```

角括號換成 `digests.txt` 裡的值。在既有叢集安裝 chart 的步驟見[在既有叢集安裝](../get-started/install.mdx)。

## 發行流程

維護者推送 `v<version>` tag 後，release workflow（本 repository 的 `release.yml`，它呼叫 `zeabur-oss/.github` 裡共用的那一個）建置 Linux 和 macOS 版本、做 smoke test、發布映像檔和 chart，再以 Sigstore keyless 簽署映像檔、chart 和 checksum 清單，並為三者產生建置來源 attestation。

Workflow 最後建立 GitHub release 草稿，維護者檢查後才公開。Releases 頁面上看得到的版本，才有可下載的檔案。

下載和驗證都不會動到叢集，用完的下載目錄可以直接刪掉。要移除已安裝的 Zeabur，見[移除流程](../leave/uninstall.mdx)。
