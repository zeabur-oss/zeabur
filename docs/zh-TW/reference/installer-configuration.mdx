把網域、元件選擇和主機設定寫進 YAML，執行 `zeabur-installer --config config.yaml plan` 先看安裝內容。檔案預設放在 `/etc/zeabur-installer/config.yaml`。欄位用 camelCase，拼錯或多出欄位時，installer 會直接停下。

網頁介面的選擇也存成這份檔案。用網頁介面安裝見[在一台伺服器安裝 Zeabur](../get-started/quickstart.mdx)，用指令安裝見[用設定檔和指令安裝](../get-started/advanced-install.mdx)，各指令的選項見 [Installer 指令](./installer.mdx)。

## 建立叢集的檔案

下面的例子用自己的網域。兩個 DNS 名稱都要指向伺服器，外部也要連得到連接埠 `80`，Let's Encrypt 才能完成 HTTP-01 驗證。

```yaml title="/etc/zeabur-installer/config.yaml"
profile: single-node
access:
  mode: domain
  identity: login.example.com
  zeabur: zeabur.example.com
  invitations: true
zeabur: true
host:
  requireEncryptedDisk: true
```

### 頂層欄位

| 欄位 | 預設 | 用途 |
|---|---|---|
| `use` | `team` | `team` 是團隊用。`personal` 改成自己用，可用的欄位見[自己用的檔案](#自己用的檔案) |
| `distribution` | `k3s` | `k3s` 或 `rke2`，見[`distribution` 與版本](#distribution-與版本) |
| `access` | 必填 | 登入服務與 Zeabur 的網域和憑證模式 |
| `profile` | `single-node` | `single-node` 或 `multi-node`，選取 Catalog 對應的元件設定 |
| `enable` | `[]` | 在[預設元件](#元件選擇)之外加入的 capability 或完整元件 ID |
| `disable` | `[]` | 從預設元件排除的 capability 或完整元件 ID |
| `allowDataLoss` | `[]` | 同意移除時連資料一起刪掉的元件 ID，例如 `replicated-storage/longhorn` |
| `zeabur` | `true` | 安裝 Zeabur Identity 與 Zeabur。`false` 只安裝 K3s/RKE2 與選定元件 |
| `telemetry` | `true` | 加入[體驗計畫](./telemetry.mdx)。`--no-telemetry` 和 `DO_NOT_TRACK=1` 可在該次執行時關閉 |
| `inputs` | `{}` | 依元件 ID 分組的一般輸入值 |
| `secretFiles` | `{}` | 依元件 ID 分組的機密檔案路徑 |
| `k3sVersion`、`rke2Version` | installer 釘選版本 | 覆寫 K3s 或 RKE2 的版本 |
| `host` | 空 | API 憑證的額外名稱和磁碟加密要求 |
| `sources` | 空 | 選填，用自己準備的 Catalog、映像檔和 chart 取代釘選的版本 |

`zeabur: false` 只決定這次安裝什麼，不會移除已裝好的 Zeabur。要移除，用 [`uninstall`](./installer.mdx#uninstall)。

### `access`

| 欄位 | 預設與規則 |
|---|---|
| `mode` | 必填。`domain` 由 cert-manager 向 Let's Encrypt 申請憑證（HTTP-01）。`local` 在伺服器上建立私有 CA，只適合測試機 |
| `identity` | 必填。Zeabur Identity 主機名稱，issuer 為 `https://<identity>` |
| `zeabur` | 必填。Zeabur 主機名稱，必須與 `identity` 不同 |
| `invitations` | `true`。是否接受 Zeabur **成員**頁產生的設定連結。成員只由版本控制管理時關掉 |
| `suffixes` | 伺服器有公開位址時是 `<位址>.sslip.io`，例如 `203-0-113-7.sslip.io`，否則沒有。新服務的網址會建議在這些應用程式網域底下，預設用第一個，例如 `[apps.example.com]`。每個網域要一筆指向伺服器的萬用字元紀錄 `*.apps.example.com`，見[設定 DNS 紀錄](../configure/dns.mdx)。填 `[]` 表示不建議網址 |

主機名稱不加 `https://`、連接埠或路徑，只用小寫英文字母、數字、連字號和點，至少兩段。每段最多 63 個字元、不能以連字號開頭或結尾，總長最多 253 個字元。

瀏覽器和伺服器都要能解析這兩個名稱。Pod 用 DNS 解析，看不到主機 `/etc/hosts` 裡的設定。`local` 模式的 CA 憑證在 `/var/lib/rancher/zeabur-installer/local-ca.crt`，匯入使用者電腦的信任儲存區後，瀏覽器才會信任這兩個網址。

### 元件選擇

預設會安裝 Catalog 為這個 profile 建議的所有元件，再加上 `builds`（Zeabur Builder 和 zot）、`image-updates`（Keel）和 `databases/cloudnative-pg`，裝完就能用映像檔或 Git 部署，也能建立 PostgreSQL 資料庫。Zeabur Builder 用有特權的 buildkitd 建置，逃出沙箱的建置可以碰到節點；用不到時在 `disable` 加上 `builds`。Zeabur 要有 ingress、憑證和 metrics-server 才能執行。

想要執行期偵測、漏洞掃描和入侵防護，就加上：

```yaml
enable: [runtime-security, vulnerability-scanning, intrusion-prevention]
```

`enable` 可以寫 capability（例如 `runtime-security`）或完整元件 ID（例如 `volume-backup/velero`），相依的元件會一起加入。`disable` 排除了另一個元件需要的元件時，`plan` 會列出兩者並停下。最後裝哪些元件、順序和排除原因，看 `plan` 的輸出。

已經裝好的元件從清單拿掉後，下次 `apply` 會移除這個元件。移除會連資料一起刪掉的元件，要先寫進 `allowDataLoss`，見[移除元件](./installer.mdx#移除元件)。

```yaml
inputs:
  volume-backup/velero:
    bucket: backups
    s3-url: https://s3.example.com
```

每個元件有哪些 input、型別是什麼，由 Catalog 定義。少了必填值時，`plan` 會指出要補哪個欄位。

Zeabur Builder 的 `cluster-ip`（zot 的固定位址）由 installer 自己填。要修改時，在 `inputs` 寫上值即可。

Velero 的 `region` input 是儲存貯體的區域，預設 `us-east-1`。Cloudflare R2 要寫 `auto`。網頁介面會分別詢問存取金鑰 ID 和私密存取金鑰，再自己組成 `credentials` 檔。

### `secretFiles`

機密輸入寫成檔案路徑，檔案權限設為 `0600`：

```yaml
secretFiles:
  volume-backup/velero:
    credentials: /root/secrets/velero-credentials
```

```sh
sudo chmod 0600 /root/secrets/velero-credentials
```

檔案內容依元件 input 的格式填寫，installer 會用這些檔案建立元件需要的 Secret。機密值放在檔案裡，不要寫進 `inputs`。Catalog 標為 `generate: random` 的機密如果沒指定檔案，第一次 `apply` 時自動產生，之後沿用。

### 儲存類別

installer 一定會建立 `local-path`，資料放在節點的 `/var/lib/zeabur/storage`。裝了 Longhorn 時，由 Catalog 對這個 profile 的設定決定誰是預設：`multi-node` 用 `longhorn`，`single-node` 維持 `local-path`。`plan` 會列出預設類別和其他類別。

- `local-path` 的磁碟區留在原本的節點，換預設類別不會搬移既有資料。
- Longhorn 成為預設時，installer 原本設為預設的 `local-path` 會改成一般類別。
- 叢集已有別的預設類別時，installer 保留原本的預設類別。如果這次要把 Longhorn 設為預設，`apply` 會停下，先拿掉原本類別的預設註解再執行一次。

選了 Longhorn 時，`apply` 會在這台主機安裝 iSCSI initiator 和 NFS client、載入 `iscsi_tcp`、啟動 `iscsid`。每個執行 Longhorn 的節點都要有這些，見[加入節點](../cluster/nodes.mdx)。

### `distribution` 與版本

不填 `distribution` 就裝 K3s。伺服器有 8 GiB 以上記憶體，或之後想用三台伺服器執行控制平面，就設成 `rke2`。

| 欄位 | 預設與用途 |
|---|---|
| `distribution` | `k3s`。K3s 比較省記憶體，只執行一台伺服器，可以再加工作節點。`rke2` 可以加工作節點和伺服器，三台伺服器時壞一台控制平面也不會停 |
| `k3sVersion` | installer 釘選的版本。要換 K3s 版本時填，例如 `v1.37.1+k3s1`。只能搭配 `distribution: k3s` |
| `rke2Version` | installer 釘選的版本。要換 RKE2 版本時填，例如 `v1.37.1+rke2r1`。只能搭配 `distribution: rke2` |

填了另一種的版本欄位，installer 會停下，例如：`rke2Version applies to distribution: rke2; this one is k3s (set k3sVersion)`。

預設版本的檔案用編譯進 installer 的 digest 驗證。換成其他版本時，只能用該 release 頁面自己的 checksum 清單驗證，`plan` 會標示這是未支援的版本，Catalog 測過的 Kubernetes 版本也可能對不上。

### `host`

| 欄位 | 預設與用途 |
|---|---|
| `host.tlsSan` | `[]`。Kubernetes API server 憑證額外加入的 DNS 名稱或 IP 位址，只用於 server |
| `host.requireEncryptedDisk` | `false`。設為 `true` 時，根目錄或資料目錄不在加密裝置上，`apply` 就停下 |
| `host.nodeName` | 主機名稱轉小寫。主機名稱不能當節點名稱，或是由 IP 位址組成（例如 `ip-10-0-0-5`）時，改用 `node-3f9a2c` 這類名稱。installer 把這個名稱寫進 K3s 或 RKE2 的設定，之後主機名稱改了，節點名稱也不會跟著改變。只能用小寫英文字母、數字、`-` 和 `.` |

節點裝好後就固定用當初的名稱。再執行一次 `apply` 會沿用原本的名稱；`host.nodeName` 填了別的名稱，`apply` 會停下，因為 Kubernetes 會把新名稱當成同一個位址上的第二個節點。

### `sources`

發行版的 installer 不需要 `sources`，installer 已經釘選了 Zeabur Catalog、Zeabur Identity 和 Zeabur 的版本，下載到 `/var/lib/rancher/zeabur-installer/downloads`，並用編譯進 installer 的 SHA-256 核對。

`sources` 用來改裝自己建置的版本，通常是開發測試。只寫要換的欄位，其他照用釘選的版本。自己編譯的開發版 installer 沒有釘選任何版本，所以 `catalog`、`identityImage`、`identityctl`、`zeaburImage`、`zeaburChart` 都要寫，少了哪個 `plan` 會列出來。路徑換成實際準備好的檔案：

```yaml
sources:
  catalog: /root/releases/catalog/index.json
  identityImage: registry.example.com/identity@sha256:<digest>
  identityctl: /root/releases/zeabur-identityctl
  zeaburImage: registry.example.com/zeabur@sha256:<digest>
  proxyImage: registry.example.com/proxy@sha256:<digest>
  zeaburChart: /root/releases/zeabur-chart
```

| 欄位 | 接受內容 |
|---|---|
| `catalog` | 本機 `index.json` |
| `imageArchives` | `docker save` 產生的封存檔路徑陣列，K3s 或 RKE2 啟動時匯入 |
| `identityImage` | Zeabur Identity 映像檔參照 |
| `identityctl` | 本機 `zeabur-identityctl` 執行檔 |
| `zeaburImage` | Zeabur 映像檔參照 |
| `proxyImage` | Zeabur Proxy 映像檔參照。可不寫，不寫就用 chart 內建的映像檔 |
| `zeaburChart` | Helm chart 目錄或封裝好的 `.tgz` |

從 `imageArchives` 拿掉的檔案，下次 `apply` 時也會從 K3s 或 RKE2 的匯入目錄移除。這份清單放的是已經在主機上的封存檔，和私有 registry 的存取設定無關。

## 自己用的檔案

頂層寫 `use: personal` 時，installer 改裝 KubeSolo 和元件，不裝 Zeabur 面板和 Zeabur Identity。做法和限制見[自己用：在小機器上安裝](../get-started/personal.mdx)。

```yaml title="/etc/zeabur-installer/config.yaml"
use: personal
enable: [builds]
host:
  tlsSan: [solo.example.com]
```

同一份檔案只能再放下表的欄位，`profile`、`access`、`zeabur`、`distribution`、`k3sVersion`、`rke2Version` 和 `join` 都不接受。

| 欄位 | 預設與用途 |
|---|---|
| `enable` | `[]`。Ingress 和憑證是預設的，只能再加 `builds`（Zeabur Builder，會連 zot 一起裝，記憶體要 1800 MiB 以上）、`databases`，或這幾個 capability 底下的元件 ID |
| `disable` | `[]`。排除 capability 或完整元件 ID |
| `allowDataLoss` | `[]`。和建立叢集的檔案一樣 |
| `inputs` | `{}`。和建立叢集的檔案一樣，依元件 ID 分組 |
| `secretFiles` | `{}`。和建立叢集的檔案一樣，檔案權限要是 `0600` |
| `host.tlsSan` | `[]`。自己的電腦用別的位址或網域連 API 時，把位址或網域加在這裡 |
| `host.requireEncryptedDisk` | `false`。設為 `true` 時，`/var/lib/kubesolo` 不在加密裝置上，`apply` 就停下 |
| `host.nodeName` | 和建立叢集時一樣，寫進 KubeSolo 的設定 |
| `sources.catalog` | 選填。本機的 Catalog `index.json`，取代釘選的版本 |

元件裝在 KubeSolo 內建的 `local-path` 儲存類別，資料放在 `/var/lib/kubesolo` 底下。KubeSolo、helm-controller 和 kubectl 的版本由 installer 釘選，沒有欄位可以改。

## 加入既有叢集的檔案

頂層有 `join` 時，installer 把這台機器當成要加入的新節點，只安裝 K3s 或 RKE2。同一份檔案只能再放 `distribution`、對應的版本欄位（`k3sVersion` 或 `rke2Version`）、`host` 和 `sources.imageArchives`，不能放 `profile`、`access` 這些建立叢集的欄位。

在既有 server 執行 `zeabur-installer node add` 取得完整 YAML，存到新主機。權杖和 server 設定都在裡面，不用自己拼。

| 欄位 | 預設與規則 |
|---|---|
| `distribution` | `k3s`。叢集用的種類，照 `node add` 印出的填 |
| `join.server` | 必填。server 的位址：K3s 用 `6443`，例如 `https://10.0.0.5:6443`；RKE2 用 `9345` |
| `join.role` | `worker`。`server` 只能用在 RKE2 |
| `join.token` | 和 `tokenFile` 擇一。直接寫權杖時，設定檔權限要是 `0600` |
| `join.tokenFile` | 和 `token` 擇一。權限 `0600` 的權杖檔案 |
| `join.serverConfig` | `server` 必填，worker 不接受。照抄 `node add --role server` 印出的 `disable` 和 `identity` |
| `join.longhorn` | `false`。`true` 時在 K3s 或 RKE2 啟動前先裝好 Longhorn 需要的主機套件 |
| `join.nodeNames` | `[]`。叢集裡已有的節點名稱，照 `node add` 印出的內容。新主機的名稱已經有人用時，節點會改用 `node-3f9a2c` 這類名稱 |

`host.nodeName` 用法和建立叢集時一樣，但不能和 `join.nodeNames` 裡的名稱重複。worker 不接受 `host.tlsSan`。`distribution` 和版本要和叢集一致。worker 的 bootstrap token 不能用來加入 server，要用 `node add --role server` 產生的設定。

## 設定無法使用時

- unknown field：檢查欄位大小寫，刪掉拼錯或放錯層級的 key。
- 主機名稱無效：拿掉 `https://` 和路徑，`identity` 和 `zeabur` 要用不同名稱。
- 缺少必填 input：依 `plan` 列出的元件和欄位補上，再執行一次 `plan`。
- K3s 設了 `join.role: server`：K3s 只執行一台用 SQLite 的伺服器，只收工作節點。要讓控制平面在少一台伺服器時繼續運作，改在三台伺服器上安裝 RKE2（`distribution: rke2`）。
- `host.nodeName: this host is already node …`：這台主機之前用別的名稱裝過。拿掉 `host.nodeName`，或改成訊息裡的名稱。
- 權杖檔案權限不對：在新主機執行 `chmod 0600`。含權杖的設定檔不要放進 Git 儲存庫。

改完設定檔先執行 `plan`。要移除產品、清理主機檔案，見[移除 Zeabur](../leave/uninstall.mdx)。
