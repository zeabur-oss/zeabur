到 **叢集** → **概覽** 的 **節點** 查看每台主機的狀況。要多一台主機執行服務，見[加入節點](#加入節點)。主機要停機維護時，在該節點的操作選單選 **維護模式**，等副本移到其他節點後再關機。

![叢集概覽的節點清單](https://oss.zeabur.com/shots/zeabur/zh-TW/light/cluster-nodes.avif)

## 開始之前

- 只有用 Zeabur Installer（RKE2）安裝的叢集能用 `zeabur-installer node add` 加節點。其他叢集用原本的安裝工具。
- 準備一台能用 root 操作的新 VM，以及安裝第一台伺服器時用的同一個 `zeabur-installer` 執行檔。
- 所有節點放在同一家主機服務商的同一個區域，同區域內不同的可用區域沒有問題。跨服務商或跨區域時，延遲會拖慢 etcd、Kubernetes API 和儲存。
- 維護需要修改 Node 和驅逐 Pod 的權限，移除節點還要能刪除 Node。節點終端機需要叢集管理員權限。

節點之間的防火牆要開放：

| 方向 | 連接埠 |
| --- | --- |
| 連到 RKE2 伺服器 | TCP 9345、6443 |
| 所有節點之間 | TCP 10250、9099，UDP 8472（Canal VXLAN） |
| RKE2 伺服器之間 | TCP 2379–2381 |

UDP 8472 只對叢集節點開放，不要對網際網路開放。Installer 的連線檢查測不到 UDP 8472，如果它被擋住，不同節點上的 Pod 會連不到彼此。

## 加入節點

加入節點的指令都在 `zeabur-installer`，完整選項見 [Installer 指令](../reference/installer.mdx#node-add-與-node-sync)。

<Steps>
<Step>

### 在現有的伺服器產生加入設定

以 root 登入現有的伺服器，執行：

```sh
sudo zeabur-installer node add --ttl 1h
```

指令印出新 VM 要執行的內容：寫入 `/etc/zeabur-installer/config.yaml` 的設定，以及 `plan` 和 `apply`。輸出裡的權杖等同密碼，不要貼到公開的地方。

加入工作節點用會過期的 bootstrap 權杖，`--ttl` 預設 1 小時，最長 24 小時。要加入伺服器（控制平面），加上 `--role server`，用的是叢集的 server 權杖，不會過期。新 VM 連不到伺服器的內部位址時，用 `--address` 指定它連得到的位址。

叢集跑 Longhorn 或 zot 鏡像時，輸出會自動帶上對應的設定。設定檔還寫著 `profile: single-node` 時，輸出會提醒你改成 `multi-node` 並重新 `apply`。

</Step>
<Step>

### 在新 VM 執行

把安裝第一台伺服器用的 `zeabur-installer` 複製到新 VM，以 root 貼上上一步的輸出。它會寫好設定檔，再執行：

```sh
zeabur-installer plan
zeabur-installer apply
```

`plan` 只列出網路檢查和警告，不改任何東西。有警告時先處理再繼續。`apply` 安裝 RKE2，等節點就緒才結束。

</Step>
<Step>

### 回到伺服器確認

```sh
sudo zeabur-installer node sync
sudo /var/lib/rancher/rke2/bin/kubectl --kubeconfig /etc/rancher/rke2/rke2.yaml get nodes -o wide
```

`node sync` 把新節點的位址加進 Installer 建立的基準網路政策。新加入的伺服器會自己同步，加入工作節點後要手動執行一次。看到新節點 `Ready` 後，撤銷工作節點的權杖，把 `<ID>` 換成 `node add` 輸出最後一行裡的 ID：

```sh
sudo /var/lib/rancher/rke2/bin/kubectl --kubeconfig /etc/rancher/rke2/rke2.yaml \
  -n kube-system delete secret bootstrap-token-<ID>
```

已加入的節點不受影響，之後也不能再用這份權杖加入。

</Step>
</Steps>

etcd 需要過半數的伺服器才能運作。要在少一台時繼續運作，至少要三台伺服器。只有兩台時，任一台停機整個叢集就會停擺。

## 讓節點停機維護

只想讓新副本不再放到這個節點，在節點的操作選單選 **停止排程**，檢查後套用。上面正在執行的副本會繼續執行。

要先移走副本再維護主機：

1. 選 **維護模式**。視窗會分成 **移到其他節點**、**無法移走**、**不屬於任何服務** 和 **留在節點上** 四類列出副本。
2. 看其他節點放不放得下。Zeabur 只用副本的保留量估算，不考慮 taint 和 affinity 這類排程限制。
3. 確認本機磁碟區、暫存空間和不屬於任何服務的副本怎麼處理，再按 **套用**。
4. 保持視窗開著，直到進度跑完。Zeabur 只在視窗開著時移出副本，移動途中離開頁面會先詢問。離開後節點維持停止排程，節點名稱下方會出現 **繼續維護**，按下就能移走剩下的副本。受 PodDisruptionBudget 限制的副本會等待，處理原因後按 **再試一次**。
5. 畫面顯示節點已進入維護後，看一下留在原地的副本，再安排主機停機。

<Callout type="warn">
local-path 磁碟區的資料只在這個節點上。維護預設把用到這些資料的副本留在原地。如果勾選仍要移走，這個節點回來前，這些副本都無法使用。移走的副本，暫存空間會清空。不屬於任何服務的 Pod 刪掉後不會再啟動。
</Callout>

DaemonSet 和節點自己啟動的 Pod 會留在節點上。節點執行控制平面時，控制平面的元件也會留在上面，這台主機停機時叢集可能沒有回應。

Zeabur 本身也在這個節點上時，會等其他副本都移走後最後才移走，頁面會斷線一分鐘左右。之後重新整理頁面、重新登入，再開一次管理員權限。

## 開啟節點終端機

**節點終端機** 會在主機上開一個完整的 root shell。先取得管理員權限，在節點列按 **節點終端機**，看過要建立的終端機 Pod 和時限，再按 **開啟終端機**。

<Callout type="warn">
節點終端機能動主機上所有的檔案、程序和網路介面。在裡面做的事不經過 Zeabur 和 Kubernetes 的權限檢查，也無法復原。
</Callout>

節點會記下一筆事件，寫明是誰在什麼時候開啟的。畫面顯示 **其他人也能進入這個終端機** 時，表示有角色綁定讓叢集管理員以外的人能在終端機所在的 Namespace 建立 Pod。移除列出的角色綁定後再重新檢查。

關閉終端機時，Zeabur 會移除終端機 Pod，Pod 最多保留 30 分鐘。如果 Pod 留了下來，在節點下方的終端機 Pod 清單按 **移除終端機 Pod**，檢查後確認。

## 常見失敗

- 加入時連不到伺服器：確認新 VM 連得到 `node add` 印出的伺服器位址的 TCP 9345、6443，以及上面表格的其他連接埠。
- 新節點已就緒，但不同節點上的服務連不到彼此：檢查 UDP 8472，以及網路政策是否已放行新節點。
- 副本移不走：維護視窗會寫出原因，例如 **等待 PodDisruptionBudget 放行**、**你沒有權限移走它**，或資料只在這個節點上。
- 維護視窗被關掉：節點維持停止排程。按節點名稱下方的 **繼續維護**，看過剩下的副本後再套用。
- 終端機 Pod **無法啟動**：看該 Pod 的事件，常見原因是映像檔下載失敗。

## 恢復排程與清除

主機維護完、節點回到就緒後，在操作選單選 **恢復排程**，檢查並套用，新的副本就會再排到這個節點。確認受影響的服務都恢復後，移除用不到的終端機 Pod。

## 移除節點

要讓一台 VM 永久離開叢集，在節點的操作選單選 **移除節點**。

1. 節點就緒而且上面還有能移走的副本時，視窗會請你先按 **開始維護**。照「讓節點停機維護」移走副本，跑完後按 **移除節點**。
2. 有副本把資料放在這個節點的磁碟區時，要勾選 **連同節點刪除這些資料** 才能繼續。
3. 檢查後按 **移除節點**。Zeabur 會刪除 Kubernetes 的 Node 物件。
4. 在那台 VM 以 root 執行畫面列出的指令，解除安裝 RKE2 和 Installer 的檔案：

   ```sh
   /usr/local/bin/rke2-uninstall.sh
   zeabur-installer uninstall --purge
   ```

   執行之前，只要 RKE2 重新啟動，這台 VM 就會再加入叢集。`/var/lib/zeabur/storage` 底下的磁碟區會留在 VM 上，不再需要時手動刪除。

叢集唯一的節點，以及唯一執行控制平面的節點都不能移除。要移除伺服器時，先加入另一台伺服器。移除後剩不到三台伺服器時，視窗會提醒控制平面少一台就無法運作。

移除後，在伺服器執行 `sudo zeabur-installer node sync`，把已移除節點的位址從基準網路政策拿掉。
