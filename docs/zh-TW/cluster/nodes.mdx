到**叢集** → **概覽**的**節點**查看每台主機的狀況。要多一台主機執行服務，見[加入節點](#加入節點)。主機要停機維護時，在該節點的操作選單選**停止排程**，需要移走副本時再用 kubectl 的 `drain`。

![叢集概覽的節點清單](../images/shots/cluster-nodes.avif)

## 開始之前

- 準備一台能用 root 操作的新 VM。K3s 只能加工作節點；RKE2 可以加工作節點和伺服器，三台伺服器時壞一台控制平面也不會停。
- 所有節點放在同一家主機服務商的同一個區域，同區域內不同的可用區域沒有問題。跨服務商或跨區域時，延遲會拖慢 etcd、Kubernetes API 和儲存。
- 停止排程和恢復排程需要修改 Node 的權限。`drain` 和 `delete node` 在 kubectl 終端機執行，用的是你自己的權限。節點終端機要用管理員帳號開啟。

節點之間的防火牆要開放：

| 方向 | K3s | RKE2 |
| --- | --- | --- |
| 連到伺服器 | TCP 6443（[限制來源](../reference/security.mdx#kubernetes-api)） | TCP 9345、6443 |
| 所有節點之間 | TCP 10250，UDP 8472（flannel VXLAN） | TCP 10250、9099，UDP 8472（Canal VXLAN） |
| 伺服器之間 | 不用 | TCP 2379–2381 |

用 zeabur-installer 裝的 K3s 叢集使用 Calico，UDP 連接埠是 4789，不是 8472。UDP 連接埠只對叢集節點開放，不要對網際網路開放。防火牆擋住 UDP 時，不同節點上的副本會連不到彼此。

## 加入節點

Zeabur 不負責加入節點；用 Zeatend 裝好的叢集，由 Zeatend 加入。先開好上面的防火牆連接埠，再到伺服器執行：

```sh
sudo zeatend node add
```

指令會印出一份含加入權杖的設定，以及要在新 VM 執行的指令。RKE2 要加伺服器而不是工作節點時，加上 `--role server`。在新 VM 上先[下載 Zeatend](https://github.com/zeabur-oss/zeatend#download-zeatend)，再以 root 執行印出來的指令。`zeatend plan` 會檢查連接埠和到伺服器的距離，`zeatend apply` 會讓 VM 加入叢集，並等節點變成 `Ready`。

工作節點的權杖一小時內有效，可以用 `--ttl` 調整。節點 `Ready` 後，用 `node add` 印出的最後一行指令撤銷權杖。RKE2 伺服器拿到的是叢集的伺服器權杖，不會過期，不要貼到聊天室或工單裡。

不是用 Zeatend 裝的叢集，照發行版自己的步驟把 VM 加進來。節點在**節點**清單顯示 `Ready` 後，新的副本就能排到它上面。

RKE2 的 etcd 需要過半數的伺服器才能運作。要在少一台時繼續運作，至少要三台伺服器。只有兩台時，任一台停機整個叢集就會停擺。K3s 叢集只有一台伺服器，這台停機時控制平面也會停止，伺服器回來後才會恢復。

## 讓節點停機維護

### 只是重開機

在節點選單選**停止排程**，節點列就會標示已停止排程。新的副本不會再排到這台節點，已經在執行的副本會留在原處。只是要重開機，做到這一步就夠了，不需要執行 `drain`。

也可以在 Zeabur **叢集**頁標題旁點**開啟 kubectl 終端機**，執行：

```sh
kubectl cordon <node>
```

把 `<node>` 換成節點名稱。重開機完成後，再恢復排程。

### 要先移走副本再維護

到 Zeabur **叢集**頁標題旁點**開啟 kubectl 終端機**，先列出這台節點上的副本，以及這些副本使用的 PVC：

```sh
kubectl get pods -A --field-selector spec.nodeName=<node> -o custom-columns=NS:.metadata.namespace,POD:.metadata.name,PVC:.spec.volumes[*].persistentVolumeClaim.claimName
```

對照清單中的 PVC，確認哪些使用這台節點的 `local-path` 磁碟區。這些磁碟區的資料只存在這台節點上，不會跟著副本移到其他節點。

確認後，執行：

```sh
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
```

`drain` 會停止這台節點的排程，並驅逐副本，讓控制器在其他節點重新建立。DaemonSet 管理的副本會留在原處。執行時請注意：

- `drain` 會遵守 PodDisruptionBudget；預算不允許驅逐時，`drain` 會一直重試。
- 遇到不屬於任何控制器的副本，`drain` 會停下來。這類副本刪掉後不會自動啟動，確認可以刪除後，才在指令末尾加上 `--force`。
- `--delete-emptydir-data` 會清空遭驅逐副本的 `emptyDir` 暫存資料。
- 使用這台節點 `local-path` 磁碟區的副本也會一併驅逐。重新建立的副本無法在其他節點使用這些磁碟區，原節點回來之前都會維持 `Pending`。資料不會因為 `drain` 遺失；對這些副本來說，結果跟直接停機一樣，都得等這台節點恢復。

如果 Zeabur 自己也在這台節點上執行，`drain` 時頁面會斷線約一分鐘。重新整理頁面並重新登入；kubectl 終端機也會斷線，需要重新開啟。

等 `drain` 完成後，再將節點停機維護。

## 恢復排程

維護完成、節點恢復運作後，在節點選單選**恢復排程**。

也可以到 Zeabur **叢集**頁標題旁點**開啟 kubectl 終端機**，執行：

```sh
kubectl uncordon <node>
```

恢復排程後，新的副本就能排到這台節點。

## 移除節點

**不要移除叢集唯一的節點，也不要移除最後一台控制節點。**

先到 Zeabur **叢集**頁標題旁點**開啟 kubectl 終端機**，確認控制節點數量：

```sh
kubectl get nodes -l node-role.kubernetes.io/control-plane
```

如果只剩一台控制節點，不要刪除。移除後如果剩不到三台 server 節點，控制平面再少一台就無法運作。

`local-path` 磁碟區的資料只在這台 VM 上。節點移除後，使用這些磁碟區的副本沒有地方可以啟動。依照「讓節點停機維護」的步驟檢查副本與磁碟區，再執行 `drain`，完成後才刪除節點：

```sh
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
kubectl delete node <node>
```

接著登入移除的那台 VM，執行：

```sh
sudo zeatend uninstall
```

節點不是用 Zeatend 加入的，就改用發行版的解除安裝腳本，例如 `k3s-agent-uninstall.sh`。

**刪除 Kubernetes 節點後，還要完成 VM 上的解除安裝**。在執行解除安裝前，只要 `k3s-agent` 或 RKE2 重新啟動，這台 VM 就會再次加入叢集。

`/var/lib/zeabur/storage` 底下的磁碟區會留在 VM 上。確認不再需要這些資料後，再加上 `--delete-volumes`。

如果叢集使用 Longhorn，Longhorn 會替已刪除的節點留著節點資料。節點上還有副本時，Longhorn 不會讓你刪除。請先確認每個磁碟區在其他節點都有健康的副本，再執行：

```sh
kubectl -n longhorn-system patch nodes.longhorn.io <node> --type=merge -p '{"spec":{"allowScheduling":false}}'
for r in $(kubectl -n longhorn-system get replicas.longhorn.io -o jsonpath='{range .items[?(@.spec.nodeID=="<node>")]}{.metadata.name}{"\n"}{end}'); do kubectl -n longhorn-system delete replicas.longhorn.io "$r" --wait=false; done
kubectl -n longhorn-system delete nodes.longhorn.io <node>
```

## 開啟節點終端機

**節點終端機**會在主機上開一個完整的 root shell。用管理員帳號登入，在節點列按**節點終端機**，看過要建立的終端機副本和時限，再按**開啟終端機**。

<Callout type="warn">
節點終端機能動主機上所有的檔案、程序和網路介面。在裡面做的事不經過 Zeabur 和 Kubernetes 的權限檢查，也無法復原。
</Callout>

節點會記下一筆事件，寫明是誰在什麼時候開啟的。畫面顯示**其他人也能進入這個終端機**時，表示有角色綁定讓叢集管理員以外的人能在終端機所在的 Namespace 建立副本。移除列出的角色綁定後再重新檢查。

關閉終端機時，Zeabur 會移除終端機副本，副本最多保留 30 分鐘。如果副本留了下來，在節點下方的終端機副本清單按**移除終端機副本**，檢查後確認。

## 常見失敗

- 加入時連不到伺服器：在新 VM 執行 `sudo zeatend plan`，它會逐一檢查連接埠。K3s 要通 TCP 6443，RKE2 要通 TCP 9345 和 6443，上面表格的其他連接埠也要開。
- 新節點已就緒，但不同節點上的服務連不到彼此：檢查 UDP 8472（用 zeabur-installer 裝的 K3s 叢集是 4789），以及網路政策是否已放行新節點。
- `drain` 一直停著：`drain` 在等 PodDisruptionBudget 放行，或停在不屬於任何控制器的副本上。用 `kubectl get pdb -A` 看哪個預算擋住了，處理後再執行一次。
- 副本在新節點 `Pending`：副本用的是舊節點的 `local-path` 磁碟區，要等舊節點回來。
- 終端機副本**無法啟動**：看該副本的事件，常見原因是映像檔下載失敗。
