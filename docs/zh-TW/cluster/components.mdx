打開**叢集** → **元件**，**已安裝**列出偵測到的元件，**目錄**列出 Zeabur Catalog 裡的元件。在 K3s 和 RKE2 上，叢集管理員可以直接在這裡安裝和移除元件。其他叢集，或想把元件放在 GitOps 儲存庫管理時，用 `zeaburctl components export` 印出 manifest，自己套用。

![叢集元件頁的已安裝清單和目錄](../images/shots/cluster-components.avif)

## 開始之前

你能讀取整個叢集的 CRD、IngressClass 和各 Namespace 的工作負載，元件頁才偵測得到已安裝的元件。

## 確認叢集裡有什麼

**已安裝**列出偵測到的元件、版本和安裝來源（K3s、HelmChart 或 Helm），並標出版本是 Zeabur Catalog 的**已測試版本**，還是**比已測試版本新**。元件停擺時會標**異常**。

**目錄**可以用**已安裝**或**推薦**篩選，也可以用**搜尋元件**找名稱或用途。

如果備份、通知這類功能頁已經能用，元件卡片卻還顯示**安裝**，代表元件頁沒偵測到它，多半是用其他名稱或方式安裝的。先找到現有的部署，不要再裝一份。

## 從頁面安裝

只有能在叢集裡做任何事的人（`cluster-admin`）可以從這裡安裝：Zeabur 會把每個 Chart 交給叢集的 helm-controller，由它用完整權限安裝。叢集要有 helm-controller，K3s 和 RKE2 都內建。

<Steps>
<Step>

### 檢查步驟

在元件卡片按**安裝**，視窗會列出每個步驟和它要寫入的物件，按物件可以看 YAML。叢集缺少這個元件需要的其他元件時，會先安裝缺少的元件。這時還不會寫入任何東西。

</Step>
<Step>

### 安裝

按**安裝**。Zeabur 用你的帳號一次寫入一個步驟，前一步就緒後才寫入下一步。視窗開著，等每個步驟和健康檢查都顯示**就緒**；中途關掉的話，在卡片按**管理**會從停下的地方接著做。健康檢查花的時間比預期久時，視窗會說明該檢查什麼。

</Step>
</Steps>

視窗顯示元件已經安裝、但不是 Zeabur 裝的時，Zeabur 不會動它。要升級或移除，用當初安裝它的工具。

## 用 zeaburctl 安裝

<Steps>
<Step>

### 看要執行的指令

**新增**選單、範本、建置設定或資料庫備份缺少元件時，按**安裝方式**會開啟視窗，一次列出這件事缺的所有元件和要執行的指令，指令可以直接複製。

</Step>
<Step>

### 印出 manifest 並套用

用 `zeaburctl components export` 印出元件的 manifest，或印出安裝它的 Helm 指令：

```sh
zeaburctl components export velero > velero.yaml
zeaburctl components export velero --format helm
```

一次要裝好幾個時，把 ID 都寫上，例如 `zeaburctl components export zeabur-builder keel`，內容會依序接在一起。

預設印出 K3s/RKE2 的 `HelmChart`，由叢集內建的 helm-controller 安裝。其他叢集用 `--format` 改成 `helm`、`flux` 或 `argocd`。元件要填的值會留成 `<名稱>`，先換成實際的值，再用 `kubectl apply -f` 套用，或提交到 GitOps 儲存庫。指令說明見 [zeaburctl](../reference/zeaburctl.mdx#components-export)。

</Step>
<Step>

### 確認安裝結果

回到**叢集** → **元件**，**已安裝**會出現這個元件和版本。再到需要它的功能頁確認，例如 Velero 對應**叢集** → **備份**，VictoriaMetrics 對應**叢集** → **通知**。

</Step>
</Steps>

### 替換 K3s/RKE2 內建元件

匯出的內容開頭要你先停用內建版本時，依叢集的發行版處理每台 server，再套用：

- K3s：在 `/etc/rancher/k3s/config.yaml` 把列出的元件加進 `disable`，重新啟動 `k3s`。
- RKE2：metrics-server 是在 `/etc/rancher/rke2/config.yaml` 把 `rke2-metrics-server` 加進 `disable`；Traefik 是在同一個檔案設定 `ingress-controller: none`。之後重新啟動 `rke2-server`。

<Callout type="warn">
停用內建的 Traefik 會刪除 Traefik 的 CRD 和所有 IngressRoute、Middleware 物件，新的元件開始執行前，Ingress 流量會中斷。停用內建的 metrics-server 時，新版本開始執行前 metrics API 無法使用。挑可以中斷的時段切換。
</Callout>

## 移除元件

要移除 Zeabur 裝的元件，在卡片按**管理**。每個步驟和健康檢查都就緒後，視窗會改成移除；安裝還沒完成時，例如健康檢查失敗，視窗會在**安裝**旁邊顯示**移除**。檢查步驟後按**移除**。Zeabur 會照相反的順序刪除元件的物件；刪掉 Chart 後，helm-controller 會解除安裝。視窗會列出會留下的東西，例如 CRD 和金鑰。還有其他已安裝的元件需要這個元件，或它的自訂資源在自己的 Namespace 以外還有物件在用時，Zeabur 會拒絕移除，並列出是哪些。

不是 Zeabur 裝的元件，用當初安裝它的檔案或工具移除，例如 `kubectl delete -f`、`helm uninstall`、Flux 或 Argo CD。

移除前先確認沒有東西還在用它，例如還有這個元件的自訂資源、還有 Longhorn 的磁碟區，或還有副本從 zot 拉映像檔。Longhorn 這類保存資料的元件，移除時會連資料一起刪掉，先備份。

移除後，元件的 Namespace 和磁碟區會留著。有些 Chart 會連 CRD 和它們的所有物件一起刪掉，其他 CRD 會留著。確定用不到留下的東西後，再手動刪除。

## 目錄從哪裡下載

Zeabur 從 `https://oss-catalog.zeabur.com/v1/` 下載 Zeabur Catalog，手上的版本超過 10 分鐘就重新下載。最後下載到的版本會存在它所在 Namespace 的 ConfigMap `zeabur-catalog`，重新啟動或目錄暫時連不上時都還在。元件頁會顯示目前用的版本和下載時間。

Zeabur 下載不到目錄、手上也沒有存好的版本時，頁面會說明原因，並提供**重試**。已安裝的元件和所有服務照常運作，只有安裝元件時才需要目錄。

### 改用鏡像

叢集連不上網際網路時，自己用 HTTPS 提供一份目錄：

1. 從 [Zeabur Catalog 的發行版本](https://github.com/zeabur-oss/catalog/releases)下載 `api-v1.tar.gz` 並解開，裡面是 `v1` 資料夾。
2. 用任何網頁伺服器提供裝著 `v1` 的資料夾，走 HTTPS，憑證要是叢集信任的。用私有 CA 時，見[信任私有 CA](../install/existing-cluster.mdx#信任私有-ca)。
3. 讓 Zeabur 改從鏡像下載：

   ```sh
   helm upgrade zeabur oci://ghcr.io/zeabur-oss/charts/zeabur \
     --version <版本> \
     --namespace zeabur --reset-then-reuse-values \
     --set catalog.url=https://catalog.example.internal/v1/
   ```

網址必須以 `https://` 開頭。目錄只寫了要裝哪些 Chart 和映像檔，helm-controller 和節點還是會從原本的 Registry 拉，所以這些也要準備鏡像。

[範本更新](../reference/telemetry.mdx#範本更新)也從這個網址讀取。

## 常見失敗

- 元件頁顯示權限不足：把畫面列出的缺少權限交給叢集管理員。
- 步驟顯示**失敗**：看它的訊息。Chart 的話，也看 `kube-system` 裡 `helm-install-<名稱>` Job 的日誌。
- 裝完一直沒出現在**已安裝**：看 `kube-system` 裡 `helm-install-<名稱>` Job 的日誌，以及元件的工作負載有沒有啟動。
