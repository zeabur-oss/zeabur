The service's **Networking** tab covers three things: **Private network** lists the addresses other services in the cluster use to connect to it, **Public ports** lets clients outside the cluster connect directly without a domain, and **Connection rules** controls which services can connect to it and where it can connect. For public domains and HTTPS, see [Add a public domain and HTTPS](./domains.mdx).

![The web service's Networking tab, showing public domains and the private network](../images/shots/service-networking.avif)

## Before you start

- You need permission to modify services in the project. For services managed by Helm, Argo CD, or Flux, use that tool to expose ports or add rules instead.
- Connection rules depend on the cluster's network plugin (CNI) to enforce them. K3s's built-in controller supports them. If the plugin doesn't, you can still create rules, but they block nothing.
- Exposing ports requires a load balancer. K3s's built-in ServiceLB and the RKE2 setup installed by the Zeabur installer both include one.

## Connect to other services with private addresses

Each row in **Private network** is a Kubernetes Service, such as `web:8080`. Services in the same project connect directly to this address, for example, `http://web:8080`.

To connect from another project, use the full address next to **From another project**, such as `web.demo.svc.cluster.local:8080`. If **Isolate** is enabled for the project, first add the other project to **Let a project in** under **Network** in the project's **Settings**. See [Isolate from other projects](./projects.mdx#isolate-the-project-from-other-projects).

These addresses only work inside the cluster. They aren't reachable from the internet.

### When a service has no private address

A background service that only makes outgoing connections doesn't need a private address. To let other services or a public domain connect to it, create a Service first. **Private network** shows a command you can copy, for example:

```sh
kubectl -n demo expose deployment web --port=8080
```

If the traffic check uses a numeric port, the command includes that port. Otherwise, it uses `--port=<port>`. Replace `<port>` with the port the app listens on before running it.

## Expose a port to the internet

Use public ports to let clients outside the cluster connect to non-HTTP services, such as databases, game servers, and MQTT.

<Steps>
<Step>

### Choose a port

Under **Public ports** in the service's **Networking** tab, click **Open a port**, then choose the port in **Port**. Only ports on private addresses are available.

</Step>
<Step>

### Review and apply

Click **Review changes**, confirm the changes, and apply them.

</Step>
<Step>

### Get the address

The list shows each node's address and port, such as `203.0.113.7:5432`, with a copy button next to it. If it shows **Port 5432 is waiting for the load balancer to assign an address.**, the load balancer is still processing the request, or another service is already using that port on the node.

</Step>
</Steps>

<Callout type="warn">
Public ports have no password or HTTPS protection in front of them. Anyone on the internet can connect, so the service must authenticate incoming connections itself. When you expose a database, the interface labels it **Database open to the internet**. If only services in the project need to connect to the database, use a private address instead.
</Callout>

ServiceLB listens on the same port number on every node, so a port number can only be exposed once across the cluster. Zeabur rejects the change if another service in the same project already exposes that port.

To close a port, click **Close** in its row, review the change, and apply it.

## Restrict incoming and outgoing connections with connection rules

The top of **Connection rules** states who can currently connect, such as **web only accepts connections from 1 service**. Below it, the **Incoming** and **Outgoing** columns list which connections are allowed, partially allowed, or blocked. If the project has no rules, all connections are allowed.

Click **Add rule** and choose a type:

| Rule | Effect |
| --- | --- |
| **Isolate this service** | Only replicas in the same project can connect to it. It can only connect to services in the same project and DNS, not the internet. |
| **Allow traffic from public domains** | Lets Traefik forward requests from public domains to the service. |
| **Allow from a service…** | Choose a service in the same project and let it connect. |

Rules are additive. A common setup is to **Isolate this service** first, then add **Allow traffic from public domains** and the services that need to connect.

<Callout type="warn">
After isolation, the service's public domains stay unreachable until you add **Allow traffic from public domains**.
</Callout>

To let an isolated service connect to an external API, add the address to **Where its replicas can connect** under **IP limits** on the same page. See [Restrict incoming and outgoing IP addresses](./ip-limits.mdx).

To delete a rule, click its name to open the **Objects** page, then click **Delete** in the YAML view.

## Do the same with kubectl

Private addresses use standard ClusterIP Services, public ports use `LoadBalancer` Services, and connection rules use standard NetworkPolicies. The examples below use the project `demo`.

### Private addresses

```yaml
apiVersion: v1
kind: Service
metadata:
  name: web
  namespace: demo
  labels:
    app.kubernetes.io/name: web
spec:
  selector:
    app.kubernetes.io/name: web
  ports:
    - name: http
      port: 8080
      targetPort: 8080
```

The `selector` must match the Deployment's replica labels.

### Public ports

When Zeabur exposes a port, it creates `<Service name>-public-<port>`, copies the source Service's `selector` and that port, and sets the type to `LoadBalancer`. The `app.kubernetes.io/name` label holds the service name, so this Service is deleted along with the service. To expose port 5432 on `db`:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: db-public-5432
  namespace: demo
  labels:
    app.kubernetes.io/name: db
spec:
  type: LoadBalancer
  selector:
    app.kubernetes.io/name: db
  ports:
    - name: postgres
      port: 5432
      targetPort: 5432
      protocol: TCP
```

To close the port, delete this Service:

```sh
kubectl -n demo delete service db-public-5432
```

### Connection rules

All rules Zeabur creates have the label `app.kubernetes.io/managed-by: zeabur` and a name in the form `zeabur-<rule>-<service>`, truncated to 63 characters if needed. The examples below use the service `api`.

**Isolate this service**:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-isolate-api
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector:
    matchLabels:
      app.kubernetes.io/name: api
  policyTypes: [Ingress, Egress]
  ingress:
    - from:
        - podSelector: {}
  egress:
    - to:
        - podSelector: {}
    - to:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: kube-system
          podSelector:
            matchLabels:
              k8s-app: kube-dns
      ports:
        - protocol: UDP
          port: 53
        - protocol: TCP
          port: 53
```

**Allow connections from a service**, letting `web` connect to `api` in this example:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-allow-web-api
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector:
    matchLabels:
      app.kubernetes.io/name: api
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector:
            matchLabels:
              app.kubernetes.io/name: web
```

**Allow traffic from public domains**. The rule allows Traefik from two locations: K3s's built-in Traefik in `kube-system` and Traefik installed by the Zeabur installer in a namespace labeled `zeabur.com/platform: "true"`:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: zeabur-allow-ingress-api
  namespace: demo
  labels:
    app.kubernetes.io/managed-by: zeabur
spec:
  podSelector:
    matchLabels:
      app.kubernetes.io/name: api
  policyTypes: [Ingress]
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: kube-system
          podSelector:
            matchLabels:
              app.kubernetes.io/name: traefik
        - namespaceSelector:
            matchLabels:
              zeabur.com/platform: "true"
          podSelector:
            matchLabels:
              app.kubernetes.io/name: traefik
```

Delete a rule:

```sh
kubectl -n demo delete networkpolicy zeabur-isolate-api
```

## Verify the result

**Private network** lists each Service and its ports. **Public ports** lists each node's address and labels databases **Database open to the internet**. **Connection rules** lists the names of rules applied to this service and which connections **Incoming** and **Outgoing** allow.

```sh
kubectl -n demo get service
kubectl -n demo get networkpolicy -l app.kubernetes.io/managed-by=zeabur
kubectl -n demo run probe --rm -it --restart=Never --image=busybox:1.37 -- wget -qO- -T 3 http://api:8080
```

In the `TYPE` column of `get service`, private addresses use `ClusterIP`, and public ports use `LoadBalancer`. `EXTERNAL-IP` is the node's address. The last command connects to `api` from a temporary replica in the same project. If `api` is isolated and doesn't allow `probe`, the connection times out after 3 seconds. From outside the cluster, use `nc -vz 203.0.113.7 5432` to check that the public port is reachable.

## Troubleshooting

| What you see | What to do next |
| --- | --- |
| **web has no private address** | Run the `kubectl expose` command shown in the interface, or apply the Service above. |
| `kubectl expose` returns `couldn't find port via --port flag or introspection` | The container doesn't declare a port. Add the port the app listens on after `--port=`. |
| **Waiting for the load balancer to assign an address** doesn't go away | Another service is already using that port on the node, or the cluster has no load balancer. Choose another port, or ask an administrator to check ServiceLB. |
| Exposing a port returns a message that another service already exposes the same port | That port number is already exposed in the same project. Close the existing one first. |
| Public domains time out after isolation | Add **Allow traffic from public domains**. |
| A service can't connect to an external API after isolation | Isolation only allows connections within the same project and to DNS. Add the external API's address to **Where its replicas can connect** under **IP limits**. |
| Connections still work after adding a rule | The cluster's network plugin doesn't support NetworkPolicy. |
